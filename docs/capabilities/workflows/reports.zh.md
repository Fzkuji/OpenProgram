# 准备每周报告

报告套件包含三个独立版本的子 Workflow 和总入口 `report`，需要安装到 Programs 目录。
源码 checkout 本身不会安装这些包；这些 Workflow 支持独立执行和通过 `report` 组合。微信读取依赖可访问的搜索与会话控件；控件不可用时返回可恢复状态，不会标记汇总完成。

| 入口 | 用途 | 外部写入 |
| --- | --- | --- |
| `weekly_report(task)` | 个人草稿、明确要求的飞书查看或修改 | 仅独立的明确提交或修改请求允许写飞书 |
| `group_weekly_report(task)` | 收集组员周报、核对缺失人员、生成本地汇总 | 不发送微信消息 |
| `tencent_weekly_report(task)` | 周五下午给 leader 的约 100 字腾讯进度 | 只生成本地稿 |
| `report(task)` | 路由多类报告并分别保留结果 | 组合调用只生成草稿，不继承个人提交授权 |

## 准备多份报告

在 Abilities 中选择 `report`，将下面 JSON 作为字符串填入 `task`：

```json
{
  "requests": {
    "personal": {
      "week": "2026-W37",
      "materials": [{"id": "p1", "week": "2026-W37", "text": "实验仍在进行，下周核对结果。"}]
    },
    "tencent": {
      "week": "2026-W37",
      "materials": [{"id": "t1", "week": "2026-W37", "text": "腾讯评估仍在进行，尚无最终性能结论。"}]
    }
  }
}
```

各类报告的材料分别提供。个人与腾讯结构化输入要求 ISO 周次一致、来源 ID 唯一。
证据不足时返回待补充或待核验，不补造进度。模型辅助语义检查不能保证事实绝对正确。

小组请求需提供 `source`（`wechat` 或显式提供材料时的 `supplied`）、`group`、`week`
和有序的 `members`。提供的每条材料还需标识 `member`。微信不暴露消息控件时，可使用有页数限制的窗口 OCR，保留截图和原始 OCR 行作为本地来源。无法核实作者、日期、截断消息或低置信度边界时，不将内容列为已核实材料。搜索焦点无法核验时，先打开指定群再恢复，消息读取与整理由 Workflow 执行。窗口禁止截图时返回 `WINDOW_CAPTURE_UNAVAILABLE`，不更改屏幕或微信设置。总入口使用非交互等待，其他报告仍可完成。

自然语言可选择报告类型。明确的单一类型使用代码路由，混合材料使用有界模型提取，
并验证来源片段保持原文。类型不清楚时要求明确受众。

## 继续未完成项

总入口为每项返回状态及 `resume_task`。将恢复对象重新作为 `task`，可增加按报告区分的补充信息：

```json
{
  "resume": "/absolute/path/to/checkpoint.json",
  "updates": {
    "tencent": {
      "materials": [{"id": "t2", "week": "2026-W37", "text": "补充的已核实腾讯进度。"}]
    }
  }
}
```

已完成报告不会重跑；恢复时不能直接替换已完成或结果不确定的报告。
中断后标为 `IN_PROGRESS` 的子项不自动重复，需核对结果后再发起新请求。
本地保存失败保留已有稿件；腾讯模型失败保留生成与核验预算。检查点和恢复输入含私人报告材料，应保留在本地。

## 腾讯周五下午汇总

腾讯稿件目标约 100 字，接受 80–120 个非空白字符。用途时间为 `Asia/Shanghai` 周五下午。
Workflow 本身不创建定时任务，也不发送给 leader；启用定时运行前需另外配置精确时刻和材料来源。
