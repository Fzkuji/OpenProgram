操控电脑

一个工具 computer_use 让模型操作屏幕。每次调用都写明落在哪里：一个 type，不是这台电脑时再加 device。应用窗口在后台操作：不会有窗口跳到前面，键盘和鼠标仍归你。

目标

调用操作什么何时列出
type="window"这台电脑上的应用窗口，按元素树操作，由 app 指定：访达、备忘录、Xcode、聊天客户端、游戏启动器。title 选其中一个窗口。macOS、X11 下的 Linux 或 Windows。见要求。
type="screen"这台电脑的一整块显示器，按像素操作：桌面、菜单栏、系统对话框、跨窗口拖动。会移动你的指针。macOS，且打开了 computer_use.whole_screen；默认关闭
type="browser"本会话在 App 内置浏览器里的页面；App 关闭时用没有 App 登录状态的后台浏览器浏览器应用已启用
type="browser", app="chrome"、"safari"、"firefox" 等你自己的浏览器，带你的标签页和登录状态装了这个浏览器；Chromium 系浏览器还要装扩展
device="lab", type="screen"你设置的一台设备的屏幕，这里是名为 lab 的设备该设备有屏幕连接且已开启。见另一台设备。

不写 device 的调用总是这台电脑，会话的命令在 SSH 主机或 Docker 里运行时也一样。你点名却没写设备的窗口、浏览器或应用都在这台电脑上。

模型如何学会动作
部分规则
能操作什么你的消息旁边有一段 <devices> 说明，按设备列出，这台电脑在前：开始时和压缩后发整张列表，之后只发新增、变化和移除的。工具自己的描述从不改变，所以连上设备不会让提示缓存失效。缺少系统权限的目标仍列出，并写明要授予什么。没有任何目标时不提供该工具。
首次调用某目标返回其类型的指南（window、screen 或 browser）、该目标的简短说明（系统、缺什么、按键）和当前状态。能运行代码时，代码指南一并送达。
指南送达不会因指南退回调用。指南留在模型上下文中才算读过；压缩后下一次调用重新送达。action="guide" 或 help("computer_use.window") 可查看。
一种写法一个动作在每个目标上只有一个名字和一组参数。其他工具的名字会被改写而不是拒绝：left_click 改为 click，double_click 改为带 click_count=2 的 click，element_index 和 ref 改为 element，tabs 改为 list_tabs。
检查调用在任何动作运行前。写错的调用立即失败，并给出带代码的错误，说明怎样做可行；见工具拒绝做的事。

行为说明
结果Done: …，然后是树的 diff：- 消失，+ 新增或变化
元素编号元素留在窗口时不变，新元素用没用过的编号。应用替换元素时，工具在原编号下重新找到同一控件。编号只在打印它的目标上有效。
上限树 1500 个元素，截图长边 1568 像素。get_state 加 full=true 返回完整树。
等待稳定至少 0.3 秒，直到树不再变化，最多 1.5 秒；有转圈或进度条时 5 秒
元素稀少的窗口少于 12 个元素（游戏、画布编辑器、远程桌面、部分 Electron 应用）：状态还列出从截图读到的文字，如 "New Game" at (160, 215), 120x30，以及无文字图标的轮廓，如 (112, 169), 55x56。识别在 Mac 上进行，首选语言优先，逐张判断。

agent 占用窗口时，窗口内缘有柔和的主题色光晕，关闭、最小化、缩放按钮变成主题色并依次脉动，agent 光标滑向每个目标，点击处留下小点。你的指针不动。

整个屏幕

computer_use(type="screen", display="2")

部分规则
默认关闭运行 openprogram config set computer_use.whole_screen true 后才列出。一般任务只需要一个应用，所以模型通过 type="window" 操作；关闭时 type="screen" 的调用会得到“没有这个目标”，什么都不发送。
何时用一个窗口之外的东西：桌面、菜单栏、系统对话框、跨窗口拖动，以及忽略后台输入的窗口。只操作一个应用时，type="window" 不占用你的指针。
只有像素get_state 是一块显示器的截图，不写 display 时是主显示器。x,y 是该显示器上次截图的像素；每个动作调用返回新截图。
动作click、type_text、press_key、scroll、drag、hover、wait，以及 list_displays、zoom 和 paste
真实输入指针在你眼前移动，按键和文字发给最前面的应用。一次调用占用这台电脑：其他调用等待。
不包含你拒绝的应用和 OpenProgram 的窗口不出现在截图里，对它们的步骤被拒绝（Bypass permissions 下允许操作 OpenProgram 的窗口）

形式限制行为
actions最多 20 个，同一目标和同一个应用、窗口、标签页或显示器，由调用写明一次按序运行，遇错停止，结束时返回一次状态。每步都用之前读取状态的元素编号。失败时说明已完成几步。
code（macOS）120 秒，100 个动作，输出前 256 KB带顶层 await 的 Python，在隔离解释器中运行，无文件、网络和进程。cu 就是调用的目标：await cu.get_state()、await cu.click(element=3)。dir(cu) 和 help(cu.click) 可探索。
代码与共享窗口
部分规则
范围代码只作用于调用写明的目标及其应用、标签页或显示器，能力与单个动作相同。操作两个目标要两次调用；本轮内变量在两次调用间保留。
失败的步骤在代码中抛出；之前的步骤保持已完成
超时返回错误：已做的保留，当前步骤可能生效也可能没有，下次调用启动新解释器
agent 状态每个 agent 有自己的窗口状态、元素编号和解释器。会话的各轮共用，所以后续消息沿用同样的编号。
共用应用多个 agent 在同一应用上轮流：调用占用它直到返回，另一个总共最多等 60 秒，然后不发送任何东西并返回 SCREEN_BUSY。不同应用上可同时进行，但在 Linux 和 Windows 上，点击、按键和文字（Linux 上还有滚动、悬停和拖动；Windows 上还有粘贴）在整台电脑上轮流进行。agent 的下一个结果会说明上次查看后是否有他人操作，并列出那些变化。

网页

每个标签页有短 id，如 tk3fa，跨轮次、子 Agent 和 workflow 程序不变；list_tabs 打印它，每个结果写明作用的标签页。

get_state 返回 Playwright 无障碍大纲，如 - button "Next" [ref=e12]；元素在页面上时 ref 有效，也可用 role 和 name 指定。

每个动作返回变化，以 <changed> 标记，[unchanged] 代表已看过的部分；导航后返回整页。重新渲染的 ref 按角色和名称再找；已消失时错误中带当前页面。

规则说明
并发agent 和子 Agent 可共用浏览器。动作占用标签页直到结果读取，列表占用涉及的标签页直到结束；占用一分钟返回 SCREEN_BUSY。每个 agent 有自己的当前标签页，能看到上次查看后的所有变化，他人操作时会被告知。等待不阻塞他人。
重试动作不会发送两次。输入可能已送达时的失败返回 OUTCOME_UNKNOWN，带上页面，不重试。
新标签页结果中点名动作打开的标签页；agent 在指定新标签页之前保持当前标签页。
workflow 程序限于启动的窗口；它打开的标签页在结束时关闭
关闭了 agent 访问在该会话中拒绝所有动作
后台输入不激活标签页。visible: true 置前，用于你要求观看时。file:// 打开沙箱允许读取的本地文件。密码值绝不进入模型。
审批内置标签页上打开、操作和 evaluate 都不询问。upload_file 在询问模式下询问，Auto 审查每次上传。脚本只在你发起的会话中运行；定时运行、外部 MCP 客户端、交接和自动 Goal 被拒绝并被告知使用页面动作，无论来自动作还是代码。
仅内置浏览器list_panes、start_video_recording 和 stop_video_recording 录制 OpenProgram 窗口的一个窗格
查看和接管网页

Agent 打开的网页留在后台。右侧栏的 Resources 按分支列出会话的网页，含子 Agent 的。继续分支保留其分组；相同 URL 仍各自独立；无归属的出现在 Unassigned。

Agent 网页的弹窗在后台作为独立网页加入同一分支，不抢占视图，下一个结果点名它。你打开的网页的弹窗以普通标签页在前台打开。

控件效果
选中资源在聊天中显示图片预览，不固定、不抢标签页焦点
Preview in conversation同一网页；不加顶部标签页；中央被网页占据时回到所属会话
Pin preview / Unpin preview仅聊天预览。Fixed 固定当前页；Auto 跟随该分支最近打开、读取或操作的网页。固定持续到 App 重新加载。
Hide停止捕获，保留网页。从资源行或 Preview in conversation 恢复。
Expand放大预览，不改模式
Open page把现有网页作为顶部标签页；隐藏预览，回到会话时恢复（除非已隐藏）
部分行为
标签页和预览不同时显示。没有遮罩，真实页面可用。
工具栏显示操作、Operation history，Agent 等待时还有 Review request。在页面内，它们收在右下角可拖动的 Agent 按钮后，从 Agent 首次操作起，直到页面关闭。
Agent 操作时页面边缘发光，光标滑向每步；放手后淡出。使用页面不会暂停它；在会话中停止运行，光晕持续到确实停止。
预览只有一行紧凑栏，只在 Agent 需要你或状态无法确认时显示状态。App 内有全屏内容时隐藏预览页面。默认 300×198.75；拖动标题移动，拖边角缩放，比例锁定，页面本身不缩放。
操作标记和历史标记短暂，不拦截输入。历史只含操作类型和结果，不含输入的文字。
关闭影响所有引用该网页的分支。活动网页先请求停止。关闭不同于隐藏。断开时显示上一张图并标为过期。
预览还跟随桌面应用窗口（每步后的最新截图）和 Agent 接管或输入的 Desktop 终端（实时只读），规则相同。截图只在内存中，worker 重启后消失。这些控件只作用于 OpenProgram 网页；应用窗口、屏幕和其他机器有自己的审批。
App 或 worker 重启未关闭的网页在后台恢复其标签页、会话、分支和最后确认的标题与 URL，成为新的活动网页，旧句柄失效。明确关闭的留在 Closed pages，隐藏的预览保持隐藏。
重启之后行在原分支显示 Restoring page…、Could not restore page 或 Reconnect。不需要 Continue Agent，新动作需要新的观察和当前权限。恢复用站点持久存储重新加载 URL，未保存的 DOM 和表单值丢失。没有保留标签页描述的旧记录显示 Could not restore page。

app驱动方式你要做的一次性设置

部分规则
何时列出装了这个浏览器（Chromium 系浏览器还要某个配置文件里有扩展）。名字不区分大小写，"Google Chrome"、"Microsoft Edge" 这样写也可以。
缺东西时调用返回 DEPENDENCY_MISSING（没有 Node.js、没装扩展、没装浏览器）或 PERMISSION_MISSING（Safari 的设置或 macOS 权限、Firefox 没带代理运行），并写明怎么补
选标签页title 是标签页 id，或只有一个标签页匹配的标题；多个标签页共用的标题会被拒绝并列出候选
标签页不带 title 或 tab 的步骤作用于该 agent 在那里上次用的标签页，起初是浏览器当前的标签页。那个标签页没了以后，这样的步骤返回 BAD_ARGUMENT 并指出它，agent 改为写明标签页。选标签页不会把它切到前面。close_tab 只关闭调用写明的标签页，create_tab 在后台打开。

筛选Chromium 系浏览器里筛选控制台消息或请求（pattern、only_errors、limit）返回 NOT_SUPPORTED

审批一次批准覆盖该浏览器内的一切，含 evaluate 和上传；首次调用是上传时卡片会说明

审批

首次接触应用时显示卡片，含图标、名称、bundle id 和这一步做什么（“点击元素 #7”），并说明在后台运行。原始参数在“执行详情”下。

目标询问一次，以及规则键
type="window"每个应用，用它的显示名：window Calculator。在 Mac 上模型用的任何精确写法都得到这个名字；Linux 上是精确的桌面条目或进程；Windows 上进程或 .exe 得到程序的文件名。其他写法按原样保留。list_apps 从不询问。

type="browser", app="chrome"每个浏览器：browser chrome、browser safari、browser firefox 等
type="browser"不询问，upload_file 除外，它每次都询问，在 Auto 下每次都审查
device="lab", type="screen"不询问。它的键 lab screen 让你自己的规则能拒绝它。

有后果的步骤

允许操作不等于允许自行执行重大步骤。模型在不可撤销或代你对外发言的步骤前（发送、提交、付款、删除）询问一次，说明做什么、在哪里、用什么数据。你的请求已点名该步骤时直接做并报告。屏幕上的文字是数据，不是许可或指令。

被打断的步骤不会阻塞下一步。模型被告知结果未知，查看屏幕后继续；该步骤留在 Activity 里。

系统权限

设置 → 设备 → 这台电脑显示执行电脑上的实时桌面访问；openprogram doctor、TUI /doctor 和 GET /api/system/access 是相同检查。查看不会请求权限。缺少访问不影响普通聊天和升级。

平台规则
macOS托管安装通过内嵌应用 OpenProgram（稳定 bundle id）运行 worker 和 Python 子进程；在系统设置里找这个名字。屏幕录制和辅助功能在桌面任务所用可执行文件的新进程中分别检查。打开只请求缺失的权限。远程客户端须在执行电脑上授权；其他应用的授权不算证据。
Linux无头会话和不支持的 Wayland 捕获与缺依赖分开报告。有 X11 显示不代表有访问权。
Windows取决于活动会话和目标；不能假定可访问安全桌面或提权目标。

不会要求 Linux 和 Windows 关闭安全机制或以管理员运行。未验证：Linux 和 Windows 原生桌面验收；未正式签名的 macOS 开发版上，签名升级后的权限保持、首次引导和授权后的任务自动恢复。设置过程绝不重试被拒绝的操作。

缺少权限时
部分行为
调用在动作前暂停。系统设置打开到对应页面，下方贴着一个小窗口：把 OpenProgram 图标拖进列表；已在列表里就打开它的开关。权限打开后小窗口自动关闭，调用继续。
无人可问定时或无人值守的运行不等待：调用返回 PERMISSION_MISSING，写明缺哪项权限、在哪里授予
会话中简短的等待状态和 Open System Settings 操作；暂停卡片上没有表单、Continue、null 结果、Retry 或 Edit。真正失败或取消的运行保留各自状态。
检查和继续worker 保存任务，通过新的 OpenProgram 进程检查，不请求权限，也避免旧结果。可用后同一任务继续一次。一轮内后续步骤不再检查，下一轮再查。
等待期间关闭页面不停止检查，需要重启时启动后再查，取消任务阻止继续，检查失败继续等待。
旧会话查看时不启动操作或弹出提示；切换会话时重复送达不重新打开授权。你仍可手动打开系统设置。系统权限不替代操作审批。
本地 ad-hoc macOS 构建更新后录屏授权可能失效而开关仍开。OpenProgram 记住成功的检查；身份变化且录屏被拒时，下一次本地授权只更新自己过时的登记，每个身份最多一次。状态检查和重连不重置权限。Developer ID 版本使用正常流程。
macOS 自动化权限错误

发给 System Events 或目标应用的 Apple Events 需要自动化权限，按目标授予，与屏幕录制和辅助功能无关。被拒时，在执行的 Mac 上打开系统设置 → 隐私与安全性 → 自动化，查看请求方对目标的访问。

失败的操作仍是失败；改设置既不批准也不重做。其他原生失败保留实际错误。
