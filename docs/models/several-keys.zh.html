使用多个密钥

一个 Provider 可以有多个 API 密钥或登录账号。它们组成一个列表，从上往下使用。

添加密钥

设置 → 模型服务，在 Provider 卡片上（或它在公司卡片里的那一节）点添加密钥（Provider 还没有密钥时是实心按钮）；订阅服务点登录另一个账号。有多种连接方式的 Provider 会先列出这些方式，推荐的排在最上面。

密钥保存前先向 Provider 检查，对话框会说明结果：

结果是否保存
密钥可用 · 42 个模型保存
密钥可用 · 余额不足保存，附带去充值页面的“充值”
密钥已保存 · 未能验证保存：Provider 接受了密钥，但没法证明它能应答
无法连接 Provider保存，附带“重试”
密钥被拒绝不保存：换一个密钥粘贴，或点“获取密钥”

名称可以不填，不填时这一行显示“Key ····c41e”。密钥不会再显示，只显示最后四个字符。Worker 环境变量里的密钥单独占一行，显示变量名；把同一个密钥粘贴到这里也会保存，变量不在了照样能用，列表里只显示一次。

顺序和策略

有两个或更多密钥时，凭据区的列表上方可以选择：

按顺序
用第一个可用的密钥，其余作为备用。默认选项。
平均
新对话在可用的密钥之间轮流使用。
最少使用
新对话使用今天用得最少的密钥。

按住行首的把手拖动，或在行的 ⋯ 菜单里选上移 / 下移。暂不使用保留密钥但跳过它，恢复使用让它回来。删除…是唯一需要确认的操作。

把对话固定到一个密钥

输入框的模型菜单里，有两个或更多密钥的服务商在模型下面接着写这个对话使用 Personal，再列出自动（按顺序）和每个密钥的状态；选一个密钥，这个对话就固定用它，勾从自动移到那个密钥上。

现在无法应答的密钥不能选。其他对话仍按列表使用。

密钥停用时

行上显示会怎样，怎么处理
14:32 恢复被限流：在那之前跳过，到时自动恢复使用
额度用完额度重置前跳过。Provider 卡片上的充值会打开这一行
密钥无效Provider 拒绝了它。更换把新密钥粘贴到同一行，名称和位置不变
需要重新登录登录已失效。重新登录更新同一行

所有密钥都在等待时，回复里写着“等待 Work，30 秒后恢复”。

在终端里

openprogram providers keys openai list
openprogram providers keys openai add --name work
openprogram providers keys openai move work --to 1
openprogram providers keys openai strategy evenly

终端界面里，/login <provider> 打开同一个列表：检查、重命名、暂不使用、移动、删除，或添加密钥和账号。
