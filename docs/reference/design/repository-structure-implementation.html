Repository structure implementation#

For contributors changing directory ownership, public imports or packaging. The scope is repository structure; this page does not certify a release.

Public entry

CLI commands, HTTP/WebSocket routes, Web and Desktop.

Canonical implementation

Applications under apps/; shared Agent core under openprogram/.

Compatibility and verification

Preserve public imports, validate layout and exercise packaging outside the checkout.

The repository structure design defines ownership and dependency boundaries. This page maps those boundaries to source locations, compatibility requirements, and verification. Migration chronology and previous review output are available in Git history; they are not current acceptance results.

Compatibility and remaining ownership#

openprogram/cli/__init__.py resolves the canonical CLI application in a checkout or installed package and rejects an already-loaded foreign canonical package. openprogram.cli, python -m openprogram, and CLI module entry points remain compatibility surfaces; moving internal files must preserve their behavior.

openprogram/webui/ remains a Server compatibility surface. The checkout still contains openprogram/webui/routes/agents.py, so Server ownership is not yet physically confined to apps/server/. Do not describe the complete Server move or removal of all compatibility modules as finished.

scripts/install-release.sh remains the public installer entry, while its implementation resides under scripts/release/. The root npm workspace and lock file coordinate Web, Desktop and CLI dependencies. Consumers must not assume a separate lock file or dependency installation below each application.

The default local runtime uses port 18100 and ~/.openprogram. Installed-App acceptance uses /Applications/OpenProgram.app; repository layout changes must preserve packaging and installed imports as well as source-checkout execution.

Verification#

The repository contracts check directory ownership, application locations and compatibility requirements. Run the existing contract from the repository root:

uv run --locked --extra dev python -m pytest -q tests/contracts/repository/test_repository_layout.py

A layout contract alone does not verify runtime behavior. For an implementation change, also exercise the affected public CLI or HTTP/WebSocket entry, build a wheel and check imports outside the checkout, and verify affected application packaging. Use the contributor checks and test-system design to select the required gates.

For documentation changes, rebuild before checking links; the checker reads docs/_site/, not source Markdown:

python -m scripts.docs_site.build
python -m scripts.docs_site.checklinks
