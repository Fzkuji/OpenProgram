占用与压缩

圆环、面板和压缩报告读同一视图：下一轮模型收到的内容。压缩不移动 HEAD，所以 HEAD 不变不代表图不变。

一个度量

rendered_history 是当前有效摘要加未覆盖的尾部。

使用方视图规则
session_stats.compute_breakdownrendered_history唯一度量。按折叠后的消息计数，含 thinking 和工具块
engine.compactestimate_total_used压缩前后各一次，写入 compaction_finished
refresh_context_stats分项和总量递增 _context_rev，依据改为 estimated。手动或自动压缩后运行
GET /api/sessions/{id}/context当前快照仅图未变时复用
session_context_stats上次请求仅 HEAD 和 _context_rev 都未变时复用
_get_messages、get_branch未折叠分支聊天历史。占用计算不用它

缓存只按 HEAD 取键时的症状：/compact 报告 40.7k，面板仍显示 Messages 125k。摘要已存，快照是旧的。

窗口

分母是请求所用模型的上下文窗口，和压缩对同一个 Model 读到的数相同。每次显示时现场解析，不从保存的记录里读回。

何时模型
运行中的轮次里一次请求报告用量轮次解析出的 Model。报告带 provider/model 和它的窗口；对话记下两者，供轮次结束时的报告使用
图变化、重新加载、面板按顺序取第一个给出模型的来源：选择器固定的模型、上一轮解析出的模型、运行中的 runtime、会话行的固定模型、跟随 Agent 的对话取 Agent 当前的模型、会话行里上一轮写下的 model
读的是未选中的分支GET /context?head_id= 指向另一个已记录分支的末端时，用那个分支自己在 branch_config 里的模型，没有就用它的 Agent 的模型。不看选中分支的固定模型、上一轮和 runtime
选中了另一个分支上一轮解析出的模型和窗口随 runtime 一起丢弃：它们属于离开的那个分支。没有自选模型的分支随后读它的 Agent 的模型
任何存下的模型字符串provider/model 和 provider:model 在第一个分隔符处拆开（split_model_ref）；不带 provider 的 id 用会话的 provider
给出的模型解析不到没有窗口。圆环和面板只显示 token 数，不显示上限和百分比。只有压缩保留 128k 默认值，让它提早触发

查找失败时保存的记录带着 128k。加载对话、面板路由和下一次广播都会换成当时解析出的窗口。

压缩结果

  1. 准备：从渲染历史构建提示，计算 budget_pct。
  2. 达 80% 压缩：模型写摘要，追加摘要节点。
  3. 再次准备：本次请求读摘要和尾部。
结果条件事件
开始决定调用摘要模型compaction_started
成功摘要已存，summarised_count > 0compaction_finished
无可压缩消息少于 4 条，切点不超过受保护的开头，自动重试被暂缓，或摘要未覆盖任何内容compaction_finished 带 no_op: true。调用模型前已知时，不发开始事件，不发请求
失败摘要调用或流程异常；或保留历史并给出原因：摘要过长、未缩小、已取消、上下文已变、范围无效、插入无结果compaction_failed；保留历史时同时带 no_op: true

触发：/compact 或面板按钮；请求前预算达 80%；从 413 或 prompt_too_long 恢复。一个会话最多一个活动摘要。insert_summary_node 保留旧轮次。

圆环和面板

状态显示
正常中性轨道，弧线按比例着色。没有建议边框或建议状态。点击打开面板
来源圆环、提示和面板标题读同一份快照（lib/chat/context-occupancy.ts）：会话最近一次 context_stats；第一次到达前用面板缓存的快照（新对话的估算，标 est.）；还没有会话时用草稿估算。三处永远显示同一个数
草稿变成会话第一条消息的确认（ack）让草稿以自己的键成为会话。草稿估算复制进这个会话的快照，同时开始取它的 GET /context，所以数字和窗口一直保留，先被会话估算、再被 context_stats 替换，不会掉到 0
分支还没有快照缓存对没有记录的分支回答会话最近一份快照，那是按另一个分支的模型算的。圆环先显示它，同时立即读这个分支自己的 GET /context（hasContextBreakdown）
窗口未知弧线为空；提示和面板标题只显示 token 数。分类行仍显示占总量的比例
终端客户端底栏按对话记下 context_stats 里的窗口。帧里的 context_window 为 null 时删掉它：底栏只显示 token 数，不显示上限和百分比，和圆环一致
压缩中分支正在运行的是 compact 操作，或处在压缩阶段的轮次时（isCompacting，从 compaction_started 到结束或失败）：圆环忙碌，面板按钮禁用
压缩对话面板行发送 {action:"compact", session_id}，与 /compact 同一 WebSocket 路径。无会话或压缩中时禁用。刚压缩完仍可点，服务端回答没有可压缩的内容
上次压缩这一行下面的一条说明，来自快照的 last_compaction（分支上生效的摘要）：上次压缩 时间：N 条消息，X → Y。分支上没有摘要时不显示

系统消息

自动和手动压缩共用 chat-handlers.ts 的同一分支。消息为双语。

事件文案
开始不加消息：运行条显示“正在压缩上下文…”
结束不加消息。对话重新读取，摘要卡片（已压缩 N 条更早的消息，带时间）折叠被盖住的消息，只出现在含有整段被盖住消息的分支上；从这段中间分出的分支没有被压缩过。压缩发生的位置不留任何标记：那里的一行与卡片重复，还把 token 数夹在两条对话消息之间。上次压缩改由面板说明
失败上下文压缩失败[：错误]
结束且 no_op上下文保持不变，本次没有应用更小的摘要

验收

  • 成功后，圆环和面板总量下降，并与 compaction_finished.tokens_after 一致。
  • 重复压缩不调用摘要模型，报告无可压缩，绝不显示“盖住 0 条，X → X”。
  • 任何占用下都没有建议边框。
  • 圆环的上限等于压缩所用 Model 的 real_context_window：自选模型的对话和跟随 Agent 的对话都一样，轮次进行中和重新加载后也一样。
  • 两个分支各选了不同模型时，各自报告自己的上限：无论是打开它，还是从另一个分支读取它。
  • 模型换成窗口未知的之后，终端底栏不显示上限。
  • 压缩期间圆环忙碌、按钮禁用，完成后恢复。
