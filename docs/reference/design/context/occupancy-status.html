Context · Occupancy & compaction

占用和压缩现在到底是什么情况

对照 2026-08-23 这个会话：Grok 4.6，窗口 500k，面板 637.7k / 500.0k (est.)，Messages 626.1k · 125.2%。下面按代码现状写，不是按「应该怎样」写。

圆环点开 Loading：已修 图可以大于窗口：开着 压缩只在发请求前：开着

01 · 两套数，不是一把尺子

面板 / 圆环

报「这根分支现在有多大」。rendered_history 本地估 token。超过窗口也原样报，百分比头行封顶 100%。

压缩开关

看下一轮要发出去的预算。budget_pct = (input + output_reserve) / window。到 80% 才在 这次 LLM 调用前 动手。

模型实际吃到的

压缩之后的 rendered 视图：一条 active summary + 没被吃掉的尾。账单是 measured。没发过、或发到一半被掐，图可以一直大于窗口。

637k / 500k 不是计算器坏了。卡在报图的体积。压缩还没把这张图写小。

02 · 压缩现在怎么跑

一次会话最多一条 active summary。再压是替换，不是叠。DAG 只追加，不删旧节点，HEAD 不动。模型读的是替换后的 rendered 链。

prepare
按 DAG 拼 prompt，算 budget_pct
→
≥ 80% 则 snip
免费砍最老完整 turn。只改这一次要发出去的 history，不写回 DAG
→
还是 ≥ 80% 则 compact
LLM 写摘要，追加 context/summary 节点
→
再 prepare
这次请求读 summary + 尾巴

什么时候会跑

触发阈值 / 条件会不会改面板看到的图
建议压缩事件 budget_pct ≥ 0.70 不改图，只发事件
自动 snip 下一轮发出去之前，且 ≥ 0.80 不改。面板继续按完整 rendered 估，所以还能溢出
自动 compact snip 之后还 ≥ 0.80 会。摘要进 DAG，之后的 estimated 应变小
手动 /compact 用户点 会
闲着看面板 / 切会话 / worker 刚起来 — 不会。没有「图大于窗口就压」这条
代码里 AUTO_COMPACT_PCT = 0.80。openprogram/context/README.md 有一处还写 0.85。以代码为准。

这次 637k 为什么还在

  • 面板走 estimated：按 rendered_history 重算。没有 active summary，或 summary 没盖住这 626k 消息，估出来就会大于 500k。
  • 自动压缩绑在「下一轮发出去」。没发、失败、或 worker restarted mid-turn 打断，摘要节点不会出现。
  • 即便某次请求只做了 snip：发出去的 prompt 短了，DAG 没变，面板照样报 637k。

03 · 圆环和面板这条线

已经是这样

占用三元组一份。切会话进 session_loaded。点圆环读缓存。没有分类时先画圆环的 total_used / window。不画 Loading。全屏遮罩去掉。read() 不再 notify()。

还开着

快照只在 worker 内存，重启要重算。头行百分比封顶、分项可以 125%、空闲地板到 0，三套规则。分类晚到时头行先有数、分项可能先空一拍。

04 · 问题总表

问题状态一句话
点圆环先 Loading 再出数 已修 现拉 GET /context。现用缓存 / 圆环占用。
点开圆环整页崩 已修 read() + notify() 死循环。
全屏遮罩挡侧栏 已修 旧 occluder。
窗口还在跑旧 JS 已处理 Electron 缓存，不是源码写回 Loading。
占用 > 窗口 开着 展示的是图体积，不裁切，也不在闲时压缩。
snip 不写 DAG 开着 下次请求变短，面板数字可以照样溢出。
压缩只在发请求前 产品未定 要不要「一看就过窗口就压」，还没定。
百分比三套规则 开着 头行 100%、Messages 125%、Free 0。
README 阈值 85% 文档错 代码是 80%。
快照不落库 铁律 worker 重启后重算。现用圆环数兜底。
重启打断进行中的一轮 过程问题 为刷前端停过 worker。和溢出无关，会拦住本该跑的 compact。
package-lock.json 脏 杂项 没进 5d3e3439。

06 · 还没做、建议先定的

  1. 图超过窗口时：只展示溢出，还是闲着也自动 compact。
  2. snip 要不要写回 DAG，否则面板和「上次真正发出去的」会长期不一致。
  3. 溢出时头行、分项百分比、Free space 用同一套说法。
  4. README 的 85% 改成 80%。
