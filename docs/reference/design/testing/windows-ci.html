Windows CI completion

The native x64 and ARM64 jobs execute platform contracts and the complete unit suite with four workers. A completed test count does not prove that error reporting and process shutdown finish.

Portable test parameters

Large parametrized payloads use explicit short test IDs. Pytest writes the complete node ID into PYTEST_CURRENT_TEST; Windows environment values must remain below 32767 characters. Generating an ID from an 8 MiB image string prevents setup and teardown and repeats the payload throughout the error report. Payload bytes remain unchanged. POSIX mode assertions apply only on POSIX systems; the catalogue round-trip still runs on Windows.

Failure diagnostics

Windows Python output is unbuffered and unit results include test names. Complete output and a separate traceback file are uploaded after success or failure. The process-wide traceback deadline replaces the pytest faulthandler plugin so exception reporting cannot cancel that deadline; it covers reporting and shutdown as well as test execution. The test step and job also have finite execution limits. Failed tests retain their nonzero exit status; no tests are removed or accepted as passing.

Acceptance

Both native architectures must complete the full unit suite and platform contracts. An intentionally blocked diagnostic process must emit its Python stack and exit unsuccessfully. Ordinary failed tests must emit their details and exit unsuccessfully.

Implementation status

Native x64 diagnostics confirm oversized parameter IDs and a POSIX-only permission assertion. Both are corrected; final native x64 and ARM64 regression checks are pending.
