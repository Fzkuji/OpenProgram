凭据状态

status原因恢复
ready可用无
cooling429：暂停到服务商给的重置时间，否则 60 秒起、每次翻倍、最多 15 分钟暂停结束或下一次成功时自动恢复
quota402，或正文说额度、套餐已用完的拒绝（CreditsError、insufficient_quota、"insufficient balance"、阿里云 400 Arrearage）暂停到额度读取给的重置时间，否则 24 小时；检查通过即清除
invalid_keykey 收到 401 或 403，且正文没说额度用完更换 key
needs_login登录凭据刷新一次后仍收到 401 或 403，或刷新令牌被拒重新登录

凭据的 status、cooldown_until_ms 和 last_error（{at, code, message}）就是它的全部状态。key 不能用某个模型时，只在这个 key 上封住那个模型（blocked_models），不算一种状态。

先看正文，再看状态码。OpenCode Zen 余额为零时回 401 CreditsError；当成 key 被拒，页面会写“更换 key”，实际该充值。这些说法集中在 errors.py BILLING_MARKERS 一份列表里，取自各适配器的返回正文和同类项目的计费表（hermes-agent _BILLING_PATTERNS、openclaw failover-matches）。

哪些响应影响凭据

响应凭据
429Retry-After 不超过 5 秒：在它上面再发一次。否则 cooling，换下一个
402、额度用完quota，换下一个
401、403invalid_key 或 needs_login，换下一个
模型不允许只在它上面封住该模型 24 小时
5xx、网络不动；在同一个 key 上重发
400、404、422不动

换 key 时对话里加一行灰色提示。没有可用的凭据时，报错用平白的话列出每个凭据的状态（“rate limited”“out of quota”“key refused”“sign in again”）。

为什么要暂停，且只对这几种

被限流或额度用完的 key 如果下一次请求还发，每一轮都要先白白被拒一次再换。5xx 和 404 说明不了 key 的情况，所以从不暂停。
