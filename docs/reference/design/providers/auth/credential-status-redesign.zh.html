凭据状态

status原因恢复
valid可用无
rate_limited429，短暂限流自动：下次成功，或窗口结束后报告 valid
billing_blocked402，或正文说额度已用完的其他 4xx（401、403、429、阿里云 400 Arrearage）（CreditsError、insufficient_quota、"insufficient balance"）；无计时充值后 Validate，或一次成功调用
needs_reauth正文没说额度用完的 401 或 403重新添加 key 或登录
revoked永久失效更换

状态列就是全部答案。账号记录没有 cooling 字段。

先看正文，再看状态码。OpenCode Zen 余额为零时回 401 CreditsError；记成 needs_reauth 时页面写“重新登录”，实际该充值。

这些说法集中在 errors.py BILLING_MARKERS 一份列表里，取自各适配器的返回正文和同类项目的计费表（hermes-agent _BILLING_PATTERNS、openclaw failover-matches）。已存为 needs_reauth 或 revoked 的 key，若 last_error 命中这份列表，加载时读作 billing_blocked。

哪些响应影响凭据

响应凭据池
429短暂 cooldown_until_ms；轮询跳过，单 key 仍发送
402、401、403停用；轮询视为不健康
404、400、422（request_error）不动
5xx、网络错误不动

聊天里以红色错误气泡显示供应商原话。账号面板只用于诊断。

为什么没有冷却窗口

404 会连累这个 key 上的其他模型，402 等待也不会恢复，5xx 说明不了 key 的好坏。只有订阅和配额账号才真的要等重置。
