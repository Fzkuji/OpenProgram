工具

工具向凭据库要自己服务的 key（auth/services.py 的 service_key）：先是厂商存的 key，没有再读变量。工具自己不读 os.environ。

服务读谁的 key
Tavily, Brave, Serper, Exa, You.com, Jina, Kagi, Firecrawl, Google PSE, fal, ElevenLabs, PlayHT它自己：一个没有接入点的厂商
Perplexity、MiniMax、Kimi、Ollama 的搜索提供模型的那个厂商。一把 key 同时用于对话和搜索。

MiniMax 和 Kimi 的搜索有国际和中国两个地址。搜索先试一个，key 被拒再试另一个，并记住哪个通了。

Google PSE 的引擎 id 不是密钥：它是设置项 search.google_pse_cx，没有再读 GOOGLE_PSE_CX。

有多把密钥时，工具按存放顺序读第一把还没被所有接入点拒绝的。在工具设置里保存密钥：纯工具厂商是替换；同时提供模型的厂商是新增一把并排到最前。

新增、删除、保留

内容
新增厂商 key 文件。目录新条目自动归位。工具服务表。一次性搬迁。到时间就放弃的文件锁。被拒的请求跟着密钥换接入点。用户自己的归位。
删除把 config.json 的 key 写进进程环境。工具直接读 os.environ。给共用变量选一个接入点。后台拿 key 去试每个接入点。同一把 key 每个接入点存一份。
保留每个接入点一个列表，放登录、顺序和状态。只读的环境变量行。按接入点记录的健康、冷却和停用模型。接入点内凭据之间的故障切换。
表里没有的条目怎么归位
  1. 它的 id 是表里某个厂商或其接入点的 id 加连字符后缀：归入这个厂商（minimax-cn-max-plan 归入 MiniMax）
  2. 几个表外条目读同一个 key 变量，且一个 id 是另一个的延伸：它们自成一个厂商
  3. 其余的各自是只有一个接入点的厂商

只是前缀相同不算：读不同变量的两个条目是两个厂商。

用户自己说的优先：config.json 的 provider_companies 把表外条目的 id 指到某个厂商的 id，指到它自己的 id 就单独成一家。

决定

决定参照原因
模型和工具的 key 进同一个库OpenCode、Oh My Pi添加、查看、删除都在一处；搜索的 key 不是另一套系统
环境变量只读不写OpenCode、Codex、Claude CodeHermes 把 key 文件写进进程环境，这里的 config.json 以前也是：每个子进程都继承全部 key
接入点和它的 key 变量来自 models.devOpenCode、Oh My Pi覆盖最全，有人持续更新
key 属于厂商，不属于某个接入点没有同类这么做：它们都把 key 存在一个目录条目下用户只有一把 key，说不出哪些条目收它。按条目存，同一把 key 要粘四次，或者放错地方。
厂商表由我们维护没有目录提供。Cherry Studio 的 presetProviderId 最接近，只覆盖三处。有自动归位，目录多一个条目不用等发版
被拒的请求跟着密钥换接入点没有同类这么做。LiteLLM 的路由在任何错误时都换部署。只有被拒才换，而且只跟着同一把密钥，所以付钱的还是同一个账号，限额不会溢到另一个套餐
换过去的请求只用它跟着的那把密钥没有同类这么做另一个接入点上可能有登录或别的账号的密钥。用它们会让用户没选的账号付钱。
密钥留在仅本人可读的文件里，不进系统钥匙串OpenCode、Pi、Hermes、Oh My Pi。Codex 和 Claude Code 用钥匙串。worker 在无界面和远程访问下运行，钥匙串弹窗没人能点；稳定版和开发版各存一份；macOS、Windows、Linux 一种格式。
MCP 服务器和消息渠道的密钥留在各自的服务器或账号下OpenCode：auth.json 旁边的 mcp-auth.json每一个只属于一个服务器或一个机器人账号。没有厂商，也没有第二个接入点可共用。
两个查找：要一把密钥，或要这个接入点用来签名的任何凭据Pi：getApiKey 返回密钥或登录的 token工具和只收密钥的请求要密钥；模型请求也接受登录的 token。一个函数加开关不如两个名字清楚。
服务里不是密钥的值算设置项OpenCode：配置里 provider 的 options引擎 id 像其他设置一样显示、修改、备份，不需要密钥文件
工具的密钥再存一次是替换OpenCode：每个 provider 一个凭据工具只有一个密钥输入框；同时提供模型的厂商保留其他密钥
用户可以纠正归位没有同类维护厂商表按名字归位可能出错，纠正不该等发版
不拿 key 去试每个接入点所有同类：保存时都不校验检查会在用户从不用的接入点上花额度或请求。LiteLLM 的检查发的是一次真实对话。

验证

tests/unit/providers/auth/test_company_keys.py：一把 key 出现在每个接入点、密钥只在一个文件、按接入点的状态、改名和移除、环境变量行、两种搬迁、工具服务、归位、请求跟着密钥换接入点。用一把真实的 MiniMax 中国密钥选任一国际接入点：那边返回 401，随后中国接入点接受这把密钥。
