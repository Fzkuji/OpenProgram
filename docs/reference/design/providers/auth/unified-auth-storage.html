Auth storage

AuthStore (models/auth/store.py): ~/.openprogram/auth/<provider_id>/credentials.json, one ordered list per provider, atomic write, a cross-process lock held from read to write (mutate), reload when the file changes underneath. An API key's secret is in its company's file, auth/_keys/<company>.json, written the same way.

What requests count (uses, last use, uses today, the rotation cursor) lives beside it in usage.json, so a request never rewrites the secrets file. CredentialProvider serves what is on disk and never re-discovers; import is an explicit step.

Login registry

auth/login/login_method_registry.py is the one provider → [method] table; the first entry is the default, and the CLI, web and TUI all render it. Handlers are in auth/methods/ and auth/login/. Anthropic has no published third-party OAuth client.

Each method carries a title and a one-line description in English and Chinese, and an import names the file it reads; the web setup dialog shows them as its list of ways in.

Refresh

A refresh token rotates: the first holder to spend it gets a new pair, and any later spend of the old one is refused (invalid_grant), which signs that holder out. So a refresh is spent by one process at a time, and each process re-reads the login after it gets the lock.

RuleBehaviour
Before sendingCredentialProvider.prepare refreshes a login whose expires_at_ms is within 60 s; the request goes out with a token that has not expired
Cross-process lockrefresh_lock.py: an advisory lock on <file>.refresh.lock beside the provider's list, separate from its write lock. Two workers, or a worker and its cron subprocess, take turns
Inside the lockRe-read the file. A login another process refreshed meanwhile is used as is; only a still-stale one is refreshed and saved
Rejected before expiryAn HTTP 401 refreshes that login once and sends the same request again at once, without a transport retry. One INFO line records the refresh

The credential layer makes the chosen login ready (prepare) in a worker thread, never on the event loop, since it can wait for another process's refresh lock and a refresh request.
