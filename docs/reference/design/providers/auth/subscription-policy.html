Subscription policy

WayRule
APIThe vendor's official API with a key the person got from the vendor, billed to their API account
PlanThe vendor's own program, run as an outside agent: Codex app-server, Claude Code, Gemini CLI over ACP (Third-Party Harnesses). The program signs in and talks to the vendor; OpenProgram talks to the program
NeverA plan's sign-in used by OpenProgram itself, an official client's identity (user agent, originator, client id), or an internal endpoint

Why

A plan's sign-in belongs to the vendor's own clients. Another client sending it while posing as an official one breaks the vendor's terms, and vendors suspend the accounts behind it (T3 Code, under Peers).

Anthropic is reached only through its official API with a key; a Claude subscription credential is refused (provider_policy.py).

Saved settings

An id in WITHDRAWN_PROVIDERS is never listed, offered or signed in. A config entry, agent or conversation that names one is skipped like any provider that is not there, and models.dev rows for it are dropped, so the model picker never shows it.

Codex plan quota

Only from Codex itself: its app-server's account/rateLimits/read when a process starts, then each account/rateLimits/updated merged in for the same CODEX_HOME (rate_limits.py), and the rate_limits in the token_count events of its own rollout files.

Only the plan's codex limit family counts, and the newer reading wins. It is kept in harnesses.db and shown on the Third-party harnesses usage page. Nothing asks ChatGPT for it.
