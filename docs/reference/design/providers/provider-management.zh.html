供应商管理

设置 → 模型服务 列出已连接的供应商，三步添加一个（选择、密钥或登录、默认模型），并显示每个供应商的健康、额度和花费。对话里只在模型选择器和额度用尽的回复卡片上显示供应商状态。额度和健康来自供应商额度。

供应商列表

  • 列表只放已连接的供应商：存有密钥或已登录，或已启用的本地服务。目录（约 236 个供应商）放在添加供应商里。
  • 卡片和紧凑行是同一个列表的两种视图。页头的分段控件切换它们；选择按用户记住，默认是卡片。
  • 一张卡片是一个页头（标志、名称、默认模型、一个 +），下面每个凭据一行：公司每种接入方式的每把密钥、每个已登录账号。还没有凭据的方式、本地服务各占一行。
  • 一行是固定的三部分，每张卡片都一样。是谁：账号的邮箱、密钥的名字、末四位或它的环境变量，下面写方式和套餐（"Go"、"Plus"、"API key"）；有多个时，绿点标出正在用的那个。
  • 额度：最多三个圆环（5h、Week、Month、Req/m、Tok/m、Limit），下面写重置时间或上限，窗口短的在前；多于三个时取最紧的三个。读取失败时是虚线的 Unread 圆环，悬停显示原因。
  • 最后一列在凭据能用时放金额：Credits、Balance，密钥写 30 天花费；包含在套餐里的为空。
  • 否则写不能用的原因：Limited、Cooling 用琥珀色加恢复时间；Invalid、Signed out、Not running 用红色加发现的时间；余额用完时红色显示；停用的密钥灰色写 Off。
  • 没有动作词：点红色的格子就处理它写的问题（重新登录、更换密钥、打开充值页、怎么启动服务）；点行的其他地方打开供应商页面。
  • 数字超过 15 分钟没更新的行变淡，悬停显示读取时间。一张卡片最多显示四行；再多时，留下正在用的和有问题的，其余收成"还有 N 个"，并写出其中的问题（"1 invalid"）。
  • 卡片用对话里按钮的那种浮起表面：一圈细边框加柔和阴影，鼠标移上去阴影加深。卡片里每一行是一块圆角小卡，材质和改文件卡片一样，行间隔 8 px，离卡片左右和底边都是 12 px，没有分隔线；鼠标移上去阴影加深，底色不变。
  • 用多种方式接入的同一家公司是一张卡片；卡片排成瀑布流（见下表）。
  • 紧凑行把同样的信息放在一行：最先用完的那个限额的进度条，然后是"62% 5h · 14:30 · 15% Week"、"$18.42 balance · ≈ 26 wk"或"46/50 rpm · no balance data"；30 天花费或 Included、走势、token、缓存占比和默认模型。
  • 紧凑行列宽固定：每个单元格在自己的列里以省略号结尾，悬停看完整文字，所以再长的状态、额度文字或模型 id 在 640 px 及以上的窗格里也不会让表格横向滚动；窄于 1040 px 时先隐藏 Tokens 和 Cache。
  • 美元余额在有三天花费后显示可用时长（"≈ 26 weeks at this pace"）。
  • 已登出或已停止的供应商数字变淡；超过 15 分钟的快照在两种视图里都变淡，悬停显示"Updated 3 h ago"，不单独占一行。
  • 供应商只报告有这个限额而不给数字时（Codex 不限量的 credits、Copilot 不限量的高级请求）写"Unlimited"。额度端点读取失败时写"Couldn't read the quota"，原因放在悬停提示里。
  • 计费标签写 API key、Local 或 Subscription。知道套餐的订阅在这个标签里写套餐名（“Plus”“Pro”）；紧凑行在原本写 Included 的位置显示同一个标签，悬停显示“Included in the Plus plan”和按 API 价的金额。不知道套餐时不变。
  • 页头有 Providers | Routing、最近更新时间、刷新、卡片 | 列表切换和添加供应商。没有说明段落。
  • 刷新按顺序重新读取每个供应商：先读登录所在的位置，再读额度端点；健康状态由两者得出。结果替换卡片之前，按钮上的图标一直转，更新时间也算上这次读取。

添加供应商

什么都没连接时，页面直接显示添加供应商里的同样选项，没有说明文字：

  1. 环境里的密钥排在最前，每个带 Use。变量按供应商的密钥名（先静态表，再 models.dev 的 env）匹配目录。页面只拿到变量名和打码的尾部；Use 让 Worker 自己读取并保存，密钥不经过网络传给页面。OAuth 令牌变量从不提供。
  2. 常用：八个一格，点一下进入第 2 步：OpenAI（ChatGPT 登录，旁边有 API 密钥）、Anthropic（只用 API 密钥）、Google Gemini、xAI、DeepSeek、OpenRouter、Kimi / Moonshot（附 Kimi Coding 和中国站）、Z.ai（附编程套餐和智谱）。
  3. 本机：Ollama、LM Studio、vLLM 和 llama.cpp，在回环地址上半秒内应答不带密钥的 GET /models 时显示。打开模型选择器、服务商页或添加服务商时再探测一次，期间先显示保留的结果；其他读取沿用 30 秒内的探测结果。
  4. 全部供应商：在整个目录里搜索。
  5. 常用供应商在设置打开时读取；到达之前格子的位置留空，读取失败时安静重试（等待不配文字）。

第 2 步是一个打码的密钥输入框加"Get a key"链接，或者登录。如果这个供应商的密钥已经在 Worker 的环境变量里（从图块、搜索结果或 ?add=<id> 进入），第 2 步先给出它，和选择列表同样的一行（变量名、打码尾号、Use），下面是"Or paste a key"。

粘贴后立即检查：先免费读取供应商的模型列表或密钥端点，只有这次读取证明不了密钥可用时才发一个 token 的测试请求。结果是一行：

一个供应商第一个 works、no_credit 的密钥，或供应商以 HTTP 200 接受的 unverified 密钥，会启用这个供应商（5xx 或没有应答说明不了密钥，什么都不启用），第一次登录也一样；没有单独的启用步骤。它的模型一个都没开启时，开启三个推荐模型。

第 2 步把同一家公司的几种接入方式做成标签页（ChatGPT 登录旁边是 OpenAI API 密钥），即公司表里标为提供的那些方式；Advanced 收起 Base URL。正在运行的本地服务一个按钮就能接入，没运行的显示如何启动。Custom 打开自定义供应商表单。

登录列出供应商的接入方式：

  • 每行有图标、标题、一行说明和箭头；导入还用小号等宽字显示它读取的文件。
  • 有多种方式时，第一种（浏览器登录）放在带底色的卡片上并标“推荐”，其余列在“其他方式”下。
  • 标题、说明和文件都来自登录方式注册表，带中英文，所以每个登录类供应商和凭据区的添加对话框显示同一份列表。
  • 选一行就启动该方式；这一行显示加载圈，直到浏览器、代码或输入框接手。

对话框的遮罩是 Nova 的浅色遮罩，不加背景模糊，所有 Dialog 和 AlertDialog 都一样，页面在后面仍然看得清。

第 3 步提供这三个：已开启的排前，其次是支持工具调用的最新模型，附上下文和价格。Start chatting 把其中一个设为输入框的模型。

一把密钥，多种方式

密钥属于公司，不属于某一种方式：MiniMax 的 API 和 Token Plan、国际和中国，都列出同一把 MiniMax 密钥，不管它是粘贴在其中一个上的，还是放在 MINIMAX_API_KEY 里。既不从密钥去猜，也不拿它去逐个试（厂商、接入点和凭据）。

情况做什么
卡片这把密钥只显示一行，各个方式报告的信息都显示：名字下面是它答复过的每个方式（在那里用过，或在那里读到了额度），放不下就换行，不截断；圆环来自这些方式，提示里写明是哪个方式的；最后一栏取有问题的方式，否则取有金额的。圆点只标卡片当前模型所在方式正在用的那把。
调用走所选模型那个方式自己的地址
在某个方式上被拒不显示：这把密钥本来就不属于那个方式，不算问题。请求改走还没拒绝这把密钥的方式。每个方式都拒绝时，这一行显示“密钥无效”。
移除已存的密钥从所有方式上消失。变量的行不能移除：取消设置这个变量。

行的字号每行是 text-fs-sm：标签用主文字颜色，重置时间用 text-fs-xs 弱化颜色跟在旁边，数值落在模型行勾选列的右边缘（数字是否等宽由设置决定）。文字和模型名从同一处开始
语气颜色语气颜色只给百分比和进度条填充；用完的进度条底色带危险色，不会消失
这一段的内容这一段列出状态路由带来的每个限额，并且总包含供应商行圆环所用的那个限额和选择器状态里的余额。选择器状态随模型送达，比状态路由（它还要汇总 30 天花费）早几秒，所以在那之前这一段显示这两项，不会比那一行显示得少
显示的限额窗口或密钥限额最多四个，最紧的在前；金额跟在后面，从不截掉。过长的标签或重置时间在行尾截断（用逻辑方向，RTL 会镜像），不撑宽子菜单，也不把数值挤出边缘
固定凭据有两个以上凭据时，供应商的子菜单最后写“这个对话使用 Personal”，再列出自动和每个凭据；勾在哪里说明是否固定。选择会固定这个对话（POST /api/sessions/{sid}/credentials，自动为 null）；管理密钥…在当前页打开供应商页面，按住 Cmd、Ctrl 或 Shift 则在新标签页打开
失效的固定固定到已不存在的密钥时，提示改回自动；固定的密钥被设为暂不使用时，请求按“要改设置”结束，而不是登录失败
用量条所有用量条都是组件库的 Progress
切换提示回复换到另一个凭据时，回复上方有一行淡色提示：“已换到 Work：Personal 触发了速率限制”。这行提示随回复保存，刷新后还在；--print 把它写成 credential_switch 事件。所有凭据都在等待时，重试行写明在等哪一个、何时恢复
菜单末尾菜单最后是 Manage providers，打开设置 → 模型服务。一个供应商都没接入时，菜单写明这一点并提供 Add provider，打开同一个页面的空状态
触发按钮所选模型的供应商还能回复时，不管用了多少，触发按钮都不加标记。只是预警的额度显示在圆环和进度条里，不上触发按钮
红点只有供应商需要处理（需登录、没有余额、Key 无效、未配置、未运行）或额度快用完（用到 95%）、已用完时，供应商图标上才有一个红点，这就是 Worker 的 attention。它的提示写明供应商和状态或窗口剩余

状态随模型一起送达（GET /api/models/enabled）；打开菜单时读状态路由取额度行，状态路由会在后台读取超过十分钟的接口。每个 provider_quota 帧更新这两份数据，并作为窗口事件 op:provider-quota 转发。

回复因额度用尽而失败时（errorCause.cause 是 quota_exhausted），回复卡片写“OpenAI Codex 5h 额度已用完”，下面是“14:30 重置 · Week 剩 71%”。余额用尽（402，或供应商状态是没有余额）写“Kimi 没有余额了”，下面是余额。原始错误留在折叠的详情里。

按钮作用

其他模型…先列出最多四个还有额度的模型，然后是完整的选择器

选中的模型只固定在当前窗格显示的分支上，并在那里重新发送失败的这一轮；其他分支和对话保持原来的模型。不会自动切换；故障转移链仍把额度用尽当作终止。

Token 用量

部分规则
拆分花费按计费方式拆开：已计费（按 token 计费的供应商、有价格的调用）、已包含（订阅调用按标价计，只在提示里显示），以及按 token 计费却没有价格的调用数。一个没有价格的调用不再让总数消失

订阅套餐供应商（OpenAI Codex、SuperGrok、OpenCode Go、Kimi Coding、GitHub Copilot、Gemini 订阅）或 id 写明编程套餐、token 套餐的供应商算作订阅

决定

选择采用原因
常用列表写在代码里OpenCode popularProviders目录没有热度字段；人扫一眼的是一个短的固定顺序
按目录的密钥名识别环境密钥OpenCode已设好的密钥不用问就能认出，一次 Use 就能连接
保存前免费只读检查Hermes坏密钥当场发现；证明不了更多时如实说"unverified"
以选择模型结束OpenCode连接在开始对话的地方结束
每个供应商的计费方式和修复ZCode每个状态都带着消除它的那一个动作
卡片和行是两种视图所有者的修改同一份数据两种密度，由人来选
一家公司一张卡片，每个凭据一行所有者的修改两张名字几乎一样的卡片读起来像重复；合在一起后公司只需找一次。供应商级别的额度看不出属于哪个账号或密钥，所以每个凭据单独一行，有自己的圆环和状态
瀑布流而不是等高的行所有者的修改公司卡片高矮差别很大；把一行拉到最高那张的高度，会在矮的卡片里留下大块空白。按最短列依次放入的显式列让列表顺序就是阅读和 Tab 的顺序，CSS 多列做不到
供应商状态只在模型选择器里所有者的修改输入框保持三段；选模型的地方就是选择器
空状态显示常用供应商所有者的修改只显示一个供应商，看起来像唯一的选择
额度用尽时推荐，不自动切换OpenCode、Codex由人决定；卡片写明模型和重置时间
紧凑行：最先用完的限额，数剩下多少Codex一眼看出哪个窗口卡住了、何时重置
最多三个圆环，加一列所有者的修改进度条旁边配文字，每张卡片读法不同，账号一多就翻倍；三个圆环下写重置时间、一列放金额或状态，每一行都一样
用应用自己的组件搭建项目规则两个分段控件用 Tabs，复用 Dialog、RadioGroup、SearchInput、HoverTip、菜单样式、ProviderIcon、ProviderLogin、BaseUrl、SetupHint、自定义供应商表单和 Routing；Token 用量的堆叠图和用量面板共用。只有 30 天迷你图是新写的。为凭据页面，组件库加了带圆点的 Badge 色调、Collapsible、Progress、CopyButton 和 SecretInput。同类产品的界面代码绑定各自的组件库和类型，所以采用它们的结构，不搬代码
一个有序的密钥和登录列表，带策略Hermes Agent 的凭据池对请求来说，备用密钥和第二个账号是一回事
对话保持自己的凭据，直到失败Oh My Pi缓存和限额留在一个账号上；淡色提示行标出切换
在模型菜单里固定所有者的修改密钥放在选对话模型的地方
保存前检查Hermes被拒绝的密钥不会进入列表
只有删除需要确认所有者的修改其他行操作都有相反操作
拖动加上移 / 下移项目规则键盘也能调整顺序
登录方式做成带说明的列表，默认方式标为推荐所有者的修改几个一样的空按钮没有选择的理由；注册表的第一种本来就是各端预选的默认方式
对话框后面不做背景模糊所有者的修改模糊后的页面让人看不出自己在哪；浅色遮罩让它留在视线里
Anthropic 只用 API 密钥项目规则Anthropic 只通过官方 API 和 API 密钥使用
套餐名取自已有的数据Codex CLI回复的限额帧里写的套餐，否则是登录 token 的 chatgpt_plan_type 声明。不为一个标签发请求，用现有的计费标签显示
刷新先读登录所有者的修改供应商注册 reread_login：快过期的 token 先刷新，刷新不了的标记出来，重新登录过的恢复使用。读取器关闭的供应商只读额度时什么都不会变
用完的委托登录按 refresh token 标记已存登录的规则被拒的 token 的摘要记在凭据上。Codex CLI 的文件里还是这个 token 时不再请求；文件里换了登录就清除标记。网络失败不标记
