供应商管理

设置 → LLM Providers 列出已连接的供应商，三步添加一个（选择、密钥或登录、默认模型），并显示每个供应商的健康、额度和花费。对话里只在模型选择器和额度用尽的回复卡片上显示供应商状态。额度和健康来自供应商额度。

供应商列表

  • 列表只放已连接的供应商：存有密钥或已登录，或已启用的本地服务。目录（约 236 个供应商）放在添加供应商里。
  • 卡片和紧凑行是同一个列表的两种视图。页头的分段控件切换它们；选择按用户记住，默认是卡片。
  • 一张卡片有顶行（标志、名称、计费标签、健康标签）、一个额度块（窗口、余额、速率限制或"No quota data"）和底栏（30 天迷你图、花费或 Included、缓存占比、默认模型）。
  • 紧凑行把同样的信息放在一行：最先用完的那个限额的进度条，然后是"62% 5h · 14:30 · 15% Week"、"$18.42 balance · ≈ 26 wk"或"46/50 rpm · no balance data"；30 天花费或 Included、走势、token、缓存占比和默认模型。
  • 紧凑行列宽固定：每个单元格在自己的列里以省略号结尾，悬停看完整文字，所以再长的状态、额度文字或模型 id 在 640 px 及以上的窗格里也不会让表格横向滚动；窄于 880 px 时先隐藏 Tokens 和 Cache。
  • 美元余额在有三天花费后显示可用时长（"≈ 26 weeks at this pace"）。
  • 已登出或已停止的供应商数字变淡；超过 15 分钟的快照在两种视图里都变淡，卡片写"Updated 3 h ago"。
  • 供应商只报告有这个限额而不给数字时（Codex 不限量的 credits、Copilot 不限量的高级请求）写"Unlimited"。额度端点读取失败时写"Couldn't read the quota"，原因放在悬停提示里。
  • 计费标签写 API key、Local 或 Subscription。知道套餐的订阅在这个标签里写套餐名（“Plus”“Pro”）；紧凑行在原本写 Included 的位置显示同一个标签，悬停显示“Included in the Plus plan”和按 API 价的金额。不知道套餐时不变。
  • 页头有 Providers | Routing、最近更新时间、刷新、卡片 | 列表切换和添加供应商。没有说明段落。
  • 刷新按顺序重新读取每个供应商：先读登录所在的位置，再读额度端点；健康状态由两者得出。结果替换卡片之前，按钮上的图标一直转，更新时间也算上这次读取。

添加供应商

什么都没连接时，页面直接显示添加供应商里的同样选项，没有说明文字：

  1. 环境里的密钥排在最前，每个带 Use。变量按供应商的密钥名（先静态表，再 models.dev 的 env）匹配目录。页面只拿到变量名和打码的尾部；Use 让 Worker 自己读取并保存，密钥不经过网络传给页面。OAuth 令牌变量从不提供。
  2. 常用：八个一格，点一下进入第 2 步：OpenAI（ChatGPT 登录，旁边有 API 密钥）、Anthropic（只用 API 密钥）、Google Gemini、xAI、DeepSeek、OpenRouter、Kimi / Moonshot（附 Kimi Coding 和中国站）、Z.ai（附编程套餐和智谱）。
  3. 本机：Ollama、LM Studio、vLLM 和 llama.cpp，在回环地址上半秒内应答不带密钥的 GET /models 时显示。模型选择器把这个结果沿用 30 秒，打开它不会再探测。
  4. 全部供应商：在整个目录里搜索。
  5. 常用供应商读取中时格子处显示加载图标；读取失败时用一行说明并给重试。

第 2 步是一个打码的密钥输入框加"Get a key"链接，或者登录。如果这个供应商的密钥已经在 Worker 的环境变量里（从图块、搜索结果或 ?add=<id> 进入），第 2 步先给出它，和选择列表同样的一行（变量名、打码尾号、Use），下面是"Or paste a key"。

环境变量里的密钥被拒时，显示那一行结果，下面仍是粘贴框。

粘贴后立即检查：先免费读取供应商的模型列表或密钥端点，只有这次读取证明不了密钥可用时才发一个 token 的测试请求。结果是一行：

unverified密钥被接受，但没有东西证明它能应答是

保存的密钥通过该供应商已验证的额度读取器读一次余额。

一个供应商第一个 works、no_credit 的密钥，或供应商以 HTTP 200 接受的 unverified 密钥，会启用这个供应商（5xx 或没有应答说明不了密钥，什么都不启用），第一次登录也一样；没有单独的启用步骤。它的模型一个都没开启时，开启三个推荐模型。

第 2 步把同一厂商的几种接入方式做成标签页（ChatGPT 登录旁边是 OpenAI API 密钥）；Advanced 收起 Base URL。正在运行的本地服务一个按钮就能接入，没运行的显示如何启动。Custom 打开自定义供应商表单。

第 3 步提供这三个：已开启的排前，其次是支持工具调用的最新模型，附上下文和价格。Start chatting 把其中一个设为输入框的模型。

供应商详情

对话里

对话里关于供应商的一切都在模型选择器里（触发按钮和菜单）。输入框里项目文件夹旁没有标签或按钮，也没有弹出提示。

供应商行显示点击

  • 子菜单开头是这个供应商的额度行，最紧的在前：窗口或密钥限额是 label [bar] NN% · reset，余额或点数是金额。什么都不报告的供应商没有这一段。
  • 菜单最后是 Manage providers，打开设置 → LLM Providers。一个供应商都没接入时，菜单写明这一点并提供 Add provider，打开同一个页面的空状态。
  • 只有所选模型的供应商需要处理或额度预警时，触发按钮的供应商图标上才有一个小点（Worker 的 attention：用到 95% 以上，或用到 80% 以上且用量跑在窗口已过时间前面）。它的提示写明供应商和状态或窗口剩余。

状态随模型一起送达（GET /api/models/enabled）；打开菜单时读状态路由取额度行，状态路由会在后台读取超过十分钟的接口。每个 provider_quota 帧更新这两份数据，并作为窗口事件 op:provider-quota 转发。

回复因额度用尽而失败时（errorCause.cause 是 quota_exhausted），回复卡片写“OpenAI Codex 5h 额度已用完”，下面是“14:30 重置 · Week 剩 71%”。余额用尽（402，或供应商状态是没有余额）写“Kimi 没有余额了”，下面是余额。原始错误留在折叠的详情里。

按钮作用
改用 <模型> 继续另一个健康供应商上的同一个模型 id；没有的话，是最近 7 天用得最多、工具、视觉和推理能力相同、上下文窗口放得下这段对话的健康模型
其他模型…先列出最多四个还有额度的模型，然后是完整的选择器
等待保留当前模型，收起按钮；余额用尽时这个位置是充值

选中的模型只固定在当前窗格显示的分支上，并在那里重新发送失败的这一轮；其他分支和对话保持原来的模型。不会自动切换；故障转移链仍把额度用尽当作终止。

Token 用量

  • 花费按计费方式拆开：已计费（按 token 计费的供应商、有价格的调用）、已包含（订阅调用按标价计，只在提示里显示），以及按 token 计费却没有价格的调用数。一个没有价格的调用不再让总数消失。
  • 花费卡片显示已计费的总数，标签旁写"N calls unpriced"，悬停显示订阅按 API 价覆盖了多少。By model 里订阅的行写 Included，悬停显示标价；By source 和 By function 的行也这样拆分花费，调用全由订阅覆盖时写 Included。
  • 套餐供应商（OpenAI Codex、SuperGrok、OpenCode Go、Kimi Coding、GitHub Copilot、Gemini 订阅）或 id 写明编程套餐、token 套餐的供应商算作订阅。
  • 所有 token 总数都含缓存 token：存下的总数漏掉缓存的旧行按各部分之和读取。
