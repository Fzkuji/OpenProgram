Provider management

Settings → Model services lists the providers that are connected, adds one in three steps (pick, key or sign-in, default model) and shows each provider's health, quota and spend. The chat shows provider state only inside the model picker and on the reply card of a spent quota. Quota and health come from Provider quota.

Provider list

  • The list holds connected providers only: a stored key or sign-in, or an enabled local server. The catalogue (about 236 providers) lives in Add provider.
  • Cards and compact rows are two views of the same list. A segmented control in the page header switches them; the choice is remembered per user and cards are the default.
  • A card is a header (logo, name, default model, one +) over one row per credential: every key and every signed-in account of each of the company's ways. A way with no credential yet, or a local server, is one row of its own.
  • A row is three fixed parts, the same on every card. Who: the account's email, the key's name, its last four or its variable, over its way and plan ("Go", "Plus", "API key"); a green dot marks the one in use when there are several.
  • Its limits: up to three rings (5h, Week, Month, Req/m, Tok/m, Limit), each over when it resets or its cap, shortest window first; with more, the tightest three. A failed read is a dashed Unread ring with the reason on hover.
  • The last column holds an amount while the credential works: Credits, Balance, or 30 days of spend for a key; nothing for an included plan.
  • Otherwise it says why not: Limited or Cooling in amber with when it comes back; Invalid, Signed out, Not running in red with when it was found; a spent balance in red; Off in grey for a key set aside.
  • No action words: a red cell fixes what it names on a click (sign in, replace the key, open billing, how to start the server); the rest of the row opens the provider's page.
  • A row whose numbers are older than 15 minutes is dimmed, with when they were read on hover. A card shows four rows at most; past that, the one in use and the ones in trouble stay and the rest fold into "N more" with what is wrong among them ("1 invalid").
  • A card is the raised surface the chat's buttons use: a hairline frame with a soft shadow that deepens under the pointer. Each row inside is a rounded tile of the file-change card's material, 8 px from the next and 12 px from the card's sides and bottom, with no divider; under the pointer its shadow deepens and its fill stays.
  • A company connected in more than one way is one card; the cards form a masonry (table below).
  • A compact row puts the same facts on one line: the bar of the limit that runs out first, then "62% 5h · 14:30 · 15% Week", "$18.42 balance · ≈ 26 wk" or "46/50 rpm · no balance data"; 30-day cost or Included, the trend, tokens, cache share and the default model.
  • Rows have fixed columns: every cell ends in an ellipsis inside its column with the whole text on hover, so a long status, quota line or model id never makes the table scroll sideways in a pane 640 px or wider; below 1040 px Tokens and Cache give way.
  • A balance in dollars shows its pace ("≈ 26 weeks at this pace") once three days have spend.
  • The billing tag says API key, Local or Subscription. A subscription whose plan is known says the plan ("Plus", "Pro") in that tag; a compact row shows the same tag where it would say Included, with "Included in the Plus plan" and the API price on hover. An unknown plan changes nothing.
  • A signed-out or stopped provider's numbers are dimmed; a snapshot older than 15 minutes is dimmed in both views and says "Updated 3 h ago" on hover, with no line of its own.
  • A limit reported without a number (Codex's unlimited credits, Copilot's unlimited premium requests) reads "Unlimited". A quota endpoint that failed says "Couldn't read the quota" with the reason on hover.
  • The header holds Providers | Routing, the time of the last update, Refresh, the Cards | Rows switch and Add provider. No paragraph of help.
  • Refresh reads each provider again in order: its sign-in where it lives, then its quota endpoint; health follows from both. The icon spins on the button until the answer replaces the cards, and the update time counts that read.

Adding a provider

With nothing connected, the page shows the same choices Add provider shows, and no prose:

  1. Keys in the environment first, each with Use. A variable is matched to the catalogue by the provider's key names (the static table, then models.dev's env). Only its name and a masked tail reach the page; Use makes the Worker read and store it, so the key never crosses the wire. OAuth token variables are never offered.
  2. Popular: a grid of eight, each one click into step 2: OpenAI (ChatGPT sign-in, with the API key beside it), Anthropic (API key only), Google Gemini, xAI, DeepSeek, OpenRouter, Kimi / Moonshot (with Kimi Coding and the China endpoint), Z.ai (with its coding plan and Zhipu).
  3. On this machine: Ollama, LM Studio, vLLM and llama.cpp when one answers GET /models on its loopback address within half a second, without a key. Opening the model picker, Providers or Add provider probes again, showing the kept answer meanwhile; other reads reuse a probe up to 30 seconds old.
  4. All providers: a search across the whole catalogue.
  5. The popular providers are read as Settings opens; until they arrive the grid's place stays empty, and a failed read is retried quietly (waiting without words).

Step 2 is one masked key field with a "Get a key" link, or Sign in. When a key for that provider is already in the Worker's environment (from a tile, a search result or ?add=<id>), step 2 offers it first, the same row as the pick list (variable name, masked tail, Use), with "Or paste a key" below it.

The key is checked when pasted: a free read of the provider's model list or key endpoint, then a one-token ping only when that read cannot prove the key usable. The answer is one line:

ResultWhenKey kept
worksThe key was proven usable (a key endpoint with credit left, a ping that answered, or a model that is only busy)yes
unverifiedThe key was accepted but nothing proved it can answeryes
no_credit402 or a no-balance answer; links the billing pageyes
not_availableA 403 naming the region or the planyes
unreachableThe host did not answer; Retry checks the stored key againyes
rejected401, or a 403 that names no region or plan; links the keys pageno

A kept key's balance is read once through the provider's verified quota reader.

A provider's first works or no_credit key turns it on, as does an unverified key the provider answered with HTTP 200, and its first sign-in; a 5xx or no answer turns nothing on. There is no separate Enabled step. When none of its models is on, the three suggested models are turned on.

Step 2 shows a company's ways to connect as tabs (the ChatGPT sign-in beside the OpenAI API key): the ways the company table marks as offered; Advanced folds the base URL away. A running local server connects with one button and a stopped one shows how to start it. Custom opens the custom provider form.

Sign in lists the provider's ways in:

  • Each row has an icon, a title, a one-line description and a chevron; an import also shows the file it reads in small mono type.
  • With more than one way, the first (the browser sign-in) sits on a filled card marked Recommended and the rest follow under "Other ways".
  • Titles, descriptions and files come from the login method registry in English and Chinese, so every sign-in provider and the Credentials section's add dialog show the same list.
  • Choosing a row starts that method; the row shows a spinner until the browser, code or prompt takes over.

The dialog's overlay is Nova's light scrim with no backdrop blur, the same for every Dialog and AlertDialog, so the page stays readable behind it.

Step 3 offers those three, models already on first, then the newest with tool use, with context and price. Start chatting picks one for the composer.

One key, several ways

A key is its company's, not one way's: MiniMax's API and Token Plan, international and China, all list a MiniMax key, whether it was pasted on one of them or sits in MINIMAX_API_KEY. Nothing is guessed from the key or tried against every way (Companies, ways and credentials).
