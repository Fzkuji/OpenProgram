Provider management

Settings → LLM Providers lists the providers that are connected, adds one in three steps (pick, key or sign-in, default model) and shows each provider's health, quota and spend. The chat shows provider state only inside the model picker and on the reply card of a spent quota. Quota and health come from Provider quota.

Provider list

  • The list holds connected providers only: a stored key or sign-in, or an enabled local server. The catalogue (about 236 providers) lives in Add provider.
  • Cards and compact rows are two views of the same list. A segmented control in the page header switches them; the choice is remembered per user and cards are the default.
  • A card has a top line (logo, name, billing tag, health chip), one quota block (windows, balance, rate limits or "No quota data") and a footer (30-day sparkline, spend or Included, cache share, default model).
  • A compact row puts the same facts on one line: the bar of the limit that runs out first, then "62% 5h · 14:30 · 15% Week", "$18.42 balance · ≈ 26 wk" or "46/50 rpm · no balance data"; 30-day cost or Included, the trend, tokens, cache share and the default model.
  • Rows have fixed columns: every cell ends in an ellipsis inside its column with the whole text on hover, so a long status, quota line or model id never makes the table scroll sideways in a pane 640 px or wider; below 880 px Tokens and Cache give way.
  • A balance in dollars shows its pace ("≈ 26 weeks at this pace") once three days have spend.
  • The billing tag says API key, Local or Subscription. A subscription whose plan is known says the plan ("Plus", "Pro") in that tag; a compact row shows the same tag where it would say Included, with "Included in the Plus plan" and the API price on hover. An unknown plan changes nothing.
  • A signed-out or stopped provider's numbers are dimmed; a snapshot older than 15 minutes is dimmed in both views and the card says "Updated 3 h ago".
  • A limit reported without a number (Codex's unlimited credits, Copilot's unlimited premium requests) reads "Unlimited". A quota endpoint that failed says "Couldn't read the quota" with the reason on hover.
  • The header holds Providers | Routing, the time of the last update, Refresh, the Cards | Rows switch and Add provider. No paragraph of help.
  • Refresh reads each provider again in order: its sign-in where it lives, then its quota endpoint; health follows from both. The icon spins on the button until the answer replaces the cards, and the update time counts that read.

Adding a provider

With nothing connected, the page shows the same choices Add provider shows, and no prose:

  1. Keys in the environment first, each with Use. A variable is matched to the catalogue by the provider's key names (the static table, then models.dev's env). Only its name and a masked tail reach the page; Use makes the Worker read and store it, so the key never crosses the wire. OAuth token variables are never offered.
  2. Popular: a grid of eight, each one click into step 2: OpenAI (ChatGPT sign-in, with the API key beside it), Anthropic (API key only), Google Gemini, xAI, DeepSeek, OpenRouter, Kimi / Moonshot (with Kimi Coding and the China endpoint), Z.ai (with its coding plan and Zhipu).
  3. On this machine: Ollama, LM Studio, vLLM and llama.cpp when one answers GET /models on its loopback address within half a second, without a key. The model picker reuses that answer for 30 seconds, so opening it does not probe again.
  4. All providers: a search across the whole catalogue.
  5. While the popular providers are read the grid shows a spinner; a failed read says so in one line with Retry.

Step 2 is one masked key field with a "Get a key" link, or Sign in. When a key for that provider is already in the Worker's environment (from a tile, a search result or ?add=<id>), step 2 offers it first, the same row as the pick list (variable name, masked tail, Use), with "Or paste a key" below it.

An environment key that is rejected shows its one line with the paste field under it.

The key is checked when pasted: a free read of the provider's model list or key endpoint, then a one-token ping only when that read cannot prove the key usable. The answer is one line:

ResultWhenKey kept
worksThe key was proven usable (a key endpoint with credit left, a ping that answered, or a model that is only busy)yes
unverifiedThe key was accepted but nothing proved it can answeryes
no_credit402 or a no-balance answer; links the billing pageyes
not_availableA 403 naming the region or the planyes
unreachableThe host did not answer; Retry checks the stored key againyes
rejected401, or a 403 that names no region or plan; links the keys pageno

A kept key's balance is read once through the provider's verified quota reader.

A provider's first works or no_credit key turns it on, as does an unverified key the provider answered with HTTP 200, and its first sign-in; a 5xx or no answer turns nothing on. There is no separate Enabled step. When none of its models is on, the three suggested models are turned on.

Step 2 shows a vendor's ways to connect as tabs (the ChatGPT sign-in beside the OpenAI API key); Advanced folds the base URL away. A running local server connects with one button and a stopped one shows how to start it. Custom opens the custom provider form.

Step 3 offers those three, models already on first, then the newest with tool use, with context and price. Start chatting picks one for the composer.

Provider detail

The header holds the way back to the list, the health chip, when the provider was last read (its quota, or a Refresh), Refresh (that provider only: sign-in, quota and health) and the on switch.

Remove provider asks once (the destructive confirm). A custom provider is deleted; any other loses its saved keys and sign-ins and is switched off, which takes it off the list. A local or custom provider also adds a model by id.

In the chat

Everything the chat says about providers lives inside the model picker (trigger and menu). There is no chip or button beside the project folder in the composer, and no toast.

  • The ring and the bars use the context meter's tokens: warning from 80 % used, danger from 95 % or when spent; a value older than 15 minutes is drawn at half opacity.
  • A submenu starts with the provider's quota rows, worst first: label [bar] NN% · reset for a window or key limit, the amount for a balance or credits. A provider that reports nothing has no header.
  • The menu ends with Manage providers, which opens Settings → LLM Providers. With no provider connected at all it says so and offers Add provider, which opens the same page at its empty state.
  • The trigger carries a dot on the provider logo only when the selected model's provider needs action or its quota warns (the Worker's attention: used 95 % or more, or 80 % or more while usage runs ahead of the time elapsed in the window). Its tooltip names the provider and the state or the window left.

The state comes with the models (GET /api/models/enabled); opening the menu reads the status route for the quota rows, which reads endpoints older than ten minutes in the background. Each provider_quota frame updates both reads and is passed on as the window event op:provider-quota.

When a reply fails because a quota is spent (errorCause.cause is quota_exhausted), the reply card reads "OpenAI Codex 5h limit reached" over "Resets 14:30 · Week 71% left". A spent balance (402, or the provider's state is no credit) reads "Kimi has no credit" over the balance. The raw error stays under the collapsed details.

Token Usage

  • Cost is split by how it is billed: billed (pay-per-token providers, priced calls), included (a subscription's calls at list price, shown only in a tooltip) and the number of pay-per-token calls without a price. One unpriced call no longer hides the total.
  • The cost card shows the billed sum, "N calls unpriced" beside its label and, on hover, what subscriptions cover at API prices. A subscription's row in By model reads Included with the list price on hover; a By source or By function row splits its cost the same way, reading Included when a subscription covers all of its calls.
  • A provider is a subscription when it is a plan provider (OpenAI Codex, SuperGrok, OpenCode Go, Kimi Coding, GitHub Copilot, Gemini subscription) or its id names a coding or token plan.
  • Every token total counts cached tokens: an older row whose stored total left them out reads as the sum of its parts.
