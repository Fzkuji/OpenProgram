Session resources

Engineering design for the collapsible right-side Session resources panel. It lists complete software and environment objects used by the session. Activity owns code executions, commands, scripts, background processes and output; files remain in file views. Status: implementation reviewed; installation acceptance verifies the default App.

Interaction

A Session resources navigation button sits in the right sidebar beside Files and Activity. It uses their shared row, icon and label classes, left-aligned label, 20px animated icon, and matching hover/focus behavior. It opens a searchable panel in the existing resizable right dock. The dock toggle collapses the panel to its icon rail. Only resources whose recorded owner matches the selected session appear. Switching sessions resets search and details and aborts previous requests. An owned webpage retains its recorded session context; drafts and unassigned views show no session resources. Legacy agent webpages without an owner stay reachable in the top strip instead of being assigned to an arbitrary session. Selecting a webpage promotes its existing browser leaf to a separate visible top-level tab, ends its floating preview, and activates that tab while preserving the session chat tab and recorded ownership. Repeated selection reuses the same webpage tab without creating duplicates. Other resources show their details while keeping the resource panel available. Collapsing the dock or selecting another dock view stops resource polling. The selected dock view persists across reloads.

The registry records use of complete software/environment objects, not code execution. Integrations must identify the actual container, VM, application or remote environment. Per-command Docker image invocations and SSH subprocesses do not register resources. ProcessStore is used by Activity and is not projected into this list. The registry does not scan the host or infer objects from arbitrary shell text.

Boundaries

The server checks session and execution authorization before returning resources. Browser rows remain renderer-owned; requests for backend rows cover only the selected session. Rows returned through authorized descendant scopes are still filtered by their actual session owner. Registry payloads contain bounded display fields only; URLs omit credentials, query parameters and fragments. The resource panel participates in the existing right-dock layout. Native browser bounds resize with the remaining center area, keeping resources and the webpage visible together.

The Chrome reference supplied by the user motivates searchable grouped resource rows. The approved placement is the right collapsible panel. The implementation reuses the existing right dock, center-tab store, authorized resource route, and native browser bounds reporting. It does not introduce a second browser manager or a generic destructive action protocol.
