Session resources

Engineering design for the top-left resource picker. It replaces the right-sidebar Pages entry. Status: implementation reviewed; installation acceptance verifies the default App.

Interaction

A compact chevron button sits after the macOS window controls and before all tabs. It opens a searchable, keyboard-accessible popover. Resources are grouped by session; groups can collapse. Closing the popover restores focus to its button. Opening a resource selects the existing view or shows its details.

The registry records resource use, not ownership of the external infrastructure. A Docker backend use identifies its image and call; a VM attachment identifies its configured endpoint. It does not scan the host, infer resources from arbitrary shell text, or expose infrastructure delete buttons. Existing long-lived processes are projected directly, not copied into the registry.

Boundaries

The server checks session and execution authorization before returning resources. Browser rows remain renderer-owned; requests for backend rows cover the sessions represented in this window. Registry payloads contain bounded display fields only; URLs omit credentials, query parameters and fragments. Popover occlusion uses the existing native-view occlusion contract, preventing native browser content from covering the picker.

The Chrome reference supplied by the user motivates the top-left search/disclosure interaction. The implementation uses the existing Radix Popover, center-tab store, process routes, and native-view occlusion. It does not introduce a second browser manager or a generic destructive action protocol.
