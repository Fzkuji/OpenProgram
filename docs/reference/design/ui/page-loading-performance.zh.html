页面加载性能

每个应用页面都加载共享界面。优化首屏代码、重复目录计算和 Provider 选择渲染，不改变认证、路由历史和模型能力。

不是端到端点击耗时。基准中十四种 DiceBear 样式全部进入首屏依赖（两个头像文件，gzip 约 270 KB），原生 Provider 列表请求耗时 1138 ms，Python profile 记录累计枚举 1.318 s。会话期间的资源计数包含三秒轮询，不是冷启动耗时。

设计

方面规则
头像可选样式用显式动态导入（React lazy）；默认 shapes 样式保持同步。合并进行中的加载，失败后可重试。卸载或配置变化后到达的结果被忽略。
SVG 缓存模块级重用，有上限（128 项，51.2 万字符）。上传和字母模式不生成 DiceBear SVG。
Provider 行React memo 配稳定回调；选择变化不重新生成未变的图标。
目录每次请求一份凭据存在快照，不跨请求，也不作为认证判断缓存。
设置读取成功的读取只在有效期内初始化 Provider 目录的首屏；配置操作使其失效。

等待不配文字

页面、面板和卡片都不说“加载中”“正在重试”“读不到”，App 自己发出的读取没有报错页，也没有重试按钮。等待要靠缩短来解决，不靠文字说明。

情况规则
还没到位置按最终大小留空，数据到了不跳动。只有答复已经到了而且确实为空，才显示空状态（“还没有运行”）。
之前看过第一帧就画上次的答复，后台再刷新：查询数据保留 30 分钟，TanStack Query 之外的读取在页面存活期间保留上次的答复。
第一次打开首屏后一秒内预取全部外壳路由和十一个懒加载标签页；每个导航页的第一次读取在空闲时和鼠标移到导航项上时开始。
读取失败上次的数据留着；按退避重试（1 秒起翻倍到 30 秒），用 console.warn 记录。页面自己发出的读取失败不弹提示。
确定的答复4xx、“不存在”或“已删除”结束重试，页面据此处理：东西不在了的详情页回到列表，不存在的会话关闭，服务端拒绝的区块不画。一个来源失败不拖住其他来源。
照常显示用户刚做的事的结果（保存或密钥被拒、乐观改动被服务端拒绝、自己打开的文件夹读不出来），内容本身的状态（压缩包损坏、图片无法解码），以及登录已过期。
服务端数据回复体检查前是 unknown（apps/web/lib/net/json-unknown.d.ts）；可能是句子、列表或对象的错误字段经 errorDetailText 变成文字。直接渲染未检查的对象曾让整个窗口崩掉。

改动前在已安装的默认 App 上实测（快机器）：首次打开 Agents、MCP、Plugins、Applications、History、Scheduler、Programs、Projects、Memory 和五个设置页时“Loading”会闪 10 到 500 ms；冷启动约 850 ms 时、打开会话约 130 ms 时也会出现。

改动后同样走一遍（冷启动、25 个页面、三个会话及各自的面板标签），没有任何加载或失败文字，也没有页面错误。

必须保持

  • 不支持的 Provider 保持不支持。本地 Provider 身份、别名、账号存在性、CLI 回退、环境变量和云认证语义不变。
  • 指标不暴露凭据值。
  • 缓存过期、请求失败和加载占位都不把另一个 Provider 显示为已选路由。
  • 上传、字母、全部生成样式、Thumbs 背景和 SVG ID 隔离保留。
验收
  • 公共头像入口只加载默认样式；所选样式只加载一次；十四种都可选。
  • 相同头像在有界缓存内重用标记。
  • 目录列表测试证明每次请求枚举一次，下次请求立即反映变更。
  • 选择更新只渲染受影响行；预热后再次访问立即显示缓存行。
  • 对比生产入口字节和同机目录耗时与基准。
  • 在已安装的默认 App 中检查聊天、Agents、能力、通用和 Provider 导航。
