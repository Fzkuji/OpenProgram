Composer 控制栏响应式设计

范围：聊天输入框上方的 environment chips，以及下方的 permission、more、active tools、chat model、execution model、effort 和 context 控件。

两排控制栏分别按自身可用宽度响应。底排沿用既有设置；上排只允许“全部完整文字”与“全部图标”两个显示状态。只要完整内容开始溢出，状态、surface、项目、目录以及 DAG 的 Fit、缩放百分比和 Legend 就同时隐藏文字；空间恢复后同时显示。切换使用同一段过渡动画，菜单、当前值、键盘操作、tooltip 和 accessible name 保持不变。

当前实现与缺口

.composer-bottom-row 继续按自身容器响应。.envChips 不再使用固定断点，因为聊天页和 DAG 页的控件数量不同，同一宽度下需要的空间也不同。它通过自身 scrollWidth 与 clientWidth 判断完整内容是否溢出，并用一个 data-compact 状态控制全部 label。单页和 split pane 运行完全相同的测量逻辑。

现有组件已经提供四类互异图标：Shield 表示权限，Message 表示 chat model，Terminal 表示 execution model，Biceps 表示 effort。所有触发器已经具备 Popover/Menu、tooltip 或 accessible name，因此不新增图标组件和菜单。

参考与选择

参考适用能力采用方式
W3C CSS Containment Level 3@container 根据组件容器尺寸控制后代样式，不依赖 viewport。采用现有 .composer-bottom-row 容器；split pane 与普通会话共用同一规则。
WAI accessible names隐藏可见文字时，交互控件仍需保留可计算的名称。沿用现有 tooltip、Popover trigger 和标签；视觉隐藏不删除 DOM 语义。
横向滚动保留任意长度的文字，但会让部分设置入口离开当前可见范围。保留为极窄宽度的后备；不作为主要响应方式。
换成两行全部文字可见，但会改变 composer 高度并影响 transcript 底部预留。拒绝；本任务保持单行。

控制按钮 surface 层级

上方 environment chips 使用填充与边缘层级，底部 controls 则只有 20px 高。底部 permission、more、active tools、chat model、execution model、effort 与 context 只复用主题级 --chip-bg，形成始终可见的浅色填充；常态 surface 不新增 border、内描边或外部阴影，避免压缩小控件的内部视觉空间。既有 hover 前景色和键盘 focus-visible 指示保持不变。

收缩规则

  1. environment chips 的 label 不参与 flex 收缩，不出现半截文字。
  2. 完整内容溢出时，全部 label 同时执行淡出和宽度收起；空间恢复后同时反向恢复。
  3. 各图标触发器保持尺寸、原顺序和操作能力。

交互与无障碍

  • 点击图标打开原菜单。
  • chat 与 execution 使用不同图标。
  • effort 图标颜色继续反映当前级别。
  • focus、tooltip 和 accessible name 不随文字隐藏而消失。

边界

  • 不改模型、权限和 effort 状态。
  • 使用原生 ResizeObserver 与 MutationObserver，不新增依赖。
  • 不换行、不隐藏整个控件。
  • 不调整 composer 高度和 splitRatio。

实施 brief 与验收

本次上排实现限定为 web/components/chat/composer/index.tsx 与 composer.module.css：前者只负责测量和切换一个 compact 属性，后者统一负责所有 label 的动画与 icon-only 尺寸。回归入口使用现有 npm --prefix web run check:chat-ui。不修改 Popover、Menu、provider、session store 或提交逻辑。

  1. public-entry 检查必须证明 environment chips 由实际溢出切换单一 data-compact 状态，不存在固定宽度特例或 label 的 flex-shrink:1。
  2. 状态、surface、项目、目录、Fit、缩放百分比和 Legend 必须共用同一动画规则；不得使用 display:none 或只收起其中一部分。
  3. 默认安装版在 split pane 中把 divider 向左拖到触发阈值后，右侧四个设置入口和左侧 permission/more 均可见、无重叠。
  4. 分别点击 permission、chat model、execution model 和 effort 图标，原菜单或面板正常展开。
  5. 把 pane 拉宽到完整内容可容纳后，所有文字一起恢复；重新选择 split、切换聊天/DAG 和刷新不改变该行为。
  6. 底部所有可见控制按钮在未 hover 时均有非透明的 --chip-bg surface，computed border 为 0 且 shadow 为 none；hover 或菜单展开时背景必须比常态更明显。键盘 focus-visible 指示不属于常态边框，继续保留。
