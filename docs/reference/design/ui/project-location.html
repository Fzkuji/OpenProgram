Implementation, plan and acceptance (expand)

Conversation storage comparison

Claude Code stores sessions under ~/.claude/projects/; OpenCode under ~/.local/share/opencode/. Their storage is separate from the working directory. These sources establish storage placement, not experimentally verified unplugged-drive UI behavior. OpenProgram normally stores project sessions in <project>/.openprogram/sessions/, with default, legacy and fallback sessions in user state. The design must distinguish actual placement and must not present cached content as an available project.

User-visible behavior

Same-volume rename or move

Resolve the existing directory after an event, verify identity, and update its location without a confirmation. Keep conversations, Memory associations and settings.

Moved while the app is closed

At startup check registered projects only and resolve persistent references. If that fails, wait for project access before a bounded candidate search.

Disconnected volume

Show that the disk is disconnected. Keep the record and location. Recheck on mount or explicit access; do not search other disks for replacements.

Copies and Git clones remain separate projects. A recreated old path must not inherit the relocated project's data. Cross-volume moves without native identity continuity require explicit candidate selection. Permission failures and unreachable network volumes are distinct from deletion. Never recreate a missing directory, elevate permissions, mount a volume automatically or silently execute in Home.

Separate application identity, physical identity and location

A fixed project_id owns conversations, settings and Memory associations. New projects use random IDs; existing IDs are preserved. A host-scoped native reference identifies the directory. path is only its last verified location; location_revision rejects stale asynchronous results. Physical identity must be checked even when the old path exists.

Persist available, resolving, offline, permission-denied and needs-location states without changing ownership or pruning history. Names, Git remotes, commits and copied session markers are candidate hints, not identity proof. The existing device/inode string is not a complete cross-reboot or cross-volume guarantee. Update trusted physical identity only on registration, explicit location or verified relocation, never on ordinary metadata edits. Replace automatic session-footprint adoption in _claim_moved_project with candidate reporting. Do not add a copyable marker and claim it uniquely identifies a physical directory.

Unsupported backends and exhausted watcher resources degrade to access-time checking, never polling. Library and bridge choices remain gated by platform experiments. Untested platforms are not labelled supported.

Explicit triggers and consistent recovery

Triggers are native move events, volume mounts, startup, project access or execution encountering an invalid location, and manual retry. Registry mutations reconfigure watchers through existing events. Share watches on common parents and avoid recursively subscribing to project content. Overflow revalidates registered targets only, never a whole disk. Content edits do not trigger global recovery.

  1. Capture project ID and location revision; process only affected projects.
  2. Resolve the native reference first. Validate physical and volume identity, directory type and destination ownership.
  3. Classify failures. Offline and permission failures do not start searches.
  4. Only project access or manual retry can launch one bounded candidate search: the nearest accessible former parent, two levels, 1,000 directories and two seconds. No home-tree or common-folder traversal. Reaching a bound leaves manual location available.
  5. Ask the user to select a candidate unless identity continuity is proven. Stop without timed retries.

One recovery task per project; coalesce duplicate events and discard stale results. At most one candidate search per interaction. Blocking native resolution needs a terminable task boundary and a deadline, not merely a thread with a timeout. Shutdown cancels work and releases all native watchers and handles.

Location changes must survive partial writes

The current registry-first update with best-effort session-index repair is insufficient. Reuse an operation journal for expected revision, old/new location and affected mappings. Persist intent, apply registry and derived indexes, then publish projects_changed only after consistency. Restart completes or rolls back incomplete work. Never hold project locks while acquiring session locks. Validate each session's project ownership, expected old location and revision during its update; deletion or reassignment must not be undone. Reject candidate substitution before commit.

Resolve project-owned paths through project_id plus relative path. Preserve absolute references outside the project. Sessions, file browsing, Memory sources, pickers and execution use one resolver; do not rewrite historical message text. A running process retains its cwd and tool calls are never replayed automatically. Before launching a new tool, validate the revision and physical directory; pause directory-dependent work when unavailable. Independent worktrees have independent location records. Remote locations are resolved only by their owning host.

Code boundaries

Replace periodic coordination in discovery.py. Extend project_store.py without changing existing IDs. Share resolution with agent/internals/_workdir.py and session_store.py. Own cancellation in server.py and reuse projects_changed invalidation. Verify actual native adapters; do not reuse polling program/skill watchers or refactor them.

Acceptance criteria

  • Thirty idle minutes: zero recovery directory traversals, timed stat passes and automatic retries. Editing 1,000 files does not trigger global recovery.
  • Root rename, ancestor move and rapid repeated moves resolve to the final path. One-second event-to-update latency is a local acceptance target, not a network-volume promise.
  • Offline app movement uses supported persistent references or an honest fallback.
  • Copies, multiple copies, reused paths and changed volume identity never silently merge projects. Git or session-marker equality alone never authorizes adoption.
  • Unmount/remount, permissions, overflow and resource limits produce no retry loops, UI stalls or recreated folders.
  • Crash at each persistence step and restart: project identity, settings, history and session mappings remain consistent. Concurrent session deletion cannot deadlock.
  • Public execution never starts in a substituted directory; running tools are not replayed. Independent worktrees and external source paths remain correct.

Run platform experiments, identity unit tests, native-event and persistence component tests, service/execution integration tests, relevant contracts, then real directory movement through the installed App. Prove costs with counters; the absence of sleep is not sufficient.

Implementation status

Current-code audit and design draft are complete. Periodic scanning is still installed. Native event service, persistent native references and transactional relocation are not implemented. Each stage needs its own acceptance evidence; incomplete stages remain incomplete. Design review precedes production edits.
