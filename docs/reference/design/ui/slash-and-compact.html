斜杠命令和上下文压缩，现在到底是什么情况

压缩后端是活的。斜杠菜单也画得出来。断在「点了 / 按了回车之后，命令经常根本没发出去」，以及「就算发出去了，界面也不告诉你正在压」。

后端压缩管道可用 手动 /compact 经常发不出去 自动压缩会跑，但界面无声 圆环只展示占用，不能压缩

一句话

「上下文压缩」不是圆环上的按钮，是 /compact。它会让模型把旧对话收成一段摘要，接到 DAG 上，后面只带「摘要 + 最近几轮」。

你现在觉得斜杠和压缩都不能用，主要是 Composer 把可选参数命令当成「只填字、不执行」，再加菜单收起那 380ms 把回车吃掉。压缩引擎本身没有停。

压缩现在是什么

模型上下文就那么大。对话一长，旧轮次必须让位。OpenProgram 用的是滚动摘要：同一时刻只有一份有效摘要，再压一次是把「旧摘要 + 更多轮次」收成新摘要，不是叠两层。

下一轮模型实际看到的是：

[系统提示] [当前摘要] [没被吃掉的最近几轮] [你刚发的话]

三条触发路径

谁触发条件现在的真实状态
手动 /compact 你在输入框执行命令，可选留下最近 N token 后端有。前端经常发不出去，所以看起来像没做。
回合前自动压 本轮预算 ≥ 窗口的 80%。先尝试免费剪掉最旧轮（snip），还超再打一次摘要 LLM 会跑。dispatcher 在 loop_runner.py 里做。界面不提示。
爆窗抢救 模型返回 413 / prompt_too_long。每回合最多一次 会跑（reactive.py）。同样没界面。

另外还有一条「建议」：占用到 70% 会发 compaction_recommended。前端完全没接，圆环不会变成「该压了」，也不会弹出建议。

压的时候具体干什么

读取
从 SessionDB 拿「渲染后」的历史：已有摘要 + 还在枝上的轮次。再压不会回头重读已被盖住的原文。
门槛
少于 4 条就停。手动路径会回一句系统说明；引擎自己的 compact() 则是静默成功、什么都不写。
摘要
另打一次 LLM。最近尾巴默认按窗口的 10% 留，夹在 8k–40k token，至少 5 条有字的消息。可被 /compact 2000 覆盖。
落下
写入一个 summary_* 节点（role=llm，name=context/summary），covers_ids 标出被替换的那一段。会话 meta 记下这份摘要，方便下次接着压。
图
DAG 上是一颗胶囊。旧摘要标成 superseded，不再参与渲染。聊天记录里被盖住的原文还在库里，只是不在当前枝上。

圆环和 /context 面板不是压缩

右下角圆环只显示「此刻占用 / 窗口」。点开是 token 分类（系统提示、工具、记忆、消息…）。上面没有压缩按钮。 颜色：不到 50% 绿，50–80% 黄，≥80% 红 —— 红了正好是自动压缩该动手的线，但圆环不会替你执行 /compact。

工作区里未提交的 badge 改动只是预热缓存、拿掉全屏遮罩，跟压不压得动无关。

斜杠命令现在是什么

输入以 / 开头、还没有空格时，菜单从输入框顶边卷上来。空格一开始，菜单用 380ms 收起。回车时看第一个词在不在命令表里：在就执行，不在就当普通聊天（所以 /usr/bin 坏了 仍能发出去）。

内置表在 slash-commands.ts。另会拉 /api/commands 把技能 / 插件 / 用户命令拼进来。派发时内置排在前面。

命令点选后本应怎样现在怎样
/compact立刻压缩（参数可选）只填 /compact ，常常发不出去
/rewind、/branch立刻跑（参数可选）同上，只填字
/context打开圆环面板点选能开（无参数）
/clear、/new新会话点选能跑
/task、/skill、/merge先填前缀，等人补必填参数这一步是对的
/help打开列表只是把输入设成 /，指望菜单再出现
/sandbox、/doctor、/memory各自动作点选能跑；doctor 有会话时会把报告当用户消息发出去

断在哪

P0 · 手动压缩和大半斜杠「没反应」

1. 有 args 就只填字。 selectSlashCommand 看见 args 就 setInput("/compact ") 然后 return。可 /compact 的参数是 [keep_recent_tokens]，方括号表示可选。它又是表里第一项，所以输入 / 再回车，默认路径就是「填空格，不干活」。

2. 收起动画还在截回车。 visible 不看 closing。空格或点选之后 380ms 内，Enter 再次走进「填字」而不是 submit → runCommand。人手动等半秒再回车才能发出去。

3. 还没有 session 时假装成功。 if (!sessionId) return true。输入被清空，后端收不到，也没有提示。新开的空白对话上压，就是这种情况。

P1 · 就算发出去了，你也看不见

  • 后端会发 compaction_started / compaction_finished / compaction_failed，聊天转发是 catch-all，事件能到浏览器。
  • 前端只处理了 compaction_finished（刷新 DAG 明暗）和「不到 4 条」的 local_command 系统行。
  • 摘要 LLM 可能要好几秒。输入没了、圆环不动、对话不动 —— 和「根本没执行」长得一样。
  • 70% 的建议事件、自动压、抢救压，界面全是静音。

P2 · 次要

  • 统一注册表如果也叫 compact，菜单会出两个同名项（key={c.name} 还会撞）。派发仍走内置，先不是主因。
  • Jump to latest 的 z-index 是 7，输入框是 5。按钮出来时可能盖住菜单该在的位置。
  • /help 不是独立页。
  • /doctor 有会话时会把体检报告当聊天发出去。

建议先改什么

只动 Composer 斜杠路径和压缩状态提示。不动压缩算法、DAG 胶囊、圆环算法。

  1. 可选参数（只有 […]）点选 / 回车立刻执行。/task 这类必填参数继续先填前缀。
  2. 菜单 closing 时不要截 Enter，让它落到 runCommand。
  3. 没有 session 时不要 return true 清空输入，给一句「先发一条再压」。
  4. 接上 compaction_started / failed，用现成系统行即可。

做完 1–3，默认 / + 回车和点选 /compact 就应该能压。第 4 条用来分清「在跑」和「没跑」。

怎么确认现状（你现在就能试）

  • 空白新对话打 /compact 回车：多半输入没了、什么都没发生（P0-3 或 P0-1/2）。
  • 已有好几轮的对话，点菜单里的 compact：变成 /compact 。马上再回车，大概率还是原地不动（P0-2）。
  • 等大约半秒再回车：这次会发出 action: compact。消息够则开始压（界面仍可能沉默几秒），不够则出现「还不能压缩」系统行。
  • 圆环点开只有分解，没有压缩。
