OpenProgram / Web UI / Runtime contract

聊天发送队列可靠性设计

基线：b6460fdcb67b6b12843491490968696a5438d4d6。本页定义用户在 turn 运行期间提交下一条普通文本消息时，浏览器队列、WebSocket 和后端 session 独占之间的合同，并记录实现与验证状态。

确定方案。 每个 session 的运行中消息模式为 queue（默认）或 steer。queue 保持 renderer 内存态并沿用既有 FIFO；steer 通过 session 文件 inbox 在 agent-loop checkpoint 注入当前 turn，注入时立即写入带 steering: true 标记的 user node。服务端拒绝已结束 turn 的 steer；turn 收尾把尚未消费的 steer 按 FIFO 作为后续普通 turn 输入。goal/workflow 使用自己的 loop，不接入普通 chat 的消费器。

01 · 目标与边界

必须保证

  • 同一 session 同时最多发送一个队首。
  • 重复 clear 不会发送后续项。
  • 断线前未成功写出的项留在队首。
  • run_active 拒绝不会产生错误气泡或丢失文本。

产品边界

  • 队列不写磁盘，页面刷新会清除未发送项。
  • 队列只处理普通纯文本 turn。
  • slash、fn-form、附件继续使用各自入口。
  • 不同窗口各自持有其提交的队列和 session mode。

不引入

  • 不恢复已删除的 v2 MessageStore。
  • 不增加 broker、数据库表或新依赖。
  • 不把 queued message 提前写进服务端 transcript。
  • 不修改 goal/workflow 的 loop 或消费语义。

socket write 失败时，队首放回原位置且不进入 running。run_active 表示服务端已有 turn：被拒绝的普通发送放回队首，当前 session 保持 running，等待真实 clear。普通本地 idle→idle 更新不是 drain 信号；服务端 running_task_clear 是权威完成事件，即使 UI 已因 stop 乐观显示 idle，也必须尝试 drain。

steer 路径先把该项标为 injecting，按 request id 等待 steer_ack。accepted 后移除临时 queued row，服务端持久化的 user message 接管显示；not_running 解除 injecting 并沿用普通 queue/drain；超时保留原 queued row。agent loop 每次只消费一条 steer。消费时写入 user node，并把当前 assistant placeholder 的 predecessor 指向最新 steer node；turn 收尾取走剩余 inbox 项并依次启动后续普通 turn。

03 · 组件职责

组件唯一职责禁止行为
state/send-queue.tsFIFO、按 session 隔离、发送失败恢复队首。不判断服务端权威状态，不持久化 transcript。
composer/submit/send-chat-message.ts写 WebSocket；成功后立即设置该 session 的 optimistic running。不得在同一 session 已有 provisional send 时把第二条视为成功。
session-storerunning→idle 转换触发 drain；服务端真实 clear 可显式重试 drain。普通 idle→idle 更新不得触发 drain。
use-ws.ts连接恢复后，当前 session 通过 load_session 恢复；后台队列通过无焦点副作用的 get_run_state 查询状态。不得在未知 run 状态下直接发送队列，也不得为后台队列改变 socket 的 focused session。
ws_actions/chat.py原子占用 session，成功者才能写 user message 和启动 turn。不得把“检查”和“占用”分成可并发穿过的两个阶段。
ws_actions/runtime.py仅在 session 仍运行时接受 steer，并返回 request-correlated 结果。不得对已结束或无法写入的消息返回成功。
agent/dispatcher/loop_runner.py普通 chat 消费一条 steer、注入 agent loop 并同步持久化 conversation chain。不得让 agent_spawn 或 goal/workflow 消费普通 chat steer。

04 · 附件、断线与失败语义

  • 附件：运行期间若 composer 含图片或文档，提交动作不入队、不清空文字、不清空附件；界面维持草稿，等待当前 turn 完成后正常发送。
  • 写入前断线：sendChatMessage 返回 false，队首恢复；连接恢复且 session 确认 idle 后重试。
  • 写入后断线：本设计沿用 WebSocket 已写出即由服务端处理的现有合同；队首已经从浏览器队列移除。可靠跨进程投递与持久化幂等键不在本次范围。
  • 服务端拒绝：run_active 携带原文本，前端放回队首；其他错误仍按普通 turn 错误显示。
  • 停止并立即发送：目标项移到队首并发送 stop；optimistic clear 只更新 UI，不发送队首。收到服务端真实 clear 后才 drain，后端仍以原子占用为最终保护。
队列不是持久消息系统。它保证当前 renderer 生命周期内不因重复状态事件、已知 socket 写失败或服务端忙拒绝而丢失文本；页面刷新和已成功写入但 ACK 丢失仍遵循现有非持久边界。

06 · 实现记录

实现完成。queue 仍是默认且保持既有 FIFO。composer 的 per-session 设置新增 queue/steer 模式；steer 请求复用 queued row 表示 injecting 和失败回退。普通 chat agent loop 读取共享文件 inbox，持久化 steering user node 并同步 conversation edge；收尾关闭接受状态和最后 sweep 使用同一个 session 锁，避免 ACK 成功后遗留文件。goal/workflow loop 未修改。
