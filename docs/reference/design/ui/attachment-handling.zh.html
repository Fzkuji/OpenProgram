所有场景共同遵守的规则

图片是否需要调整

按所选模型已知要求调整发送版本，保留可用原图。没有可查询上限时使用明确的处理规则；不能承诺自动查到所有模型限制。

失败后输入还在

确认成功前保留文字和附件。上传、读取或发送失败要指出原因；断线后先确认上次结果，避免重复发送。

是否保留当时版本

引用原文件会受到修改、移动和删除的影响。保存副本才保留当时版本；目录列表和文字摘录都不等于原文件副本。

核实依据与开发备注

当前 OpenProgram 与建议行为有什么差别

当前上传流程也会保存普通文件，尚不是“只引用原文件”的默认行为。图片缩略图不会缩小实际发送的图片；完整图片编码计入执行输入大小，可能在用户消息保存前被拒绝。前端在收到持久保存确认前清空输入，因此可能留下只有标题的聊天。

本次目标聊天日志记录了输入过大的错误；原请求没有完整保留，不能断言是哪一个字段导致。已用本地最小请求复现图片编码超过执行输入限制，不涉及调用模型。

修改时要分别处理聊天保存、图片发送和文件读取。不能仅压小所有图片来适应执行输入限制，也不能把所有本地文件复制一份作为默认解决办法。附件中的文字作为用户提供的材料处理，不自动视为用户新指令。

附件保存与消息提交 · 执行输入检查 · 输入框提交行为

图片调整与保存范围的证据限制

Codex 公开图片处理代码包含多种调整方式，选择取决于能力和配置；默认工具中的尺寸常量不能当作每个模型的上限。OpenCode 的自动调整依据可配置限制，也不保证符合所有模型要求。OpenClaw 不同渠道的接收限制不能当作统一模型限制。

“保存为临时文件”“上传到运行环境”和“长期保留聊天副本”是不同的承诺。其他框架没有明确说明的保留期限，这里不作推断。OpenProgram 已选定图片保存副本，实施时需明确聊天删除、导出和迁移时如何处理副本。
