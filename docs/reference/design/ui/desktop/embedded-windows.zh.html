嵌入其他应用的窗口

类型为 window 的标签页放着另一个应用的一个窗口。每个平台按它的窗口系统允许的方式来做；标签页、发给 worker 的请求和归还窗口在各平台上都一样。聊天里的小预览可以同时显示同一个窗口，而不移动它。

决定

决定依据
Windows 和 X11 用窗口系统自己的嵌入窗口仍是那个应用真正的窗口：没有延迟，输入、菜单和辅助功能都是它自己的。窗口管理器就是这样嵌入窗口的。
macOS 用实时画面加转发输入那里只有这一条路；Codex Computer Use 也让它操作的窗口保持实时采集，输入走的是 computer_use 后端已经在用的路线（参照 cua-driver）。
macOS 上窗口待在标签页后面，大小相同菜单、弹窗和输入法候选框是应用在窗口旁边另开的窗口，所以会出现在标签页显示窗口的位置上。应用把窗口提到前面时，它正好盖住标签页。
画面按窗口原大小从标签页左上角画起显示的内容和后面的窗口对齐；标签页里的一个点换算到窗口只需乘页面缩放。
输入走一个队列、一个线程事件按用户操作的顺序到达应用；移动和滚轮在页面里每帧合并一次，不会堵住连接。
按键先进一个隐藏的输入框输入法可以在那里组字；组好的文字按文字发送，其他按键按物理键码发送，任何键盘布局下快捷键都能用。不经按键进来的文字（听写、表情面板）也按文字发送。
采集源经 getUserMedia 打开不需要点击，所以刷新后恢复的标签页能自己重新显示窗口。
预览从不移动窗口预览跟着 Agent 或用户正在做的事；为了缩略图把窗口挪走，会改变它显示的内容。回复里的窗口位置让预览知道窗口的宽高比。
Windows 预览的输入在后台投递和 computer_use 后端后台点击走同一条路：鼠标消息发给点下面最深的子窗口、用它的客户区坐标，滚轮用屏幕坐标，按键发给线程的焦点窗口，都走一个队列。投递的按键不改变键盘状态，所以可打印的键按字符发送，Ctrl 加字母按控制字符发送，也就是 TranslateMessage 本来会生成的消息；要读键盘状态的快捷键需要窗口在前台。
computer_use 从窗口树里找嵌入的窗口嵌入的窗口是 App 窗口的子窗口，只遍历顶层窗口会漏掉它。后端找 OpenProgram App 窗口下属于别的进程的子窗口（Windows：进程映像名 openprogram*；X11：WM_CLASS 为 openprogram*，用 XQueryTree），列在它所属的应用下。不读 worker 的记录，所以智能体子进程里的后端也能看到；屏幕矩形取自窗口本身。
App 先归还窗口再关闭子窗口会随父窗口一起关闭。页面先归还窗口再回复；2 秒后 App 无论如何都会关闭。

跟随窗口

预览不按定时器去看。窗口移动、改变大小、最小化或恢复、改名或关闭时，由操作系统告知；Worker 发出以窗口 ID 为键的 embedded_windows，预览在下一个动画帧读一次窗口状态。

变化来源
窗口，macOS每个进程一个辅助功能观察者：窗口上的 AXMoved、AXResized、最小化和恢复、AXTitleChanged、AXUIElementDestroyed；应用上的焦点窗口变化、隐藏、显示和激活。kqueue 的 NOTE_EXIT 接住不关窗口就退出的进程。一个 CFRunLoop 线程
窗口，Windows在窗口所属进程上 SetWinEventHook：位置、名称、显示、隐藏、销毁、最小化和前台，只算窗口对象本身。一个线程处理这些消息
窗口，X11用单独的连接在窗口上选 StructureNotifyMask 和 PropertyChangeMask：configure、map、unmap、reparent、destroy、名称和状态。一个线程在 select 里等
App 窗口Electron 的 move 和 resize，作为 embedded-window:host-changed 发给页面；页面缩放就是页面自己的 resize
标签页在页面里的位置ResizeObserver、一个裁成标签页自身矩形的交叉观察器（位置变了而大小没变时）、滚动，以及页面显示或隐藏
丢失的画面窗口变化、页面重新显示或重新获得焦点时重新采集

Worker 的线程随预览显示的第一个窗口启动，随最后一个结束。启动不了时（没有辅助功能权限），连接的回复里没有 follows，这个预览每 1.5 秒读一次状态并以同样的间隔重试丢失的画面，只在它打开期间。

请求

连接动作作用
embedded_windows列出其他应用的普通窗口，不含 App 自己的进程
embedded_window_attachwindow_id、holder（默认 "tab"）、place（默认 true），摆放时还有 host。摆放或观察窗口；回复模式、标题、frame（屏幕矩形）、placed、input：这个持有者是否转发输入，以及 Worker 按事件跟随窗口时的 follows
embedded_window_layoutholder、host：标签页移动、改变大小、隐藏或显示；预览发来的忽略
embedded_window_state窗口是否还开着、标题和位置；带 holder 时还有这个持有者的 input
embedded_window_detachholder 放手；结果见持有者表
embedded_window_input指针、滚轮、按键、文字和焦点事件，x、y 从窗口左上角算起；不回复。input 为 true 时才接收

每个回复都是一条 embedded_window 消息，带着请求的 request_id。worker 停止时会归还它接管的所有窗口。

情况行为

实现状态

摆放在三个平台的真实桌面上都验证过：macOS 在 App 里，Windows 11（Arm64）用记事本，X11 在 Xvfb 上的 Openbox 下。Wayland 仍然不可用。持有者、观察、Windows 预览输入和 computer_use 找到嵌入窗口有单元测试覆盖，还没在真实的 Windows 或 X11 桌面上验证。

按事件跟随在三个平台上都有单元测试；Windows 和 X11 的事件来源以及 macOS 观察者的通知还没在真实桌面上验证。
