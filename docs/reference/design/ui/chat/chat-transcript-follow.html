Chat transcript follow

One React-owned policy for the App and browser: opening a conversation and sending both land on the latest; model output only keeps a reader who is already there.

What latest means

MainPeer
Pad--main-composer-height + 24--peer-composer-h = overlay + 24
Overlay--main-composer-height, the measured composerComposer root, measured

latestScrollTop = max(0, scrollHeight - clientHeight). The pad follows the composer as it grows or shrinks, so the room under the last row is one size on every visit.

Three distances

Distance from the latestMeaning
≤ 2 px (AT_LATEST_PX)The bottom itself: the view follows from here and nowhere else
≤ 70 px (JUMP_HIDE_DISTANCE_PX)Jump is hidden. The view is not moved
70 to 240 pxJump keeps what it had: a small move up shows nothing, and it does not blink at one edge
> 240 px (JUMP_SHOW_DISTANCE_PX)Jump shows, unless the view is following

All are fixed pixels; a distance derived from the pad moved with the window and the composer (32 to about 190 px).

70 and 240 decide the button only. Following starts at the bottom itself, so a reader who stops a little short of it is not pulled the rest of the way; use-stick-to-bottom reattaches within 70 px, which reads as the view snapping.

Follow operation lifetime

A note identifies a send; it is not permission to scroll forever. Every async completion, resize snap, welcome retry and animation callback first checks session, scroller key, generation and interaction epoch.

Note storage
  • Stored per (sessionId, scrollerKey), so main and peer in one session stay independent.
  • Never deleted on read. Completion and cancellation are recorded separately, with per-view applied generations; starting a latest request does not complete one.
  • Idle completed notes with no viewport are capped at 32; waiting notes are kept. Releasing a viewport prunes after the current turn, so a same-tick remount retains it.
  • turnSeed is the accepted optimistic turn, not the last row after ack.
  • A newest page nobody asked for (renewal, retry) becomes a note for each viewport with no follow lock.

Jump completion

  • The ride lasts 480 ms whatever the distance (sine ease-in-out). Chromium's own smooth scroll grows with distance, up to about 1.5 s, and cannot be timed: a timeout cut it short and covered the rest in one frame.
  • A longer distance first moves to 1.5 screens above the latest, so each frame moves a readable amount (at most about 80 px on an 800 px view).
  • Every frame reads the target again, so a streaming reply or a page that arrives during the ride is absorbed and the ride ends on the current latest with no correction; resize does not pin meanwhile.
  • Jump hides only after that, if the operation is still current. Reduced motion uses the same check.
  • Cancel (pointer, wheel, scroll key, send) stops the ride at the current frame, and no cancelled operation corrects.

Opening a conversation

SituationOpens at
First opening, switching to it, a reload, a tab or pane shown againThe latest, followed through delayed layout and file-card growth. No reading position is kept from one opening to the next
The cached window is an older one (after set)The newest page is requested; the view attaches and snaps when it is published. Jump stays hidden while it loads and shows only if the load fails
A fresh read of the conversation in view (reconnect, renewed snapshot)A reader in history stays on the row they were on, remembered in memory by that view only; a reader at the latest stays at the latest
Arriving at one message: a message link, a search hit, the navigation rail, a parent return, a branch checkoutThat message. The view lands on the latest first and is then taken up to the message, which detaches it like any move up

A tab that was only hidden is an opening like the others: hiding unmounts its rows, and a remembered pixel offset no longer matches them once they are measured again. Restoring it would put a returning reader at a different height on each visit.

Details
  • A reader's own gesture cancels pending following.
  • An empty transcript keeps latest intent: rows that commit before ResizeObserver delivery keep the follow state. Height growth is not a reading gesture.
  • The ResizeObserver watches the scroll area as well as the column: a window made only shorter changes neither the column's box nor scrollTop, and the latest would slide under the composer with nothing to pin it or show Jump.
  • The first render of a conversation mounts its last screen of rows, not the rows at the scroll offset the previous conversation left.
  • Rows keep their height after layout: a task block or step that mounts open is drawn open, with the opening transition kept for a change made after mount, and the file-summary probe of a reply takes no room.
  • A pending welcome send survives activation until its view is ready.
Legacy file-change summaries
  • Loaded only near the viewport, then kept in the session message store. A remounted card renders the result at once, including a confirmed empty one.
  • Errors stay retryable. Aborted or stale responses never update another session.
  • History preflight stays fresh and undo authorization stays server-side; a summary is a description, not permission to undo.

History windows

  • Older, newer and around replacement: each registered area captures its own anchor, top and height before the update, and restores after flushSync only if still registered for the same session and chatKey. Height caches use that area's key.
  • A registered area that lost registration is not restored. The unregistered #chatArea fallback applies only when nothing was registered at capture and the node is still the live main scroller; being connected is not enough.
  • Restoration skips a viewport holding a follow lock.
  • Rows shared by main and peer: each non-requesting pane keeps its anchor. If eviction removed it, the reader keeps the distance from the surviving end. A negative result (an expired snapshot renewed to the newest page) shows the end of the new window, not the top.

Selects when to request; never writes scrollTop. Serialization, cursor and generation validation, retry backoff, snapshot renewal, hidden-view suppression, recovery and disposal are separate.

Failure and limits

CaseBehaviour
Latest load fails or goes staleDetached, Jump visible, stale page untouched; a failure settles the note
Storage write failsSwallowed
VirtualizationRecycling keeps measured placeholders so scrollHeight stays honest; pin after recycling. No virtual-list library
Width changeMeasured heights stay as estimates, so the list is not re-rendered. While changing, the area has data-width-settling and off-screen rows use content-visibility: auto. After 120 ms still, the first visible row keeps its place unless the view is pinned at the bottom
KaTeXtypesetMath on the observed column, inside the pin path; no document scan

Not followed: DAG strip expand, compaction fold easeScrollBy / pinWhile, parent-return scrollIntoView, message-rail seek, task-block seek (from outside the area it announces itself with chat-reader-seek, handled like a wheel), branch checkout _postCheckoutScrollTo. The CLI ScrollBox is separate. No backend protocol change, and occupancy, queue admission and ack pairing are unaffected.
