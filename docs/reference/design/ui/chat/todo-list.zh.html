任务存储

一个任务是一份清单，一个步骤是一条待办，按对话保存在 todos.json 里。任务块从它画出。

任务
T3：标题、目的、打开、做完或被顶掉、结果、是否推进过、它所属的 Goal
步骤
plan 等于任务 id 的一条待办：等待、进行中、已完成或已放弃，带半句 result
段
每条回复和每个任务一段：任务和它全部步骤在这条回复最后留下的样子

看板

项规则
每个分支一块看板任务、步骤和段。重试、编辑或分叉出来的分支从它离开的那块看板的副本开始，两个分支不会互相覆盖。
每个 agent 一个开着的任务开新任务会关掉开着的那个。子 agent 的任务是它自己的（scope 为 agent:<id>）。
Id任务是 T<n>，按看板计数。步骤沿用待办 id；模型按步骤在任务里的位置称呼它，第一步是 1。
放弃的步骤不计入进度，也不是 Goal 的要求。仍然列给 Goal 的验收者。
没有任务的子 agent勾对话里开着的任务的一步；更新父任务最新的一段

段

字段内容
anchor_id、plan_id回复和任务。同一条回复里之后的改动替换这一段；之后的回复里的改动新增一段，所以更早的回复保留它当时留下的任务。
staterunning、done、carried（开着，在之后的轮次继续）或 displaced（被另一个任务顶掉）。停止和失败不保存：由回复的状态说明。
current最后一次改动时进行中的步骤；停止后保留
earlier这一段开始时已经完成的步骤：就是“前几步已完成”那一行
advanced是否有步骤调用推进过这个任务
todos每一个步骤：id、标题、状态、结果
title、purpose、outcome、started_at、ended_at标题行显示的内容

每个分支保留 500 段；最早的被丢掉。

发给界面的内容

帧携带
todos_updatechanged：一次调用或一轮结束改动的那些段。客户端按回复和任务替换自己的那一份。
session_loadedtodo_plans：所有分支的段
goal_updateprogress：Goal 最近的任务、进行中的步骤、已完成和计数的步数、它最新的块所在的回复
块和文字帧每个文字、思考和工具块上的 task 和 step

任务之前保存的数据

条目读成
没有 title 的段一份普通的待办清单，按保存的样子读。对话把一条回复下同一个 agent 的条目合成一份清单，收起来画一次。
不属于任何任务的待办留在看板上；仍然计入创建它时所属的 Goal
只有一块看板的文件属于第一次读取时选中的分支

依据

决定原因
任务下面仍是待办存储Goal 验收、Goal 的清单和子 agent 勾父任务的步骤本来就读待办。任务只是在上面加了名字和状态；它们都不用改。
每条回复一段以后再读一条回复，看到的是它当时留下的任务；跨多轮的任务在每一轮画自己那一部分
只发改动的段长 Goal 有几百段；重新连接时整份重新加载
停止不是保存的状态回复已经说明了它怎么结束；第二份副本可能与它不一致
