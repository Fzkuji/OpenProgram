工作图上的消息

工作图上的消息块最多三行：任务标题、读者输入的内容、现在的状态。进行中写现在在做什么、做了多久；结束后写用时和做了什么。

一个按钮，只在需要读者时

运行块上
等回答或授权Answer 或 Review：转到输入框上方的卡片
已暂停Continue
进行中没有。用输入框停止（停止键或 Esc）；运行时打的字会补充进去。

为什么。我们看过的同类产品都不把运行控制放在列表项上，用现在时写正在做的那一件事；没有一家像我们原来的“Running Ran · 4 commands”那样混用时态。

产品控制放在哪状态怎么写
Codex 桌面版输入框上一个按钮：Stop、Steer 或 Queue“Working for 1m 5s”“Worked for 2m 3s”“You stopped after 12s”；列表项上显示 Needs input、Needs approval
Claude 桌面版输入框上的停止“Thinking…”“Running a command”“Waiting for your answer”
Codex CLI、OpenCode、PiEsc“Working”“Thinking…”“Retrying (2/3)”
Cline等待时一对回答按钮，生成时 Cancel“Thinking...”“Running”

我们照最接近的 Codex 桌面版做；保留 Continue，因为暂停的运行在输入框里没有对应的控件。

不放占位

  • 消息有了任务才有标题行；在此之前只显示输入的内容。
  • 没人发起的运行，说了话之后才有标题。
  • 还没归入话题的消息，话题块什么都不画：只占位置，没有名字，不能点。这一列顶上的路径也是空的。
  • 所有话题都还没有名字时，图表直接从消息那一列开始，也退不回空的话题列；话题有了名字，退回的入口才出现。
  • 输入的内容取第一行有字母或数字的，所以贴进来的邮件开头那条 ______ 分隔线会被跳过。

新出现的东西

  • 每次图表更新，移动了的块从原来的位置滑过去，用慢档（240 ms）和 --ease-standard。
  • 之前没有的块淡入：刚开始的消息、刚有名字的话题。
  • 已画出的块上新出现标题时，标题淡入，下面几行往下让出位置，块同时变高。
