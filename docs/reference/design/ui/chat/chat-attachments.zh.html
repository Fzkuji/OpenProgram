聊天附件

消息里的每个文件都由同一种文本标记表示：

[attachment: notes.txt (txt, 18 KB, 4210 lines) @json "/abs/path/notes.txt"]

只由 openprogram/state/attachments.py 的 format_marker 写入，新增来源也调用它。网页端只由 parseAttachments 读取。可选的 @previewjson 指向保存的预览。旧写法 @ /abs/path 仍可读取。内容如何进入模型上下文：附件处理。

组装本轮最终文本时（with_attachments），模型为本轮没有记录的文件打出的标记改成文件名，回复内容和文本块里都一样：不出卡片、路径和自动预览，实时和重新加载后都是如此。用户消息里的上传和提及标记保持不变。

  • 只有标记的路径和 @previewjson 路径都被记录过，标记才保留。
  • 回复流式输出期间存下的文本（被重启打断的回复会保留它）和常驻 Agent 的报告也一样处理。
  • parseAttachments 只认服务器会检查的写法。

回复里链接的脚本（[build.py](/abs/build.py)）或智能体只读过的文件仍是正文里的链接（回复里的路径）。

聚焦的对话里一条回复结束时，它第一个还没在回复里显示的附件在旁边的预览里打开：这一轮刚做出的成果。

预览下方：文件类型图标、名称、类型和大小（及页数或文件数），然后是打开和在 Finder 中显示（按平台为资源管理器或文件管理器）。应用无法显示的文件，打开位换成下载；Worker 不在用户机器上时，显示位改为下载。卡片接近屏幕时才加载预览。

HTML 沙箱和压缩包
  • GET /api/file-page 只提供 .html 和 .htm，带 sandbox allow-scripts，没有 allow-same-origin。srcdoc 框架会继承应用的 script-src 'self'，靠脚本绘制的页面会变成空白。
  • 页面为不透明来源：无法访问应用及其存储，Origin: null 请求被拒绝，不能导航或打开窗口。相对路径资源在缩略图中缺失，因为严格 Cookie 不发送；在浏览器标签页中打开时有这些资源。
  • FileViewer 把 zip 或 tar 交给 ArchivePreview：左侧完整目录树，右侧用同一个 FileViewer 显示所选成员。不解压到磁盘。

回复里的路径

回复只是提到的文件，比如 `exports/plan.pptx` 或 [plan](/Users/me/exports/plan.pptx:3)，是指向该文件的链接。点击后在对话旁的预览里打开：Office 文件进文档编辑器，PDF 进 PDF 查看器，网页按网页打开。

步骤规则
候选已落定回复里的行内代码和 markdown 链接目标（不看代码块，流式输出时不看）。形状像路径的字符串：含目录分隔符，或是带扩展名的文件名；绝对路径、~ 或相对路径；去掉 :12、#L12 后缀。命令、网址和指向应用自身页面的链接（/s/…、/settings）不算
由 Worker 确认GET /api/file-paths 回答哪些候选是文件：绝对路径和 ~ 路径按 readable_roots 检查，相对路径先接到对话的工作目录上。只有确认过的路径才变成链接，所以长得像文件名的代码不会成为死链接
开销屏幕上所有回复的候选，每个对话合成一次请求（每次最多 64 条，只做 stat）；答案保留五分钟（不存在的文件二十秒，因为智能体可能还在生成）。文字先画出来，从不等待
不是路由只可能是本地路径的 markdown 链接（不是应用页面的 /…、~/、./、../、file://、盘符）在外壳路由之前被拦下，否则路由会把 /Users/… 当成页面。尚未确认的链接在点击时再查；文件不在时会提示。不带前缀的目标（notes/plan.md，或省略了协议的网址 docs.example.ai）要等确认后才变成文件链接，之前点击保持链接原本的行为
样式和应用里渲染的 markdown 链接（文件预览里的链接）一个画法：链接色，下面一条淡下划线，悬停时变实。行内代码保留底色，也用链接色和这条下划线，所以即使链接色和代码色相近，不悬停也能和普通代码分开。只改装饰，路径变成链接时段落排版不变。回车可打开

本轮产出的文件不需要 send_file 调用也会附上（见下）

本轮产出的文件

模型用脚本做好一份演示文稿，回复“好了，在 exports/plan.pptx”，其实什么也没附上。轮次结束时，produced_files 自己把这类文件附上，用同一种标记，所以出现同样的卡片，频道也会上传。

步骤规则
候选回复里提到的路径：markdown 链接目标（包括 <…> 和 %20）、代码片段和裸写的词；绝对路径、~ 路径，或相对于项目、再相对于会话 workdir 的路径；去掉 :12、#L12 后缀。另加 write 写出和 image_generate 保存的文件
保留条件sendable_roots 内的普通文件，不超过 32 MB，修改时间不早于本轮开始（留一秒余量）；恢复的轮次用它的用户消息时间。用户自己发进来的文件（workdir/attachments/、steer-images/）不算，它们的修改时间也落在本轮里
格式Office 和其他文档、PDF、图片、音频、视频、压缩包；HTML、Markdown、CSV、TSV、SVG 和 notebook 只在编辑工具没改过时才附上，因为编辑卡片已经带 diff 显示了它们。无论是回复里提到的，还是 write 或 image_generate 保存的，每个候选都按同一条规则判断，所以生成 deck 的脚本不会附上。源代码和日志一律不附，.key 也不附，因为它同时是私钥的扩展名
限制最多看 64 个候选，只用 stat；最多附 8 个，每个一次，排在 send_file 的文件之后。任何失败都只是什么也不附，不会影响本轮
范围只在有 send_file 的地方（不含 cli、tui），且发言人有 fs.read

修改时间就是防线：模型只读过或提到的文件早于本轮，不会附上。

基础指南要求模型把自己产出的每个文件写成指向绝对路径的 markdown 链接，并用 send_file 附上交付物；send_file 的说明写明它适用于用户该看的任何文件，包括脚本生成的 Office 文件。

没有项目的对话

这样的对话在默认项目的文件夹里工作，常是主目录，所以它做的演示文稿落在那里。这个文件夹只以 WorkdirRoot 的身份算作根目录，而且只对存在、没有真实项目的对话。文件系统根目录永远不算，否则整块磁盘都成了根目录。规则如下：

位置规则
预览、路径链接、文件卡片、显示位置（readable_roots）该对话自己的请求允许。这些都只在主人自己的 App 里
send_file 和回合结束附加（sendable_roots）对话不往聊天平台投递时允许。绑定了频道的主人对话（meta 里有 channel），或从平台联系人来的对话（meta 里有 peer_id，解除绑定后仍在，因为联系人的下一条消息还会回到这里），保持窄根目录：工具拒绝主目录里的文件，回合结束再检查一次也拒绝，所以主目录里的东西不会上传到微信或 Telegram
这个文件夹下始终拒绝经过点开头的文件夹或文件的路径（~/.ssh、~/.aws、~/.openprogram*、.env）；经过名为 Library 或 AppData 的文件夹的路径，macOS 和 Windows 的钥匙串、浏览器配置和 Cookie 都放在那里；密钥和密钥库文件（.key、.pem、.p12、.kdbx 等）；id_ed25519、credentials.json、token 这类名字；以及状态目录，它的会话文件夹本身另有根目录。上传文件和插话图片照旧不参与回合结束附加
选择原因
不当普通根目录这个文件夹可能就是 $HOME，而 send_file 能到达聊天平台
也不排除否则没有项目的对话做出的东西既发不出、也链接不了、打不开。Claude Code 桌面版、Codex、Hermes、MiniMax Code 和 KimiCode 都能从回复里打开本轮写的文件，不管工作目录在哪
不按文件记账根目录之外、由本轮工具写下的文件不额外开放：工作文件夹已覆盖它们落地的位置，记账会成为第二套规则
路由约定
GET /files/raw项目和相对路径，服务文件面板和中央标签页。始终拒绝绝对路径，保持这一不变量
GET /api/file-raw绝对路径，按 readable_roots 检查；nosniff、CSP sandbox，PDF 为浏览器查看器豁免
GET /api/file-read文本。根目录下的相对路径，或按 readable_roots 检查的绝对路径
GET /api/archive-list从 zip 中央目录或 tar 头读取条目，最多 5000 项，截断时标记
GET /api/archive-member单个成员，最大 32 MB，响应头同 /api/file-raw。名称只在压缩包索引中查找，../ 够不到任何东西
POST /api/file-reveal同样检查后在 Worker 的文件管理器中选中路径。从不打开或运行文件；用默认应用打开由桌面应用负责，它自己检查文件（文件菜单）
GET /api/file-paths多个 path 参数，最多 64 个；每个映射到它在 readable_roots 内指向的绝对文件，否则为 null，不区分不存在、是文件夹还是在根目录外。相对路径接到对话的工作目录上。只做 stat
事件循环/api/file-paths、/api/file-search 和 /api/file-resolve 要在会话锁下找对话的工作目录，搜索还要遍历文件夹。找目录这一步在该会话通道的工作线程里运行，轮次占着会话时只推迟这些请求，不卡住 Worker。搜索随后遍历文件夹，在通道外的普通工作线程里做，所以遍历大文件夹时输入 @ 提及，不会让同一对话的发送或停止排在后面

两个压缩包路由都接受绝对路径，或项目 id 加相对路径。FileViewer 只有一个 abs 开关，图片、PDF、Markdown、带行号代码和下载卡片的渲染都是同一实现。

opencode（网页、TUI）base64 data URL 存 SQLite。@ 在提交时运行 read，注入两个合成纯文本 part。5 MB、2000 px、Lanczos3图片卡片带灯箱；非图片不可点击；@ 在文本中高亮没有；工具附件进入模型上下文GET /file/content；图片、音频、SVG、标签页、diff。随会话行删除
hermes-agent（频道）每轮路由：原生 base64 加路径提示，或 vision_analyze 文本。文档给路径，文本内联。无初始上限，被拒后压到 4 MBTelegram、Discord 原生；CLI、TUI、xterm 网页不可点击最完整：MEDIA:、send_message、先解析符号链接的根检查、按平台提示；提取 ![alt](url)Rich Markdown。24 小时 TTL
pi-mono（TUI）@file 内联并带 <file name> 标记。剪贴板写临时文件并插入路径。2000 px、4.5 MB，可关闭唯一真正的终端内联图片（Kitty、iTerm2），tmux 和 screen 下关闭；只渲染工具结果，不回显用户图片没有Markdown、diff；不支持 PDF，不清理临时图片
pi-ai（协议层）pi-mono 包的只读副本。模型未声明图片输入时移除图片块；工具结果中的图片拆成文本和合成用户消息无无无
weclaw（微信）图片被拦截保存，回复“Saved: filename”；Agent 看不到。语音用微信转写。无上限微信就是客户端隐式：裸绝对路径行或 ![](url) 被上传并替换为“Attachment sent”。根目录默认 ~/.weclaw/workspace，有扩展名允许列表Markdown 被剥成纯文本

发送文件的四种方式

设计使用者优点代价
工具参数claude-code、OpenProgram有类型，工具层检查文件存在占一次工具调用；说话和发文件分开
指令行openclaw、hermes随文字发送，无额外往返；按频道提示错误路径需要检查；提取不完整会泄露
隐式扫描weclaw无需学习，无提示成本提到路径就可能发送
宿主附上本轮产出Claude Code 桌面版、hermes Deliverable Mode、OpenProgram模型忘了用工具、文件由脚本生成时也有效需要规则判断什么算产出
无codex-cli、opencode、pi-mono、pi-ai无需实现模型只能贴路径

指令行和隐式方案都把路径限制在允许的根目录内，并先解析符号链接。

交付产出文件：同类做法与取舍

frontierharness.org/live 上的 21 个框架里，做得好的都不靠模型记得附上每个文件。它们叠加三层：宿主自己呈现、回复里的路径可操作、一行提示，发送工具只是兜底。

框架做法
Claude Code 桌面版、Cowork自己呈现 Write、Edit 产出的文件；SendUserFile 用于脚本生成的文件。有设置项自动打开它写出的 HTML、图片、PDF、视频
hermes Deliverable Mode扫描回复里以 .pptx、.docx、.xlsx、.pdf 结尾的绝对路径或 ~ 路径并上传；文档承认 agent 默认不会主动交文件
Codex app、MiniMax Code任务结束后打开生成的文件；把生成或引用的文件列为结果
Codex、Antigravity 提示词要求模型把文件路径写成可点击链接，不要只说报告好了却不给链接
取舍原因
轮次结束时附上，不只靠工具Claude Code 桌面版的分工。Office 文件和 PDF 来自脚本，编辑日志不记录；附件被拒过一次的模型不会再试
要求本轮修改过hermes 的扫描没有这条，提到输入文件就会把它发回去。时间检查只需一次 stat，能区分产出和提及
接受相对路径和链接模型更常写 exports/plan.pptx 和 markdown 链接，而 hermes 只认裸写的绝对路径
与 send_file 同样的根目录宿主这一步不能比工具走得更远。根目录外的文件仍可从回复里的链接打开
fs.read 而不是 reply附文件是回复，但会展示文件内容。用 reply 会让无权读主人文件的配对发言人拿到这些文件
不加新提示，不用 MEDIA: 标签产品方向是少弹确认；标签仍然依赖模型记得写

回复里的路径：同类做法与取舍

同类做法
Claude Code 桌面版回复里的路径点击后在文件面板或浏览器面板打开；右键有 Attach as context、Copy（绝对、相对、文件名）、Open in、Show in Finder
KimiCode点击打开文件预览；右键有复制路径和显示位置
OpenCode v2行内代码里的路径先确认文件存在才做成链接，此前未经检查的猜测产生过死链接
Codex 应用提示模型写成 [app.py](/abs/path/app.py:12) 链接，并在自己的编辑器里打开
取舍原因
只链接 Worker 确认过的路径OpenCode v2 的修法。os.path.join 这样的代码也有路径的形状；问一次只是一个合并的 stat 请求，不会画出死链接
一个批量路由，而不是逐个调用 /api/file-resolvefile-resolve 只回答一个相对根目录的路径，且拒绝对话目录外的绝对路径；documents/stat 只回答一个路径，不给绝对形式。一条回复会提到很多路径，菜单的复制也需要真实路径
Claude Code 桌面版的菜单，用应用自己的菜单部件用户点名的就是这个菜单。用 ContextMenu 和 MenuRow 搭建，和其他右键菜单一个样子；路径、卡片、改动文件行共用一个组件
用默认应用打开放在桌面应用，不放在 Worker桌面应用运行在用户面前的机器上；Worker 路由保持只读、从不运行文件。桌面应用拒绝系统会运行的文件，所以这一项不能用来启动智能体写的脚本
只扫描已落定的回复流式回复每个增量都会重画最后一块；链接会闪烁，问题也会重复发

其他技巧

  • 输出为页面：openclaw 用 [embed ref=…] 嵌入 canvas 文档；Codex 把 ::codex-inline-vis{ 物化到沙箱查看器（2 MB、严格 CSP）；pi-mono 的 /share 把会话发布成私有 gist。
  • 签名令牌：openclaw 的 mediaTicket，v1.<payload>.<signature>，五分钟 TTL。
  • chip 作为编辑单元：claude-code 只有在 [Image #N] 留在文本中时才发送图片。
  • Hermes 把宿主缓存路径改写成容器路径。Codex 有 view_image。
