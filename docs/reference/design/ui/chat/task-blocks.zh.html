任务块

任务块是回复里一段有名字的工作。agent 用每次工具调用自带的 task_progress 参数说明这次调用在任务里的位置，所以报告进度不多花一轮模型往返；哪些工作属于它由运行时决定，回复结束时由运行时收尾。

组成

部分规则
形状回复列里的一段。不画边框卡片。状态画在标题的状态图标上。
层级三层，只靠缩进区分，每层差一个单位：标题；步骤；一个步骤的工作。单位是标题图标加它后面的间距，所以每一层的节点都对齐上一层的文字。字号和粗细不区分层级：任务名、它下面那一行说明、每个步骤和步骤的备注都是同一个字号，即工具组摘要的字号，进行中的步骤也一样。
标题状态图标、任务名、进度、耗时、+N −M 标记、箭头。行高 28px，字号与工具组摘要相同。运行中，进度是进行中步骤的位置（3/5：正在第三步）；停下或带到下一轮时是已完成的步数。任务没有步骤、或没推进过就结束时不显示。
窄列任务名最后才被截断：先缩短结果和当前步骤，列宽不到 480px 时标题里不显示耗时和标记。
用途名字下面一行淡色的文字，说明这个块是做什么的
步骤缩进一层，每个步骤一行，节点排在一条从第一步连到最后一步的轨上。状态靠节点和文字颜色表示。已完成：对勾、标题、淡色的半句结果。当前：转圈和现在时的摘要。等待：空心圆。放弃：划线，不计数。
一个步骤的工作默认收起，进行中的步骤也一样，读者点这一步才展开，再点一次收起。展开后是现有的步骤行（工具调用、思考、子 agent 行）和这一步里说的话，再缩进一层，不另画轨。Normal、Thinking、Verbose 在这里照常生效。
没有步骤只给名字也能开一个块；工作平铺在它下面。一次都没推进就结束的任务画法相同，步骤只作提纲：不替它勾任何一步，也不显示 N/N。它还在运行时处于第一步，工作算在这一步下。
块外开工前的那句话、两个任务之间的话、最终回答。始终可见。
小工作没有块。回复和没有任务时一样：摘要行和文字。

状态

情况画法
运行中展开到名字、用途和步骤；每个步骤一行，工作收起
运行中，手动收起一行：名字、当前步骤、3/5、耗时
做完原地收成一行：名字、结果、步数、改动量、耗时。没有写结果时用确定性的摘要；从不根据文字去猜。
停止、失败、中断保持展开，带现有的“已停止”“已中断”或失败标签和 3/5。停在的那一步在节点上显示状态；等待的步骤仍是等待。标签只在块上：回复里它后面的内容不再带一次。耗时算到回复结束；不知道回复何时结束就不显示。
等用户处理仍是运行中：展开，没有标签。图标和名字不再动，回复继续后恢复。
停止后继续新回复里一个同名的段，从那里第一次 task_step 调用开始
同一条回复里的第二个任务前一个块收起。没做完的写“停在 3/5”，不打勾，它未完成的步骤被放弃。
跨多轮的 Goal一个任务跨多轮。每条回复只画自己那一段；前几轮完成的步骤是一行“前 5 步已完成”，点它跳过去。
子 agent它现有的那一行在派它的步骤下面。它运行期间块保持展开。它自己的任务块只在它自己的对话里显示。它开的任务只属于那一次运行：同一个 agent 的两次运行不共用任务。
重新打开的对话归属从保存的调用所在的位置得出，与实时一致
保存着待办清单的对话一份清单是一个收起的块，名为“待办”，带计数，画在最早有它的那条已加载回复的第一次待办调用处。放不下的清单仍是摘要行里的“updated todos”。不改写任何数据。
压缩之后开着的任务（标题、步骤、当前步骤）再交给模型一次
手动展开或收起块：优先于它自动的展开和收起。步骤：只能这样展开；工作流进来、这一步做完，都保持读者的选择。两者都按回复记在本浏览器里，保留最近 500 次选择。Enter 和空格切换；左方向键收起，右方向键展开。

工具

每次调用上一个参数，它说不了的交给两个工具。一个任务是待办存储里的一份清单，一个步骤是一条待办，所以 Goal 验收和子 agent 勾父任务的步骤读的是同一份数据。

工具约定
task_progresstask?, steps?, step?, result?回合提供任务工具时，模型能调用的每个工具（包括 MCP 工具）都多一个可选参数。它说明这次调用的位置：step 是这次调用所做步骤的序号。task 不是任何开着的任务的标题时，按 steps 开一个新任务。step 变化时，进行中的步骤完成，result 留在它上面。原样再发一次什么都不变。超过最后一步的序号让最后一步继续进行。
task_starttitle, purpose?, steps?标题是不超过 40 个字符的名词短语；目的是一句话；步骤是 1 到 7 个短语，一次写全。第一步立即开始。已经开着的块先被关掉。
task_stepnext?, step?, add?, drop?, result?, outcome?next 完成当前步骤并开始下一步，不需要 id。step 跳着做。add 追加，drop 标为放弃。result 给刚完成的步骤留半句话。outcome 带着结果结束任务；还没做的步骤被放弃。没有开着的任务时返回一句提示，不是错误。没有自己任务的子 agent 用 step=N 勾掉派它来的那个任务的第 N 步。
task_list只读：任务和它们的步骤。按需加载，不常驻。
各自发给谁task_start 常驻：规则写在它的说明里。task_step 按需加载，用于目的、追加或放弃步骤、结果。加载器、任务工具和结构化输出的提交工具不带 task_progress；自己的参数里已有同名属性的工具保留自己的。
写在说明里的规则进度挂在真实调用上，从不单独占一个响应；不为收尾发最后一次调用。计划不在文字里重复。三个步骤或十几次调用才值得开任务；一条回复里没有、一个或两个。被改方向时，放弃步骤或另开任务。
结果任务工具的结果是一行说明任务到哪了。真实调用的结果是它自己的；只有它的 task_progress 没能生效时才补一句。

运行时决定的事

规则原因
归属只看位置回复的块按顺序读。一次任务调用，或 task_progress 推动了任务的一次调用，是分界：它自己和它之后的每个块属于它设定的任务和步骤。每个文字、思考和工具块都盖上 task 和 step。保存下来的块在流式中、结束后、重新读回时给出同一个答案。
块到它最后一次真实调用为止排在任务最后一次非任务工具调用之后的带戳文字画在块外。两个任务之间的话和最终回答因此始终可见，不需要模型标记。段还没收尾时，这次调用之后的思考也算这一步的工作：一步的工作从一开始就在步骤里，停止时块下面也不会多出一行。
进度在调用运行前生效分发器在校验参数前取出 task_progress，先让它生效，再运行调用，所以这次调用的卡片一开始就在它的步骤下，工具、MCP 服务器和插件都看不到这个参数。卡片和历史保留模型写下的原样调用，之后的请求发出同样的字节。
只生效一次暂停后再次分发的调用只生效一次：记在任务上的是这次调用的出现（所在回复、位置和 id），不是单独的 id，因为 Gemini 每次回复的调用 id 都一样。
进度不往回走已完成或已放弃的步骤不会被重新拿起：同一批并行调用里写给前一步、却排在推进之后运行的调用，不改变任务的位置。
参数在组装工具列表时加上由一处给发出的每个工具加上，每次请求都一样，缓存的前缀不变。严格模式的提供方收到的是多一个可为空的属性。工具自己的定义和它的加载记录不动。
一条回复开头不属于任何任务例外是开着的任务所属 Goal 的那一轮：它从第一个块起继续这个任务，它的段从第一次真实调用开始。
正常结束会收尾只有勾掉它就能结束任务时，才替模型完成进行中的步骤：任务推进过、后面没有等待的步骤、不属于任何 Goal。Goal 的一轮在模型不再调用工具时就结束，所以它的步骤保持进行中，留给下一轮。没有剩下的：任务做完。从未推进且不属于任何 Goal：做完，不勾任何步骤。其余情况任务保持打开，步骤仍是进行中，这一段带到下一轮。
子 agent 的一次运行自己收尾任务按这次运行的回复区分。一次运行没有下一轮：正常结束时还有步骤没做的任务按被顶掉收尾，未完成的步骤被放弃，不勾任何步骤。
停止、暂停、失败不收尾段仍然写着运行中；由回复自己的状态画成已停止、失败或已中断。这个状态没有第二份副本，不会与回复不一致。
被顶掉的任务放弃未完成的步骤按正常结束的规则，勾掉进行中的步骤就能结束任务时，先勾掉它。否则 Goal 会一直等没人再勾的步骤。段里保留步骤被顶掉那一刻的样子，Goal 验收仍把放弃的步骤列给验收者。
段可以晚于它的块到达任务还没有段的块按不属于任何任务来画，段到了再归入。

决定原因
工作挂在它的步骤下上面没有一个框架把调用和它服务的步骤连起来；对话旁边的清单说的是计划了什么，不是为它做了什么。回复下面一份做完的清单没有话可说，也不会再被读到。
一个任务一个块，原地收起很长的回复只剩几行；每一行仍能展开到它背后的全部内容
步骤点开才展开读者靠步骤，也就是 agent 定下的目标，跟进一个任务；一步背后的调用只在要核对时才看。自己展开的步骤会让搜索和读取占满整个块，把后面的步骤挤出视野。
缩进表示层级步骤的节点和任务名的节点对齐时，一个步骤看起来像第二个任务；更粗或更大的步骤看起来像标题。每层缩进一格，像 Hermes Agent 画子任务那样，一眼就是一棵树，不需要另一套字号。
保留工具Claude Code 在较新的模型上不提供任务工具，Pi 完全没有。这里 Goal 靠这份数据跨轮继续，所以保留，约定小到几乎不占成本。
进度挂在真实调用上Claude Code 和 Codex 用单独的调用报告进度。在 openai-codex/gpt-6-luna 上，不管说明怎么写，这种调用都单独发出，每次多一轮模型往返（见下表）。Cline 把清单放在每次工具调用上；这里保留这个形状，做成一个可选参数，由运行时在工具运行前取出。
参数是状态，不是变化给它 {start} 和 {next} 这种变化时，模型在每次调用上重发开头那一条，从不往下走，每个块都停在第一步。给它步骤序号时，它每次重复这个状态，而重复的状态什么都不改。
不用调用来收尾回复结束时收尾，新任务开始时收掉前一个，两者都只在没有等待的步骤时才勾掉最后一步。回复进行中不靠猜测勾掉任何步骤。没写结果的完成块显示确定的摘要，从不从回答里摘。
task_step 按需加载常驻时，一半的回复里它仍被单独发出，和 task_progress 里同一次步骤变化重复。只有它能做的事（放弃步骤、结果）很少用到。
步骤一次写全Codex 的 update_plan 一次调用带整份计划；一次只能写一条时，模型每次只计划一步
运行时收尾模型忘了最后一次勾选，正常结束后也不会留下半截的块
不画边框卡片状态画在图标上，不画在框上，和图节点一样；一条回复里几个带框的盒子看起来像几个独立的窗口

限制

限制后果
归属跟着模型给的步骤序号走从不改 step 的模型得到一个平铺的块：提纲，下面是全部工作。跳过的步骤保持等待，回复结束后任务仍开着。task_step 调用排在同一响应的真实调用之后时，那次调用算在上一步。
开任务仍多一个响应模型在第一次真实调用前先单独调用 task_start 开任务。改成按需加载后，它先搜索再单独调用，变成两个响应，所以它保持常驻。
文字的戳在流式中是定死的在任务调用返回前建好的文字块保留最初的归属，到回复落定才更正；工具块立即更正
每个分支 500 段超过后最早的回复重新把工作平铺画出；内容不丢
在待办清单上开始的 Goal它没做完的待办不属于任何任务，也没有工具能勾掉；编辑 Goal 会开一个不含它们的新修订
块内的文字随块折叠只有块外的文字和最终回答始终可见
