网页标签的呈现位置 center tab · 复合分屏 · 会话悬浮窗 (PiP)

读者：维护 apps/web 中心区的开发者 范围：渲染进程内的呈现与绑定 不含：跨窗口 transfer、主进程 View 几何

本文回答：一个网页叶子在界面里此刻出现在哪里、被谁控制、agent 能对它做什么。散落的交互规则都从同一条不变量推出，而不是一串补丁。

1 · 概念模型

会话 S 与网页 W 的配对是唯一一等关系。分屏与悬浮窗是同一配对的两种呈现。一个 WebTab 叶子同一时刻只有一个页面宿主：center pane、split pane，或某会话的 PiP。

配对来自 agent 在 S 打开 W、用户把 W 拖进 S 的分屏/组、或收起时建立。show() 写入配对表；覆盖函数只决定这份配对此刻画在哪个宿主。独立网页没有配对，也就没有「收起到悬浮窗」。

叶子 identity center-tabs store 里 kind:"web" 的条目。规范 id 是 w:<url>；fork 用 nextPopupWebTabId 写成 w:<url>:popup:…。叶子本身不因浮动而消失。 tabs[] / groups[] / splitWebTabId / activeId
配对 pairing 会话↔网页的持久关系，记在 pairedOwnerByTabId。一个会话可配对多张网页；任一侧关闭才清掉。悬浮窗槽位每会话只有一个，显示 agent 当前工作页，其余配对页驻留标签条。 模块级 Map，随 show() 登记
绑定 binding 全局至多一份活跃 (tabId, ownerTabId)：此刻哪张配对页占据悬浮槽。切走会话不改绑定；hide() 才把绑定挪进 background 记忆。换绑另一张页不会抹掉旧页的配对。 useWebTabPip 单例，不持久化
宿主 host 真正画出页面的地方。由 pipCoversCenter(tabId, ownerTabId, center) 从「绑定 × 当前激活标签」纯函数推导。组件不另存「显隐」状态。 pane · pip · none（遮罩 / 消失）

因此系统的一等状态是配对，加上布局（谁在条上、谁成组、谁激活）、活跃绑定和 background 记忆。分屏与悬浮是配对的两种呈现，不是两套关系。

复合组 groups[] 至多两个成员；条上投影为一个条目。用户建组走 groupTab；PiP「展开为分屏」走 setSplitWebTab，把当前会话与该叶子配成一对。splitWebTabId 是兼容指针，规范化时若叶子尚未入组且激活的是会话，才物化成 group。

agent 在同一会话连续 open / activate 多张页时，悬浮槽跟随注意力：新工作页 show 进槽位（或 revealPairedPipTab 把已配对但不可见的页装进去），先前那张回到标签条。独立网页不进入这条路径。

    3.2 PiP store 字段

    字段 / 动作含义
    tabId · ownerTabId活跃绑定。二者同时有值或同时为 null；pipBoundTabId() 据此判定遮罩。
    backgroundTabId · backgroundOwnerTabIdhide() 留下的恢复票据。唯一读者是 WebPreviewChip。
    rect小窗几何，仅内存。clampPipRect 限制在 .center-pane-chat 内，最小 240×160。hide/end 都不清 rect。未拖动时默认落在会话页头部（.chat-view-controls：视角切换 + ⋯）下方右上角；拖动后以 inline rect 为准。
    show(tabId, ownerTabId)登记 pairedOwnerByTabId，建立活跃绑定并清空 background。全局单例槽位，新绑定覆盖旧绑定；旧页的配对仍在。
    hide()清活跃绑定，写入 background。语义：用户暂时收起，可一键恢复。
    end()绑定与记忆全清。语义：这个网页不再是任何会话的悬浮窗。

    3.3 覆盖函数 pipCoversCenter

    小窗渲染（且 native view 摆到 PiP 位置）当且仅当 pipCoverBase 与 owner 校验同时成立：

    1. 叶子仍在且 kind === "web"；
    2. activeId !== tabId — 用户盯着该标签时让位给 pane；
    3. 叶子不在当前激活组的 visibleIds — 分屏已经在画它，不再叠一层；
    4. 当前激活标签 kind === "session" — 小窗只浮在聊天面板上；
    5. activeId === ownerTabId — 只属于 owner。

    WebTabPip 把 1–5 收成 live；不满足则返回 null 并撤销 bounds。store 订阅 center-tabs：owner 或叶子被删 → end()；background 引用失效 → 清记忆。

    4 · 各场景行为

    R1每会话一个悬浮槽；切走消失，切回重现当前工作页

    配对表可以记下多张页，活跃绑定只有一份。呈现是 pipCoversCenter 的输出（条件 5）。切到会话 B 时 store 仍持有 (ex.dev, A)，组件因 live === false 不画；切回 A 同一函数再为真。这不是两次事件。

    7 · 已知不一致

    下面是代码与产品语义之间已经存在的缝，不是待办清单里的新设计。

    fork 不管 hide 之后的记忆。pipOpenMustFork 只看活跃绑定。A 点 ✕ 后会话 B 开同 URL，走 ensureWebTab 复用同一叶子并 show(id, B)——show 清掉 background，A 的恢复 chip 无声消失。「不劫持」的准确范围是「正在显示的悬浮窗」，不是「某会话的悬浮窗资产」。

    fork 只认规范叶子。判定是 webTabId(url) === boundTabId。已被 fork 出去的 popup id 再被第三方打开时，条件为假，ensureWebTab 拿到的是另一片规范叶子——结果碰巧正确，守护的却是 id 形态而不是「任何被绑定的同 URL 叶子」。每次 fork 留下一个孤儿叶子，靠 op=close 或用户手关。

    close 不按打开者记账。产品说法是「agent 能关自己打开的 tab，不能关用户布局里的 tab」。实现只看「是否在 group」。用户自己打开的独立网页可以被关；agent 打开后又被拖进组的不能关。

    fork 不进入 split 路径。桌面宽屏且组内已有 web 时，openWebTabInSplit 会改已有窗格的 URL，不调用 pipOpenMustFork。同 URL 冲突只在 PiP 分支上成立。

    「不劫持」只管叶子，不管槽位。R3 的 fork 让 B 得到新实例，但同一句 show(id, B) 覆盖全局唯一绑定。A 的规范叶子还在，绑定没了；切回 A 小窗不重现。用户对另一张网页点「收起到悬浮窗」同样静默顶掉旧绑定。产品句「不劫持」若理解为「A 的悬浮窗资产不被拿走」，实现没有做到。

    show 不解组。agent 把已在别人 group 里的规范叶子绑成自己的 PiP 时，不调用 ungroupTab。回到该组会看到 R2 遮罩：组成员还在，页面宿主却声明给了另一个会话。

    region 口径不统一。surfaceRefForChat 把未入组的配对页（含 PiP）标成 region:"right"；browserPageInventory 把未入组且可见的页标成 "center"。agent 看到的左右/中心与库存不一致。

    条件 4 被条件 5 蕴含。所有 show 的 owner 都是 session 标签，activeId === ownerTabId 已保证 kind === "session"。pipCoverBase 仍保留这条，是为 WebPreviewChip 在恢复前单独复用 pipCoversCenter 做兜底。

    PiP 不进 version-2 payload。刷新后绑定、background、小窗位置全部丢失，叶子退回普通中心标签。「切回 owner 重现」只在同一渲染进程生命周期内成立。
