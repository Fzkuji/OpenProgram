试一下：操作后界面怎么变

只改变这页示意，不会移动你的文件或归档真实对话。

后台怎么做、实施顺序与验收（展开查看）

用户移动目录时会发生什么

同一磁盘改名或移动

系统收到变更事件，解析原目录的新位置，验证后更新路径。原来的对话、Memory 关联和设置保留，不弹确认框。

关闭 App 后移动

启动时只检查已登记项目，先解析持久位置记录。不能直接解析时，等待用户打开该项目，再进行一次有限定位。

外接盘断开

显示“磁盘未连接”，保留登记和原位置。不当作删除，不扫描其他磁盘寻找替代。重新挂载或用户再次打开时检查。

情况结果不会发生的操作
复制项目或 Git clone原项目继续使用原目录；新副本显式打开时登记为独立项目不因为名称、remote、commit 或复制的标识相同而自动合并
跨磁盘移动系统不能证明连续身份时，显示找到的候选，请用户定位确认不把“复制后删除”和移动视为必然相同
旧路径出现新文件夹识别为不同目录；原项目继续指向原来的实体不因为旧路径存在就恢复为可用
权限不足、网络盘不可达分别显示权限或连接问题；手动重试只检查该项目不自动提权、不挂载远程盘、不持续重试
目录被删除保留项目和历史，显示“找不到文件夹”及定位操作不重建空目录，不悄悄换到 Home 执行

项目身份、实体身份、路径分开保存

project_id 是应用中的固定标识；实体身份用于确认目前指向哪个真实目录；path 仅是最近验证的位置。三者职责不同。新项目使用随机 ID；已有 ID 原样保留，不迁移对话主键。

记录用途更新规则
project_id对话、设置、Memory 关联移动不变；复制不继承关联
host_id + 原生位置记录在所属主机重新解析目录macOS bookmark；其他平台记录各自支持的句柄与卷/文件标识
path + location_revision显示和执行前解析；拒绝旧异步结果身份验证后原子更新；路径存在不等于身份相同
位置状态可用、正在定位、磁盘离线、权限不足、需要定位状态不改变项目归属，也不清理会话

Git remote、分支、提交、目录名称、复制过去的 .openprogram 标识只能提供候选线索。现有 dev/inode 记录不能作为跨重启、跨卷的完整身份保证。可信实体身份只在首次登记、用户明确定位或验证成功的移动后更新；普通名称、图标或设置修改不得重写身份。现有 _claim_moved_project 不再凭 session 标识自动认领，只提供候选。不会在每个项目里新增“唯一文件”并声称它不会被复制。

原生事件与位置解析：分平台验证

平台运行期间重启后实施门槛
macOS验证 FSEvents WatchRoot 或 kqueue 对根目录及祖先改名的通知；活跃句柄解析当前路径保存 NSURL/CFURL bookmark；无界面、禁止自动挂载地解析，更新 stale bookmark先实测根目录改名、祖先目录移动、重启、外接盘和拷贝；选择能满足这些行为的最小原生适配器
WindowsReadDirectoryChangesW 通知；允许 FILE_SHARE_DELETE 的目录句柄与 GetFinalPathNameByHandle在受支持的本地文件系统使用卷身份及 OpenFileById；不声称所有网络盘都支持验证 NTFS、长路径、卷离线、权限及句柄关闭；原生 Windows 验收未完成前不标为支持
Linuxinotify 监听目录/必要祖先，处理事件合并、溢出和失效；活跃目录 fd 提供定位依据不依赖需要额外特权的 open_by_handle_at；一般情况采用访问时的一次候选定位或手动选择验证祖先移动、跨挂载点、队列溢出；不承诺任意离线移动都可自动定位

系统能力不支持、监视资源耗尽或平台适配器缺失时，明确降级为“打开项目时检查”，不自动启用轮询。未选定的原生库和桥接方式由阶段 1 的实测决定，先验证再写完整适配层。

恢复只由明确事件触发

触发来源：目录移动事件、卷重新挂载、启动恢复、项目打开/执行前的位置失效、用户手动重试。项目新增和位置更新通过现有事件通知重新配置监视器。同父目录共享监听，不递归订阅项目内容；事件队列溢出只校验已登记目标，不能触发全盘扫描。普通文件内容修改不触发全项目定位。

  1. 读取 project_id 和 location_revision 快照，只处理受影响项目。
  2. 优先解析原生位置记录。成功后校验实体身份、目录类型、卷身份及目标是否已属于另一项目。
  3. 失败时分类原因。离线与权限问题不扫描；不把删除、不可访问和移动混成一个状态。
  4. 一次有限搜索只在用户访问或明确重试时启动，只生成候选。默认仅旧位置的最近可访问父目录，最多两层、1,000 个目录、2 秒；达到上限即显示手动定位。无 HOME 全树或常用目录遍历。
  5. 候选不能证明连续身份时由用户选择；没有新事件或用户操作就停止，不设置定时重试。

同一项目同时只运行一个恢复任务；重复事件合并，旧版本结果丢弃。一次交互内最多一次有限搜索。网络文件系统探测不在主事件循环运行；可阻塞的原生解析使用可终止任务边界，超时后本次停止。服务关闭必须取消并回收监视器、文件句柄和任务。

路径更新要么可恢复，要么不对新任务生效

现有实现先写项目路径，再尽力更新 sessions/locations.json，失败只记日志。这不能作为新设计的一致性保证。使用已有操作日志机制记录旧位置、新位置、预期 revision 和受影响映射；先记录待完成操作，再更新登记和派生位置。失败或重启后继续完成或回退；全部一致后才发布 projects_changed。项目锁不跨越会话锁。每个会话更新同时验证归属项目、旧位置和版本，防止迁移期间被删除或转移的会话被重新绑定；候选目录在提交前被替换也必须拒绝。

项目归属仍由 project_id 决定；项目内文件和附加目录用 project_id + 相对路径表达，项目外引用保留绝对路径。会话存储、文件浏览、Memory 来源、项目选择器和执行工作目录必须使用同一位置解析结果。不全文替换历史消息里的路径。

已经运行的进程不修改 cwd，也不自动重放工具调用。新工具启动前重新验证位置版本与实体；不可用时暂停依赖目录的操作并显示定位入口。独立 worktree 有独立位置记录，主项目移动不盲目重写所有 worktree。远程项目只由所在主机解析。

1 · 原生能力实测用临时目录验证三平台的事件、句柄、持久引用、祖先移动及离线边界记录真实可用能力；未实测的平台保持降级，不做虚假能力声明0；macOS 先验收，Windows/Linux 各自原生环境
2 · 身份与一致性新增位置版本和原生引用；重用现有 ID；统一解析入口；迁移操作日志与恢复复制、旧路径复用、迁移中崩溃、并发删除均不串项目、不丢关联1 的身份验证结论
3 · 事件驱动服务按能力注册监视器；事件合并、启动恢复、访问触发、资源释放能直接证明身份的移动自动恢复，其余情况稳定进入定位状态2
4 · 全入口验收与发布同步管理页、侧边栏、选择器、文件浏览和工具执行；按平台运行验收矩阵自动化检查和独立审查通过 → 更新默认 App → 实机验收 → 交付3；不以单个模块测试代替产品验收
主要代码范围与复用点
  • openprogram/store/project/discovery.py：移除周期扫描，替换为事件触发协调。
  • project_store.py：保留稳定 ID，增加位置版本及原生引用；停止凭路径存在判定身份。
  • openprogram/agent/internals/_workdir.py 与 session_store.py：共用解析和可恢复位置映射。
  • apps/server/openprogram_server/server.py：服务生命周期与取消；现有 projects_changed 刷新各界面。
  • 适配器代码必须有真实平台测试，不把轮询 watcher 当作原生事件源；不改无关程序/技能监听器。

验收必须证明的行为

  • 空闲 30 分钟，项目恢复模块的递归扫描、定时 stat 和自动重试计数均为 0；正常编辑 1,000 个文件不触发全项目定位。
  • 同盘根目录移动、祖先改名、快速连续移动：最后路径正确，通常在事件后 1 秒内完成；这是本地验收目标，不是网络盘保证。
  • App 关闭后移动：有原生持久引用的平台正确恢复；没有能力的平台显示真实降级状态。
  • 复制、多个副本、旧路径新目录、卷身份变化：不误关联。Git 相同和 session 标识相同均不足以自动接管。
  • 外接盘断开/重连、权限拒绝、事件丢失、监视器资源上限：无重试循环、无 UI 卡顿、无意外目录创建。
  • 每个持久化步骤注入崩溃并重启；项目 ID、设置、历史、会话位置最终一致；删除会话并发不死锁。
  • 真实执行入口不会在错误目录启动工具；已运行任务不会被自动重放；独立 worktree 和外部来源路径保持正确。

顺序：各平台小型能力试验 → 解析/身份单元测试 → 原生事件与持久化组件测试 → 服务/执行集成测试 → 全部相关契约 → 安装 App 实际目录移动验收。性能数字由记录证明，不仅检查代码中没有 sleep。
