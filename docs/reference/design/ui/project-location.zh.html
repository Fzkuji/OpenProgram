保存布局、移动规则、迁移与验收（展开）

采用什么，不照搬什么

采用三家的共同点：应用拥有会话存储，工作目录不是聊天保存位置。采用 Claude Code、DeepSeek Harness 的按项目分目录组织。项目目录使用稳定 ID，不用路径编码，避免改名后存储目录变化。保留 OpenProgram 已有 Git 会话格式、分支和撤回能力，不为统一布局改写成 JSONL。

Codex 的当前目录筛选比较记录中的 cwd，也检查最新 turn context。DeepSeek 的 workspace 关联验证会话 header.cwd 对应的真实目录，目录不存在或不匹配时拒绝。这些源码证明了路径参与筛选和关联，不能据此声称它们会自动追踪任意文件夹移动，也不能声称移动会删除其聊天。

进一步核实：Codex 的 Project 独立保存 id 和 roots，update_project 按 id 更新根目录，线程通过 project_id 关联。我们采用这一点。DeepSeek Workspace 同样有独立 ID，但当前 path 明确不可变；不照搬这一限制。

保存位置与身份

实际根目录由现有 profile/state 设置决定，默认 ~/.openprogram。沿用已登记项目 ID；新项目使用无路径含义的唯一 ID。会话 ID 全局唯一，项目名称仅用于显示。项目位置记录包含路径、位置版本和可用的原生身份/持久引用。已有默认会话保持兼容，不为了目录整齐额外迁移。

~/.openprogram/
  projects/
    projects.json                    # registry / location / identity
    <project-id>/                    # existing project settings
  sessions/
    index.json                       # rebuildable listing
    locations.json                   # legacy compatibility
    projects/
      <project-id>/
        <session-id>/                # complete session Git repository
        .file-recovery/<session-id>/ # external rewind data
    <legacy-session-id>/             # existing default sessions
  memory/                            # existing memory store, unchanged

移动与事件

macOS 优先验证 bookmark 持久引用和原生目录/卷事件；Windows 验证卷身份与文件 ID、句柄及目录事件；Linux 验证存活句柄和 inotify。只有经本机实测的能力才能标为实现。Linux 跨重启的任意移动不承诺自动找回；跨卷、权限拒绝、事件丢失和资源上限均保留手动定位。

触发限于目录/祖先的移动删除事件、卷重连、启动、用户访问失败和明确定位操作。不按分钟轮询，不递归搜索 HOME；普通文件内容编辑不启动项目恢复。事件合并，同一项目只保留一个恢复任务。原生解析在可终止的独立任务中限时执行，超时不重试循环。关闭服务时释放事件订阅、句柄和任务。

相同名称、Git remote、Git 内容或复制的 .openprogram 标记都不能证明目录连续身份。旧位置仍存在也必须验证身份，不能在修改项目名称时重新采集身份覆盖原值。手动定位显示旧、新路径并确认；新位置属于其他项目时拒绝直接接管。符号链接按真实目录统一，远程项目只在对应主机解析。

执行与引用

聊天读取不依赖工作目录。工作目录不可用时禁止启动该项目的新任务，不能回退到 HOME、服务器 cwd 或会话 workdir。已启动的子进程不重定向、不自动重放；后续文件操作重新验证位置。独立 worktree 单独检查自己的目录，不随主项目盲目改写。

不全文替换历史消息和 checkpoint manifest 中的绝对路径。新增项目文件引用使用项目 ID 与相对路径；旧附件引用在原路径不可用时明确提示，不冒充本地副本。已有上传附件、会话内部资源和外部撤回备份必须逐项审计物理存储位置，纳入迁移清单。记忆正文与历史保留；彻底删除来源会话时移除可点击来源或标注已删除，不额外复制来源文档。归档来源仍可访问。

旧数据迁移与删除

迁移前先停止该会话的一切写入，包括模型任务、fork 子进程、jobs、checkpoint 和附件写入。仅持有 Python 锁或单 worker 锁不足以证明安全。首批迁移在执行服务启动前完成；离线旧数据重新出现后也必须先进入同一静止写入边界才能迁移，不在普通读取中偷偷搬运。

迁移日志记录来源、目标、会话和项目身份及完整清单。先复制到私有暂存目录，校验内容和来源未变化，持久化正文与外部恢复数据，再原子发布目标与权威位置；最后清理旧位置。映射失败不得继续删除来源。每一步可中断、重启后恢复；目标冲突不覆盖。删除操作与迁移互斥，以持久化删除记录防止恢复过程重新生成已删除会话。只剩一个权威可写位置。

索引可由新布局与兼容旧布局重建，不能把迁移中的暂不可达会话清为空壳。项目移动不再改聊天位置索引；只更新项目位置版本并在验证后通知界面。项目管理删除登记、归档会话、永久删除会话和删除工作文件夹必须保持不同操作，不连带删除用户工作文件。

实施顺序与验收

  1. 先完成目录事件与持久引用的临时文件夹实测，确认平台能力边界。
  2. 新增用户目录内项目会话布局及兼容读取、索引重建、正确删除；保留所有已有 ID 和 Git 数据。
  3. 完成有静止写入边界的可恢复迁移，验证复制、发布、清理失败及重启、并发删除。
  4. 替换每分钟扫描，共用位置解析、身份检查和执行拒绝入口，接入可视状态。
  5. 独立规格审查通过后进行质量审查；运行相关与完整检查，再更新默认 App 并实际操作验证。

验收：移动后重启仍读到同一对话；外接盘断开仍读已迁移历史；新任务不在错误目录执行；同名副本和原路径复用不串项目；归档不影响存储；每一个迁移阶段失败后消息、分支、Git 提交与撤回备份完整；空闲期间没有目录遍历或定时定位；观察器关闭后无残留资源。

兼容与操作的精确定义

页面中“移动后聊天文件不搬动”和“离线可读”均指新建或迁移完成的会话；首次从项目内迁入用户目录会复制物理数据。当前安装版仍每 60 秒扫描，尚未替换。

已有路径派生 ID 原样保留，不重新计算。新版本注册新项目时生成 UUID；先按经过身份验证的规范路径查已有登记，再生成新 ID，冲突时重新生成，不合并会话。迁移前后的同一项目继续使用原 ID。

自动定位必须证明目录身份连续；手动定位允许用户在展示旧、新路径后明确选择替换，不要求新目录具有原 inode。两者都在提交前重新检查位置版本、权限及目标占用；目标属于其他项目时均拒绝。对旧布局，定位必须把兼容 locations 映射纳入持久操作日志，未修复完成标为“位置正在更新”，不返回完全成功、不开放新任务；恢复成功后发布通知。新布局只更新项目位置。

迁移期间所有更新版本的会话写入入口（包括 CLI、worker、fork 子进程和撤回）共用用户目录下按会话 ID 定位的进程间锁，并在取得锁后重新读取存储版本与位置。停止接收新任务，等待已登记写入任务结束；超时则延期，不强制杀死任务或继续复制。复制与切换持有独占迁移权。升级前旧版本进程必须通过现有生命周期管理停止；不支持旧、新版本同时写同一 profile。不得用“进程内无任务”替代这个条件。

主项目工作路径以项目位置记录为准，不信任会话中旧 work_dir。属于主项目内部的已登记额外目录与 source_folders，以确认过的旧根和相对路径派生新位置，再验证身份与权限；外部额外目录保留绝对路径，独立检查，不随主项目替换。无法访问的必需目录阻止相应文件操作并显示修复入口。历史消息、历史授权快照和撤回 manifest 不改写；移动后撤回如仍指向旧位置，必须明确提示不可用，不直接在旧路径创建或覆盖文件。新的位置需要重新验证执行权限，不能继承另一目录的授权。

侧边栏判定来自当前会话集合中过滤 archived 后的有效会话；管理页的总数包含归档，另显示归档数。不能拿总 session_count 作为侧边栏非空依据。归档/恢复/删除后统一刷新该派生集合。注册记录移除或隐藏不改变工作文件。
