还在的问题

1. Web 上回退不会真的改 HEAD P1 · 已证实

后端默认 phase = "plan"：只出方案，new_head_id 永远是 None，不改对话、不改文件。CLI 会再发 phase: "apply" 加 plan_hash / idempotency_key。Web 气泡 Rewind 和 /rewind N 只发 {action:"rewind", session_id, target_msg_id}。

气泡把「没有 new_head_id」显示成 Rewind failed: unknown error。斜杠路径若当时没有气泡监听 rewind_result，就是静默没反应。文件：ws_actions/chat.py、openprogram/agent/_rewind.py、message-actions.tsx、slash-commands.ts。

2. 斜杠 send() 失败仍当成功，草稿被清掉 P2 · 已证实

WebSocket 没开时 wsSend 返回 false，但 /compact、/branch、/rewind 的 run() 仍 return true。菜单和提交接着清空输入框。命令没出去，字也没了。

3. 输入 / 再回车会立刻压上下文 P2 · 已证实

菜单 / 列出全部命令，第一项是 /compact，可选参数现在直接执行。没高亮时回车等于选第一项。想打开列表却按了回车，就会开压。

4. 跳到最新和斜杠菜单的层级 未证实会挡

Jump z-index: 7，输入框 5，但按钮在 bottom: composer + 12px，和菜单是否重叠没在真机上证明。先不按缺陷修。

5. /skill 没写名字会被吞掉 P2 · 已证实

slash-commands.ts：if (!name) return true。回车算「已处理」，输入清空，技能没跑，也没有提示。点选会先填 /skill （有 <name>），再回车空名字就踩中。

5b. 菜单收起 380ms 内历史 ↑/↓ 失灵 P3 · 已证实

回车已经不截了（visible && !closing），但历史回忆仍看 !slash.visible。收起动画期间 visible 仍为 true，↑/↓ 不能翻历史。

6. /task 可以空跑成一条聊天 P2 · 已证实

点选会先填前缀（args 里有 <prompt>）。若有人提交光秃秃的 /task，run() 会 send({action:"chat", text:"/task "})，模型会接到一句空任务。没有「先写 prompt」的拦截。

7. 爆窗抢救（reactive compact）没有自己的界面 P2 · 已证实

reactive.py 会发 reactive_compact_started/done/failed 和 reactive_snip。chat-handlers.ts 没接这些 type。里面若调用了 engine.compact，仍会走普通的 compaction_* 行。纯 snip 抢救可能完全没字。

8. /help、/doctor 行为别扭 P3 · 产品

/help 只把输入设成 /，指望菜单再打开。焦点一丢就什么都没有。

/doctor 有会话时把体检报告当用户消息发出去，模型会接着回。没有会话才 alert。

9. TTS 未实现 P3 · 明示未做

openprogram/tts.py 对未接的 provider 打印 [tts] not yet implemented。不是回归，是功能缺口。

10. 附件过大 / 非文本会静默丢掉 P3 · 注释写明

image-attach.ts：非文本、超大文件直接 skip，没有气泡。用户会以为贴上了。
