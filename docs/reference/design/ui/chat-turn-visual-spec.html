采用、调整与拒绝

结论设计项OpenProgram 处理
采用Codex 的精确增量归因本轮统计只来自 committed file mutation event；没有精确 before/after 就不进入本轮卡。
采用Claude/Codex 的独立审查面聊天只保留摘要；Review 使用左侧文件导航、右侧单文件内容，并支持行级评论。
调整Claude 的 session diff 与 Codex 的 turn/repo diff放进同一个 Review tab 的三个 scope：This turn、Current branch、Workspace；切换 scope 不改变术语含义。
调整Claude 的 checkpoint 恢复保留 turn 级快速 Undo，但必须先完成全量冲突预检；恢复记录作为新的不可变 journal transaction 保存。
拒绝Bash 目录扫描归因删除 Bash 前后 cwd 遍历与候选文件预复制。普通 Bash、后台进程和外部修改不计入本轮，也不能由本轮 Undo。
拒绝近似本轮 diff 与静默部分恢复无法证明来源时只进入 Workspace Review；Undo 预检失败时不修改任何文件，并列出冲突路径。
调整参考产品的 header 操作层级采用“文字 Undo + 中性描边 Review”的主次关系；左侧使用 FeatherIcon 表示直接文件编辑，尺寸、间距、颜色和 Review 页面继续沿用 OpenProgram 视觉系统。

三个 Review scope

Scope权威数据源包含Undo
This turn当前 turn 的精确 mutation journal主 change set；关联 child change set 按真实 producer 保留，并通过 origin 分组，不复制 mutation。仅当全部记录为 recoverable 且 current digest 等于记录的 after digest。
Current branch当前 active lineage 的 mutation projection所有已完成 turn 与显式 revert/restore/reapply；不包含 sibling branch、普通 Bash 和外部写入。从具体 turn/checkpoint 发起，不提供无范围的一键 branch Undo。
WorkspaceGit tracked diff + ls-files --others --exclude-standard当前未提交 tracked/untracked 文件；遵循 .gitignore。非 Git 工作区显示 unavailable，不使用目录扫描替代。无。Workspace 变化可能来自用户、其他 session 或后台进程。

目标 mutation journal

1 · Before mutation

直接编辑工具在写入前记录规范路径、文件类型、before_digest 与可恢复 baseline。无法安全保存 baseline 时标记 recoverability=unavailable，绝不写成“原文件不存在”。

2 · Commit mutation

写入成功后记录 after_digest、operation、行数、binary/large、turn_id 和 actor_id；失败不产生 committed mutation。

3 · Persist summary

turn finalize 只归并本轮 mutation，生成净文件列表和增删统计并随 transcript 持久化。复杂度只与 changed paths 有关，不扫描 cwd。

4 · Review on demand

Review 先读取摘要；选择文件后才请求一个有界 diff。切换文件取消旧请求；聊天 DOM 永远不挂载 diff。

必须删除的当前逻辑：agent_loop._snapshot_cwd、_walk_scan 与 _checkpoint_changed_files 不能继续参与文件归因。特别是“超过 5 MiB 未暂存 → 使用不存在路径 → pre_existing=false”必须消失；baseline 缺失只能表示不可恢复，不能表示新建文件。
