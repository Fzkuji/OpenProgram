Shared file type icons

Design for file browsing in the desktop and web interfaces. Status: implemented with component, integration and default-App acceptance evidence.

One filename produces the same icon in the file tree, file tabs, split picker, review list and composer file suggestions. Each icon supplements a visible filename.

Verified implementation

The sidebar and central Files page share FileTree. FileGlyph currently groups Python, TypeScript and shell into the same generic code outline in the previous renderer. The shared FileTypeIcon now resolves filenames across all listed surfaces. Existing folder expansion, hierarchy guides, searching, opening and mutation behavior remain outside this change.

Presentation contract

Use 16px icons in file rows and 14px icons in tabs. Preserve row height, indentation and folder controls. Recognizable colors remain visible in light and dark themes. Unknown files use a neutral document icon. Exact filename matching precedes extensions; normalize path separators and case before matching. AGENTS.md uses Markdown; CLAUDE.md uses Claude. Git metadata uses Git. Dotted parent directories do not affect matching.

Data flow and boundaries

Existing filename or path → basename normalization → shared FileTypeIcon → SVG. No file content reads, network lookups, new state, persistence, permissions or mutation APIs are introduced. Filenames and extensions that match inherited object properties use the default icon before entering the library resolver. The renderer is decorative and hidden from accessibility APIs; existing labels and focus behavior stay authoritative. No changes to attachment upload states, file cache, unsaved drafts or review state.

Acceptance

  • Python, TypeScript, shell, JSON, Markdown and Git examples resolve to distinct expected SVGs.
  • CLAUDE.md, AGENTS.md, uppercase extensions, Windows paths and unknown types render correctly.
  • Sidebar and central Files, file tabs, split picker, review list and file suggestions use the shared renderer.
  • Default installed App at port 18100 displays the icons; expanding a folder and opening a file preserves behavior. The default App theme shows readable filenames and icons; manual verification of additional themes is recorded separately.

Implementation status

Independent specification and quality reviews pass. The full Web check command, 355 unit tests, TypeScript, production build and documentation link checks pass. The default installed App displays Python and Shell icons in the expanded scripts directory, opens profile_startup.py with a matching tab icon, and displays Git, Markdown, Claude, package and default icons in the central Files page. Manual visual acceptance covers the default light theme; a separate manual dark-theme check remains unverified. Source and regression evidence: shared renderer and public component tests.
