侧栏动态视图

列表筛选按钮旁的铃铛把侧栏聊天列表原地切换成动态：近 7 天里正在运行、等你输入、失败或未读的对话，按天分组，新的在上。再点铃铛或按 Cmd+Option+U 回到项目列表。

参照：Codex 侧栏的铃铛，它在同样的时间范围内做同样的事。

部分决定原因
位置就是列表本身，不是页面或面板。分区标题显示动态，铃铛呈按下状态。行上的状态点、Running 面板和任务页的收件箱各自回答了“什么需要我”的一部分；在用户本来就看的位置给一个视图，全部回答，又不离开当前对话。
列出谁按会话状态的标记：等待输入、运行中、失败且未读、未读。归档的从不列出。最后活动在 7 天内。列表说的正是状态点说的，两者不会矛盾。
行真实的聊天行（ConvItem）和它的标记，第二行是项目和状态词（等待、失败、运行），右侧是相对时间，悬停时让位给 ⋯。点击、菜单、重命名和打开即清除未读都还是这一行自己的。
分组今天、昨天，然后是日期Codex 也这样分；一周几个标题就够。
铃铛小点任一未归档对话在等输入时显示琥珀色（--status-needs-input）等待输入是唯一会卡住工作的状态；其余状态可以等用户来看。
⋯ 菜单全部标为已读：WebSocket 动作 mark_sessions_read 清除所列 id 的 unread 和待处理消息，和逐个打开一样，并广播 session_updated。不改变任何客户端的焦点。mark_session_read 还会记录这个连接的焦点，批量清除不能这样做。
为空标题加一行浅色文字：“没有要处理的对话”侧栏不放加载、报错或重试提示。
记住每个浏览器的列表视图里的 activity（lib/prefs/recents-view.ts）和其他列表视图选择一样，它描述的是这个浏览器的显示方式。
快捷键lib/tabs/navigation/tab-shortcuts.ts 里的 toggle-activity；App 的“视图”菜单用加速键发送它沿用 Codex 的按键；App 的菜单加速键在网页有焦点时也有效。
  • 代码：activity.ts（筛选和分组）、activity-header.tsx（铃铛和菜单）、sessions-list.tsx（原地切换的列表）、conv-item.tsx（两行的行）；后端 openprogram/interfaces/server/ws_actions/session/lifecycle.py。
  • 测试：apps/web/tests/ui/rails/sidebar-activity.test.mjs、tests/component/webui/runtime/test_session_unread_dot.py。
