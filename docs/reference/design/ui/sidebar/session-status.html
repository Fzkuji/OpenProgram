What counts as running

A row is running while any turn of its conversation holds a run slot, on whichever branch: the selected branch's turn (runningTasks) or a turn on another branch (sessionsWithBranchRun over lib/chat/run/other-branch-runs.ts). The composer's Stop stays the selected branch's alone (turn occupancy).

TurnRow
A typed message, a retry, an editRunning from its admission to its end
A Goal's next turn, its verification, a Goal started from the controlsRunning for the whole turn, on the branch the Goal follows; between two turns nothing runs and the row is idle
The notice of a background command that endedRunning while the agent answers it
A turn on a branch that is not selectedRunning; a turn there that waits on the person or has failed is not
A helper agent, a Job, an always-on check-inNot the row's state: they show in the Activity panel
  • Why any branch: the row stands for the conversation, not for the branch a pane shows. A Goal keeps working on its branch after the person selects another one, and an idle row would say nothing is running.
  • A client that connects mid-turn asks get_running_sessions once per connection and applies the answer (lib/chat/run/running-sessions.ts); a row it still showed running that the answer does not list is asked about with get_run_state and cleared.
  • The stored status of a conversation stays running when one turn ends while another still runs (mark_session_finished); the row's marker does not read it for running.
  • Tests: apps/web/tests/chat/run/running-sessions.test.mjs, tests/component/runtime/test_owner_turn_run_slot.py.
Installation and acceptance

Source TSX and CSS go through the normal release asset pipeline; installed minified JavaScript and generated asset names are never patched by hand. The workspace root package manifest holds the workspace definitions and is separate from the desktop manifest.

  • Web tests and checks, production build, Desktop checks, repository contracts and documentation links pass.
  • Every installed frontend JavaScript chunk parses.
  • The App renders the affected conversation and another one without a client exception.
  • Worker health and the installed source revision match the validated checkout. A source check alone does not establish installed-App health.
