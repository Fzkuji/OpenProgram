Sidebar Activity view

A bell beside the list's filter button switches the sidebar chat list in place to Activity: the last 7 days' conversations that are running, waiting for the person, failed or unread, by day, newest first. The bell again, or Cmd+Option+U, returns to the project list.

Reference: Codex's sidebar bell, which does the same over the same window.

PartDecisionWhy
PlaceThe list itself, not a page or panel. The section label reads Activity and the bell shows pressed.The status dots on rows, the Running panel and the Tasks Inbox each answered part of "what needs me"; one view in the place the person already looks answers all of it without leaving the conversation.
Who is listedThe marker state of session status: needs input, running, failed and unread, unread. Archived conversations never. Last activity within 7 days.The list says exactly what the dots say, so the two never disagree.
RowThe real chat row (ConvItem) with its marker, a second line with the project and a status word (waiting, failed, running), and the relative time on the right, which steps aside for ⋯ on hover.Click, menu, rename and the unread clearing on open all stay the row's own.
GroupsToday, Yesterday, then the dateCodex groups the same way; a week fits in a few headers.
Bell dotAmber (--status-needs-input) while any non-archived conversation waits for inputWaiting is the one state that blocks work; the other states can wait for the person to look.
⋯ menuMark all as read: the WebSocket action mark_sessions_read clears unread and the pending news of the listed ids, like opening each one, and broadcasts session_updated. It moves no client's focus.mark_session_read also records the socket's focus, which a bulk clear must not do.
EmptyThe header and one muted line: "Nothing needs you"No loading, error or retry notices in the sidebar.
