内置浏览器、资料导入与新建 Pane

本设计把通用的新建内容入口与浏览器内部页面分离，并为大量 History、Bookmarks 与登录 Cookie 的显式导入定义边界。它不改变 Agent 的网页控制协议。

1. 当前实现与问题

  • NewTabPage 同时承担“选择内容类型”和“浏览器首页”两个职责：新会话、网址输入、快捷网站与书签显示在同一页面。
  • 当前一级入口只有新会话和网址输入，没有 Files、Side chat、Browser、Terminal 四个平级入口。
  • 主页按钮把 web tab 退回通用 ntp，无法区分“新建 pane”与“浏览器主页”。
  • History 复用书签的两行卡片，完整 URL 单独占一行；大量记录下信息密度低。
  • 桌面端只记录 OpenProgram 自己产生的最多 5000 条 History；没有来源浏览器/profile 发现和导入流程。
  • 内置浏览器已经使用持久化 persist:webtabs session，具备写入 Cookie 的目标容器，但没有外部 Cookie 的可信来源适配器。

3. 信息结构

3.1 通用 New pane launcher

空白 pane 只显示四个一级入口，不显示地址栏、Bookmarks、快捷网站或 History。

Files — 打开当前项目文件视图
Side chat — 在当前 pane 创建独立会话
Browser — 将当前 pane 原位切换为浏览器主页
Terminal — 将当前 pane 原位切换为项目终端

3.2 Browser home

Browser 被选中后才显示浏览器 toolbar、地址输入、导入提示、快捷网站和 Bookmarks。主页按钮回到 Browser home，不回到通用 launcher。首次导入提示可以关闭，之后仍能从 toolbar 的导入按钮重新打开。

3.3 History

History 使用专用紧凑行：选择框 | 时间 | favicon | 标题 | 域名 | 更多。记录按本地日期分组；搜索结果仍保留日期分组。单行高度目标为 36–40px，标题与域名分别截断，不再显示第二行完整 URL。支持单条删除、批量删除和清空。

4. 导入流程

发现
列出已安装浏览器和本地 profile 名称，不读取内容。
选择
用户选择来源、profile、History、Bookmarks、Cookies。
暂存
只读复制目标文件到权限为 0700 的临时目录；校验类型、数量和上限。
提交
History/Bookmarks 合并；Cookies 逐条写入 persist:webtabs；返回计数。

4.1 History

  • 从来源 profile 的 Chromium History SQLite 副本读取 http/https 访问记录。
  • 按 url + visitedAt 去重，保持 OpenProgram 当前记录，不覆盖标题更新之外的数据。
  • 导入采用有界批次；错误时不清空现有 History。

4.2 Bookmarks

  • 解析 Chromium Bookmarks JSON，只接受 http/https URL 与有界字符串。
  • 导入到 Imported from <browser/profile> 文件夹；同 URL 不重复添加。
  • Bookmarks 仍使用现有树和 localStorage 格式，不新增数据库。

4.3 Cookies 与登录态

  • 禁止把外部 Cookies 数据库直接复制到 OpenProgram partition；产品密钥、数据库版本与活动 WAL 都可能不同。
  • 源浏览器必须负责解密：对 Chromium 浏览器，复制最小 profile 到临时目录后，由该浏览器自己的无界面进程打开副本，并经本机 CDP 返回 Cookies。
  • 临时浏览器不导航网站、禁用扩展与后台联网；正常完成或报错后终止进程并删除临时目录。
  • 只接受 http/https Cookie，校验 domain、path、sameSite、secure、expirationDate；写入失败逐条计数，不输出 Cookie 值。
  • 导入可以减少重复登录，但网站仍可能因设备绑定、过期、二次验证或服务端撤销要求重新登录，UI 不承诺所有会话均可恢复。

4.4 明确排除

  • 本阶段不导入 Passwords、支付信息、地址、扩展、下载记录、缓存、localStorage 或 Service Workers。
  • 不实现 OpenProgram 密码管理器、系统 Credential Store 或自动填充。
  • 不修改、关闭或以远程调试方式接管用户正在运行的源浏览器。
  • 不在 Web-only 模式声称支持本地浏览器导入；该能力仅存在于桌面 App。

6. 公共入口验收

  1. 新建 pane 只显示 Files、Side chat、Browser、Terminal 四项，DOM 中不存在 URL input、shortcut tile 或 bookmark row。
  2. 选择 Browser 后原位显示浏览器 toolbar、导入入口、快捷网站和 Bookmarks；导航 URL 后变为普通 web tab；Home 返回 Browser home。
  3. 导入对话框列出来源浏览器/profile 和实际支持的数据类型；执行前关闭对话框不产生目标变更。
  4. 导入 History 后按日期分组显示，至少 1000 条数据时行高保持紧凑、搜索和滚动可用。
  5. 导入 Bookmarks 后只增加一个来源文件夹，重复导入不产生重复 URL。
  6. 导入 Cookies 后目标 partition 可读取对应 Cookie；IPC、日志、History 和 renderer 均不出现 Cookie 值。
  7. 来源文件损坏、浏览器缺失、临时进程超时、Cookie 部分失败均返回稳定错误码，并保留导入前的数据。
  8. 可见验收只使用安装的 /Applications/OpenProgram.app、默认 18100 worker 和 ~/.openprogram。
