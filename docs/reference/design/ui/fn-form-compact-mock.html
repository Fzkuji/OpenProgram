Function form

Advanced parameters use a compact 28px disclosure control with a thin chevron, a neutral low-contrast background and visible keyboard focus. There is no extra divider above the control. Native details/summary semantics and reduced-motion preferences are preserved.

The parameter body retains 12px padding on every side. Automatic height measurement releases textarea flex growth and includes its native row height and border, so the last field cannot consume the bottom padding.

gui_agent

Function-form controls retain their existing header placement. Decision cards own their bottom action row, with no wrapper-level discussion overlay.

Discussion behavior

Chat about this opens an inline feedback field within the existing decision card. The original question or operation stays visible. Opening or cancelling the field sends nothing and leaves the wait unresolved. The user writes what they want to discuss and explicitly sends it. Deny remains a separate action that declines the operation without creating a discussion turn.

Sending discussion binds the original question, tool details and the user's feedback to the exact canonical wait. Only after decline is acknowledged does the existing session queue send the contextual feedback and request a text-only reply. Ordinary chat drafts and attachments are unchanged. Unknown delivery retains the same command and feedback for retry; competing approval controls are blocked during submission. Switching conversations cannot retarget the message.

Reference

Claude Agent SDK associates denial feedback with the original tool invocation. OpenCode allows rejection feedback. OpenProgram keeps its canonical terminal decline and existing chat queue; it does not synthesize a first-person rejection speech or treat ordinary questions as tool permission requests.

Acceptance

In the default installed App, opening discussion exposes an empty feedback field with original context; cancelling retains the request; sending contextual feedback produces a model reply with no tool execution; Deny alone produces no discussion message. Confirm pending submission cannot approve and retries keep one command and one message.

The implementation uses QuestionMode, the shared Textarea and the existing canonical wait command and session send queue. Runtime acceptance evidence is maintained with the release.
