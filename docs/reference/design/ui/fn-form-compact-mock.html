Interaction and acceptance

Choosing an approval option does not submit. Send commits its original scope. Chat about this declines only the displayed wait, restores the session composer with an editable context draft (prompt and displayed detail), preserves existing draft text, and focuses that composer when it is available. It sends no chat message and grants no approval. The draft stays local until the user sends it. Other queued decisions remain pending; focus waits until they no longer occupy the composer. Switching sessions cancels the pending focus request. Enter on a button activates that button; text-input submission and IME handling remain unchanged. Verification covers scopes, keyboard behavior, multiple questions and narrow/default App layouts.

Discussion transition

The previous implementation only declined and removed the card; it did not prepare a draft or focus the input. Acceptance clicks the real discussion control, checks the decline target, draft preservation and focus, then sends a follow-up in the installed App. Permission policies and wait-command transport remain unchanged.
