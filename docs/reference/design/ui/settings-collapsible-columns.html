交互与状态边界

独立控制收起 Settings 或 Provider 不修改另一列状态。 用户状态优先改变窗口宽度不自动展开或收起导航列。 持久化刷新和重新进入 Settings 后恢复用户最后一次选择。 键盘与读屏按钮保留原生 button、aria-expanded、aria-controls 与明确名称。 内容适配窄窗口只触发表单控件换行；详情数据、选择和滚动状态不变。 Provider 详情展开的 Provider 列表在窄内容区连续缩至最多 42%，为详情保留剩余宽度，但不改变用户的展开状态。Provider 开关属于标题行，不单独占一行。每条凭据显示为账户卡片：名称与验证状态在卡片头，密钥在卡片主体，使用状态在卡片底部；重命名、替换、重新验证和删除在窄宽度下使用图标按钮。新增凭据先显示单一入口，展开后才显示表单。 层级表达OpenProgram 品牌标题为 20px；Settings 二级导航标题与右侧内容页标题均使用 18px，保持低一级层级；Provider 第三级不增加独立名称栏头。 纵向网格Settings 分类列表整体下移 15px，使 General、LLM Providers 等行与主侧栏 New chat、Programs 等行逐行对齐；行高和 1px 行距不变。 导航顺序General → LLM Providers → Memory → Web Search → Browser → Channels → Token Usage → System；基础设置优先，模型与记忆相邻，统计和系统置后。

采用与排除

采用

  • 复用现有两态收起状态和图标。
  • 删除全局 Settings 顶栏。
  • Memory 不增加重复页头，Providers 恢复完整页面标题栏。
  • 只在 Settings 二级栏头显示名称和按钮。

排除

  • 不增加拖拽调整列宽。
  • 不按 breakpoint 强制改变用户状态。
  • 不修改 Memory、Provider 或模型数据。
  • 不改变应用主侧栏行为。

验收标准

  • Settings 页面不再渲染独立的全局 Settings 顶栏。
  • OpenProgram 品牌标题为 20px；Settings 分类栏的 Settings 与右侧 LLM Providers 内容页标题均为 18px；按钮与名称同一行，按钮顶边与主侧栏按钮一致。
  • Settings 分类列表的前四行与主侧栏前四行具有相同的 y 坐标、32px 行高和 1px 行距。
  • Settings 分类链接按 General / LLM Providers / Memory / Web Search / Browser / Channels / Token Usage / System 顺序呈现；URL、图标、激活态和键盘顺序随同一数组保持一致。
  • LLM Providers 列表栏不显示新增名称栏头，折叠按钮恢复到搜索框旁；原有状态和 49px 收起行为不变。
  • LLM Providers 在列表和详情上方显示页面大标题与介绍，路由 loading 状态保持同一结构。
  • Memory 内容区继续不显示重复标题和介绍。
  • Provider 详情变窄时不出现控件重叠或横向溢出；账号名称、密钥、状态和三个操作按钮仍完整可用。
  • API Key 名称、验证状态、掩码值和启用状态位于同一个账户卡片内；验证状态本身可触发重新验证，不再单独显示 Validate 按钮。
  • 已有 Key 时，新增 Key 表单默认不显示；用户通过 Add API key 展开表单，并可取消。
  • 窄详情缩减左右内边距，Provider 开关保持在标题区域；图标操作具有 title 和 aria-label。
  • 窄详情只重排内部内容，不自动收起 Settings 或 Provider 列表，不缩小字体，也不修改数据与交互行为。
  • 现有两处 localStorage key、键盘语义、图标选择和 49px 收起宽度保持兼容。
