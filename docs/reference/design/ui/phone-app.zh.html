手机界面

在触屏手机上（商店里的 App 或手机浏览器），界面是一套手机 App 的页面，而不是桌面窗口。useTouchPhone() 成立时，AppShell 渲染 PhoneApp，代替侧边栏、标签栏和右侧面板。窄的桌面窗口仍用桌面外壳的手机布局。

  1. 项目/chats
  2. 项目里的对话/chats?project=<id>
  3. 一个对话/s/<id>，新对话在 /chat
  4. 详情?details
  5. 改动、文件、活动、资源?details=files …

页面

页面内容
项目顶部是当前显示的电脑和设置按钮，然后是大标题、搜索，下面每个项目一行：带首字母的彩色方块、名字、最近对话的时间或几个在等你、对话数和最新标题。有对话在等你的项目排最前，再按时间。搜索会找所有项目里的对话。
底部胶囊项目列表和项目页底部是一整条胶囊，高 60pt、两端全圆，离两边 16pt，紧贴 Home 条上方：新对话的设置（打开新对话并弹出它的设置菜单）、新对话输入框、语音（打开新对话并开始录音）。列表在它下面渐隐。
电脑点顶部的电脑名，在它下面弹出菜单，和 Files 点标题一样。里面列出这台手机配对的电脑（各自一条连接，由 App 切换），以及当前电脑连接的其他电脑（设置 → 机器），它们的项目本来就在列表里。一次只显示一台电脑（phone-computer-switcher.tsx）。
边距标题、搜索、列表行、导航栏和胶囊统一离边 16pt（--phone-gutter）。列表是平铺的：行直接在页面上，之间是细分隔线，没有灰色底。搜索框圆角 20pt。
一个项目‹ 项目、项目名、搜索，下面是它的对话，分“进行中”和“更早”两组。每行是标题，下面是状态词和最后一行，右边是时间、状态点或“等你”标记。左滑露出归档；长按时这一行浮起来，弹出置顶、重命名、复制链接、归档，最后是红色的删除。底部输入框写着“在 <项目> 里开新对话”。
对话导航栏：‹ 项目名（或返回）、标题，运行、等你或失败时标题下有状态点，ⓘ 打开详情。输入框是一个框，离屏幕两边 10pt、圆角 30pt：文字，下面一排 44pt 的按钮：+、写着模型和思考力度的芯片、表示权限的盾牌、麦克风；有文字时麦克风变成发送。
消息用户消息是浅色气泡；每组工具调用折成一行灰字，点开后点其中一步会以一页打开。消息下面没有按钮：长按时按住的文字或气泡浮起来，弹出它的操作。
设置菜单点任一芯片打开一个菜单，放这一轮的全部设置：Harness、模型、思考力度、权限、智能体，每行下面写当前值，选项在子菜单里；然后是高速模式、网页搜索、沙箱、无人值守，开着的打勾（外部智能体的对话没有网页搜索和沙箱）。
详情推到对话上面：改动（带 +增加 −删除 行数）、文件、活动、资源各一行，点开各是一页（桌面的右侧面板）；然后是显示方式，再是置顶、重命名、自动重命名、复制链接、复制会话，归档和删除单独一组。删除后回到项目列表。
其他页面设置、历史和其他路由都以一页打开，上面有 ‹ 项目。

实现

部分做法
页面和返回每个页面是用 history.pushState 推入的地址，Next 会让 usePathname 跟着变。商店 App 里从左边缘滑动返回一页，页面跟手（use-edge-swipe-back.ts）：WKWebView 自带的返回手势不认这些地址。手机浏览器里用浏览器自己的手势。
页面切换新页面从右边滑入盖住旧页面，旧页面向左挪一点并变暗；返回时倒着放（use-page-transitions.ts）。旧页面是它最后一帧的静态拷贝，屏幕不会空白。没用 View Transitions API：WebKit 给长对话截图要两秒。
不出现半成品页面页面按历史记录条目区分，被替换的地址（比如新对话拿到 id）保留原页面。还没读过的对话等消息到了再打开（最多 700ms），拷贝停着不动，直到对话内容画出来。
数据不重复取数据：列表读会话 store，对话页用分屏视图里自成一体的 PeerSessionPane，详情页挂右侧面板原有的面板。聊天页的外壳在看不见的地方保持挂载，因为连接和地址里对话的加载由它负责。
和桌面共用模型、智能体和会话操作菜单拆成了 hook 和内容（useChatModel、useChatAgent、useSessionActions），手机的面板、详情页和桌面的芯片、菜单跑同一份代码。
中日韩文字iOS 的 WebKit 遇到系统字体没有的字，会画成带问号的方框，而不是去试下一个字体，所以每个字体栈都把 PingFang SC、Hiragino Sans、Apple SD Gothic Neo 放在 -apple-system 前面（lib/prefs/appearance/font-stacks.ts）。
菜单商店 App 里所有菜单都由 iOS 自己画（lib/mobile/native-menu.ts、NativeMenus.swift），样子和动画就是系统的：点按钮时网页把菜单项交给 App，手指一落到对话或消息上就先交过去，长按时菜单已经备好；选中的项以事件传回网页。浏览器里仍用网页自己的面板。
长按消息的菜单列出它桌面操作栏里的按钮（操作栏留在页面里隐藏），点选就是点那个按钮，所以每个操作跑同一份代码（phone-message-menu.tsx）。输入框以外不能选中文字。
触感商店 App 的桥接提供轻、中、选择、成功四种震动（lib/mobile/bridge.ts 里的 haptic()）：长按、开关和分段选择时用。
权限卡片选项竖排成全宽 44pt 按钮，推荐的在最下面，靠近拇指。
不缩放在两个控件上快速各点一下会让页面放大：页面用了 touch-action: manipulation，商店 App 还锁住了视口缩放。

为什么单独写手机界面，而不是继续改桌面

第一版手机界面保留桌面结构（标签栏、两个抽屉、芯片行）再改样式，怎么修都像是把电脑塞进手机。

画了三种做法：继续改样式（A）、在网页里单独写手机页面（B）、原生重写（C）。选了 B：页面按手机习惯来，数据层、消息渲染和输入框仍是一份代码；C 要多维护一套界面，手机 App 已经排除了。

同类手机上怎么做采用
Happy原生的会话列表，推入的会话页标题下写状态，输入卡片的控件收成一行，长按消息出操作并震动标题下写状态、输入框一行控件、长按菜单、触感
Paseo手机上面板变成推入的页面；输入框的智能体控件收成一个按钮，点开是面板；工具调用折成一行；列表行左滑归档一个设置按钮、推入的页面、折叠工具行、左滑归档
Claude、ChatGPT底部固定的新对话框、带返回的导航栏、分组列表式设置固定输入框、分组列表、ⓘ 进详情
GitHub改动、文件、活动是详情页里的几行详情页第一组
