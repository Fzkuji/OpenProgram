bash

bash(command, workdir, yield_time_ms, tty, description)

  1. prepare_command 解析 workdir（worktree、沙箱检查、远程 cd 防护）。
  2. session.run 检查会话上限，processes.start 在独立的 supervisor 下启动命令，supervisor 在 stdout 上写出一行、说明记录已在运行时返回。
  3. supervisor 每次响铃（见唤醒），collect 就把未读输出读入 1 MiB 的首尾缓冲，直到命令结束或等待时间到。
  4. 已结束：Process exited with code N 加输出，记录移除。仍在运行：记录设 background=True，回复 Process running with session ID <id>。

唤醒

运行中的命令没有任何东西按固定节拍醒来。processes.db 记着一切（输出、状态、停止和 stdin 行）；唤醒只是说“现在去看”。

谁在等被什么唤醒
supervisor 的控制循环命令结束：进程组组长的 SIGCHLD 经 signal.set_wakeup_fd 送来（POSIX）；作业对象的 I/O 完成端口，由一个线程跟着（Windows）。停止、中断或 stdin 行：写入方插入后连上门铃。stdin 管道重新有空间（POSIX）或写线程写完（Windows）。唯一的截止时间：停止后到 SIGKILL 前的 5 秒宽限
collectsupervisor 每写一段输出、每改一次状态后的响铃；它的连接关闭（supervisor 已结束：仍为活动状态的记录转为 unknown，调用返回）；这一轮被停止（cancellation.on_cancel）；等待时间到；10 秒一次的重新同步
等待确认的 controlsupervisor 执行完后的响铃；停止最多 8 秒，其他 3 秒
processes.startsupervisor 在继承来的 stdout 上写的 ready 行，或这条管道关闭；最多 10 秒
命令的 shell 结束后的 group_guard进程组里其余每个成员都交给操作系统看住（kqueue NOTE_EXIT、pidfd）并等它们退出；然后再列一次进程组，因为成员可能又启动了别的进程。两者都没有时才每 0.1 秒列一次

门铃（channel.py）是每个 supervisor 自己监听的一个回环 TCP 端口，和一个随机令牌一起记在它的私有记录里。不带令牌的连接被断开。

等待方先连接再读取，连接时发令牌；supervisor 每写一次就给它发一个字节。写入方插入行之后再连接，它的令牌行唤醒 supervisor 去读命令。

方案为什么不用
processes.db 的文件事件只到得了 Worker（到不了 --print 或脚本），而且要等 watchfiles 的去抖，约 0.7 秒：每条很快的命令都得等这么久。它仍然服务窗口和退出通知循环
Unix 套接字或 FIFOWindows 上的 Python 没有 AF_UNIX，macOS 上路径限 104 字节；FIFO 只有 POSIX 有
一个线程阻塞在 waitpidSIGCHLD 写进循环自己的套接字，不需要线程；Windows 上完成端口还能数到比组长活得久的成员，进程句柄做不到

会话上限

每会话最多 64 个活跃会话。到达上限时，停止最近八个之外最久未用的会话并标为 reported，新回复会指明它。没有空闲超时。

退出通知

run_exit_notices 在 worker 中运行。进程记录变化时扫描，输出持续写入时最多每 2 秒一次；有通知等着忙碌对话时，在对话可能空下来时扫描。

  1. unreported_exits()：background、未 reported、状态 exited 或 failed。stopped 的命令不发通知。
  2. 会话有运行中轮次或非终态执行时跳过，之后重试。
  3. 克隆最新的聊天请求，设 source="process_exit"、新的用户消息 id 和通知文本（命令、退出码、耗时、最后 2000 字符），以键 process_exit:<id> 准入。没有聊天执行时直接标记已报告，不发通知。
  4. 用户节点为 display="runtime"，记忆跳过它。

审批
write_stdin，空或 "\x03"无需决定（SESSION_POLL）；bash 已批准该命令
write_stdin，其他输入按模式处理，同 bash。在 Auto、MCP 和委托约束、危险允许规则中算高风险工具。
terminal_use input, interrupt, close任何标签页都按模式处理。卡片（TerminalApproval）显示标签页、目录、是否有命令运行、未完成的人工输入，以及拼写出控制字符的确切输入。
进程层
部分行为
group_guard，管道以 /dev/null 作 stdin 运行命令
group_guard，tty打开 pty 作为自身会话的控制终端，把进程组置前台，设 30×120，并泵送 master 与 supervisor 管道。进程组和会话里其他进程组（set -m 的作业、调用过 setpgid 的子进程）都空了以后停止读取，最晚在进程组结束两秒后：macOS 上 guard 持有终端时不会报告输出结束，而完全关闭的 pty 会丢弃未读输出
group_guard，信号忽略 SIGINT 和 SIGTERM，因此中断到达命令
Supervisorwrite 不加换行；interrupt 向进程组发 SIGINT（Windows：终止进程树）。写入 running 时一并记下门铃的端口和令牌（从不进 public_record）
ProcessStore记录 tty、sandboxed、background、reported、last_used。take() 返回未读输出和读取前丢弃的字节数。
tty 支持macOS 或 Linux 的本地后端

界面
Activity只列后台会话；第一次等待中的命令是活动工具调用
Resources运行中的后台会话列在 Terminal 组的 Background terminal；保留的输出在 xterm 中只读显示，带停止；进程记录变化时刷新（processes 变更帧）
工具行write_stdin：“等待输出”“中断命令”“输入”。terminal_use 输入：“在终端输入”。
