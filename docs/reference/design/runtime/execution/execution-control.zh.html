会话分支与运行控制

Activity 在首次加载、重连或游标重新同步期间不显示错误提示。只有当前会话已经确认的请求失败才显示错误；切换会话不会显示上一会话的错误。真实读取失败时保留已取得的记录并自动重试。

这里说明三件事：统计什么、什么时候需要你处理、暂停或停止后会发生什么。

Activity 按会话分支统计。在同一分支继续发消息，不会多出一条 History。

恢复时只处理仍对应当前执行检查点的已结束等待。旧问题的答案不能恢复、取消或结束后续的新等待；重复恢复不会重复执行。回归覆盖第一个等待已回答、第二个等待未回答或已回答两种情况。本恢复修正已通过规格与质量审查，受控测试覆盖连续等待及重复启动恢复。

恢复同一轮运行

恢复 Agent 时重新绑定原会话、轮次、回复、运行环境和工具配置，并在完成、暂停或错误时释放绑定。浏览器页面凭据仍属于原来的调用方，不接受其他调用方的凭据。浏览器拒绝作为明确的工具错误返回，保留原原因。达到配置的迭代上限时记录为未成功完成，保留此前文字和操作记录。

只有权威执行更新确认消息属于当前会话和当前执行时，才在该助手消息旁显示等待审批；审批操作仍在原输入区域进行。重连或恢复待回答问题时请求现有执行快照，依据快照中的消息归属恢复状态，并兼容旧事件格式。缺少归属证据时，不将其他运行的审批显示在该消息上。

验收覆盖暂停后恢复、使用新取得的页面凭据观察原页面、异常时释放绑定、拒绝其他调用方凭据、迭代上限，以及审批在消息和会话之间的隔离。实现状态：规格与质量审查通过。受控回归验证恢复后的页面凭据归属、明确的浏览器错误、绑定释放、迭代耗尽时的失败状态，以及审批提示的消息归属。默认 App 实机验收作为独立发布检查。

1. 先分清三个对象

对象含义显示在哪里
会话分支一条连续的对话路径。真正分叉时，才产生另一条路径。Activity 中的一项。
一次执行一次任务运行，例如回答一条消息。放在分支详情中。暂停、继续、取消等操作用它的 ID 确定目标。
受管理的进程工具启动的一条命令，例如运行脚本。归属于启动它的那次执行，可单独查看输出或停止。

2. 分支怎样计数

例子计数详情
发一条消息，再说“继续”。1两次执行仍属于同一个分支。
从前面的某个位置创建另一条回复。2原分支和新分支各显示一项。
同一分支后面的一次执行失败。1失败保留在详情中，不会因此创建分支。
两个分支有相同的早期消息。2共同的早期执行可出现在两边的详情中，但不会额外计数。

History 统计已结束的分支。需要处理或仍在运行的分支，显示在对应区域。

3. 应该显示什么状态？

情况所在区域含义
等待审批、回答、暂停处理，或工具结果尚未查明。Needs attention打开详情查看实际请求。发新消息不会自动撤销它。
执行、子任务或所属进程仍在运行。In progressAgent 回答完了，不代表后台进程也停止了。
分支已结束，没有运行中的工作或待处理请求。History失败记录和输出仍可在详情中查看。
执行者已结束，只缺模型响应记录；也没有实际等待或待处理的非取消操作。History显示“已结束 · 响应记录不完整”。遗留的取消请求不会使它变成待确认事项。只有子任务仍在运行时才保留 Cancel。这不表示任务成功。

分支的一般状态取最新一次执行，同时检查真实等待、子任务和所属进程。无法关联的记录会单独保留，不猜测它属于哪个分支。

4. 每个操作会做什么？

操作结果限制
Pause请求在下一个安全位置暂停。当前动作可能先完成，不是停在任意一行代码上。
Continue从已保存的进度继续同一次执行。必须有有效的保存状态，且该执行支持继续。
Step执行一个已定义的步骤，再次暂停。步骤可以是一次工具动作，不等于一行代码。
Steer补充后续工作要遵守的指令。不改写已经完成的工作。
Cancel结束选中的执行及其下属执行。不能撤销已经完成的外部操作。受管理的进程另有独立控制。
Fork / Retry从允许的保存位置创建独立的后续执行。原历史保留。聊天 Agent 的新执行先暂停，需点击 Continue；其他类型遵循各自调度规则。

界面只提供该执行支持的操作。“已接收”表示请求已保存；“已生效”才表示操作完成。

5. 重启后保留什么？

记录简单解释作用
检查点在规定位置保存的执行进度。继续时从这里开始，不恢复被冻结的线程。
操作结果记录模型或工具请求是否结束，以及已确认的结果。不盲目重复已确认的操作；外部动作结果不明时先核对。
本次运行的所有权当前哪个 worker 有权更新这次执行。旧 worker 不能覆盖接替它的新 worker 的状态。

命令完成与终态同步并发时保持幂等：比较并交换发生冲突后，服务只接受属于同一执行、结果版本相同且已应用的命令，保留持久化回执，继续报告其他冲突。验收通过公开取消入口的观察器确定性插入终态同步，并确认拒绝或版本不匹配的结果仍然报错。

工程参考：标识和安全规则
标识用途
session_id确定会话范围和访问权限，不能直接作为执行控制目标。
run_id关联原执行及其分叉、重试执行。
execution_id精确控制目标。暂停、继续保留它；分叉或重试创建新 ID。
attempt_idworker 的一次实际运行；恢复时可创建新的 attempt。
revision_id程序及其运行规则的不可变版本。
command_id + expected_version防止重复操作，并拒绝基于旧状态发出的命令。
  • 各入口使用同一个命令服务。先保存请求，再由执行者处理；界面状态不能代替权限检查。
  • 取消优先于暂停、单步、继续和补充指令。只有当前执行者可提交进度或最终状态。
  • 已返回的模型错误和中止会登记响应。工具结果未知时仍需核对，History 标签不会清除它。
  • 分叉前验证保存位置、程序版本和权限。修改程序、模型或工具规则，仍需独立审批。
  • Agent 和后台 Job 使用同一套执行管理。Job 的 job_id 等于 execution_id。资源分配与执行状态分开管理。
  • 分支归属取自已有会话图和消息 ID。压缩上下文后仍保留早期关联；加载项目会话时读取最新保存位置。
  • 读取和控制限制在有权访问的会话内。重连使用已保存的版本和事件位置，不重复创建任务。
  • 受管理进程保留 ID、归属和有上限的输出。重启后检查监督进程，不能只凭保存的 PID 发送终止信号。

6. 实现与验证

部分已有实现怎样验收
分支统计按真实会话分支显示，每次执行保留在详情中。连续会话 → History 1；确有三个分支的会话 → History 3。
待处理状态区分单纯缺模型记录、真实等待和工具结果不明。真实审批仍显示；已结束的模型请求不会单独要求确认。
执行控制已有统一命令、检查点和版本控制；不同执行支持的能力不同。只验证该执行声明支持的操作；强制工具、spawn 和 merge 路径仍有限制。
进程与恢复默认 macOS App 已验收进程归属、独立停止、输出保留和刷新。这些验收不能证明 Windows 或 Linux 的实际运行结果。

限制：不恢复任意线程栈，不自动撤销操作，也不补造从未保存的进程记录。普通函数内部提问仍需预先声明交互边界；等待的最长时间和 Job 的运行预算，尚未统一接入资源管理。
