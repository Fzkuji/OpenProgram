OpenProgram Runtime · normative architecture

统一运行控制：暂停、继续、单步、调整与取消

本页是 OpenProgram 运行控制的唯一权威设计。它固定执行标识、持久状态、命令协议、安全点、检查点、owner 合同、恢复规则和未来逻辑修改方式。Chat、Agent、Workflow、后台 Job、工具与子进程共享这一控制模型；各界面不再维护自己的 stop、pause 或 resume 语义。

1. 固定设计结论

所有运行控制都是对一个持久 Execution 提交命令。用户可以暂停、继续、执行一个安全步骤、调整未执行部分、取消，或从检查点创建新 revision。Runtime 先持久化命令，再由当前 attempt 的 owner 执行；界面只读取 canonical Execution Record 和事件，不推断运行状态。

同一控制对象

run_id → execution_id → attempt_id

会话负责归属，run 负责逻辑链，execution 绑定不可变 revision，attempt 表示一次物理激活。控制命令只接受精确 execution_id。

同一持久协议

command → event → materialized state

所有 transport 调用同一个命令服务。命令幂等，状态有版本，迟到响应不能覆盖新状态。

同一恢复模型

safe point + checkpoint + effect receipt

暂停和恢复只发生在声明过的安全边界。已确认副作用不重放，结果不确定的副作用必须先核对。

暂停不是冻结 Python 线程。Runtime 不保存任意指令地址、调用栈、锁状态或不可序列化对象。暂停请求在下一个 durable safe point 生效；继续从已发布的 checkpoint 恢复。这个边界同时支持跨进程恢复、server restart 和后续 revision 修改。

2. 当前实现与必须移除的分歧

当前代码包含可复用的取消、checkpoint、rewind 和 steering 能力，但还没有统一运行控制。下列入口只作为迁移证据，不是目标合同。

当前实现实际行为目标处理
/api/pause、/api/resume切换进程全局 threading.Event；没有精确 execution identity，主执行路径没有稳定安全点调用。删除全局事件。只保留 execution.pause 与 execution.continue。
WS stop、REST /api/stop可按 session_id 推断前台执行，再调用 exact cancellation。删除 session fallback。所有 surface 直接提交 execution.cancel。
mark_cancelled(..., execution_id=None) 与 token alias迁移期入口允许调用者绕过 canonical command。取消公共导出；owner 只响应已经持久化的命令。
session-scoped steering inbox消息按会话落盘，接收 execution 由运行中状态推断。改为 execution-scoped durable command，并记录 accepted/applied/rejected。
Workflow 函数名、调用序号、参数 hash checkpoint可复用已完成结果，但不能稳定表达 revision、step identity、attempt 和外部副作用。迁入正式 Checkpoint Manifest。
DAG、Job、Workflow 和 UI 本地状态分别保存或推断 lifecycle，局部 finalizer 补写部分终态。全部成为 Execution Record 投影；只有 Control Service 写 canonical lifecycle。
目标架构不增加“旧 stop 调新 cancel”“session pause 转 exact pause”一类长期适配层。存量数据使用明确 schema migration 一次转换；旧代码入口在切换提交中一起删除。

3. 能力与边界

正式能力

  • pause：目标执行子树到达安全点并发布 checkpoint。
  • continue：从当前 checkpoint 继续同一 execution。
  • step：只推进到下一个声明的安全点，然后再次 paused。
  • steer：调整未执行逻辑，不修改已提交历史。
  • cancel：终止目标执行子树，Runtime 必要时自动升级终止。
  • fork：从 checkpoint 与不可变 revision 创建 execution 分支。
  • retry：从失败或中断执行的合法 checkpoint 创建新 execution。

明确不提供

  • 通用 Python 源码行级暂停与恢复。
  • 保存线程栈、锁、socket、生成器或 provider stream 的内存快照。
  • 通用事务回滚或未知外部系统的自动撤销。
  • 客户端提交 PID、timeout、force、checkpoint 内容或 finalizer。
  • 按 session 猜测目标，或关闭页面时自动取消。
  • 对运行中的历史 revision 原地修改代码。
  • 由 UI 组合低层命令模拟正式能力。

5. 标识与不可变边界

标识生命周期规则
session_id对话或工作区容器用于授权、查询和 UI 分组，不能作为运行控制目标。
run_id一个用户目标的完整执行链包含原 execution、retry 和 fork；不绑定某一代码版本。
execution_id一个不可变 revision 下的逻辑执行唯一公共控制目标。pause/continue 不改变它；fork、revision 修改和 terminal 后 retry 创建新 execution。
attempt_id一次 worker/进程激活owner lease 与日志边界。恢复同一 execution 可创建新 attempt；旧 attempt 由 fencing token 禁止回写。
revision_id不可变 Program、plan、tool contract 与 policyexecution 创建后不可更换。修改未来逻辑必须创建新 revision 和新 execution。
step_idrevision 内稳定的语义步骤不能由临时调用序号生成；用于 frontier、step、兼容性校验和调试展示。
checkpoint_idsafe point 的不可变快照只有原子发布的 checkpoint 能用于 continue、fork 或 retry。
command_id一次控制意图全局唯一幂等键；重复提交返回第一次结果，不重复执行。
暂停后继续同一个 execution。逻辑和 revision 未改变时，continue 只推进原 execution；如果 worker 已释放，则新建 attempt。只有 revision、执行分支或 terminal 后重试变化时，才新建 execution。

6. Canonical Record 与命令记录

Runtime Store 保存 append-only events，并维护可按版本 compare-and-set 的 materialized record。DAG node、Job row、Workflow state、消息状态和 UI indicator 都只读取或投影该记录。

ExecutionRecord {
  execution_id, run_id, session_id,
  parent_execution_id, revision_id,
  status, status_version, reason_code,
  current_attempt_id, owner_lease,
  checkpoint_head_id, safe_point,
  active_child_ids, pending_command_ids,
  capability_set, effect_summary,
  created_at, updated_at, terminal_at
}

ControlCommand {
  command_id, execution_id, expected_version,
  kind, payload, actor, submitted_at,
  status: accepted | applying | applied | rejected,
  result_version, rejection_code
}
  • 每个状态变化产生 event；materialized record 可从 events 重建。
  • expected_version 防止旧页面覆盖新状态；重复 command_id 不重新执行。
  • terminal transition 只发生一次；late owner 只能附加审计事件，不能改终态。
  • Runtime Store 是唯一事实源；owner registry 只保存短期运行句柄。

7. 两层状态机

逻辑 Execution 与物理 Attempt 分开建模。用户看到 Execution 状态；worker lease、进程退出和恢复使用 Attempt 状态。

running：存在有效 attempt lease，owner 可以派发新 managed action；Runtime 在每个 safe point 检查待处理命令。

Attempt 状态

leased → active → checkpointing → ended。pause 可以在 checkpoint 发布后结束 attempt，也可以短暂保留 lease；这是调度策略，不改变 Execution 的 paused 语义。失去 lease 的 owner 无权写 checkpoint 或终态。

命令优先级固定：cancel > pause > step/continue > steer。已经持久化 cancel 后，continue、step 和 fork 拒绝；cancel 会解除 pause、question、approval 和 resource wait。

9. 安全点与单步单位

safe point 表示此前工作已提交、此后工作尚未派发。每个 Execution Driver 声明边界与能力；没有 checkpoint 能力的 owner 可以 cancel，但不能声称支持 pause/continue。

类型合法 safe point一个 step
Chat / agent loopprovider 请求前；完整响应提交后；tool dispatch 前；tool result 持久化后。一次 provider decision 或一次 tool action。
Workflow稳定 step_id 前后；branch join；显式 checkpoint。一个确定 step 或控制流节点。
后台 Job领取任务前；durable item 完成后；batch 边界。一个 item 或声明 batch。
Tool / subprocessdispatch 前；带 receipt 的完成后。一个完整 invocation。
Question / approval请求已持久化且尚未 resolved。接收并提交一个 answer/decision。
Child executionadmission 前；child terminal 或 paused 后。创建并等待 child 到下一个 durable boundary。
  1. pause intent 持久化后立即关闭目标子树 admission gate。
  2. 已 dispatch 的 provider/tool/child action 继续到结果、超时或 cancel；Runtime 不伪造中间结果。
  3. owner 到达边界时提交 checkpoint fragment 和 effect receipts。
  4. 所有活动后代确认后，根状态从 pausing 进入 paused。
  5. step 只发一个 permit；涉及 child 时覆盖到 child 的下一个 durable boundary。

10. Checkpoint Manifest

Checkpoint 是不可变内容对象。Runtime 先写 payload 与 blobs，验证 hash 和 schema，最后 compare-and-set 更新 checkpoint_head_id；未发布对象由 GC 清理，不能用于恢复。

CheckpointManifest {
  checkpoint_id, execution_id, revision_id,
  parent_checkpoint_id, status_version,
  frontier: [{step_id, phase, branch_id}],
  completed_frontier: [{step_id, contract_hash}],
  program_state_ref, conversation_state_ref,
  completed_actions: [{action_id, input_hash, result_ref}],
  effect_receipts: [{effect_id, classification, receipt_ref, outcome}],
  child_frontier, pending_commands,
  schema_version, created_by_attempt_id, content_hash
}

必须包含

revision、稳定 frontier、可序列化 Program state、已完成 action receipt、子执行关系、待处理 durable command、schema 和 content hash。

不包含

线程栈、mutex、PID、socket、provider stream object、任意闭包、未提交局部变量或原进程对象地址。

现有 mutation journal、Workflow checkpoint 和 DAG history 作为 manifest fragment 或 projection 接入，不再分别定义“resume 已完成了什么”。

11. 外部副作用与恢复安全

分类自动恢复规则例子
pure可重算；保存输入与结果 hash 即可。解析、格式转换、确定计算。
idempotent使用稳定 effect_id / provider idempotency key 重试。API upsert、内容寻址写入。
compensatable保存 receipt 与显式 compensation；只有 Program policy 明确请求才执行补偿。创建后可按 resource ID 删除的资源。
nonrepeatabledispatch 后失联则进入 reconciliation_required。发送消息、支付、部署、无幂等键提交。
unknown按 nonrepeatable 处理，禁止自动重放。未声明 effect contract 的第三方工具。
dispatch 已发生但 receipt 未持久化时，Runtime 不得自动再次调用。reconciler 通过外部查询、人工确认或 Program 专用逻辑，把 effect 标记为 committed、not_committed 或 compensated；完成前 continue、step、retry 和 fork 均拒绝。

12. 调整后续逻辑与从检查点分支

Steer：同 revision 的输入调整

补充约束、改变下一步优先级或提供新上下文。命令在 safe point 应用；如果会改变已完成 step contract，owner 拒绝并要求 fork。

Fork：新 revision 的结构调整

修改 workflow graph、后续代码、工具集合、model policy 或输出 schema。先暂停，选择 checkpoint，创建不可变 revision，再创建同一 run_id 下的新 child execution。

Fork 校验

  1. 源 checkpoint 已发布且没有 unresolved effect。
  2. 新 revision 声明 compatible_prefix：完成的 step_id、输入/输出 schema、effect contract 和依赖 hash。
  3. 一致的完成前缀可复用；受影响 step 从更早 checkpoint 重新执行。
  4. 新 execution 记录 parent、forked checkpoint 与新 revision；原 execution 保持 paused 或原 terminal。
  5. UI 同时显示两个分支，不把新结果写回原 execution。
未来可以增加源代码断点、条件断点、step in/out 和变量修改，但它们只能作为特定 Driver capability。基础协议的 identity、command、safe point、checkpoint 和 revision 边界不改变。

13. Runtime Control Service 与 Execution Driver

protocol ExecutionDriver:
    capabilities() -> CapabilitySet
    activate(attempt, activation) -> DriverHandle
    request_pause(handle, command_id) -> Ack
    request_cancel(handle, command_id) -> Ack
    inspect(handle) -> RuntimeSnapshot
    terminate(handle, reason) -> TerminationReceipt

runtime.arrive_safe_point(attempt_id, manifest_fragment, effect_receipts)
runtime.finish_attempt(attempt_id, outcome)

activation 是独立的 ActivationInput，包含原始、不可变且可验证的 CheckpointManifest，以及按 submitted_at, command_id 排序的 durable pending steer inputs。Driver 不得把 steer 临时写入 checkpoint 或修改 checkpoint 的 content_hash；后续 safe point 负责发布包含实际输入的下一份 checkpoint 和 applied receipt。

  • Control Service 唯一负责授权、状态 CAS、命令优先级、父子传播、fencing、recovery 和 terminal finalization。
  • Driver 负责执行类型特有的协作信号、checkpoint fragment、inspect 数据和受控 terminate。
  • Capability 包含 can_pause、can_step、can_steer、can_fork、safe-point kinds 和 state schema version。
  • Driver 不直接写 canonical status；projection failure 进入可重试 outbox。

14. Cancel 算法

01 · COMMIT

持久化 intent

授权 exact execution，按版本写 cancelling，关闭目标子树 admission gate，记录 reason。任何信号都不能早于此步。

Gate: durable command + canonical cancelling
02 · PROPAGATE

固定后代集合并传播

对非终态后代写 cancel intent；竞态创建的 child 因祖先 gate 关闭而拒绝 admission。

Gate: no child escapes the subtree
03 · COOPERATE

请求 owner 协作结束

中止 provider stream、取消 async task、解除 question/approval/resource wait，并通知所有 Driver。

Gate: every live owner receives one exact request
04 · ESCALATE

宽限后自动终止

对仍持有相同 fenced lease 的 owner 执行 terminate。用户不提交第二个命令，不传 force 或 timeout。

Gate: ownership rechecked immediately before terminate
05 · FINALIZE

控制面写唯一终态

完成 usage、resource、question、checkpoint 和 projection finalization。已 terminal child 保持原状态；因父级终止的 child 记录 parent_cancelled。

Gate: no active owner; terminal compare-and-set
cancel 不等于 rollback。已提交消息、文件 mutation、tool result、usage、checkpoint 和外部 receipt 保留。Program 可提交显式 compensation，但 cancel 本身不撤销历史。

15. Restart 与 owner 丢失恢复

  1. 启动时扫描所有非终态 Execution Record 和未完成 ControlCommand。
  2. 使旧 owner lease 过期并增加 fencing generation；旧进程迟到写入拒绝。
  3. queued 或 paused 若遗留尚未 activate 的 leased attempt，结束并 fencing 旧 attempt、清除 owner，同时保持逻辑状态，使新 owner 可以重新 lease。
  4. cancelling 继续 cancel finalization，不恢复业务逻辑。
  5. 任何状态存在 dispatched 或 uncertain effect 时先进入 reconciliation_required；checkpoint 不能覆盖该判断。
  6. pausing 在 effect 已解决且存在已发布 checkpoint 时转 paused；没有合法 checkpoint 时转 interrupted。
  7. paused 保持 paused，不自动创建 attempt。
  8. running 只有 Driver 可恢复、checkpoint 合法且无 uncertain effect 时创建新 attempt，否则 interrupted 或 reconciliation_required。
  9. 唯一 startup entrypoint 先完成 canonical recovery，再 reclaim outbox leases，最后由已有 consumer replay；没有 consumer 的项目保持 pending。
  10. projection outbox 重放到 DAG、Job、Workflow 和 UI；projection 不能反向覆盖 canonical record。
Question 和 approval 不依赖原进程内 Event 恢复。请求是 durable resource；continue 时新 attempt 重新订阅 unresolved request，cancel 时 Control Service 关闭它。

17. 权限、审计与资源

  • 服务端从 Execution Record 解析 session、owner、revision 和 process handle；客户端字段不能替代记录。
  • 未授权或跨租户 execution 返回统一 not found，避免泄露存在性、状态和输出。
  • command event 记录 actor、surface、reason、expected version、结果和 receipts，但不记录秘密、完整 prompt 或环境变量。
  • paused execution 默认释放 worker slot、GPU/CPU admission 和并发配额；只保留声明过的 durable storage 与外部 lease。
  • pause 期间 timeout、预算和外部租约是否继续由资源类型声明；UI 显示 policy，Runtime 不隐式补时。
  • 强制终止只针对 registry 解析的 fenced process group；不接受客户端 PID 或路径。

Session policy 与 Execution command 分离

attended 是 session 级 capability policy，不是 execution lifecycle。所有 surface 通过同一 session.policy.update 写持久 session metadata；新 execution 在 admission 时得到 policy snapshot。attended=false 表示工具目录不提供 ask/clarify 能力，但不能暂停、取消或改变已经运行的 execution。需要改变活动 execution 时，仍提交精确的 execution command。

三端同步使用同一规则：连接先读取 session、active execution 和 pending command 快照，再从 event cursor 继续；任何 surface 都不保存独立的 attended、running、paused 或 steering truth。

18. 一次切换的实施顺序

内部组件可以分片实现，但公开协议只在 canonical path 完整后切换。每个分片使用最终字段和命令名称，不引入待删除的中间 API。

SLICE 1 · CORE

Store、Command 与状态机

建立 events、materialized record、idempotency、CAS、run/execution/attempt/revision identity 和 projection outbox。

Exit: every legal and illegal transition is tested
SLICE 2 · OWNER

Driver、lease、safe point 与 checkpoint

先接 Chat/Agent 和 Job，建立 capability、fencing、manifest 原子发布和 effect ledger；不公开半成品 pause。

Exit: restart and stale-owner fault injection pass
SLICE 3 · CANCEL

把当前 cancellation 迁入统一命令

重实现 exact cancel、传播、wait wake、自动升级和 finalization；未合并分支只移植验证过的语义和测试，不整体合并旧结构。

Exit: every execution kind cancels through one service
SLICE 4 · CONTROL

Pause、Continue、Step 与 Steering

接入稳定 safe point；steering 从 session inbox 迁为 durable execution command；UI 只显示真实 capability。

Exit: pause/restart/continue and step pass without memory stack reuse
SLICE 5 · FORK
