agent 统一原语

编排层只有一个 LLM 原语：agent()。一次简单的模型调用是"无工具的 agent"这个特例， 不是第二个接口。runtime.exec 退回基础设施层（provider 传输、嵌入、测试）， 业务与编排代码不再直接使用它。本文定义 agent() 需要补齐的能力， 以及全部现存调用方的迁移路线。

1. 统一后的调用路径

2. agent() 补齐的四个能力

能力现状目标
单轮直通任何调用都建分支、走完整 turnprofile 无工具时：不建分支、不进循环， 直接一次模型调用；返回纯文本，不追加 [spawned agent …] 尾巴
逐调用覆盖模型/思考量只能由 agent_id 的 profile 决定新增可选参 model=、effort=：profile 给默认值，调用处可覆盖，对齐 runtime.exec 换模型的灵活性
多模态输入prompt 只收 str同时接受 content blocks （text/image 混排）。GUI harness 的定位调用每次都带截图，这是迁移的硬前提
可测试性调用方测试靠 fake Runtime提供注入缝：测试能替换 agent 的执行实现 （复用 scripted provider 路数），迁移后的模块测试不需要起真会话
不做的：并发调度器、批量接口、流式返回——现有调用方没有这些需求，出现了再说。

3. 迁移路线

四批，每批一个 codex 任务，测试全绿才进下一批。批内文件机械替换： runtime.exec(content=[…]) → agent(…)，函数签名里的 runtime: Runtime 参数随之删除，调用链同步收紧。

批范围说明
1openprogram/functions/tools/agent/补齐第 2 节四个能力，含单测。 在 self-programmed workflow 实现落地推送之后开工，避免同仓大改互踩。
2本体 agentics：deep_work、ask_user、 extract_pdf_figures、extract_pdf_tables、research/（六个 stage 文件）、 llm_call_example、interaction_demo约 15 个文件；对应单测同批适配。
3三个 harness 仓库，逐仓一个子任务：Research-Agent-Harness（约 80 个 stage 文件）→ GUI-Agent-Harness（planning / tasks / benchmarks，6 个）→ Wiki-Agent-Harness（2 个） 嵌套仓库随改随同步。GUI 的截图调用依赖批 1 的多模态输入。
4收尾全库确认编排层无 runtime.exec 残留；文档同步 （本页、各 harness 文档）；examples 与 provider 层明确保留 Runtime，不迁。

4. 边界与取舍

决定理由
统一在 agent()，不是消灭 Runtimeagent() 每轮说话 底下就是 Runtime，它是实现材料不是竞争接口；嵌入/测试场景要求无会话可跑。
简单调用的边界靠结构不靠约定多轮的燃料是工具；无工具 profile 想多跑也没有路径。 不需要"最多 N 轮"这类补丁参数。
每批全绿才进下一批批 2、3 是大面积机械替换，一旦批 1 的语义有错会成倍放大； 串行是最便宜的隔离。
examples 不迁它们演示的就是嵌入层（Runtime(call=mock_llm) 独立运行）， 迁了反而把这层能力的文档删掉了。
