第一部分 · OpenProgram 当前状态
当前有入站 Web 身份和 Origin/Host 校验，也有默认断网的本地命令沙箱；但 Runtime 自己发起的 HTTP 请求没有统一目标校验。 因此 Origin 校验不能作为 SSRF 证据，功能矩阵中的该项在实现前应为未确认，而不是部分确认。

02当前出站面与信任来源

SSRF 策略不能简单包住所有 HTTP 请求。OpenProgram 同时需要访问公网内容、用户明确配置的 localhost 服务和固定 loopback 回调；三类目标必须使用不同规则。

出站面URL 来源当前调用方式目标策略
web_fetch模型或用户直接提供urllib.request.urlopen；有 scheme、timeout 和大小限制，但自动重定向不逐跳检查非可信 URL：只允许公网，连接时约束地址并逐跳校验
渠道附件、远端媒体远端消息或渠道 API 返回值requests，允许服务端重定向非可信 URL：只允许公网，逐跳校验并限制响应体
skills discovery、plugin marketplace、MCP catalogowner 登记入口，后续链接和重定向由远端内容决定多个独立 httpx.AsyncClient混合来源：首个 origin 受配置约束，派生 URL 仍按非可信规则处理
provider、remote MCP、渠道和 TTS APIowner 配置的 service endpointSDK、httpx、requests受信服务：允许显式私网地址；携带凭据时禁止跨 origin 重定向
MCP OAuth redirectRuntime 生成固定 loopback listener内部回调：只允许精确 loopback host 与已分配端口
Playwright、Electron WebTab、agent_browser模型、用户、网页脚本或 CDP URL多个浏览器控制后端，不经过统一 Python client；普通导航没有目标策略归入“浏览器控制”条目单独验收；不能用 Runtime fetch 的完成状态代替
上游返回的 upload URL、generated asset已连接服务的响应内容requests 或 urllib 二次获取派生非可信 URL：固定服务 origin 或重新执行公网策略，不继承原请求凭据
shell、插件代码、外部安装器任意代码子进程或宿主进程内执行由 sandbox/插件信任边界约束；URL 字符串校验不构成代码执行的网络边界
当前判定：Runtime-owned 非可信 URL 获取没有统一防护。功能矩阵中的该行改名为 “Runtime URL 获取 SSRF 防护”并记为未确认；浏览器导航、CDP 和页面派生请求随现有“浏览器控制”条目单独设计；模型命令的网络隔离继续归入“操作系统级沙箱”。
第二部分 · 其他项目怎么设计
参考对象选择 Hermes、OpenClaw 与 OWASP。Hermes提供统一 URL safety 和多入口覆盖；OpenClaw明确区分应用层拦截与网络层边界；OWASP给出受信服务 allowlist 与任意公网访问两种不同模型。

03参考机制比较

对象已采用机制仍有限制对 OpenProgram 的用途
Hermes共享 url_safety；覆盖 web、browser、vision、gateway media；DNS 失败默认拒绝；阻止 loopback、RFC1918、link-local、CGNAT、metadata、reserved、multicast 和 unspecified；逐跳检查重定向；日志 URL 去凭据；媒体流式限额提供进程级 allow_private_urls 开关，开启后多个入口同时放宽；应用内检查仍不能代替 OS 网络隔离采用共享校验、fail-closed、地址全集、逐跳检查、脱敏和大小限制；把全局开关改为按 service origin 的精确例外
OpenClawprivate/internal/special-use 默认拒绝；hostname 精确或通配例外；导航前、交互产生的加载和最终 URL 多阶段检查；明确记录 speculative navigation 与 browser 子资源风险官方文档明确请求拦截不是网络防火墙，redirect、popup、Service Worker 和后台资源仍可能绕过；完整预防依赖 egress isolation 或策略代理采用严格默认和显式例外；保留“应用层不等于网络边界”的声明；浏览器能力不并入 Runtime fetch 的完成结论
OWASP区分“只访问已知服务”和“允许任意公网目标”；限制协议；校验所有 A/AAAA 结果；受信服务优先 allowlist；建议网络层共同限制单次 DNS 预检本身仍存在 DNS pinning/TOCTOU 风险采用两类策略模型；在连接阶段再次约束实际地址，不把预检结果作为唯一边界

来源： Hermes url_safety.py、 Hermes Security、 OpenClaw Security、 OWASP SSRF Prevention。

04采用、修改与拒绝

结论机制原因
采用一个纯 URL/IP policy 模块；所有 A/AAAA 结果必须通过；DNS 失败即拒绝；重定向逐跳验证；流式大小上限；日志脱敏覆盖公共绕过方式，并使所有 Runtime fetch 使用相同判定
采用受信 service origin 与任意公网 URL 使用不同策略保留 localhost provider、内网 MCP 和企业代理等明确配置能力，同时不允许模型自行扩大信任范围
修改Hermes 的全局 allow_private_urls改为 owner 配置中的精确 scheme/host/port 或 CIDR 例外；例外只作用于指定 consumer，不全局放宽
修改OpenClaw 的 browser 请求拦截浏览器单独验收；Runtime HTTP 完成不能覆盖浏览器的 popup、Service Worker 和后台资源
拒绝只检查 URL 字符串或只在请求前调用一次 DNS无法处理重定向和 DNS rebinding，不能作为完整状态依据
拒绝把 Origin/Host、CORS 或入站 owner auth 计入 SSRF 完成度保护方向不同
拒绝把所有 HTTP 客户端强行套用公网-only 规则会破坏用户明确配置的本地模型、MCP 和内网服务
第三部分 · OpenProgram 后续完整方案
目标不是增加一个 URL 检查函数，而是让每个 Runtime-owned 出站入口带上来源类型，经统一策略决定目标、重定向、凭据和响应限制；无法进入统一边界的入口不能计为完成。

05.1 模块边界

模块责任不负责
openprogram/security/url_policy.pyURL 规范化、scheme/userinfo/host/port 校验；ipaddress 分类；A/AAAA 全结果判断；scope 精确例外；稳定 reason code；安全日志表示不发送网络请求，不读取调用者业务配置
openprogram/security/safe_http.py同步和异步受管 client；手动 redirect；连接阶段地址约束；跨 origin 凭据剥离/拒绝；流式读取上限；timeout不决定某个 URL 属于哪个信任来源

doctor 与审计日志列出未迁移 consumer、危险例外、代理委托和最近拒绝原因；URL 只保留 scheme/host/port 与截断路径不显示 userinfo、query、fragment、authorization header 或 token path

05.2 四类策略

  • 非可信公网 URL：只允许 HTTP/HTTPS；禁止 userinfo；所有解析地址必须是公网 global unicast；禁止 loopback、private、link-local、CGNAT、multicast、reserved、unspecified、documentation/test range 和云 metadata host；默认不继承环境代理；每次 redirect 重新执行完整策略。
  • 固定公网服务：目标来自随版本发布并经审计的常量；仍校验公网地址和连接结果；变更 origin 必须修改声明清单；凭据不随跨 origin redirect 发送。
  • 用户配置服务：owner 保存配置时固定 scheme、规范化 host 和有效 port；允许显式 localhost/私网；携带 credential 的请求只发送到该 origin；跨 origin redirect 默认拒绝，不能把 authorization、cookie 或 URL credential 转发到新目标。
  • 内部回调：只允许 Runtime 当前分配的 loopback IP 与端口；不接受 hostname 通配、私网 CIDR 或 redirect。

05.3 DNS rebinding 与代理

非可信公网请求不能采用“校验一次域名后让普通 client 再解析”的流程。受管 transport 在建立 TCP 连接时解析并检查地址，然后连接到同一已检查地址；TLS SNI 和证书验证仍使用原 hostname。连接池按规范化 origin 与 policy scope 隔离，不能在不同信任策略间复用。

非可信 URL 默认设置 trust_env=false。若 owner 选择策略代理，配置必须声明该代理承担 DNS 与目标地址强制责任；此时 doctor 显示“策略委托给代理”，实现测试必须证明请求不会绕过代理直连。普通 provider proxy 配置不能自动扩大非可信 URL 的网络权限。

05.4 迁移范围

第一批必须同时迁移 web_fetch、渠道附件、skills discovery、plugin marketplace、MCP catalog、generated asset 和所有 Runtime-owned 任意 URL 下载入口。provider、remote MCP、渠道与 TTS 的固定 endpoint 接入 configured-service 校验，重点阻止带凭据的跨 origin redirect。浏览器导航留在“浏览器控制”功能项；shell 和第三方插件继续由 sandbox 与插件信任模型负责。

06何时可以从未确认改为完整确认

验收组必须通过的行为
地址分类IPv4、IPv6、IPv4-mapped IPv6、IDNA、大小写与尾点 hostname、异常端口、userinfo、十进制/八进制/十六进制混淆输入均得到固定结果；所有非 global 地址默认拒绝
DNSNXDOMAIN、timeout、空结果、A/AAAA 混合公私地址全部 fail-closed；连接使用已验证结果，测试用改变两次解析结果证明不能 rebind 到 loopback
重定向相对与绝对 Location、协议切换、跨 origin、redirect loop 和超限均有测试；任一跳转到 metadata/私网均在发送下一跳请求前拒绝
凭据configured service 的 token、Authorization、Cookie 和 URL credential 不会发送到其他 origin；异常和审计日志不含秘密
资源限制连接、首字节、整体读取和空闲 timeout 有界；Content-Length 缺失或造假时仍按流式累计上限终止；临时文件失败后清理
入口覆盖web_fetch、附件、skills、plugin marketplace、MCP catalog、generated asset 与任意 URL 下载均有真实调用链测试；静态检查阻止这些目录新增裸 requests/httpx/urllib 调用
兼容性公网 CDN、GitHub、Telegram 附件、本地 provider、localhost MCP、企业内网 service 和显式策略代理分别通过；既有 proxy 与 provider failover 测试不回归
边界说明doctor 能显示 scope 例外和未迁移 consumer；文档明确 Runtime fetch、browser、sandbox、plugin 四个边界，不把一个边界的测试替代另一个
状态门槛：只有上述各组测试、完整单元测试和至少一次真实 loopback 拒绝集成测试全部通过，且入口清单没有未分类项时，“Runtime URL 获取 SSRF 防护”才能标记为 ●。设计完成、存在纯校验函数或只迁移一个调用者都不能标为 ◐。
