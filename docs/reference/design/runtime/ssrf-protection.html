Part I · 现状
OpenProgram 当前状态

当前有入站 Web 身份和 Origin/Host 校验，也有默认断网的本地命令沙箱；但 Runtime 自己发起的 HTTP 请求没有统一目标校验。 因此 Origin 校验不能作为 SSRF 证据，功能矩阵中的该项在实现前应为未确认，而不是部分确认。

04采用、修改与拒绝

结论机制原因
采用一个纯 URL/IP policy 模块；所有 A/AAAA 结果必须通过；DNS 失败即拒绝；重定向逐跳验证；流式大小上限；日志脱敏覆盖公共绕过方式，并使所有 Runtime fetch 使用相同判定
采用受信 service origin 与任意公网 URL 使用不同策略保留 localhost provider、内网 MCP 和企业代理等明确配置能力，同时不允许模型自行扩大信任范围
采用Claude Code / CodeBuddy 的工具权限与网络限制分层，Codex 的结构化 deny reason 与受管策略权限回答“谁能请求什么”，transport 回答“实际连接到哪里”；两者必须分别记录和验收
采用CodeBuddy 对固定渠道媒体使用官方服务域名 allowlist 并禁用 redirect固定服务资源不需要接受任意公网 URL；比通用公网规则更窄
修改Hermes 的全局 allow_private_urls改为 owner 配置中的精确 scheme/host/port 或 CIDR 例外；例外只作用于指定 consumer，不全局放宽
修改OpenClaw 的 browser 请求拦截浏览器单独验收；Runtime HTTP 完成不能覆盖浏览器的 popup、Service Worker 和后台资源
修改Codex 的全进程 egress proxy作为 sandbox、插件和 shell 的后续网络层；本功能先保证 Runtime-owned HTTP 全部经 safe client，不把代理部署设为单机基础功能的前置条件
拒绝只检查 URL 字符串或只在请求前调用一次 DNS无法处理重定向和 DNS rebinding，不能作为完整状态依据
拒绝只要求用户确认，或只配置 hostname allow/deny确认与域名权限不校验实际连接 IP；不能替代 DNS 全结果、连接约束和逐跳 redirect
拒绝把 Origin/Host、CORS 或入站 owner auth 计入 SSRF 完成度保护方向不同
拒绝把所有 HTTP 客户端强行套用公网-only 规则会破坏用户明确配置的本地模型、MCP 和内网服务
Part III · 计划
OpenProgram 后续完整方案

目标不是增加一个 URL 检查函数，而是让每个 Runtime-owned 出站入口带上来源类型，经统一策略决定目标、重定向、凭据和响应限制；无法进入统一边界的入口不能计为完成。

05.1 模块边界

模块责任不负责
openprogram/security/url_policy.pyURL 规范化、scheme/userinfo/host/port 校验；ipaddress 分类；A/AAAA 全结果判断；scope 精确例外；稳定 reason code；安全日志表示不发送网络请求，不读取调用者业务配置

05.2 四类策略

  • 非可信公网 URL：只允许 HTTP/HTTPS、GET/HEAD 与 80/443 端口；consumer 如需其他端口必须在 registry 中逐项声明；禁止 userinfo、请求凭据和调用者 Cookie；所有解析地址必须是公网 global unicast；禁止 loopback、private、link-local、CGNAT、multicast、reserved、unspecified、documentation/test range 和云 metadata host；默认不继承环境代理；每次 redirect 重新执行完整策略。
  • 固定公网服务：目标来自随版本发布并经审计的常量；仍校验公网地址和连接结果；变更 origin 必须修改声明清单；凭据不随跨 origin redirect 发送。
  • 用户配置服务：owner 保存配置时固定 scheme、规范化 host 和有效 port；允许显式 localhost/私网；携带 credential 的请求只发送到该 origin；跨 origin redirect 默认拒绝，不能把 authorization、cookie 或 URL credential 转发到新目标。
  • 内部回调：只允许 Runtime 当前分配的 loopback IP 与端口；不接受 hostname 通配、私网 CIDR 或 redirect。

05.3 DNS rebinding 与代理

非可信公网请求不能采用“校验一次域名后让普通 client 再解析”的流程。受管 transport 在建立 TCP 连接时解析并检查地址，然后连接到同一已检查地址；TLS SNI 和证书验证仍使用原 hostname。连接池按规范化 origin 与 policy scope 隔离，不能在不同信任策略间复用。

非可信 URL 默认设置 trust_env=false。若 owner 选择策略代理，配置必须声明该代理承担 DNS 与目标地址强制责任；此时 doctor 显示“策略委托给代理”，实现测试必须证明请求不会绕过代理直连。普通 provider proxy 配置不能自动扩大非可信 URL 的网络权限。

05.4 各 HTTP 栈的确定实现方式

场景实现决定验收条件
同步与异步直连safe_http 基于现有 httpx/httpcore 实现同步和异步 transport；每个 redirect hop 创建绑定本次 policy decision 的连接上下文。自定义 network backend 只连接 policy 返回的已验证 IP，HTTP Host、TLS SNI 与证书验证继续使用规范化原 hostname测试记录 resolver 结果、实际 socket peer、Host 与 SNI；四者不一致即失败。不得采用把 URL host 改成 IP 后关闭证书验证的做法
requests、urllib 调用者consumer adapter 改调 safe_http，不为两个旧 client 各写一套安全 hook；自动 redirect 关闭，由 safe_http 统一处理迁移目录静态检查不再出现裸网络调用；行为测试覆盖原调用链，而不只测试 policy 函数
连接池与重试连接池 key 至少包含规范化 origin、policy scope、consumer 与 proxy mode；只在已验证 IP 集合仍有效时复用。连接失败只能在同一批已验证 IP 中重试，重新解析后必须生成新 decision不同 consumer、不同私网例外和直连/代理请求不能复用同一连接；retry 不得转向未验证地址
显式策略代理非可信 URL 只接受 owner 配置的 policy proxy，禁止读取环境代理。Runtime 只能连接该代理 origin；HTTPS CONNECT 目标、DNS 与 private-address 拒绝由代理强制，凭据与目标策略仍由 safe_http 控制集成测试证明直连不可达、代理能拒绝 hostname 指向私网及跨 origin 凭据；未声明 enforcement capability 的普通代理不能用于非可信 URL

05.5 第三方 SDK 不能替换 transport 时的处理

SDK 能力处理是否允许计入完整
支持注入 http_client、transport 或 fetch callback注入 safe_http adapter，并固定 consumer 与 policy scope有真实 SDK 调用链测试后可以
只接受 base_url，但仅访问 owner 配置的固定 API归入 configured_service；启动时校验 exact origin，禁用跨 origin redirect；若 SDK 无法禁用 redirect，则必须经策略代理证明目标和凭据不能离开 exact origin 后可以
SDK 会根据远端内容继续获取任意 URL，且不能注入 transport把派生下载移到 SDK 外由 safe_http 执行；无法拆分时，只能把 SDK 进程放入强制策略代理或关闭该入口仍可活动且没有等价网络边界时不可以
SDK 绕过代理、使用自有 socket 或行为无法验证默认禁用相应 URL consumer，并由 doctor 报告 unmanaged_transport不可以；不得写成“由 SDK 保证”

05.6 迁移范围与覆盖清单

第一批必须同时迁移 web_fetch、渠道附件、skills discovery、plugin marketplace、MCP catalog、generated asset 和所有 Runtime-owned 任意 URL 下载入口。provider、remote MCP、渠道与 TTS 的固定 endpoint 接入 configured-service 校验，重点阻止带凭据的跨 origin redirect。浏览器导航留在“浏览器控制”功能项；shell 和第三方插件继续由 sandbox 与插件信任模型负责。

safe_http 内维护唯一的 consumer registry：每个 consumer 固定声明来源类型、允许 scheme、redirect 规则、响应上限、content type、credential policy 与 owner 例外范围。调用者必须传 registry key，不能传临时 policy 对象。doctor 和测试从同一 registry 生成覆盖清单；仓库中发现 Runtime-owned 网络调用而 registry 没有对应项时，验收直接失败。

06何时可以从未确认改为完整确认

验收组必须通过的行为
地址分类IPv4、IPv6、IPv4-mapped IPv6、zone ID、IDNA、大小写与尾点 hostname、反斜线与控制字符、异常端口、userinfo、十进制/八进制/十六进制混淆输入均得到固定结果；所有非 global 地址默认拒绝；非可信 URL 默认只允许 GET/HEAD 与 80/443
DNSNXDOMAIN、timeout、空结果、A/AAAA 混合公私地址全部 fail-closed；连接使用已验证结果，测试用改变两次解析结果证明不能 rebind 到 loopback
