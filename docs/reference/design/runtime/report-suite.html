三个周报 Workflow 与 report 总入口

面向开发与验收。目标是可独立运行、可组合、可恢复的代码 Workflow。腾讯周报在每周五下午整理约 100 字进度，个人周报维护飞书记录，小组周报只读微信并生成汇总。实现已通过代码审查与隔离测试；已安装版本的总入口、部分完成状态和恢复行为已验证；微信真实消息读取仍未完成。

公开入口

入口输入与结果外部写入
weekly_report(task)保留个人报告查看、草稿、新建与修改能力；明确成员、周次与字段。只有明确提交或修改请求才执行，并核验持久化结果。
group_weekly_report(task)明确群、成员顺序、周次；查找、来源索引、缺失覆盖、汇总与恢复。仅保存本地稿件，任何分支不发微信。
tencent_weekly_report(task)本周腾讯工作证据、成果、阻碍和下一步；默认目标 100 字，验收范围 80–120 字。信息不足时明确等待，不补造结果。生成给 leader 的本地稿件，不自动发送。
report(task)显式选择 personal/group/tencent 或多个目标；代码调用对应子 Workflow，保存每项结果与恢复信息。默认生成草稿；多报告组合不得隐式继承个人提交授权。

样例与验收

  1. “整理腾讯本周进度”：只选择腾讯来源，围绕完成内容与结果压缩，保持未完成、计划和风险的原意。成功时输出汇报正文，字数与来源索引保存在本地。
  2. “整理这周三个周报”：分别准备三类请求；小组微信不可访问时仍可完成有材料的其他两份，总结果列明每个状态。
  3. “继续小组汇总”：只恢复小组检查点，其他已完成报告不重新生成或重复提交。
  4. “提交个人周报”：先查是否存在，保留未修改字段；远端写入结果不确定时停止自动重试。
  5. 腾讯材料不足或不属于本周：请求所缺信息；不从小组私人消息或个人科研记录推断腾讯工作。
  6. 自然语言路由不明确：一次有界模型解释或向用户澄清；显式结构化路由不调用模型。
  7. 周五下午：使用 Asia/Shanghai 周次和执行语义；精确时刻、接收渠道未配置时不擅自启动定时发送。
  8. 来源、模型、保存或访问失败：由 Workflow 返回明确状态、原因和可恢复参数；外部助手临时补稿不计验收。

自然语言使用与正文输出

用户请求整理本周腾讯汇报时，流程先读取当前明确提供的材料；材料不足时检索 OpenProgram memory 与已有个人、腾讯周报，保留来源和周次。明确腾讯证据优先；个人报告和日期明确的 memory 片段由模型选择相关原文，代码验证引用。检索限制文件数量、深度、字节数与上下文大小，读取前检查访问权限。历史记录用于确定研究主题与写法，只有本周证据进入成果正文；日期或归属不明确的记录不自动当作本周事实。检索与写作分阶段保存上下文，不要求用户重复整理已经存在的材料。面向用户的成功结果只显示汇报正文，组合流程使用结构化结果继续路由；来源、字数、核验和恢复参数保存在本地执行记录。

模型生成和核验使用独立、有界调用。框架 LLMError 与普通运行异常均转换成可恢复状态，失败调用消耗预算，恢复不重置预算。腾讯短文本生成采用低推理强度并允许有界执行时限；模型失败不能冒充成功稿件。

代码管理上下文

各子 Workflow 自己持有按周次、成员和受众划分的证据。总入口只持有请求、子任务状态、结果引用和恢复令牌，不把三类材料合成一个无差别模型上下文。模型只负责必要的语言解释、归纳与压缩；路由枚举、预算、来源范围、字数、检查点和外部写入状态由代码管理。恢复记录必须校验版本与输入范围。

实现顺序与证据

先核验现有独立包并恢复必要共享依赖，再完成三个子流程和总路由、公开入口失败复现与回归测试。随后执行独立规格审查和质量审查；最终运行包隔离测试、相关组件和集成测试、仓库契约、静态与文档检查，正式发布并更新本地 App。微信真实成功读取与问题卡片显示单独记录，不用假接口测试替代。

微信窗口读取

微信的自绘消息界面不提供可用的辅助功能消息行。读取器在精确辅助功能读取不可用时，使用 GUI Harness 的窗口截图文字识别。代码将目标限定为微信的单一主窗口。多个同名应用进程并存时，只选择唯一具有符合标题和尺寸条件主窗口的进程；不存在进程返回 APP_NOT_RUNNING，无法唯一选择返回 APP_NOT_UNIQUE。多进程状态不按 bundle 重新打开应用，避免激活另一个实例。读取器只允许定位搜索框、输入单行群名、选择核验后的群结果和在消息区域翻阅。每次读取重新核验窗口身份和群标题；不提供消息编辑、发送或任意键盘接口。截图文字识别用于定位搜索位置，键盘输入前仍须通过原生接口核验搜索焦点；微信不提供该接口时，返回 SEARCH_FOCUS_UNVERIFIABLE 并等待用户打开目标群。窗口截图由 ScreenCaptureKit 的实际权限与可用窗口结果判断；不把旧的窗口 sharingType 字段当作当前权限，不切换到全屏截图。原始截图和 OCR 行以本地来源引用保存，消息作者必须属于指定名单，日期必须来自可核验的页面标记；缺少、截断或不明确的来源保留为未核实。完整历史覆盖不由模型推断。

窗口读取补充已通过独立规格和质量审查，尚未完成真实群消息读取验收。已安装版本的 SEARCH_UNAVAILABLE 只证明恢复状态，不证明微信读取成功。

Apple 将 NSWindow.SharingType.none 标为系统不再使用的旧常量。窗口读取因此使用 ScreenCaptureKit 的实际调用结果，同时保留 PID、窗口身份、群标题、来源和消息归属校验。旧字段判断已移除；真实窗口调用仍返回 CAPTURE_CONTENT_UNAVAILABLE，微信消息读取尚未完成，不能把腾讯汇报成功视为小组消息收集成功。

当前实现与验收状态

自动检索、正文输出与真实 LLMError 恢复通过独立审查和完整测试。安装后的腾讯入口和 report 总入口均以“整理本周腾讯周报”完成自动取材、真实模型生成与核验，并直接显示正文。恢复检查确认已完成子报告不重复生成；微信真实消息读取仍未完成。

三个子 Workflow 和 report 总入口均有独立 Git 包。共享 report_io 与 report_wechat 已合入主线，四个独立包已发布到本地目录，默认 App 已更新。独立规格和质量审查已通过；既有正式包的隔离测试、相关组件、仓库契约、静态及文档检查已通过。安装后的公开入口验证腾讯测试材料保存为 100 字、缺少个人材料返回 NEEDS_INPUT、小组读取返回 SEARCH_UNAVAILABLE，恢复时不重复生成已完成的腾讯稿件。App 的 Abilities 页面可选择 report，执行后显示子流程状态。测试材料仅用于验收，不是用户真实工作进展。微信成功读取仍待验证。
