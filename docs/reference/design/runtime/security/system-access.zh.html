统一系统访问

宿主能力边界，独立于模型工具审批、工作区权限规则、账号凭据和 provider 授权。读取状态绝不弹出系统提示。模型或远程客户端不能授予操作系统能力。

状态含义

接口作用
GET /api/system/access报告（schema 2）：平台、主机、执行身份、时间戳，每行含 id、类别、状态、详情、说明、请求方式、设置可用性、操作、恢复元数据
GET /api/system/access/waits未结束的等待，id 和 schema 相同
POST /api/system/access/setup仅限所有者和回环地址。请求所有已注册的原生 runtime 能力，返回一份合并报告
POST /api/system/access/guide仅限所有者和回环地址。请求体 {"capabilities": [id, ...]}。在后台按顺序处理每个缺失项：对话框类能力弹 macOS 自己的对话框，列表类能力打开对应面板并显示拖拽引导。返回 {"ok": true, "started": [ids]}；非 macOS 时 started 为空；未知 id 返回 400
POST /api/system/access/{id}单行：重新检查，可选原生请求，返回新行。open_settings=true 只打开目标（列表类能力带拖拽引导），绝不声称已授权

响应禁止缓存，不含机密。前两行保持旧的 screen_recording 和 accessibility 线路格式；旧回执按旧格式读取。未知 id 是客户端错误，什么也不打开。权限规则、Auto 模式、profile、Worker 和端口不受影响。

首次设置和操作

  1. Web 设置按产品领域显示注册表、每项用途，每次加载页面做一次只读检查。
  2. 用户选择“Set up all OpenProgram access”，或某行的“Request authorization”/“Open System Settings”。页面挂载、重连、轮询、历史回放和模型输出都不会发请求；唯一的自动动作是工具等待打开时的设置引导。
  3. 后端按执行者串行化原生请求，用指定 runtime 请求后重新检查。macOS 仍可能弹多个对话框，UI 逐项报告结果。
  4. 操作前 Worker 做一次新报告，只为缺失的必需能力创建持久的 system_access 等待。调用需要哪项操作由工具回答：computer_use 由目标的 provider 回答，经运行时用 register_operation_source 装入的来源，所以宿主不点名任何目标。列出应用或显示器、浏览器目标和其他机器都不需要。
  5. 回到应用触发只读刷新。授权后等待经 Worker 对账解除，同一执行从检查点继续：没有伪造回答、重试或新执行。
轮次中报告
已确认授权的能力后续步骤不再报告；一次报告要启动进程，约 0.4 秒
有能力缺失每步都报告，授权后立刻看到
轮次中撤销授权桌面后端让该步失败并指出设置项，下一轮重新报告
没人能回应等待调用以 PERMISSION_MISSING: 失败，写明缺哪些授权、去哪里授予，模型可以转告用户

系统设置引导

屏幕录制和辅助功能（注册表标记 settings_list，行字段 settings_guide）没有能授权的对话框：授权是系统设置里应用列表中的一个开关，只打开面板会让用户自己找条目。

OpenAI 的 Codex Computer Use 用一个贴在系统设置窗口上的小辅助窗口解决这个问题（其类名 SystemSettingsAccessoryWindow、DraggableApplicationView、DragHintView）。OpenProgram 照搬这一做法。

部分行为
面板打开确切的隐私面板（Privacy_ScreenCapture、Privacy_Accessibility）
窗口无边框、不激活的浮动面板，居中贴在系统设置窗口下方；屏幕下方没有空间时盖在窗口底边上。每 0.2 秒跟随窗口移动，窗口不在屏幕上时隐藏。用 CGWindowListCopyWindowInfo 按 com.apple.systempreferences 的 pid 找系统设置窗口
图标runtime 应用的图标，是一个 NSDraggingSource，把应用的文件 URL 拖进列表。第二行提示：应用已在列表里就打开开关
身份一个短命的辅助进程，用 worker 运行的同一个可执行文件启动（openprogram.host.system_access.guide），所以它给出的图标和它检查的授权都属于 macOS 授权的那个身份
关闭授权后（每 1.5 秒重新检查）、点 ×、系统设置关闭、或 10 分钟后。授权后开始这一批中下一个缺失项；其他方式关闭则结束这一批
批次同时只有一个引导；新的请求替换正在运行的。对话框类能力（日历、提醒事项、麦克风、摄像头）保留 macOS 自己的对话框，没有引导

显式流程使用它：POST /api/system/access/guide、open_settings=true 和“Set up all OpenProgram access”。工具的 system_access 等待打开时，引导自动启动，每个等待一次，从第一个缺失的列表类能力开始依次处理；任务停在持久等待上，对账看到授权后恢复。

引导只打开页面和窗口，从不请求或声称授权。

身份和恢复

  • macOS 的检查和请求都经已签名的 runtime bundle ai.openprogram.runtime。源码检出可回落到开发解释器。已安装的 App 绝不注册裸 python3；匿名的 python3、node 和过期缓存路径都不是身份。
  • 读取状态、启动对账、重试和重复事件都不运行 tccutil，也不重置其他应用。
  • 经验证的过期回执可授权一次针对固定 OpenProgram bundle 身份的显式迁移；系统调用前写入的标记防止循环。其他情况（未验证代码、未知检查、要求未变、辅助功能迁移、其他应用）都走系统设置。
  • 产品不能预先授权从未作为目标的应用、从未选择的路径或已撤销的权限。绝不推断完全磁盘访问，也不把它当绕过手段请求。
  • Linux portal 和 Windows 完整性规则保持平台专属。浏览器目标和其他机器用自己的 provider 或 session 边界。

信任和并发

  • 只有执行主机上的本地所有者能请求或打开设置。回环和 Origin 检查必须通过，转发请求和远程客户端被拒绝。模型可以描述缺失的能力，不能调用设置接口。
  • 探测在新的有界进程中运行，每轮对账共用一份报告，不枚举屏幕内容。
  • 等待解除由执行 id、代次、检查点版本和取消状态把关。探测失败时等待保持打开；已终止或已取消的执行不能恢复。

验收
  • 报告、请求、设置、等待、标签和包声明都来自同一注册表，一致性测试在漂移时失败。
  • 重复报告、重连、回放和模型输出不产生提示。已授权行不产生请求。
  • 缺少桌面能力的 GUI 任务在规划前暂停，两项都授权后同一执行恰好恢复一次，不使用提问或审批 API。
  • unknown、unavailable、unsupported 和拒绝分开显示。可选项失败不影响安装或聊天的健康状态。
  • 已安装的 /Applications/OpenProgram.app 确认执行者身份、当前授权、设置动作，且没有 Python 或 Node 身份迁移。
  • 自动化：注册表、探测和请求路由、等待恢复、Web 渲染、不自动请求。
