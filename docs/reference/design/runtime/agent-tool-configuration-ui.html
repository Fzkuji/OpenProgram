Agent Programs 配置：与实体目录分开

本页是完整Agent配置框架中的Programs下钻设计。Programs回答“系统中存在哪些可调用实体”；Agents回答“某个Agent允许发现和调用哪些实体”。页面与数据归属分开，实际调用仍使用同一套AgentTool registry、resolver和executor。

1. 页面与数据边界

Programs · entity catalog

管理实体

Functions、Agentic Functions和Applications是系统中的可调用对象。

  • 源码、export、schema、Git状态和测试
  • 静态Calls / Used by关系
  • 安装、编辑、收藏、运行和删除
Agents · configuration

管理使用策略

Agent配置决定模型、指令、Skills、MCP及允许访问的Programs。

  • 默认访问模式和可复用Access preset
  • 允许、排除和全局不可用项
  • 首轮上下文与按需发现策略
不复制实体：Agent配置只保存工具访问意图或工具名引用，不复制Program schema、description、Python源码或Workflow仓库。删除或禁用Program后，所有Agent在下一次解析时得到一致结果。

2. Agents 配置页面原型

主页面只承担Agent选择、配置分页、访问模式和当前范围摘要。外层页面复用现有Web管理页与Settings结构，不另建Agent专用窗口；全局标题栏只放页面级操作，配置分页位于选中Agent的详情标题下。页面字体直接使用Web全局--fs-base/--fs-sm层级，不从缩放原型复制8–12px的局部字号。工具目录是一个按需打开的选择器，不随Agent详情常驻渲染；新增Agent由共享管理页标题栏提供。

5. 验收合同

  • Programs页不显示User Profile、Access preset、Agent允许/禁止状态或会话override。
  • Agents页可以创建Agent、选择Agent并保存其Tools & Programs策略；同一Program实体不会被复制进Agent配置。
  • Agent详情主页面不直接渲染完整Program目录，只显示访问模式、数量、preset和摘要。
  • 点击Browse programs后才打开选择器；选择器支持搜索、来源过滤、分类折叠和具体条目勾选。
  • 关闭选择器后，主页面保持同一滚动位置，不因Program数量增加而增长。
  • 默认聊天Agent不会把全部Workflow名称、描述、schema或源码写进首轮上下文。
  • 选择Access preset后，tool_search、显式名称加载和真正调用都受同一允许集合限制。
  • 会话Tools菜单默认显示“Use Agent configuration”；临时修改不反写Agent。
  • 全局禁用或删除Program后，所有Agent无需迁移配置即可在下一轮得到一致的不可用结果。
  • Function、Agentic Function和Application最终都进入现有统一AgentTool执行路径。

6. 实现范围与验证记录

本轮直接复用AgentSpec、现有Tool Profile存储、resolve_tools()与AgentTool executor；页面层直接复用ManagePageHeader、ManageRow、共享分栏和Settings详情容器。新增内容只保留Agent专属配置表单与Programs / Skills / MCP按需选择器，没有增加第二套页面窗口或执行语义。
