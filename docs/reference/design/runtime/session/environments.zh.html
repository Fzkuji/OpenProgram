运行环境

对话的 Shell 和文件在哪台机器上由项目决定：项目是某台机器上的一个文件夹，项目里的每个对话都在那里运行。

本页讲由此决定了什么。机器本身（每台只有一种连接方式）是一份注册表，设计见机器与目标。channel（微信、Telegram 等）只决定消息镜像到哪里。产品页：在另一台机器上运行会话。

Shell 类型后端命令形式工作文件夹本机沙箱
localLocalBackend本机子进程。macOS 和 Linux：bash -c，沙箱内外相同（没有 bash 才用 sh），所以 echo 原样输出 \n，printf 才展开；定时任务的命令同样这样运行。Windows：Git Bash 或 PowerShell，沙箱内是 WSL 的 bash本机生效
sshSshBackend(target, workdir)ssh … <target> 'cd <dir> && <cmd>'远程绝对路径关闭；隔离靠远程账户
dockerDockerBackend(image, container, mounts, labels)docker exec -i [-w cwd] <container> sh -c <cmd>本机路径，以相同路径挂载关闭；隔离靠容器

命令功能在 SHELLS（openprogram/host/backend/__init__.py）里对应能跑命令的连接方式：local、ssh、docker，各带 backend；Docker 另有 instance_scope="conversation" 和 remove_instances。同一模块向设备层登记 ssh 和 docker 两种方式（设置 schema、check）。backend_for(machine, session_id) 按机器的连接方式构造后端，不点名任何方式。

轮次绑定

TurnBindings.bind 设置 _current_environment ContextVar。current_environment() 先读它，再读当前 session 项目的机器，没有 session 时是这台电脑。get_active_backend() 据此和当前 session 构造后端。

Shell 不在这台电脑时，<environment> 块写明机器 id、名称和它的连接方式的描述，并说明对话本身和 OpenProgram 仍在这台电脑；提供 computer_use 时再说明不带 device 的调用作用于这台电脑。

  • 带 remote_files 的 Shell（SSH）：worktree ContextVar 是项目在主机上的文件夹（remote_project_folder），命令从那里开始，权限围栏也按它检查。打开项目时文件夹已在主机上转成绝对路径（cd 后 pwd -P）。
  • remote_workdir 即机器的远程文件夹设置，只是浏览项目文件夹时的起点。相对工具路径用 posixpath 拼接，不碰本机文件系统。
SSH 命令选项 
ssh -o BatchMode=yes -o StrictHostKeyChecking=accept-new
    -o ControlMaster=auto -o ControlPath=<state>/ssh/%C -o ControlPersist=300
    <target> 'cd <dir> && <cmd>'
  • 连接共享让首次之后每次工具调用只需一个往返。
  • %C 对主机、端口、用户取哈希，socket 路径不超过 macOS sun_path 上限。Windows 跳过 ControlMaster。
  • 文件夹开头的 ~ 不加引号传到远程 shell，在那里展开。
Docker 容器生命周期
  • 对话的实例：一个长期容器，container_name = openprogram-<machine>-<conversation>（[a-zA-Z0-9_.-] 以外的字符变为 -，最多 120 个），带标签 openprogram.machine、openprogram.conversation 和 openprogram.home（状态目录的摘要，两套安装共用一个 Docker 时据此分清各自的容器），用 docker run -d --init … tail -f /dev/null 启动。
  • 工作文件夹、项目文件夹和附加工作目录以相同路径绑定挂载，第一个挂载是起始文件夹。
  • 镜像加挂载的哈希存为 openprogram.mounts 标签。变了就删除重建，相同就重新启动已停止的容器。进程内缓存让首条命令后跳过 docker inspect；启动进程时不信任这个缓存，每次都检查容器。
  • 守护进程因容器已不存在（“No such container”）或已停止（“is not running”，Docker 重启或 docker stop 之后）而拒绝命令时，丢掉缓存项，重新启动或创建容器，再运行一次：旧容器什么也没收到。只有以 Error response from daemon: 开头的拒绝才算。
  • 会话的容器只在它的机器已配置且启用时创建。命令在机器上计数之后、以及那次重试之前，若机器在后端建好之后被关闭或删除，命令被拒绝（“machine '<id>' was switched off” 或 “was removed”），不创建容器。
  • remove_instances 按这些标签找本安装的容器，不看当前配置了哪些机器，在后台线程删除：对话被删除时（单独删除或“全部清除”），不论 worker 启动后是否打开过它，按对话；机器被删除、关闭或保存为关闭时按机器。
  • 按对话删除时只询问某台已配置机器（包括已关闭的）的连接方式用到的 Shell，所以没有 Docker 机器时不会运行 docker ps。“全部清除”把所有被删除的对话交给一个线程，逐个处理。
  • 没有 session ID 时用一次性的 docker run --rm，machines test 也是这样；它不按机器的状态检查。
  • 按机器时，remove_instances 先让正在进行的 computer_use 调用结束（最多 registry.FINISH_SECONDS，300 秒），再等它上面计数的命令结束（wait_idle，最多 RELEASE_WAIT，300 秒）；其间 current_environment() 拒绝新命令。
  • 计数的是 SSH 和 Docker 后端的 run 调用和启动的进程，后台命令或受监督 bash 命令的 supervisor（只要它还活着），以及为启动进程检查或创建容器的过程。
  • 在释放之前和等待之后检查，机器又被配置且启用时，删除结束，它的容器保留。
  • openprogram machines remove 和 disable 在返回之前删除机器的容器（wait=True）。CLI 的进程不计 worker 的任何调用和命令，所以它们不等这些。

远程文件工具

read、write、edit、apply_patch、glob、grep、list 调用 remote_target()。Shell 类型带 remote_files 的机器（SSH）得到 RemoteFS（host/machines/remote.py），交给 programs/tools/files/_remote.py，输出格式与本地工具相同；结果用机器 id 指明位置（devbox:/path）。

Docker 和本机得到 None，走本地路径。机器用不了的对话得到 RefusedFS：每个操作都抛带原因的 ConnectionError，工具报告它，绝不读本机磁盘。

stat一条 test 命令：存在、目录、大小

write_bytesmkdir -p，在同一文件夹写临时文件，再 mv 覆盖目标
退出码 255ssh 自身失败：ConnectionError，作为错误报告，不当文件内容
glob在远端 find，再用由 glob 转换的正则过滤。GNU -printf 取 mtime，BSD stat 兜底
grep有 rg 就用它，否则 grep -rE，用 head 截断

读 PDF字节复制到本地临时文件，用本地读取器

输入框

胶囊显示和行为
机器始终显示：项目的机器，图标与设置 → 设备里的相同（machineIconName），另一台机器带连接状态点；颜色是 worker 连接状态，机器不在时为红色；文字是名称。不能切换：菜单里只有这一台、打勾，并注明“由项目 <name> 决定”
Channel始终显示。未绑定：聊天图形和“No channel”。已绑定：ChannelLogo 和账号 id，被挤压时只留 logo。channelHealth 是角上 6px 圆点：黄色降级，红色不可达。菜单每个有启用账号的应用一行，各有账号子菜单（已绑定的打勾），绑定时再有“Disconnect”，最后是“Manage channels”

胶囊是输入框设置 channel 的唯一位置。菜单和胶囊共用 channel-choices.ts，跟随输入框所在窗格（useBoundChat）。statusBadge 和 channelHealth 是独立的 store 切片。

实现状态

已实现：运行环境作为机器注册表上的角色，由项目决定；local、ssh、docker 三种方式的 Shell；openprogram machines、向导步骤、设置 → 设备、WebSocket 动作；远程文件工具；按对话的 Docker 容器，按标签删除。

未实现：

  • WSL 和云环境
  • 密码或交互式 SSH 登录
  • 远程文件的检查点或撤销；revert 不恢复它们
  • 把项目移到另一台机器
  • 机器被删除或关闭时，等 worker 重启后仍在运行的受监督进程结束再删实例；重启之后它们不计数
