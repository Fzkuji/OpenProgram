导入其他 agent 的会话

模块职责
claude_code.py、codex.py查找、概述、解析各自的格式
model.py中立结构：一轮轮用户文字和按顺序的回复块
sanitize.py去掉宿主注入的内容，去掉凭据
writer.py把轮次写成和原生轮次一样的 DAG
ledger.py什么导入到了哪里
service.pylist_candidates、plan_imports、import_transcripts

入口：openprogram sessions import、/api/sessions/import、设置里的导入对话页。CLI 有运行中的 Worker 时分批交给它写，否则直接写存储。产品页：会话导入。

读取格式

Claude CodeCodex
文件projects/<slug>/<id>.jsonlsessions/YYYY/MM/DD/rollout-*.jsonl
来源 id文件名；sessionId 会被复制进分叉session_meta.id
对话顺序从最新记录沿 parentUuid / logicalParentUuid 往回走出的链文件顺序；压缩和分叉不改写它
标题custom-title，其次 ai-title，再次 summarysession_index.jsonl，最后一次改名
模型、cwdmessage.model、记录的 cwdturn_context.model、session_meta.cwd
跳过isMeta、isSidechain、压缩摘要、API 错误记录子 agent 的 rollout、注入的上下文块、加密的推理

不是 JSON 对象的行、还没写完的记录都跳过，文件其余部分照常导入。

决定

选择原因
按原 agent 恢复对话的方式读取Claude Code 恢复时从最新记录沿父链走；Codex 按顺序重放 rollout。导入的就是用户在那边最后看到的对话，不含被放弃的分支。
写成原生节点，不做附件搜索、导出、回退、继续对话都照常工作。这里没有的工具，其调用以文字形式重放给模型。
id 由 agent、来源 id 和轮次序号得出同一轮写两次不产生变化，来源变长时原地追加。和 OpenCode 的导入同一思路：它按原 id 存导入的会话。
台账记最后指纹和 head没变的来源不解析就跳过。在原 agent 里回退过、或在这里继续过的会话，导入成新会话，已有内容不被改写。
新旧按最后一条消息判断，不看文件大小或修改时间运行中的 agent 会不断往对话没动的文件里追加记账记录。
凭据按请求脱敏的模式去掉导入的轮次会重放给接着对话的模型。models/providers/utils/redaction.py 的高精度模式能抓到密钥和令牌，又不改写只是提到 key 或 token 的正文；导出用的宽规则会改写。标题先去凭据再截断，因为截短的密钥不再符合它的模式；列表的扫描缓存里存的第一条消息和标题也去掉凭据。登录文件从不打开。
放进所在文件夹的项目和在这里打开那个文件夹一样；原 cwd 保留在 imported_from.cwd。
--list 之外另有 --dry-run--list 列出所有对话文件及状态；--dry-run 只列出同一条命令会新建或追加的对话。它运行 plan_imports，和导入做同样的判断，所以回退过的来源显示为新对话，而不是追加。
Codex App 的对话是同步，不是导入Codex App 和 CLI 的线程通过 codex_sync.py 自己进来：它复用这里的读取、写入和台账，但把每个对话连到它的 Codex 线程，并追加 App 里新加的轮次，跳过 OpenProgram 在上面跑的轮次；见 Harness 引擎。和导入不同，它不新建项目，因为 Codex App 每个对话都会开一个文件夹。
Claude App 和 DeepSeek Harness 也同步app_sync.py 用同一份台账把 Claude App Code 标签页的对话和 DeepSeek Harness 的对话（deepseek_harness.py 读它的 zstd 事件日志）带进来，App 新加的轮次接在这里说过的之后；在 App 里回退过的对话，这里保持原样。

实现状态

  • 只扫描默认目录（或 $CLAUDE_CONFIG_DIR、$CODEX_HOME）；不能在命令行指定从别的机器拷来的文件夹。
  • 去掉凭据之前导入的会话，在来源变长之前保持原样；来源变长时只重写最后导入的那一轮。轮次指纹取自读到的原文，所以脱敏不会让这样的来源变成重复会话。
