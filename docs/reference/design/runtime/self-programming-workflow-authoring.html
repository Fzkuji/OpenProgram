Self-Programming Workflow · architecture and implementation plan

拆分 Workflow 的发现、创建、修订与执行

本页定义 OpenProgram 如何让 Chat Agent 选择已有 Workflow、如何按需创建可复用 Workflow，以及用户如何通过 auto_workflow(task) 手动触发完整流程。核心约束是：选择、创建、修订和执行必须是独立公共行为；完整入口只做编排，不再保存另一套实现。

状态：Proposed · 尚未实施范围：Workflow catalog / authoring / runtime / Programs UI读者：Runtime、Programs、Web 实现者兼容：旧 run 只读恢复
设计结论当前实现目标架构公共合同创建与复用生命周期框架对照实施计划验收实现状态

1. 设计结论

删除新的 agentic_workflow 调用入口。将其能力拆为 search_workflows、create_workflow、revise_workflow 和具体 Workflow 执行；另提供只供用户手动使用的 auto_workflow 完整入口。

Chat Agent 路径

Agent → search / create / revise / workflow

Agent自己判断是否直接调用已有Program；目录较大或候选未加载时才搜索。Agent不调用 auto_workflow。

用户手动路径

User → auto_workflow(task)

一次请求完成搜索、一次可见选择、必要时创建、随后执行；每一步仍在DAG中独立可见。

auto_workflow 是便捷编排入口，不是候选 Workflow，也不是组件。搜索结果必须排除它，生成代码不得 import 它，Agent 工具集合不得暴露它。

2. 当前实现与已确认缺口

当前事实问题目标处理
agentic_workflow(task) 是公开 @agentic_function。名称没有说明它会搜索、生成、发布并执行。新调用迁移到四个明确入口；旧名字停止注册。
_search_projects()、选择模型调用、candidate authoring、repair、执行与publish位于同一模块。只读发现、持久写入和业务执行共享一个生命周期。先按公共合同拆行为，再删除不再有调用者的分支。
已有项目以Git revision、snapshot和 project_ref.json 固定运行输入。有价值的版本和恢复能力与复合入口绑定。保留项目格式、快照、checkpoint和显式resume。
运行失败可进入候选修订并在成功后发布。一次普通执行可能静默修改已发布Workflow。发布前结构/测试修复留在create；已发布修改只能显式revise。
用户表单和Agent工具看到同一个入口。用户需要完整入口，Agent已有自己的任务路由，二者语义不同。auto_workflow 用户可见、Agent不可见。
@agentic_function 的 expose= 只是DAG语义，未传给Layer-2 register(..., expose)；Layer-2的 _unexposed/exposed_names() 机制已存在但装饰器未接线。“用户可见、Agent工具不可见”今天无法用装饰器表达。先给 @agentic_function 增加工具级曝光参数并打通到Layer-2（Phase 0），auto_workflow 用它注册。
执行失败进入执行期repair（PROJECT_REPAIR_ATTEMPTS），成功后自动发布新revision。普通运行失败会静默改写已发布Workflow。执行期repair整体删除；只保留 create_workflow 内发布前的bounded author重试（PROJECT_AUTHOR_ATTEMPTS）。已发布修改只走显式 revise_workflow。

本设计复用已有的 Workflow package、Git、snapshot、checkpoint、DAG caller 和取消状态设施；不引入第二个执行Runtime、图DSL、Workflow数据库或字符串dispatcher。

3. 目标架构与两条主路径

用户手动编排Chat Agent 决策公共 Workflow 能力持久状态与执行

Chat Agent 决策顺序

  1. 已加载的Program或Workflow明显匹配：直接调用，不先搜索。
  2. 可能存在未加载的动态Workflow：调用 search_workflows。
  3. 完整匹配：直接调用候选的固定revision。
  4. 只有部分能力：一次性任务可直接组合调用；需要复用、恢复、定时或稳定结构时调用 create_workflow。
  5. 没有匹配：普通一次性任务仍可由Agent直接使用工具完成；用户明确要求复用资产或任务具有稳定重复结构时才创建。

4. 公共能力合同

入口调用者职责禁止行为
search_workflows(task)Agent、用户确定性返回排序候选、固定revision、合同、权限和命中依据。不得调用模型、写文件、执行候选或发布。
create_workflow(task)Agent、用户读取候选组件，生成一个新package，验证后发布并返回ref。不得执行用户任务；不得修改已有项目。
revise_workflow(workflow_id, request)Agent、用户基于指定revision创建新候选，验证后发布新revision。不得由普通运行失败静默触发；不得覆盖旧revision。
auto_workflow(task)仅用户手动调用搜索，由一个可见的selection Agent判断reuse/create，最后调用确定的Workflow。通过Layer-2 unexposed注册实现Agent工具不可见。不得出现在Agent工具集合或搜索候选；不得自动revise已发布项目。
具体Workflow入口Agent、用户、其他Workflow执行确定业务合同。不得重新进入全局搜索或authoring。
 
{
  "action": "reuse | create",
  "workflow_id": "research_report",
  "workflow_revision": "<immutable git revision>",
  "result": {},
  "run_id": "<workflow run id>"
}

auto_workflow 的返回值必须说明选择了复用还是创建。搜索、创建和执行分别生成DAG子节点，不能只留下一个无法解释的总节点。

5. 搜索、组件复用与创建

搜索合同

搜索以catalog metadata和固定Git HEAD为输入，只做确定性文本召回，再把候选合同交给调用它的Agent判断。Chat路径由Chat Agent判断；手动auto路径由其内部唯一的可见selection Agent判断。搜索结果不是执行许可；权限、输入Schema和side effects必须随候选返回。

{
  "workflow_id": "web_research",
  "revision": "<git revision>",
  "retrieval_score": 4,
  "matched_terms": ["web", "research"],
  "input_schema": {},
  "output_schema": {},
  "permissions": ["network"]
}

创建时复用组件

create_workflow 获得可用Workflow的只读快照和公开Program目录。生成项目通过普通Python import引用Workflow package，不复制依赖源码；manifest固定每个依赖revision，并在发布前拒绝循环依赖、缺失入口和未声明权限扩张。

research_report/
├── pyproject.toml
├── README.md
├── workflows/
│   └── research_report/
│       ├── __init__.py
│       ├── collect.py      # imports web_research
│       └── synthesize.py
└── tests/
    └── test_research_report.py
固定输入

冻结catalog revision和可达依赖；外部新提交不改变本次authoring。

生成唯一candidate

只有candidate目录可写；源仓库、依赖Workflow和用户目录保持只读。

确定性验证

检查package、唯一入口、Schema、import、依赖闭包、循环、权限和测试命令。

发布前有限修复

只修正生成候选的结构或测试失败；次数有上限，取消和provider错误不修复。

原子发布

验证全部成功后创建一个commit并更新catalog；返回Workflow ref，不执行用户任务。

一次性任务不自动创建Workflow。创建的判据是用户明确要求，或任务需要稳定复用、恢复、定时执行、版本化审查中的至少一项。

6. 生命周期、失败与信任边界

阶段允许状态变化失败规则
search无持久run；只读结果catalog损坏项被报告或跳过；不得改变项目。
create / reviserunning → completed | failed | cancelled失败和取消不发布；candidate可回收，诊断写入run state。
workflow runrunning → completed | failed | capped | cancelled保留原错误和checkpoint；不自动改写已发布Workflow。
auto聚合子调用状态任一子调用失败即停止；不得把部分结果标记为completed。
resume只恢复指定run固定原snapshot/revision，不重新搜索或重新选择项目。

边界要求

  • authoring写入仅限本次candidate和run state；网络、凭据和外部工具遵循当前会话权限。
  • 同一目标Workflow发布必须串行；不同项目可以并行。运行snapshot不受并发发布影响。
  • 取消、权限拒绝、timeout、provider terminal error和外部Stop不进入repair。
  • 调用表单继承会话顶部Project；不提供第二个工作目录覆盖项。
  • 本地App刷新检测到活动run时拒绝刷新，不能通过重启把运行状态改写为失败或取消。
  • 旧 code.py、legacy snapshot和历史run只读恢复；新调用不再产生旧格式。

7. 官方框架对照

对照只用于确定边界，不把其他框架的Runtime或DSL引入OpenProgram。下表的“未覆盖”表示所列官方页面没有定义自动生成并发布持久Python Workflow的完整产品合同。

官方资料相关能力采用或修改未直接覆盖
OpenAI Agents SDK · orchestration区分LLM决策与代码编排；manager可把专用Agent当tool调用。采用“Chat Agent拥有用户对话，专用能力是独立工具”；auto_workflow使用代码编排。不定义本地Workflow catalog的生成、Git发布和旧run兼容。
OpenAI Agents SDK · tool search大型工具面可以延迟搜索和加载，搜索活动保持可观察。采用按需搜索，不要求每条消息先搜索；搜索返回合同而不是直接执行。不负责创建新的持久工具实现。
LangGraph · workflows and agents明确区分预定路径Workflow与动态决定工具的Agent。采用职责区分；保留Python控制流，不新增图DSL。不定义Agent自动编写、测试并发布新的Python Workflow。
LangGraph · subgraphs通过输入输出Schema复用subgraph，父子持久化边界明确。采用合同化组合和固定依赖revision；OpenProgram以Python import表达关系。不提供OpenProgram式Git项目catalog和authoring发布流程。
CrewAI · FlowsFlow使用显式事件、状态和Crew组合完成结构化流程。只采用“确定流程与Agent协作分层”的原则。所列页面不描述运行时搜索并生成持久Flow资产。

采用、修改与拒绝

选择结论边界
Agent按需搜索工具/Workflow采用已知Program直接调用；大目录才搜索。
可复用子流程的合同化组合修改采用用Python import、Schema和固定Git revision，不引入subgraph DSL。
manager式完整入口修改采用仅用户手动 auto_workflow；Agent不递归调用它。
运行失败自动重写已发布流程拒绝修改必须显式进入 revise_workflow。
所有一次性任务自动持久化拒绝没有复用或恢复价值时由Agent直接完成。

8. 实施计划

每个阶段独立提交，并依次经过公共RED、最小GREEN、规格审查和质量审查。前一阶段未通过两类审查时不进入下一阶段。现有 tests/component/agent/test_agentic_workflow.py 锚定单体入口，各阶段必须同步迁移对应测试归属，避免最后删入口时测试整体失效。

Phase 0

曝光机制接线

给 @agentic_function 增加工具级曝光参数并传入Layer-2 register(..., expose)；复用已有 _unexposed/exposed_names()。

Gate：最小注册合同测试证明参数生效；默认行为不变（现有函数仍全部曝光）。
Phase 1

提取只读搜索

从现有模块抽出 search_workflows 公共合同；返回固定revision、Schema、权限和匹配信息；排除 auto_workflow 与legacy项目。搜索相关测试迁到新入口。

Gate：调用前后catalog与run目录字节不变；Agent可读取候选但没有执行节点。
Phase 2

拆出创建与修订

将candidate、验证、依赖固定和publish迁入 create_workflow；再以显式目标和新revision实现 revise_workflow。创建不执行用户任务。删除执行期repair路径；author/validate/publish测试迁到新入口。

Gate：create只新增一个项目；revise只新增一个revision；失败、取消、terminal error均不发布；不存在执行期自动发布路径。
Phase 3

建立用户级 auto_workflow

使用前两阶段公共能力实现search → visible select → reuse/create → run。完整DAG显示每个步骤；调用表单仅含 task 并继承会话Project；用Phase 0机制注册为Agent不可见。

Gate：用户表单可见，Agent工具清单不可见；reuse和create两条真实App路径可区分。
Phase 4

移除新 agentic_workflow 调用

停止注册旧入口，删除只服务旧复合路径的selection/repair分支。保留显式 resume_workflow(run_id) 和legacy只读执行器。剩余锚定单体入口的测试删除或迁移，resume/legacy测试保留。

Gate：新catalog、新DAG和新run不出现 agentic_workflow；历史run仍可查看和恢复且artifact不变。
Phase 5

UI、文档和最终门禁

Programs按“自动入口 / Workflow / 创建管理能力”表达来源与副作用；同步产品文档；在默认App完成direct、reuse、create、cancel和legacy恢复验收。

Gate：受影响测试、完整门禁、文档构建、0死链、App可视验收和实现状态一致。

最小文件边界

范围首选改动位置明确不做
Runtime与公共函数openprogram/programs/functions/agentic/agentic_workflow/__init__.py 起步；合同稳定后才移动到对应包。不在拆职责同时重写执行Runtime。
注册和曝光openprogram/programs/_registry.py、_runtime.py 的现有exposure机制。不新增第二套权限或工具注册系统。
组件与运行测试tests/component/agent/test_agentic_workflow.py 及最小注册合同测试。不以mock-only测试替代公共入口。
Programs UI现有Programs route、catalog和page组件。不新建Workflow数据库或独立管理应用。

9. 公共验收矩阵

场景公共入口必须观察到
Agent已有精确工具Chat消息直接Workflow Call；没有search/create/auto节点。
目录中有完整匹配search_workflows → Workflow返回固定ref并复用；没有仓库或revision变化。
只有部分组件create_workflow新package以import引用组件；没有复制依赖源码；不执行用户任务。
显式修改revise_workflow旧revision可继续执行；新revision通过全部发布门后成为active。
用户完整自动运行auto_workflowDAG显示search、唯一selection Agent、可选create和最终Workflow；结果含action和ref。
Agent工具发现Chat Agent tool inventory包含search/create/revise和具体Workflow，不包含auto或旧agentic入口。
运行失败具体Workflow状态failed、原错误保留、已发布源码和HEAD不变。
取消或Stopcreate/revise/auto/run相关run最终为cancelled；没有repair、publish或遗留running。
并发发布同一项目两个revise调用串行验证active revision；不丢失commit，不覆盖新HEAD。
旧run恢复resume_workflow(run_id)固定旧artifact只读执行；不创建新项目、不发布、不改旧snapshot。
最终完成不能只依据单元测试。必须通过默认 /Applications/OpenProgram.app 的真实表单和Chat路径，并在重新加载会话后核对DAG caller、运行状态、Workflow ref和catalog变化。

11. 明确排除

  • 不新增 @workflow、图DSL、第二个Runtime、字符串 call_workflow() dispatcher。
  • 不自动把所有用户消息转成Workflow，也不为一次性任务默认创建项目。
  • 不自动修改已发布Workflow，不在普通执行错误后隐式发布revision。
  • 不建立Workflow数据库、后台Git轮询、远程push、Marketplace或远程依赖解析。
  • 不改变Agent、Program和Workflow现有Python调用语义；本设计只拆入口与生命周期。
