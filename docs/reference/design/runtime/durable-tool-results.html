Durable tool results

Tool results retain their full JSON representation in execution-owned content-addressed SQLite blobs. Checkpoints contain descriptors, and completed actions reuse the same result hash. Payload size does not change tool success or interrupt checkpoint creation.

Boundaries

The 64 KiB delta limit applies to bounded control inputs and assistant decisions, not tool results. Blob storage has no application-level 1 MiB rejection threshold. Database and available-resource limits still apply. Display pages remain bounded; large display text uses a result reference. Checkpoint metadata, reference counts, ownership, hash verification, and atomic effect/checkpoint publication remain enforced. Model input truncation and image resizing are separate policies and are unchanged.

Reference behavior

Codex budgets text separately from images. Claude Code saves oversized non-image MCP results to files. OpenCode stores full text and returns previews. These context and event policies do not justify failing durable completion of an already executed tool.

Acceptance

Production safe-point handling commits a multi-megabyte image or text result. A fresh continuation restores identical content and the completed-tool frontier. Missing or corrupt referenced payloads fail validation. Existing small checkpoints retain their format.
