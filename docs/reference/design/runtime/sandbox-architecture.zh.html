执行权限与沙箱

本文定义请求身份、工具审批、运行中权限更新和本地进程隔离。Authority 表示认证主体及能力上限；Permission 判定一次操作；Sandbox 限制获准进程可访问的资源。适用范围包括 Web、CLI、ACP、渠道、嵌套 Agent、定时任务和恢复执行。

认证身份

本地认证入口在持久化 admission 之前将完整 owner 身份写入 TurnRequest。审计 actor 与工具请求是不同字段，仅传 actor 不能授权工具。paired 渠道保留自己的权限级别，浏览器 MCP 可缩窄为 mcp_browser。嵌套请求继承身份且不能扩大权限。缺失或未知身份必须返回明确拒绝，恢复流程不能根据 source 或模型文字补成 owner。

统一操作判定

审批等待与工具执行共用同一判定函数。顺序为：固定约束、Authority、计划模式只读限制、显式 deny、显式 ask 或强制审批、精确 Web Use 授权、bypass、显式 allow、定时 Memory 例外、安全读取、acceptEdits、Auto 分类、普通审批。非交互请求不能要求本地审批。bypass 只跳过普通审批与 Auto 分类，显式规则、强制审批、插件 gate 和 Sandbox 仍生效。非法模式更新必须拒绝。

权限模式

ask 放行安全读取，其他操作要求审批。acceptEdits 额外放行工作目录内支持的安全编辑。plan 按既有只读工具策略拒绝副作用。auto 放行安全工具，其余执行风险分类。bypass 跳过普通审批与风险分类。有效模式按会话、项目、ask 的优先级解析；实际 admission 和界面确认必须使用相同的有效值。

带版本的运行中权限

现有 SessionStore 持久化 permission_state，包含模式、版本和 owner principal。原子 compare-and-set 拒绝过时客户端的修改。设置入口验证认证身份、会话范围和预期版本。工具在下一次审批检查读取该身份所属的最新设置，单个调用保留检查结果直到执行；已获准的调用不被中途取消。原始身份、admission 和恢复合同保持不可变。其他会话、paired 渠道及非交互任务不能使用这些动态放宽。

切换模式后，只重新判断普通权限审批。现在允许的调用通过既有 canonical wait-answer 命令恢复。显式 ask、强制审批、Sandbox 升级和用户问题不自动回答。若更新与等待创建交错，旧执行释放 cancellation token 后再次检查；启动恢复也检查尚未处理的持久化变更。已结束、取消或超时的任务不会重新执行。

界面区分请求中、确认模式和错误；较旧的版本不能覆盖新状态。未发送的草稿只保存本地选择，首次发送时传入。已有会话必须等待后端确认。计划模式在工具边界实施，因此能阻止模型已经提出但尚未获准的写入；工具目录保持稳定以支持中途退出计划模式和恢复执行。模型主动进入的计划状态仍需要批准 exit_plan_mode。每次后续模型请求也包含最新确认模式的运行时说明。

工具与宿主边界

文件工具执行进程内检查；macOS 子进程使用 Seatbelt，Linux 使用 bubblewrap。Browser/Web Use 使用精确 surface 授权。Docker 与 SSH 使用各自的执行边界；owner 配置的 MCP 进程不等于本地 Sandbox。workspace-write 限制写根、保护读取、过滤凭证环境并默认关闭网络；danger-full-access 使用宿主用户权限。后端缺失默认 refuse；warn 是显式回退。自动导入的 agentic applications 路径保持固定写入限制。

Sandbox 是会话 override，并在 turn 开始时冻结。修改开关只影响后续 turn，不影响当前进程、其他会话、定时任务或子任务继承的策略。普通审批不能关闭 Sandbox；bypass 不自动升级 Sandbox。

Sandbox 升级与精确审批

只有带 approval.request 的交互本地 owner 可以批准精确升级；保护应用路径和凭证过滤仍保留。always_path 只能记录具体可放开的读取路径。审批绑定会话、execution、工具和 tool call，普通工具审批不能复用为 Sandbox 升级。当前执行协议没有工具返回后的独立升级等待，实际拒绝需要用户显式修改设置后发起新调用，不能静默复用普通审批。paired、MCP、cron 和 subagent 不具备升级能力。

参考框架与取舍

保留既有参考语料：Claude Code 的权限模式、独立 Sandbox 与 Auto 概念；Codex CLI 的结构化违规和精确重试；OpenClaw 的凭证过滤、后端拒绝及嵌套分类；Hermes Agent 的固定规则、命令规范化及非交互拒绝；OpenCode 的工具和资源级规则；pi-mono 的扩展拦截与非交互拒绝。Aider 的 Git 恢复不替代安全边界；Goose / WeClaw 类适配不能自动代替 owner 审批。未重新核实上游最新版本，不将这些比较表述为本次实测结果。

不采用项目配置静默覆盖全局安全规则、自动选择 Docker、外部渠道自动批准，以及将可选隔离显示为默认隔离。每工具 Sandbox override 和完整后台 Auto 产品流程仍未实现。

失败与兼容性

缺失身份、过时版本、非法模式、能力拒绝、显式规则、分类失败和 Sandbox 拒绝需要可区分。任何失败都不回退为 owner 或 bypass。没有 permission_state 的旧会话继续读取 permission_mode；新认证提交携带完整身份。旧 admission 缺失身份时必须经认证入口重新提交，恢复流程不为其提权。

宿主进程限制可能阻止 ps、top 和 lsof；Docker socket 不自动暴露。Linux 通配路径遮蔽存在平台限制。域名和端口 allowlist 需要受管代理与重定向校验，目前未实现；浏览器和远程网络控制独立。

代码职责与验收

agent/authority.py 定义身份和能力；agent/permissions/state.py 管理版本化状态和原子更新；policy.py 管理统一操作判定、显式规则和硬限制；approval.py 管理审批清单、精确等待消费和工具执行；lifecycle.py 管理调用快照与持久化等待恢复；session_config.py 解析配置；production_driver.py 保留 admission、恢复和等待生命周期；WebSocket 设置入口处理认证与确认；Web 和 CLI 显示确认状态、更新中和错误。

验收覆盖真实聊天身份与继承模式、安全工具、运行中双向切换、待审批恢复、显式 ask/deny、强制审批、计划模式、跨会话和身份隔离、版本冲突、刷新重连，以及 Sandbox 不变。

实现状态

权限生命周期实现已通过独立规格审查和质量审查。回归测试通过真实 production driver 检查认证聊天入口、带版本更新与继承、操作快照、审批恢复及审批卡关闭。完整仓库验证与默认 App 验收在发布证据中单独记录，不与局部检查混为一项。

域名 allowlist、资源配额、Windows Sandbox、每工具 Sandbox override、工具返回后的独立升级等待，以及完整后台 Auto 分类产品流程不属于本次实现。
