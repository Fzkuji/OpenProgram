2. Skills配置规则

规则语义显示
allowed为空，categories为空允许全部未被disabled命中的SkillsAll Skills
categories非空有category的Skill必须匹配类别，再应用disabledSelected categories
allowed非空名称必须匹配allowed；如果同时配置categories，则两项条件取交集Selected scope
disabled命中排除优先；即使category或allowed命中也不可用Excluded chip
引用不存在保留引用，标记Missing；用户保存后才能删除Missing row
唯一Runtime语义：disabled先判定；非空allowed限制名称；非空categories继续限制声明了category的Skill。页面保存这些策略，不另行实现一套判定。

3. MCP配置规则

集合含义运行结果
AllowedAgent可以使用的MCP服务范围服务已连接时，其工具可以进入按需发现
Disabled明确禁止的服务；优先级高于allowed即使全局已连接也不提供给Agent
RequiredAgent启动必须可用的服务任一required服务缺失时Agent状态为Cannot start，并列出缺失项
Credential由全局MCP Servers页面管理Agent页面不显示、复制或导出secret
Required不是默认勾选：允许服务失败时可以降级运行；只有Agent逻辑无法在缺少该服务时正确执行，用户才将其标为required。

4. 统一解析流程

1 · References

读取Agent策略

读取Programs、Skills和MCP的allowed、disabled、categories、required等稳定引用。

2 · Registry

查询全局实体

只从各自唯一registry取得当前存在、启用和可连接的实体，不使用页面缓存作为运行事实。

3 · Resolution

统一生成结果

同一个Runtime resolver返回available、excluded、missing和required-missing，供页面预览与Agent启动共同使用。

结果UI行为Runtime行为
available计数并允许在选择器中查看进入按需发现范围
excluded显示明确排除原因拒绝调用
missing保留引用，标红并提供Remove不提供；非required时Agent仍可启动
required-missing页头显示Cannot start阻止Agent启动并返回缺失服务列表

5. 交互与状态合同

场景预期行为
主页面只显示模式、摘要、计数和Manage入口；不常驻渲染完整实体目录。
打开选择器按来源或类别分组，可搜索、筛选Included/Excluded/Missing；关闭后返回原滚动位置。
实体在另一页面被删除重新解析后显示Missing，不自动修改AgentSpec。
全局连接状态变化只更新可用状态，不改变allowed/disabled/required选择。
会话override只允许进一步收窄能力，不能绕过Agent级disabled或required限制。
大目录选择器分页或虚拟滚动；搜索和分组由API支持，不把全部schema下载到页面。
窄屏来源导航变为横向筛选条；列表保持单列且所有操作可由键盘完成。

6. 验收条件

  1. Programs、Skills、MCP三页共享相同的主页面层级和保存状态，但保留各自不同语义。
  2. 主页面不渲染完整实体目录；用户点击Manage后才查询和显示选择器。
  3. 所有计数和预览来自与Runtime相同的resolver结果，而不是前端自行推导。
  4. 失效引用保留并显示Missing；不会因为页面打开而被删除。
  5. MCP required缺失会明确阻止Agent启动；普通allowed服务缺失只产生降级状态。
  6. Agent配置不包含Program schema、Skill正文、MCP server配置或凭据。
  7. 会话级override不能扩展Agent级禁止范围。
