一个模型，四种操作

四个词不能互换。操作名称直接表达修改代码还是对话、作用于一轮还是一段历史。点击左侧操作查看完整影响。

Operation
四种语义不是四个同级按钮。Turn card 只显示当前适用的 Undo 或 Revert；user checkpoint 进入 Restore sheet；assistant message footer 才提供 Branch。成功 Undo 后，严格预检可用时在 UI 显示 Redo；历史 Revert 的反向操作显示 Reapply。两者都执行新的 reapply transaction，不维护独立线性 redo 栈。

目标架构与信任边界

对话 DAG、精确 mutation journal 和 Git workspace view 是三个独立事实源。历史操作 planner 可以读取三者，但只有 journal 中的可恢复 receipt 能授权文件恢复。

普通 Bash 与 Workspace Review 的边界：Bash 可以在沙箱或 worktree 中运行，但本地共享工作区里的通用 shell 结果不自动归因给某个 turn。Git 能显示当前 workspace 变化，却不能证明它属于哪一轮，也不能赋予 turn Undo 权限。

不变量

  • 原始写入先持久化 prepared receipt，再写文件，确认 after state 后转 committed；prepared 持久化失败时 trusted mutator 必须在写盘前失败。
  • {kind:"absent"} 只表示已精确确认路径不存在；baseline 获取失败只能由 recoverability=unavailable 和 reason 表达，永远不能编码成 absent。
  • recoverability=unavailable 只用于 journal 已成功持久化、但因明确大小或文件类型策略不保存 recovery blob 的 mutation，不用于吞掉 journal 故障。
  • 每个 user prompt 定义 before_turn；assistant 完成后定义 after_turn。UI 必须写清恢复哪一个边界。
  • 同一 turn 多次修改同一 file lineage，摘要折叠为 first-before 到 last-after 的净变化；rename 后仍保持 lineage。
  • 所有共享 checkout 的 transaction 在 workspace lock 下领取全局单调 workspace_sequence；多轮投影按 sequence 和 lineage，不按 DAG seq/DFS。
  • before/after regular state 都保存 blob ref，才能稳定显示历史 diff、恢复和条件式 Reapply。
  • 路径在 capture/plan/apply 时都重新规范化；保存并复检父目录链 identity、leaf lstat、device/inode 和 hardlink count，使用已验证 directory handle 或等价 no-follow 原语。
  • Current branch 只折叠 active lineage 的 transaction，不混入 sibling branch。
  • Revert/Restore/Reapply 本身也写 mutation transaction，原记录保持不可变。

恢复记录不变量

  • Plan 是只读预览；Intent 是确认后的持久执行记录，两者由 plan hash 绑定。
  • 每个 action 在文件替换前后分别持久化状态；重启不通过目录内容猜测执行位置。
  • Rollback 只在 current digest 仍等于该 action 的 applied digest 时写回 rollback blob。
  • 任何 action 无法安全 rollback 时，intent 保留每个路径的真实状态并进入 recovery_required。
  • target branch 只在所有代码 action verified 后激活；source branch ref/head 始终不变。

三个 Review scope

Scope事实源包含恢复能力
This turn指定 origin turn 的 committed change sets父 turn 直接 change set + owned child change sets；child 始终保留独立 producer_turn_id，按 transaction id 去重并显示 actor。所选 causal closure 全部 receipt exact、所有 actor terminal 且 current digest 匹配时可 Undo/Revert。
Current branch当前 active lineage 的增量 mutation projection所有 turn、显式 revert/rewind/reapply；不包含 sibling branch 和外部写入。从具体 turn/checkpoint 发起，不提供无范围的一键 branch Undo。
WorkspaceGit tracked diff + git ls-files --others --exclude-standard当前未提交变化；遵循 .gitignore。内部再切换 Unstaged、Staged、Branch 或 Commit。无 turn Undo。Git Discard 与 checkpoint Restore 使用不同入口和确认文案；非 Git明确 unavailable。

多轮 Rewind：一次规划，一次事务

每轮同时有 before_turn 与 after_turn checkpoint。User message 的 Restore 入口默认选择“恢复到本次请求之前”；assistant turn card 可选择“恢复到本次回复之后”。目标 suffix 只沿 source branch predecessor chain 计算，不碰 sibling branch。Source branch ref 和 HEAD 始终保留；conversation 模式立即创建新的 target branch ref，并在协调事务提交后切换 active branch。

选择 checkpoint 和恢复模式。

PLANNING

冻结 expected HEAD、workspace version 与 suffix。

READY

展示 turn/file 影响、不可恢复项和 branch 结果。

多文件恢复不是单个文件系统原子操作。目标保证来自 durable intent、rollback staging、逐文件原子替换和重启恢复；若 apply 与 rollback 都失败，状态必须是 Recovery required，不能显示 Reverted 或移动 conversation HEAD。

规划算法

阶段规则失败结果
Resolve lineage从当前 HEAD 沿 conversation predecessor 回到目标 user checkpoint；caller subtree 只按明确 ownership 纳入。目标不在 active lineage：拒绝，提示先切换分支。
Fold target state按 journal 投影 checkpoint 时每个路径的目标状态；同文件跨多轮只生成一个最终 restore action，不逐轮覆盖。journal 不连续或历史 receipt 不精确：代码模式 unavailable，对话模式仍可选。
Preflight从全局 current_workspace_revision 规划到 target checkpoint，只比较实际 plan actions 涉及的 file lineage；检查 blob、父目录/leaf identity、file type、root、空间和权限。任一失败进入 BLOCKED，列出每个路径，零文件改变。conversation/workspace mismatch 本身不是 source digest。
Prepare intent保存 plan id、expected branch/head version、workspace revision、before images、目标 images、writer epoch 和恢复模式；请求幂等。确认前状态变化返回 stale-plan，重新预览。
Apply files获取 workspace mutation lock；每个 action 持久化 pending/applied/verified/rolled_back 和本 transaction applied digest；逐文件原子替换，删除仅在 current digest 匹配时执行。回滚前再次确认 current digest 仍等于本 transaction applied digest；外部 actor 已改写时不覆盖，进入 RECOVERY_REQUIRED。
Create conversation branchconversation-only 或 code+conversation 先准备新的稳定 target branch id/ref，source branch HEAD 不变；首轮前目标统一为持久 synthetic ROOT，禁止 head_id=None fallback。创建/激活使用 expected source head_version CAS；失败则按 intent 恢复文件并保留 source/active branch。
Finalize追加 rewind transaction 和 navigation event；不把旧节点全局写成 rewound。提升 branch writer epoch，使旧异步任务无法回写当前 branch。重启时扫描未终态 intent，完成或回滚，不猜测成功。

分支、Checkout 与 sub-agent

场景目标语义文件规则
Branch from assistant result立即创建稳定 target branch id/ref，HEAD 指向该 assistant，并切换 active_branch_id；source branch HEAD 保持原位置。默认不修改文件，按钮副标题明确“Files stay as they are”。纯浏览历史只移动 navigation cursor，不创建/移动 branch。
Fork into new task创建 source-preserving 新 task/thread，原 task 和 HEAD 不变；可选择复制 conversation only 或携带 checkpoint 文件状态。Git 项目中“with files”优先创建隔离 worktree 后物化 checkpoint；非 Git 不提供无提示目录复制，改用同 task 的显式 Code + conversation Restore。
Checkout sibling branch切换当前可见与模型使用的 conversation lineage。计算 branch/workspace alignment。浏览允许；开始文件修改前必须选择保持当前 workspace 或恢复该 branch 的代码投影。
Owned child（前台或后台）判据是 relation + creates_agent + origin_turn_id，不是前台/后台。child 始终有独立 producer turn/change set，父 turn 只按 origin 分组。运行中时阻止父 restore；完成后进入父级 owned causal closure，plan 逐个列出并按 transaction id 去重，不能靠 caller DFS 猜测。
Independent actor无 owned relation 的 background terminal、job runner、channel 和 scheduler 注册独立 workspace writer identity。运行中时阻止同 workspace restore；完成回写必须校验 branch writer epoch，旧任务不能在 restore 后重新写入当前 branch。
Existing peer / cross-session dispatchagent(to=existing)、send message 和既有 peer 是 linked collaboration，不是父 turn 独占后代。父 restore 默认不修改 peer 的对话或 change set；impact sheet 单独列出 linked actor，重叠 workspace/path 时阻止 code restore。
Worktree child文件状态属于独立 worktree。父 workspace 的 Undo/Rewind 不触碰；merge/discard 使用 worktree 自己的事务和冲突语义。
Worktree mergemerge 产生独立 mutation transaction，归属于执行 merge 的 producer turn。父 workspace 只从 merge transaction 恢复；不依赖可能已删除的 child worktree checkpoint。
Sibling branchRewind 只作用于 active lineage suffix。不改变 sibling journal；切回 sibling 时重新计算 alignment。
Branch、Fork 与 Restore 不共用含糊按钮。同 task 的 Branch 是对话导航，默认不碰文件；Fork 创建 source-preserving 新 task；Restore 是显式历史恢复。需要在当前 task 从历史代码继续时使用 Code + conversation Restore；需要两套同时可运行的代码状态时使用 Git worktree-backed Fork。

Resume、Archive 与 Purge 不变量

操作合同禁止
Resume session未知 session 返回 not-found；先恢复所有 prepared/applied/recovery-required transaction，再加载真实 node ids、active_branch_id、branch HEAD/version 和 workspace revision。不能把未知 ID 当新 session；不能生成 loaded-<index> 伪 ID。
Resume empty branch首轮前 HEAD 指向持久 synthetic ROOT；Web/TUI/Rich CLI 使用同一 branch result schema。不能用 persisted_head or tip 或 head_id=None 自动选择其他 tip。
Archive branch默认删除操作只 archive branch ref，保留 nodes、journal、checkpoint refs 和重新激活能力。不能删除共享祖先或把 predecessor 留成意外新 tip。
Purge branch显式高级操作；仅释放没有其他 branch、checkpoint、operation、audit 或 active intent 引用的独有对象，使用引用计数 GC。不能按 leaf 向后删一个节点，也不能让 blob GC 绕过引用。

性能、保留、安全与兼容

Turn finalize

复杂度只与 committed changed paths 有关；不遍历 workspace。摘要在 finalize 持久化并随 transcript 返回。

Review loading

文件列表每页 100；只保留相邻页。选中文件后每批最多 200 行或 256 KiB，并支持继续加载。

Diff budget

计算超预算返回 timeout metadata；不阻塞 Agent 完成，也不回退到 before 与当前磁盘的跨轮近似 diff。

Snapshot pagination

分类、搜索、排序和 cursor 都绑定同一 snapshot revision；workspace 变化后旧页标 stale 并整体刷新，不能混页。

Request generation

切文件取消旧 diff 请求；迟到响应必须匹配 scope、snapshot revision、change set、blob pair 和 request generation。

Large restore plan

上千文件预检作为可观察后台任务，冲突结果分页；进入 APPLYING 后不可取消，只能完成或事务回滚。

Recovery blobs

使用独立内容寻址存储，按 digest 去重，权限限于本地用户；不进入 session Git。默认保留最近 100 个 checkpoint 和每个 file lineage 的首个 baseline。

GC visibility

Pinned、活动 task、未解决冲突、prepared/applying intent 和仍被 branch ref 引用的 checkpoint 不回收。其余 blob 到期后显示 Review available / Code restore unavailable。

Secrets

blob 不进入日志、遥测或模型上下文；session 删除一并清理无引用 blob。外部路径必须有当时和恢复时的明确授权。

Legacy sessions

旧 checkpoint 只用于只读 Review 或明确标记 approximate；没有 digest/recovery contract 时不提供新 Undo/Rewind code 模式。

TUI parity

/rewind 先展示同一 server plan，再选择模式并确认；不能继续直接调用旧 rewind_to。

App/Web parity

同一 plan/apply 协议和幂等 request id；UI 只渲染 server 返回的 canonical impact，不在客户端重算。

Line comments

绑定 change_set id、before/after blob pair、side 与 hunk/line；scope、branch 或 restore 变化后标 stale，不能发送到另一版本。
