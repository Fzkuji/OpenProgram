常见格式的实际目标与复用方案

文本、代码、Markdown：预览、源码编辑和自动保存。DOCX、PPTX、XLSX：本地完整引擎预览与编辑，必须通过真实文件的打开、修改、导出和重新打开验证；不能以提取文字替代页面或幻灯片预览。旧 DOC/PPT/XLS 与 ODT/ODS/ODP 纳入兼容测试，若引擎只能转换则明确另存新格式，不覆盖原格式。CSV/TSV 至少可表格预览和文本编辑。PDF：分页、缩放和搜索，批注或编辑按组件实际能力开放。PNG/JPEG/WebP/BMP/GIF/SVG/TIFF：预览；静态位图提供裁剪、旋转与标注，动画或矢量不得在普通保存时静默栅格化。PSD：合成图和图层信息预览，保留原始 PSD；只有通过无损回写验证的操作才能启用原格式编辑。音频与视频复用本地 HTML 播放器。无法解析、加密、超限或尚不支持的文件有明确状态与下载入口。

候选 Office 方案包括 ONLYOFFICE Docs、OnlyOffice browser/WASM 与 LibreOffice WASM。默认方案必须本地可部署，不要求用户上传文档到第三方网站。完整服务器方案保留为可配置适配器候选，不能作为默认安装缺失时唯一能力。

PDF.js 是 PDF 浏览候选；TOAST UI Image Editor 是位图编辑候选，关闭 usageStatistics 并自带资源；ag-psd 是 PSD 预览候选，其色彩模式、文字图层与效果限制要求保留原文件。Photopea 支持嵌入但属于第三方托管页面，不默认加载或传入本地文件。最终选型以固定版本源码与本地样例验证为准。

统一打开、编辑和版本协议

文件引用包含稳定的项目或会话归属及相对路径，显示路径不是权限凭证。能力识别先核实扩展名、类型和文件内容，再选择预览或编辑适配器。适配器只获得该文档的内容与版本，不获得任意磁盘权限；统一导出 bytes/Blob、修改事件、错误事件和销毁方法。Office 与图片大资源只在打开相关文件时加载，不能拖慢聊天首屏。

人工编辑与模型写入共享版本校验、完整文件发布和 immutable before/after 存储原则。既有 project_file_write 的幂等记录只有操作结果与指纹，不等于可恢复的文件版本；本次补齐实际版本保存。人工修改记录 actor=user，模型修改关联 session/turn，不伪造聊天轮次，也不把人工历史变成侧栏会话。History 按文件汇集来源，模型本轮 Review 继续保留其归属语义。

版本数据按归属保留：项目中的人工编辑历史归项目，模型记录仍关联实际会话与轮次；汇总索引只引用已有版本，不另复制来源文档。归档会话仍可打开原记录；彻底删除会话后，其入口与归属版本按现有删除规则清理，汇总页不得用缓存重新显示原文。Memory 中残留来源仅标记“原会话已删除”或移除链接，不为此建立来源副本。项目文件及其独立人工历史不因删除一段聊天而一并删除。

自动保存和版本归档分开：编辑器正常撤回处理即时修改；草稿先持久保存，文件在有修改事件后的短暂合并窗口自动发布；History 默认按连续编辑时段归档，间隔约五分钟形成版本，切换文档、结束编辑或恢复操作也完成归档。文件内容不等待五分钟才保存。每次发布校验读取时的 revision，重复请求幂等，乱序响应不能覆盖新草稿；保存失败保留草稿并显示可重试错误。重启后读取持久记录，不根据当前文件补造过去版本。

富文档编辑器的生命周期独立于标签视图。切换标签时先隐藏视图，仍在导出的引擎继续保留；最新内容进入持久草稿后才能释放引擎。Office iframe 在同一文档会话中不因 React 重新挂载或 DOM 移动而重建。关闭、重命名和版本恢复均先等待最终导出，失败保留编辑器和草稿。预览与编辑复用同一实例；只读历史实例不能回写当前文件。

Office 在独立来源加载本地固定版本资源，只开放该资源树的 GET/HEAD，不开放主应用 API、认证和 WebSocket。父子页面同时校验来源、实例和消息请求，宏默认禁用。大型资源随安装部署或从已准备的同版本本地缓存读取，打开文件时不请求第三方 CDN；远程部署没有配置独立资源来源时明确显示不可编辑，不转交第三方网站。PDF、图片与媒体按需加载，保持聊天首屏资源预算。文件窗口只在打开文件时加载；KaTeX 保留完整 WOFF2 字体，不再重复引用面向旧浏览器的 WOFF/TTF 回退。资源检查保留 2 MiB 首屏压缩传输与 350 KiB 单块压缩脚本上限。

大型二进制通过受限字节上传或本地暂存传输，不编码到普通聊天消息。边读边检查体积，取消时清理临时文件；引擎消息校验来源、实例和请求 ID。文档脚本、宏、HTML/SVG 活动内容不获得主窗口权限；第三方服务仅在用户主动配置并知悉文件将送往该服务时使用。原格式不支持安全写回时，提供明确的导出副本，而不是把 PNG 或 OOXML 内容写进其他扩展名。

完整交付与验收，不以部分格式通过替代整体完成

工作顺序：验证复用引擎；完成统一文件版本与二进制发布接口；接入格式预览和编辑；统一预览优先、自动保存和 History；验证历史恢复、窗口切换、重启与错误状态；执行独立规范与质量审查及组合版本全量检查；最后更新默认 App。每个适配器都需要真实有效文件，不用伪造二进制证明格式支持。

验收逐项覆盖 Word、PPT、表格、图片、PSD、PDF、文本与媒体。可编辑格式须实际修改内容、写回、重新打开并验证版本恢复；只读格式须实际渲染并明确能力。包含并发外部修改、写入中断、损坏文件、超大文件、取消、断网、项目路径变化和旧历史兼容。所有可见支持状态、源代码、测试与安装版本一致后才标记完成。

一个模型，四种操作

四个词不能互换。操作名称直接表达修改代码还是对话、作用于一轮还是一段历史。点击左侧操作查看完整影响。

Operation
四种语义不是四个同级按钮。Turn card 只显示当前适用的 Undo 或 Revert；user checkpoint 进入 Restore sheet；assistant message footer 才提供 Branch。成功 Undo 后，严格预检可用时在 UI 显示 Redo；历史 Revert 的反向操作显示 Reapply。两者都执行新的 reapply transaction，不维护独立线性 redo 栈。

正常保存、失败重试与旧版本保护

每份 before/after 使用独立且完整写入的版本文件。持久化顺序是版本内容、校验、版本目录，再发布 manifest。更新 manifest 失败时，前一份成功记录引用的内容仍完整。失败尝试不覆盖已发布版本。只有尚未成功的尝试被明确取消后，重试才以重新读取的当前文件建立 before；已成功修改始终保留本轮最初 before。

准备记录与提交记录分开。未完成的写入保留待确认标记，历史投影显示不可精确恢复，不能推断脚本成功，也不能用当前磁盘内容补造 after。取消且确认没有成功提交的尝试不展示为已修改。损坏或不支持的 manifest 返回明确错误；仅真正缺失的 manifest 表示没有记录。旧版本 manifest 和旧 blob_ref 继续可读，无批量重写迁移。

DeepSeek 与 Codex 的源码依据

DeepSeek 的 JSONL persistence 使用同步临时文件、独占发布与目录同步，并明确区分损坏记录和缺失记录；session repair 把中断工具标为结果未知，而不自动补造成功。采用这两项原则保护版本内容与中断状态。其 fs-local 提供目标锁、版本条件检查和文本写入结果，但未提供完整文件 undo/reapply 或 Office 版本管理；因此保留 OpenProgram 现有恢复事务，不把会话日志恢复等同于文件恢复。Codex 的 exact delta 归因继续保留，不把任意 Bash 操作视为精确修改。

新工具如何接入，哪些能力不属于本次实现

本地生成器统一调用 write(file_path, source_path=...) 发布完整文件。文本工具保留 write/edit/apply_patch 入口，共享 checkpoint 的 prepare/commit/abort 合同。不能只提交模型声称的“修改成功”，也不能执行任意 Bash 后扫描目录并归因。状态存储由 CheckpointStore 管理，Review 和会话摘要只作投影，不另建版本副本。未来 Office 语义差异只读取不可变版本，不承担撤销；远端存储需要条件写入和可验证版本标识，在具备这一能力前不宣称支持精确恢复。

本次保留现有单轮聚合、会话分支和恢复事务；不新增全盘扫描、定时轮询、通用插件注册框架、Office 修订视图或远端存储实现。已丢失的历史不能补回。系统崩溃与不遵守文件锁的外部程序仍可能造成待人工处理状态；系统保留证据并拒绝不确定覆盖，不承诺所有外部修改都能自动恢复。

实现与验收计划

先复现连续写入提交失败、失败后重试和损坏记录覆盖；再修复共享历史存储及未完成记录投影。通过注册工具、重新打开会话、Review 与恢复入口验证，最后进行独立规范审查、质量审查和全量检查。该节对应共享历史存储、会话摘要与 Review 投影已实现；独立规范和质量审查、故障回归及全量测试均通过。

实现方式与范围

脚本将结果写到独立临时文件，再通过现有 write(file_path, source_path=...) 发布。content 与 source_path 必须且只能指定一个。source_path 是本地普通文件，受读取权限限制；目标继续执行写权限、读取基线与审批文件指纹检查。来源和目标均纳入审批等待时的文件指纹；发布前复核。工具在目标目录生成临时文件，完整写入后替换目标，失败清理临时文件，并保留原目标。工具按原始字节写入，记录 before/after，不将文档转成文本保存。源与目标相同、目录、链接、超限或不可读取的来源在修改目标前失败。来源读取有 64 MiB 上限。已有目标在 advisory lock 下复核打开的文件句柄、内容和路径；这只能串行化遵守该锁的写入，不能阻止外部程序在最终校验与替换之间写入。Windows 在替换前关闭不共享删除权限的句柄并再次校验，因此不承诺操作系统级条件替换。

参考 Codex TurnDiffTracker 的 exact delta 检查与 shell snapshot 的暂存、验证、替换流程；后者保存 shell 环境，不是文档版本。沿用 Codex 的明确修改操作归因：通用 Bash、后台进程与外部编辑器不自动成为本轮精确修改。脚本不能直接覆盖最终目标后再补写历史。保留既有文本 write 参数、失败语义、回退事务、分支归属及持久会话布局。文档格式、图片和排版均由完整字节版本恢复；当前不提供 Word 修订标记或 PPT 视觉差异。

读取基线必须先建立：模型先用 read 读取原文件，再生成暂存版本。二进制读取返回文件类型与字节数，不向模型输出乱码。新文件不要求先读。脚本工具说明明确这一流程，无额外保存按钮，无全盘扫描与轮询。

验收经注册 write 工具、会话重新打开及公开历史操作完成：创建和覆盖 DOCX/PPTX 后保存版本；撤销及重新应用逐字节一致；外部更改导致冲突；失败不替换目标；旧文本写入仍有效。

  • 完成后 durable record 保存 canonical terminal result。相同 fingerprint 的任何重试只重放该结果，即使 request_id 不同，也不再次执行文件 mutation。进程重启先恢复或判定 in-flight record，再允许其结果被重放。

缓存与未保存草稿

存储键与容量淘汰与一致性数据保护
Read cache键为 project_id + canonical relative path + content revision；最多 64 项且最多 16 MiB，使用访问顺序 LRU。只缓存成功且完整的只读结果。写入、rename、delete、tree revision 变化和容量超限会失效或淘汰最旧的干净 read；缓存未命中只触发新的 request_id 请求。缓存不是编辑状态，也不保存 dirty text。
Dirty draft store浏览器原生 IndexedDB 的 openprogram-file-drafts 数据库，键为 project_id + canonical relative path；持久化 UTF-8 draft、baseline content revision、baseline mtime、保存状态与更新时间。容量上限为 32 个 draft 或 8 MiB。干净 draft 可删除；dirty draft 不参与 LRU 淘汰。所有 entry 与 aggregate byte/count index 在一个 readwrite transaction 中更新。页面刷新、tab unmount、切换项目和 read-cache 淘汰都不能删除 dirty draft。服务端文件变化后保留草稿并标记冲突，保存必须继续提交其原始 baseline 条件。
路径变更与清理成功 rename 在 IndexedDB transaction 中移动同项目 draft key；copy 不共享 source draft。删除文件先列出 dirty draft，要求明确的保存、保留/导出或丢弃选择。项目 draft 清理只由未来显式 project unlink/delete command 触发；当前产品没有该 action。任何文件操作失败时不变更 draft key。确认 discard 后，文件 draft 与 project aggregate index 在单个 IndexedDB transaction 中清理；清理失败保留原记录并报告失败。不得把 list_projects 中项目消失解释为用户授权。跨项目的同名 path 永不共享 cache、draft、selection 或 search snapshot；不因 tree 刷新、Review 切换、临时 registry unavailable 或后台响应重置编辑器 buffer。

  • draft 内容仅保存在当前浏览器 origin 的 IndexedDB；不进入日志、遥测、模型上下文、WebSocket payload 或跨设备同步。显式 discard、未来确认的 project cleanup、浏览器站点数据清除和应用卸载会删除本地内容；恢复时不得自动上传或重新写回项目文件。

恢复记录不变量

  • Plan 是只读预览；Intent 是确认后的持久执行记录，两者由 plan hash 绑定。
  • 每个 action 在文件替换前后分别持久化状态；重启不通过目录内容猜测执行位置。
  • Rollback 只在 current digest 仍等于该 action 的 applied digest 时写回 rollback blob。
  • 任何 action 无法安全 rollback 时，intent 保留每个路径的真实状态并进入 recovery_required。
  • target branch 只在所有代码 action verified 后激活；source branch ref/head 始终不变。

规划算法

阶段规则失败结果
Resolve lineage从当前 HEAD 沿 conversation predecessor 回到目标 user checkpoint；caller subtree 只按明确 ownership 纳入。目标不在 active lineage：拒绝，提示先切换分支。
Fold target state按 journal 投影 checkpoint 时每个路径的目标状态；同文件跨多轮只生成一个最终 restore action，不逐轮覆盖。journal 不连续或历史 receipt 不精确：代码模式 unavailable，对话模式仍可选。
Preflight从全局 current_workspace_revision 规划到 target checkpoint，只比较实际 plan actions 涉及的 file lineage；检查 blob、父目录/leaf identity、file type、root、空间和权限。任一失败进入 BLOCKED，列出每个路径，零文件改变。conversation/workspace mismatch 本身不是 source digest。
Prepare intent保存 plan id、expected branch/head version、workspace revision、before images、目标 images、writer epoch 和恢复模式；请求幂等。确认前状态变化返回 stale-plan，重新预览。
Apply files获取 workspace mutation lock；每个 action 持久化 pending/applied/verified/rolled_back 和本 transaction applied digest；逐文件原子替换，删除仅在 current digest 匹配时执行。回滚前再次确认 current digest 仍等于本 transaction applied digest；外部 actor 已改写时不覆盖，进入 RECOVERY_REQUIRED。

Resume、Archive 与 Purge 不变量

操作合同禁止
Resume session未知 session 返回 not-found；先恢复所有 prepared/applied/recovery-required transaction，再加载真实 node ids、active_branch_id、branch HEAD/version 和 workspace revision。不能把未知 ID 当新 session；不能生成 loaded-<index> 伪 ID。
Resume empty branch首轮前 HEAD 指向持久 synthetic ROOT；Web/TUI/Rich CLI 使用同一 branch result schema。不能用 persisted_head or tip 或 head_id=None 自动选择其他 tip。
Archive branch默认删除操作只 archive branch ref，保留 nodes、journal、checkpoint refs 和重新激活能力。不能删除共享祖先或把 predecessor 留成意外新 tip。

性能、保留、安全与兼容
Turn finalize

复杂度只与 committed changed paths 有关；不遍历 workspace。摘要在 finalize 持久化并随 transcript 返回。

Review loading

服务端先筛选和稳定排序，文件列表每页 100；客户端只保留当前页和相邻页。选中文件后每批最多 200 行或 256 KiB，并支持继续加载。

Diff budget

计算超预算返回 timeout metadata；不阻塞 Agent 完成，也不回退到 before 与当前磁盘的跨轮近似 diff。

Snapshot pagination

目录、项目搜索和 Review 的分类、搜索、排序与 opaque cursor 都绑定同一 snapshot；workspace 或项目变化后旧页返回 stale 并整体刷新，不能混页。

Request identity

每个文件 WS 请求有 UUID request_id；切文件或切项目取消旧请求。迟到响应还必须匹配 owner、scope、snapshot revision、change set 与 blob pair。

Large restore plan

上千文件预检作为可观察后台任务，冲突结果分页；进入 APPLYING 后不可取消，只能完成或事务回滚。

Recovery blobs

使用独立内容寻址存储，按 digest 去重，权限限于本地用户；不进入 session Git。默认保留最近 100 个 checkpoint 和每个 file lineage 的首个 baseline。

GC visibility

Pinned、活动 task、未解决冲突、prepared/applying intent 和仍被 branch ref 引用的 checkpoint 不回收。其余 blob 到期后显示 Review available / Code restore unavailable。

Secrets

blob 不进入日志、遥测或模型上下文；session 删除一并清理无引用 blob。外部路径必须有当时和恢复时的明确授权。

Read cache and drafts

Read cache 受 64 项 / 16 MiB LRU 限制；dirty draft 独立持久化，受 32 项 / 8 MiB 配额保护且绝不自动淘汰。

Legacy sessions

旧 checkpoint 只用于只读 Review 或明确标记 unavailable；没有 digest/recovery contract 时不提供新 Undo/Rewind code 模式，也不保留无 request_id 的兼容入口。

TUI parity

/rewind 先展示同一 server plan，再选择模式并确认；不能继续直接调用旧 rewind_to。

App/Web parity

同一 plan/apply 协议和幂等 request id；UI 只渲染 server 返回的 canonical impact，不在客户端重算。

Line comments

绑定 change_set id、before/after blob pair、side 与 hunk/line；scope、branch 或 restore 变化后标 stale，不能发送到另一版本。
