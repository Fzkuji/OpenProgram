Agent 协作 — 工具面

一个agent手上跟别的agent打交道的全部工具，按四个域摆开：计划、执行、实体、通讯。 这页讲清每个工具管什么、谁有权对谁做什么、两个预算怎么兜底。 设计文档：docs/reference/design/runtime/agent-collaboration.md

01四域词汇表

四个域各有一个名词。名词分清楚了，工具名就不用记：每个域的工具都在操作它自己那个名词。

计划

todo

纸面上的"打算做"

手写的计划清单。只是写下来的意图，不对应任何在跑的东西，改它不会让任何agent动起来。

todo_createtodo_updatetodo_list
执行

task

机器里的"正在做"

派出去正在跑的活：一个单号、一个状态、一份结果。它是台账上的条目，不是干活的那个实体。

list_taskstask_outputtask_stop
实体

agent

干活的那个东西

生一个新的、给已有的派活、查通讯录、让干完的退役。一个agent就是会话DAG里的一条分支。

agentlist_agentsarchive_agent
通讯

message

说话，和读历史

零权力地捎一句话过去；或者不打扰任何人，直接读任意一条分支的全文。

send_messageread_conversation
最容易混的两组：todo和task同是"任务"两个字，但一个在纸上一个在机器里，所以计划板用todo_*前缀， 执行台账用list_tasks这种动宾名。task和agent也不是一回事：停掉一个task只是停那一轮活， agent本体还在通讯录里；让agent退役是archive_agent。

02一个agent能做的四件事

生、派、聊、查。前两件产生task_id进台账，第三件不产生，第四件只读。

怎么读：四条横道从左边的"我"出发。生和派都走agent这一个工具，区别只在有没有to=： 没有to=就新建一条分支，有to=就把活交给已经存在的那条。两者都开一份台账条目，拿回一个task_id。 聊走send_message，话送到就完，没有单号。查四个工具全是只读的。
颜色：绿=造实体 · 橙=受管任务和台账 · 蓝=消息 · 青=只读。虚线=异步回流。

03权力模型：消息零权力，任务有权力

同样是"把内容送到另一条分支上跑一轮"，消息和任务给出的承诺完全不同。差别就写在收件人第一眼看到的那行抬头里。

承诺消息 send_message任务 agent() / agent(to=)
谁能发起任何agent，对任何未归档的分支同样任何agent，但产生的单号只归自己
有没有单号没有，只回一个delivery_id告诉你送到了有task_id，进台账，list_tasks能查
对方必须回吗不必。抬头明说"没什么要补充就别回"必须。这一轮的最终回复就是任务结果
能不能叫停不能。话已经送到了，撤不回来task_stop，排队中的直接撤回，在跑的停那一轮
取消会不会传染无从传染级联：停一个任务，它派生的任务全停
能操作别人的吗不涉及，消息本来就没有后续控制权不能。task_output/task_stop有归属检查
多方并发安不安全安全。零权力，最坏就是对方不理安全但有账：目标忙就排队，不会被打断
杀掉一个agent本体的权力另算，只归创造者：每次spawn都把创造者记在新分支上， archive_agent拒绝任何别的会话。没有记录创造者的分支属于它自己的会话。见下一节。

04两个预算：一个计数器，两条上限线

一条链是从一次用户轮长出来的全部东西。链上每跳一次计数加一，回复回流也算一跳。两个预算读同一个计数器，只是上限线画在不同位置。

两个都支持设0，0就是这条线不存在，什么也不拦。

# 命令行改，即时生效
openprogram config set agent.max_spawn_depth 1   # 默认：主agent生worker，worker自己干活
openprogram config set agent.max_spawn_depth 2   # worker可以再开一代，第三代被拒
openprogram config set agent.max_spawn_depth 0   # 不限层数

openprogram config set agent.max_messages 8      # 默认：一条链最多传8跳
openprogram config set agent.max_messages 0      # 不限条数，agent之间随便聊
设置页的Agent分组里是同两个数字框：Max spawn depth、Max messages per chain，改完即时生效， 落盘在~/.openprogram/config.json的agent段。 两个都设0之后，防失控就只剩并发上限（OPENPROGRAM_TASK_WORKERS，默认4）和用户自己按停。
有一条规则不受预算影响：自己发给自己一律拒。to=指向发起方当前这条分支是直接的环，立刻拒掉。

05归档：砍的是被打扰权，不是历史

分支在会话DAG里永远留着，fork、回放、读全文都指着它。所以退役不是删除，只是在分支上打一个archived标记。

06典型场景走一遍

三条最常走的路。同一批工具，组合方式不同。

场景一 · 派一批活出去

手上有五件互不依赖的事。计划先落纸，再一件件派出去，最后回来销账。

01 计划
todo_create(subject=…)
五件事写成五条。blocked_by标出谁等谁。
02 派
agent(prompt, description, run_in_background=true)
逐条派。后台形式立刻返回task_id，不占我这一轮。
03 盯
list_tasks()
五个单号五个状态。要结果就task_output，要撤就task_stop。
04 收
结果自动回流
不用轮询也行。谁跑完谁的结果就接到我这条会话后面，我醒来读到。
05 销账
todo_update(todo_id, status="completed")
纸面回到和机器一致。

场景二 · 找一个已经存在的agent

活已经有人做过一半了，不该再生一个从零开始的。先看通讯录，再决定是捎话还是正式派活。

01 看通讯录
list_agents(scope="all")
按会话分组。每条分支给名字、一个能直接用的to="SID:HEAD"、轮数和大致字数、还有末尾预览。
02a 捎话
send_message(to="名字", message=…)
问一句、通知一声、把结论同步过去。不占单号，对方可以不理。
02b 派活
agent(to="名字", prompt=…)
活确实归他做，而且我要结果。开单号，可叫停，结果必回。
03 忙就排队
目标在跑就进收件箱
不打断也不丢。他这一轮完了就接着跑我这条。

场景三 · 复盘一段旧会话

想知道上次那件事到底怎么做成的，但不想惊动任何人，也不想把整段历史灌进上下文。

01 拿地址
list_agents(scope="all")
同一份通讯录。顺手看它标的轮数和字数，心里有个体量。
02 只看结尾
read_conversation(session_id="SID:HEAD", start_turn=-10)
负数从末尾数，-10就是最后十轮。list_agents给的SID:HEAD整串粘进去也认。
03 要不要工具细节
include_function_calls=false
默认连每轮调了什么工具、参数、结果都给。只想看对话就关掉。
04 控体量
max_chars=60000
超了就丢后面的轮次。归档的分支也照读，读不打扰任何人。

07和Claude Code的对应

同名的地方是有意对齐的，差别只有一处命名冲突和三个我们多出来的口子。

这边Claude Code关系
agent同名同义。生新agent的唯一入口；to=派活是我们这边的扩展
list_agents同名同义。看得见对方是通信的前提
send_message同名同义。跨分支捎话
task_outputTaskOutput参数形状照抄：block默认true，timeout毫秒，默认30000，上限600000
task_stop同名同义。我们额外加了归属检查和级联取消
todo_create / todo_update / todo_listTaskList 同物不同名。他们的TaskList是计划板，和我们的list_tasks撞名不撞义， 所以我们的计划板一律走todo_*前缀，把list_tasks这个名字留给真正在跑的活
list_tasks没有我们多出来的：让模型自己查后台跑着的活，不必攥着spawn时那个task_id不放
archive_agent没有我们多出来的：agent不退役，通讯录就会一直堆着早就做完的worker
read_conversation没有我们多出来的：一条分支渲染成可读的文字稿，带轮次范围和体量上限，不用去啃原始记录文件
一句话收尾：四个名词分四个域，agent一个工具管生和派，消息零权力所以随便发， 任务有权力所以只能碰自己派的，两个预算兜住失控，归档只收回被打扰权。
