统一错误合同与前端展示

“后台报错前端必须显示”定义为：所有影响用户请求、持久状态、后台任务或可恢复操作的失败都必须进入可观察错误记录。它不要求把每个内部降级或重试都显示成 Toast，也不允许把 traceback、文件内容或凭据发送到浏览器。下列 schema 是唯一最终 wire 合同；TASK 1 服务端持久化切片已为公共 dispatcher 和首组管理 action 生成完整字段并在发送前记录，list/ack、前端恢复、展示和其余错误源仍按后续切片实现。

  "type": "operation_error",
  "data": {
    "error_id": "err_opaque_unique_id",
    "request_id": "client_request_id_or_null",
    "scope": "session | job | settings | channel | agent | transport | system",
    "code": "stable_machine_code",
    "message": "safe user-facing summary",
    "action": "safe_action_or_null",
    "session_id": "session_id_or_null",
    "operation_id": "action_job_execution_id_or_null",
    "retryable": false,
    "severity": "info | warning | error | fatal",
    "correlation_id": "opaque log lookup id",
    "occurred_at": "ISO-8601 UTC"

错误合同字段/状态唯一语义
request_id由客户端为请求/响应 action 生成；成功或失败必须回传同一值并结束 pending。operation_id 标识服务端实体，不能代替 request ID。
error_id每次失败唯一。Toast 去重键为 scope + code + session_id + operation_id，5 秒内相同键只显示一次；错误记录仍分别保留。
UserErrorStore使用当前 profile 下独立 SQLite 文件，按已认证 principal 隔离；创建时间起最多保留 7 天且每个 principal 最多 1,000 条。发送必须发生在事务提交之后；记录失败时不发送伪 durable envelope，而关闭连接并要求 state recovery。
severityinfo 只进入诊断；warning 显示局部 degraded 状态；error 显示卡片和一次 Toast；fatal 显示持久阻断状态并停止自动重试。
生命周期请求成功只结束对应 request_id 的 pending。恢复帧为 {type:"operation_recovered", data:{error_ids:[...], scope, operation_id, occurred_at}}；服务器必须列出要关闭的具体 error_id，前端不得按模糊 code 批量关闭。用户确认或实体删除也只关闭明确 ID；普通后续成功不能隐式清除不相关错误。
Job 失败job_status(status=errored) 是 Job 状态的唯一 wire 事件，前端由它生成 error-store 记录；不得再为同一失败发送第二个 operation_error。operation_error 只用于 Job action 请求本身失败。
事件类别前端行为持久性不得包含
当前会话请求失败对应卡片或控制项附近显示原因；首次接收显示一次 Toast。写入会话错误记录；刷新后仍可见。traceback、原始环境变量、未过滤 provider body。
后台 Job 失败会话列表显示错误标记；AttachCard/Jobs 显示摘要和可重试状态。跟随 Job 实体持久化。子进程完整 stdout、文件全文。
设置或管理操作失败保留上一个已知状态，显示操作失败；不把失败解释为空列表。错误中心保留到用户确认或后续成功。credential value、token、绝对 secret path。
可恢复内部降级默认不 Toast；相关表面显示 degraded 状态，诊断面可查询。结构化日志与指标。面向用户的重复提示。
传输断开显示连接状态；自动恢复期间不重复产生相同错误。仅在超过恢复预算或有未确认操作时进入错误中心。每次重连尝试对应一个 Toast。
Server normalization

单一安全 payload 构造器

helper 只生成经过过滤的 error data，并负责字段校验、日志关联和 session routing。WS action/channels/system 将该 data 包装为 operation_error；JobRunner 把同一 data 嵌入唯一的 job_status，不生成第二个 error envelope。

Frontend error store

单一状态入口

use-ws 只解析并交给 error store；错误卡片、会话标记和 Toast 从同一记录派生，避免不同组件各自解释 code。

Action correlation

明确请求完成

需要请求/响应的 action 使用 request ID。成功和失败都结束 pending 状态，任何按钮都不能无限保持 loading。

Compatibility adapter

旧帧逐步迁移

迁移期间前端把现有 error、action_error 和 Job error 适配到统一记录；后端逐项切换后删除兼容分支。

05

会话加载与刷新设计

目标是让首屏成本由当前可见内容决定，而不是由整个会话历史决定。持久化仍以 SessionDB/DAG 为准；Web wire 只传页面当前需要的投影。

阶段返回内容触发条件缓存键
Session manifest标题、状态、head、revision、当前链 ID、计数、功能状态、错误摘要。切换会话或无有效 manifest。session_id + revision
Viewport messages当前可见链尾部消息和必要的 compaction/attach 引用。首屏或滚动到未加载范围。session_id + head_id + cursor
Graph summary节点 ID、边、角色、状态和最小标签，不包含消息正文与工具结果。用户打开 DAG 或分支面板。session_id + graph_revision
Node/detail单节点上下文、完整工具输出、runtime tree、附件详情。用户展开或导航到具体节点。session_id + node_id + content_revision
Reconnect delta已知 revision 后的持久提交，以及每个运行中实体已知 seq 后的状态和终态事件。连接恢复且服务器仍保留连续增量。客户端提交 known_session_revision 和 known_stream_seqs: {entity_id: seq}
Full recovery新的 manifest 和有限 viewport，不是完整历史。revision 不兼容、delta 已淘汰或客户端状态无效。重置本地 session projection
唯一来源：SessionDB/DAG 是持久状态的唯一权威来源。现有 MessageStore 只复用 block、seq 和 delta 计算代码，不成为第二个持久 store；不能复用的独立持久化和 singleton 接口在 TASK 4 删除。所有 full recovery 都从 SessionDB projection 生成。
协议量定义保留与回退
session_revision每个 session 单调递增的整数。一次 SessionDB/DAG 原子提交只增加一次；manifest、message header、Graph summary 和持久错误都标记其读取 revision。永久随 session 持久化。客户端 revision 高于服务端或 schema 不兼容时拒绝 delta 并返回新 manifest。
stream_seq每个运行中 message/job 独立单调递增；只描述尚未形成持久提交的 text/tree/progress 增量。当前 worker 每实体保留最近 256 个 delta 或 15 分钟，以先达到者为准。worker 重启把未完成实体持久标记 error/aborted，客户端随后执行 manifest recovery。
delta journal由持久提交生成的 from_revision → to_revision projection change；不保存完整正文副本。内存保留最近 512 次提交或 15 分钟。缺口超过保留范围时返回 manifest + 有限 viewport。
viewport cursor稳定二元组 (created_at, message_id)，按当前 head 链逆序分页；首屏最多 100 条且未压缩 JSON 最多 512 KiB，以先达到者为准。向历史方向分页；head 改变时 manifest 给出新 cursor。单条消息超过剩余预算时只返回 header、摘要和 detail marker。
detail cursor单节点/工具结果每次最多 1 MiB 未压缩内容；更大结果按 UTF-8 安全边界分块并返回 next cursor。每次读取都重新执行 session/node/caller 授权；不得通过 cursor 跨节点或跨 session。
计算与发送的分离边界

同步线程读取不可变 SessionDB 快照、建立 ID 索引、计算当前链与 Graph summary，并返回普通数据对象。异步 handler 在发送前再次校验 session revision；若期间发生写入，发送 manifest 后追加 delta，或放弃旧快照重新读取。线程内不得直接操作 WebSocket。

需要删除的重复计算

预先创建 id → insertion_index，替代排序中的 all_msgs.index；兄弟分组按 predecessor 一次建立；同一请求只读取一次 session row；Graph summary 与消息正文分开序列化。

大字段与兼容

保留当前 32 KiB 工具结果 marker 和 get_full_tool_output 权限检查。进一步把 context tree、runtime blocks、Graph node content 和附件 metadata 纳入按需读取。旧客户端仍可请求旧 action，但服务端需要设置硬载荷上限并在超过时返回升级提示，而不是继续生成无界帧。

WebSocket 队列、顺序与恢复

浏览器标准 WebSocket API 不提供自动背压，因此服务器必须限制自己的发送队列。每个连接由一个 sender task 顺序发送，生产线程只执行线程安全的 enqueue。

帧类别示例队列规则溢出行为
不可丢终态error、question、chat final、job terminal、ack、permission result保持顺序，不覆盖，不跨 session 合并。无法在预算内排队时关闭连接并标记需要 state recovery；不得静默丢弃。
可合并增量text/thinking delta、tree update、progress、context stats按 session + entity + type 保留最新或合并相邻文本。删除被更新取代的旧增量，并记录 coalesced 计数。
快照sessions list、branches、settings、graph summary同一 key 只保留最新未发送快照。替换旧快照；不影响终态。
控制pong、auth/status、reload required小型独立预算，防止被大消息完全延迟。认证或协议错误立即关闭；pong 可丢弃旧值。

队列上限与关键预留

每连接限制 256 帧或 4 MiB，以先达到者为准；其中 64 帧和 1 MiB 只供不可丢终态。关键帧入队前先清除可合并增量，不能占用普通快照的旧版本。

发送所有权

只有 sender task 调用 ws.send_text。断开时取消 sender、释放队列并注销 focused session；其他线程不保留 WebSocket Future。

重连

指数退避并加入随机抖动；页面重新可见或用户明确重试时可提前触发。成功后先恢复协议状态，再恢复会话投影。

观测指标

记录 queue_frames、queue_bytes、oldest_age、coalesced、send_failures、disconnect_reason 和 recovery_mode，不记录帧正文。

关键帧恢复合同：source 在 enqueue 前持久化 chat final、job terminal、用户可见 error、question 和 permission request。所有用户可见 error 同时写入有界 UserErrorStore，按 error_id 查询，最多保留 1,000 条或 7 天；session manifest 只携带相关未关闭 ID，重连通过 list_user_errors(cursor) 读取详情。transport close 由客户端根据 close/timeout 本地生成，不依赖服务端错误帧。chat ack 只在用户消息落盘后发送；其他 request ack 必须能通过 request_id 幂等查询或重放。若关键预留仍满，服务器关闭该连接并标记 state_recovery_required；客户端重连后从 manifest、UserErrorStore、pending-question registry、Job store 和 request result 查询恢复，不能依赖未发送的内存帧。
MDN WebSocket

标准 WebSocket API 不提供自动背压；继续使用兼容性最好的 WebSocket，但必须在应用层限制队列。

MDN bufferedAmount

客户端可用 bufferedAmount 监测未发送字节，但该值不能替代服务端每连接队列和恢复协议。

Python asyncio.Queue

采用正数 maxsize 的 FIFO 队列；跨线程入口使用 event loop 的线程安全调度，不直接跨线程操作 Queue。

EventBus 执行模型与日志

EventBus 保留两种明确语义：gate 是同步决策；notify 是异步观察。二者不能共用“当前线程直接调用 handler”的执行方式。

属性GateNotify
用途在动作发生前允许或拒绝。记录、更新 UI、触发后续非阻塞工作。
执行位置emitter 线程；默认总预算 events.gate_timeout_ms=50。EventBus 自有 event loop；同步 consumer 在线程池执行，async consumer 在该 loop 执行。
失败维持现有 fail-open，并写结构化警告和 gate 结果。隔离消费者；重试只由消费者策略决定；不得静默跳过。
顺序注册顺序。同一 session + entity 有序；不同 key 可并发。
背压不排队；超过预算时跳过剩余 gate 并记录。有界队列；关键事件不能被普通遥测占满。
日志事件和 gate verdict 合并成一条记录。异步批量写；大型 payload 使用长度、摘要和受控片段。
Notify 队列合同规则
顺序键优先使用 session_id + entity_id；只有 session 时使用 session；两者都没有时使用 type + origin。同一键严格 FIFO，不同键可并发。
容量普通队列最多 4,096 事件；关键状态队列最多 512 事件。关键类型是 operation error/recovered、question、job terminal、turn end 和标记为 critical 的 ws.frame。
满队列progress/context stats 等遥测按键合并或丢弃并增加明确指标；关键队列满时 source 的持久状态仍是恢复依据，bus 写入 emergency loss marker 并通知 Web 连接执行 state recovery。不得只打印 stderr 后继续假定已投递。
关闭与重启正常关闭最多排空 2 秒；剩余 notify 记录 shutdown loss marker。关键业务状态在 emit 前持久化，重启后由各 store 的 recovery 扫描恢复，不把 EventBus 当 durable queue。
Gate 安全边界EventBus gate 只承载插件/工作流的附加决策，维持 fail-open。权限、认证、sandbox 和凭据校验不使用该 fail-open gate，继续由各自强制边界拒绝。
日志唯一性事件根据 session 是否存在只写 session log 或 global log 之一；同一目标文件中一个 event ID 一行。gate event 在 verdict 完成后写一次，不能先由 notify 写一行。
Registry integrity

AST 级注册检查

测试解析 Python AST 中的 emit_safe、make_event 和常量事件名，覆盖跨行调用；动态名称必须显式登记例外和消费者。

Single record

事件只记录一次

tool.before 的观察与 gate 共享同一 Event；最终日志包含 gate 字段。不能先写普通行再写 verdict 行。

Payload policy

高体积字段摘要化

tool.after.result_text 默认记录字节数、错误状态、哈希和有限预览。完整结果仍在 SessionDB/工具结果存储，不复制到事件日志。

错误不是原样转发所有事件

EventBus 到 Web 的桥只转发经过注册的用户相关 envelope。内部事件日志和用户错误流相关联，但不能直接暴露任意 payload。

兼容风险、采用与排除

选择处理理由与边界
标准 WebSocket + 应用层有界队列已选设计浏览器兼容性稳定；服务端仍需要明确队列、合并和恢复语义。
现有 MessageStore seq/delta部分复用只复用 block/seq/delta 计算；SessionDB/DAG 已确定为唯一持久来源，独立 store 接口删除。
统一 operation_error已选设计前端需要稳定 machine code 和安全文本；旧错误帧通过短期 adapter 兼容。
EventBus notify 专用执行环境已选设计满足非阻塞观察合同；gate 不迁移，继续同步。
本地打包 marked/KaTeX已选设计与严格 CSP、离线使用和可重复构建一致。
放宽 CSP 允许 CDN拒绝增加远程脚本信任和可用性依赖，不能解决首次连接等待。
WebSocketStream / WebTransport 全面迁移拒绝浏览器支持或复杂度不符合当前范围，也不能替代持久恢复和错误合同。
全局 React store/组件重写拒绝当前已有 rAF 合并、单消息订阅和行回收；未证明它们是主要限制。
自动删除 Chrome Profile拒绝可能移除登录态、IndexedDB、扩展或其他用户数据；只允许显式分类清理。
迁移风险：会话加载协议改变会影响刷新顺序、分支切换、运行中卡片、问题重放和 send queue。TASK 4 必须先记录所有现有 frame 顺序与 public-entry RED，再逐层替换；不能直接把整个 async handler 放入 to_thread。

TASK 1 长期合同与实施切片

边界长期合同当前实现
Wire envelope第 04 节 schema 是唯一最终合同；nullable 字段必须显式为 null，不得把 exception 或命令 payload 复制到 wire。公共 WebSocket dispatcher 的 unknown action、未处理 handler exception 和首组管理 action 已生成全部最终字段；chat reply 自有 error turn 不在该路径重复生成。
关联身份request_id 是客户端生成的单次命令关联值，不作为权限或幂等凭据；服务端只回显非空、无控制字符且不超过 128 个字符的值。session_id 和 action 同样只回显安全字符串。缺失或非法关联值返回 null，不得回显原始对象、超长文本或内部异常。
错误分类unknown_action 表示协议或版本不匹配且不可重试；handler_error 表示命令处理失败并保守标为不可重试。后续 action 必须使用注册 code，前端未知 code 使用通用低敏提示。当前公共路径按 session、agent、settings、channel 或 system 分类；不把 exception message、traceback、路径、凭据或命令 payload 放入 wire/store，完整 traceback 只进入本地结构化日志。
兼容新前端同时消费 operation_error 与旧 action_error；新服务端不发送双帧。Web 静态资源和 worker 属于同一发布单元，协议不承诺新服务端配旧前端。保留 actionErrorNotice 与 consumeActionError 导出作为源码兼容别名，内部归一化为同一个 notice。
持久恢复UserErrorStore 以 error_id、session 和 request 建索引，记录按已认证 principal 隔离；list、acknowledge 与 reconnect recovery 使用明确 ID。SQLite store、1,000 条/7 天界限和 persist-before-send 已实现；list/ack wire action、关闭生命周期和前端 hydration 尚未实现，因此当前不声明刷新恢复完成。
展示当前会话内错误、后台错误标记和 Toast 共享去重键；聊天回复已有 error bubble 保持原语义。dispatcher 命令失败继续显示一个 Toast；不同 session 的错误不得进入当前会话专属视图。
第一切片验收：真实 _websocket_handler 对 unknown action 和 handler exception 返回 operation_error，回显合法 request_id，拒绝非法元数据，保持连接处理后续 ping；新前端对新旧帧生成相同低敏 notice，未知 code 不显示 wire message/error。
第二切片验收：agent 的 list/add/delete/set-default、channel account/binding/session-alias 的 list/add/remove/attach/detach，以及 settings 的 get/set 存储异常均通过真实 _websocket_handler 生成且只生成一个低敏 operation_error，不发送对应正常空集合或成功结果，并继续处理后续 ping。TUI 同时消费新旧命令错误 frame，不渲染 wire message/error；带有其他有效 session ID 的错误不会写入当前 transcript，只有当前 session 的 chat action failure 会结束对应 turn。
第三切片验收：公共 dispatcher 为每次失败生成并严格校验最终 12 字段 data，先按已认证且格式有效的 owner principal 提交到 profile-scoped SQLite，再进入连接发送队列；发送失败不丢服务端记录，持久化失败不发送伪 durable frame 并以 state_recovery_required 关闭连接。存储回归覆盖 reopen、principal 隔离、线程与多进程首次并发写、跨 principal 过期清理、容量、7 天边界和低敏 wire/store。
