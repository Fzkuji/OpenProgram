Read implementation status precisely

StateRequired meaning
ImplementedThe described contract has an implementation and the required verification evidence. State the verified boundary explicitly.
PartialSome paths exist, but named implementation or acceptance requirements remain.
UnimplementedThe design specifies behavior for which implementation is still required.
Out of scopeThe behavior is excluded from the current design; it is not an implicit implementation task.
Not reverifiedExisting evidence has not been checked against the current source or target environment. Do not convert it into a current pass.

What each implementation document contains

  1. Public entry points and the observable behavior they provide.
  2. Source owners and links to the implementation, including compatibility entry points.
  3. Data ownership, state transitions and persistence boundaries.
  4. Failure, cancellation and recovery behavior where applicable.
  5. Reproducible verification commands and the specific contract each checks.
  6. An implementation-status appendix listing remaining work and acceptance gaps.

Maintain architectural rationale in the topic's design. Keep implementation notes focused on the source mapping and verification. Use Git history for migration chronology and previous review output rather than duplicating them across pages.
