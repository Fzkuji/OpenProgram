Status definitions

  • Review-passed branch: implementation exists at the exact commit and independent scoped reviews reported zero remaining findings.
  • Merged to main: reviewed head has been merged into origin/main and passes the combined regression gate.
  • Partial: earlier tasks are review-passed, but the tracked plan still has required implementation or evidence tasks.
  • Candidate only: code or reports exist, but there is no single accepted integration head with final review evidence.

4. Smaller uncompleted hardening work

Integration and release order

  1. Stabilize the main worktree. Commit, move, or discard the current uncommitted account/channel/memory/Desktop/Web work under its owner's direction. Integration must not stage it incidentally.
  2. Finish partial plans on their own branches. Complete JSON Tasks 6–7 and credential Tasks 3–5 before integration; create one accepted resource-governance head.
  3. Integrate one branch at a time. Rebase on the chosen mainline, inspect the complete diff, resolve conflicts at shared security/runtime boundaries, and rerun that feature's focused and affected suites before adding another branch.
  4. Run the combined release gate. Run unit, agent, provider, Web, CLI/TUI, security, docs build/link, Ruff, type/build, mechanical matrix, and git diff --check checks from the combined head.
  5. Publish evidence last. Update feature-matrix symbols and implementation evidence only for contracts proven on the combined head. Record unrelated environment blockers separately rather than treating partial suites as full completion.
