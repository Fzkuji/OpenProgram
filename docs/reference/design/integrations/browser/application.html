Browser application

The built-in browser is the application openprogram/programs/applications/browser/. The core never imports it: the application's setup(ctx) provides the service browser, and every core caller looks it up with _services.lookup("browser") and runs without a browser when the lookup returns None.

The Agent operates the browsers with one tool, computer_use. The application registers no target itself: the browser connection kind built_in of this computer looks the service up and yields the target type="browser", the App's tabs through the tab driver, then app="chrome" and app="edge" for each of the user's browsers with the extension installed. Their actions are in Browser tab actions.

The service's members are pages, tabs, extension, open_tab(url) and authorized_page(arguments, window_id).

A Program's web tabs

Item
Opentabs.openWebTab of the framework interface calls open_tab(url): the tab opens in the background for the running conversation, as create_tab of type="browser" does.
ActA native presentation command on a web tab names it with arguments.tab, the tab's id from list_tabs (omitted: the tab the conversation used last). authorized_page checks it against the App's current window and binding and sends the App its own tab id.
AuthorityBoth need what computer_use needs: a turn that may not use the screen tool may not reach a web tab this way either.
