远程 OpenProgram 机器

每台电脑，Mac、Linux 或 Windows，各自运行自己的 OpenProgram。与它配对的另一台电脑在自己的列表旁列出它的项目和对话，标上那台机器，并在那里打开、发消息、停止和确认。不复制任何东西。

术语

术语含义
远程 OpenProgram 机器机器登记表（机器与目标）里带 OpenProgram 连接的机器：另一台电脑 Worker 的地址，以及让 B 在那里登录的设备凭据
对话的归属日志里存着它的那个 Worker。每一轮都在那里运行：它的模型账号、工具、记忆和文件。在别处被查看不会改变归属
设备与某个 Worker 配对的任何东西：手机、浏览器，或另一台电脑的 Worker（配对设备）

与 SSH 机器不同。SSH 主机上的项目，对话仍在这台电脑上，只有命令在那里执行。

同类做法

同类另一台电脑的工作怎么出现采用
T3 Code每台电脑是一个环境。一个应用同时连多个，合并它们的项目，并通过一个以同样流格式只读转发的中转读取已连接机器的对话。工作从不悄悄跨环境多台机器在同一个列表里；转发同样的帧，不另立对话格式；对话留在它的机器上
DSH Mobile手机列出每台已配对的电脑，在它们之间切换列表里显示每台机器的在线状态
OpenClaw一个网关，已配对的设备互相批准配对是唯一入口
Warp、Nimbalyst、Cursor 云端智能体对话经厂商的同步服务复制不采用：需要服务，而且一轮需要的文件和账号不会跟着走

决定

问题选择与原因
谁连 AB 的 Worker，而不是 B 的页面。凭据留在 B 的凭据库，从不进浏览器存储；B 的每个页面，包括手机，不用各自和 A 配对就能看到 A。每台机器一条连接，负责列表和在线状态；B 上每个操作 A 的对话的页面各有一条转发连接，A 的回复只送到那个页面
复制还是转发转发。B 要时才从 A 取列表；打开对话时才从 A 取它的内容，按页读取，与在 A 上一样。B 不往磁盘写任何 A 的东西
哪些操作转给 A凡是指向归属 A 的对话的 WebSocket 操作，都原样转给 A：打开、翻页、发送、插话、停止、确认、分支。规则按对话判断，以后新增的操作自动跟随，不用逐个加转发项
列表list_projects 和 list_sessions 返回 B 的条目加上每台已连接机器的条目，每条带 machine_id；A 的项目 id 变为 @<机器>/<id>。B 向 A 请求时带 local_only，所以两台互相配对的电脑不会把对方的列表再列回去。侧边栏像对 SSH 机器的项目那样分组，并显示机器的连接点
新建对话建在项目所在的机器上。选 A 的项目就在 A 上新建
文件、@ 搜索、终端通过 A 自己的接口在 A 上读取，就像通过 SSH 主机的 shell 读它的文件。第二步
A 离线A 的项目仍在列表里，显示断开的连接点，打开时什么都不显示；没有报错页。B 不留副本，也就不会显示过时内容
版本Worker 在握手里声明 remote_machine 能力。没有声明的不连接：机器那一行显示需要更新，不转发任何东西，双方都不会读到看不懂的帧
路由B 知道列出的每个对话在哪台机器上；在 A 的项目里新建的对话，从第一帧起就归 A。与 B 自己对话同 id 的仍归 B；A 发来的、指向别的电脑对话的帧被丢弃
A 发来的帧原样交给页面，只有关于 A 的 Worker 本身的帧（函数、模型服务、构建、它自己的列表）不交，否则会覆盖 B 的
权限B 以 A 的所有者身份操作 A，和任何配对设备一样。在 A 上吊销 B，连接立即关闭

设置

这里的一切都在 App 里配置；命令行仍是同等的另一种方式。

位置作用
A 上的设置 → 设备一个列表：OpenProgram 操作的电脑，以及与它配对的手机和浏览器，每台手机可改名、可吊销，并显示最近使用时间。添加设备先问是什么设备（照搬 Codex 和 Claude 的流程）：手机或平板或另一台电脑 → 让它用这台显示二维码和链接，链接带着所有已打开的地址，十分钟有效，过期后自动换新。列表下方是从哪里打开这台电脑：同一 Wi-Fi 和任何地方（见下）
B 上的设置 → 设备添加设备 → 另一台电脑 → 在这里看它的对话：粘贴 A 的链接。B 在 A 第一个有响应的地址上兑换，这台机器带着连接点出现。它的菜单里没有编辑：只能通过配对添加
手机或浏览器扫 A 的二维码即登录 A；无需安装
设置 → 渠道 → 添加 bot → 微信在窗口里画出微信二维码，并显示等待扫码、已扫、已确认、已过期几种状态，用的是现有的 start_channel_login 操作。终端命令不再是唯一方式

连接方式

做法生效
同一 Wi-Fi在 Worker 进程里、用同一个应用再开一个监听，绑定这台电脑的私有网络地址，运行中的服务器随之接受这个地址的 Origin；web.lan 记住这个选择（interfaces/server/lan_listener.py）。地址取路由所走的网卡；代理隧道占着路由时，改取这台电脑自己的名字在本地解析出的地址；只算 10/8、172.16/12 和 192.168/16。换了网络，下次读取时监听会跟着换地址立即；主监听仍是回环
任何地方运行时 bin/ 里的 openprogram-tailnet（Go，apps/tailnet）通过 tsnet 内嵌 Tailscale，用 Tailscale Funnel 在 https://<名字>.<tailnet>.ts.net 上监听，这是带正式证书的公开地址。它把每个请求（包括 WebSocket）代理到 Worker 的回环端口，保留 Host 并设置 X-Forwarded-Proto: https，所有者认证信任来自回环地址的这一头。web.anywhere 记住开关立即；监听地址仍是回环

Worker 把它作为子进程运行，这个 profile 的 Tailscale 身份放在 <state>/tailnet，并逐行读取 JSON 状态：

  • starting
  • needs_login，带 Tailscale 登录链接
  • needs_funnel，带开启 HTTPS 和 Funnel 的管理后台链接
  • running，带地址；只在此期间运行中的服务器接受这个地址
  • error，带出错原因

配对链接列出所有地址：第一个带 #pair=<配对码>，其余每个写成 &via=<origin>。浏览器忽略其余地址；另一台 OpenProgram 全部保存，每次连接都依次尝试，就像 T3 Code 依次尝试一台机器的各条路由。

不需要安装任何东西。所有者打开开关，在浏览器里登录一次 Tailscale（免费的个人 tailnet 就够），如果 tailnet 还没开 HTTPS 和 Funnel，再开一次。

手机不需要应用，用浏览器打开地址即可。能访问地址不等于能登录；和同一 Wi-Fi 一样，每台设备仍要用一次性配对码配对。

同类做法：Claude Code Remote Control 和 Codex remote control 经它们自己的服务器中转，手机通过厂商连到电脑。OpenProgram 没有可中转的服务器，所以内嵌 tsnet。

OpenClaw 和 T3 Code 也借 Tailscale 从别处连到电脑，但要所有者自己安装它。
