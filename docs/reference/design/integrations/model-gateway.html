Model Gateway

Claude Code and Codex send their model calls to the Worker instead of to Anthropic or OpenAI. The Worker answers them with the model the user picked among OpenProgram's providers, in the harness's own protocol.

Upstream calls go only through OpenProgram's configured providers and their own credentials. An Anthropic model is reached with an Anthropic API key, as everywhere in OpenProgram; the key or token a harness sends only opens the gateway and is never forwarded.

One internal format

A request is read into the same Context, messages and SimpleStreamOptions the agent loop uses, sent through stream_simple, and the provider's events are written back in the client's protocol.

The provider adapters already convert both ways between these types and every upstream API, so the gateway adds only the client side. A call therefore gets the provider layer's credential rotation, retries and fault tolerance; the gateway adds no second retry layer.

The gateway key

The owner token changes with every Worker start, so a config file could not hold it. The gateway key is random, kept owner-only in the state folder and survives restarts.

The owner-auth middleware accepts it, as Authorization: Bearer or x-api-key, only on /gateway/ paths; the owner token works there too. Every gateway request needs one of them, from any address. Backups keep gateway/ with the credentials, because harness configs written for the terminal carry the key.

Also in the Terminalconfig.toml: model_provider, model and the table with experimental_bearer_tokensettings.json: the same variables under env and the top-level model; CLAUDE_CODE_USE_BEDROCK/_VERTEX/_FOUNDRY removed while on

ANTHROPIC_MODEL is never set: it would override the model picked with /model. Nothing else is added to a harness's config: no MCP servers, permissions or instructions, and no prompt text names the gateway.

Editing a harness's own config

  1. The file is parsed first. A file that does not parse is unknown: nothing is written and the page says why.
  2. The original value of every key about to change, or that it was absent, goes to the stash before the first write.
  3. Only those keys change. TOML is edited line by line and the result is parsed and compared with the intended change; JSON keeps its key order and indentation. Comments, CRLF and symlinks are kept; the write is a temp file renamed over the original.
  4. Turning it off, or going back to the harness's own sign-in, restores each value that still holds what OpenProgram wrote. A value the user changed since is drift: the card shows it and it is never restored over. The stash entry is deleted only after the restoring write succeeded.
  5. Codex's [model_providers.openprogram] table is never removed, because a thread started on it cannot reopen without it; only model_provider goes back.

The Codex app

The Codex app inside ChatGPT.app runs its own codex app-server on the same ~/.codex, so the same config.toml reaches it (codex_app.py).

GapWhat OpenProgram does
Its model pickerLists model/list, which shows only Codex's own models for a provider it does not ship. The enabled models are written to openprogram-models.json beside config.toml and named by model_catalog_json; the chosen one comes first. Each entry is Codex's own metadata for an unknown model: the window OpenProgram knows or 272K, the model's thinking levels as its reasoning efforts, and the prompt.md instructions of the installed Codex's release, read once and kept
Reading the changeIts app-server reads the config only as it starts. Turning on or off ends the app's own app-server (in an app bundle, stdio, on this Codex home) with SIGTERM once no session file was written for 20 seconds, for up to 15 minutes; the app starts another and keeps its windows and chats. A new model alone restarts nothing

Taken from magpie

magpie (yetone/magpie) runs the same kind of gateway.

  • Taken: explicit model refs; Claude Code's tier variables without ANTHROPIC_MODEL; Codex's provider table that is never removed; the Codex app's catalog and its app-server restart on a route change; stash-before-write with drift; refusing a config that does not parse; errors in the client's protocol with no fallback after the first byte.
  • Not taken: serving a Claude subscription by running the claude binary; rules for one vendor applied to all; additions to the harness's config that were not asked for.

Implementation status
