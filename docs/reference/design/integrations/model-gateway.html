Model Gateway

Outside agents (Claude Code, Codex, and any client of the same APIs) send their model calls to the Worker instead of to their vendor. The Worker answers them with the model the user picked among OpenProgram's providers, in the agent's own protocol.

Upstream calls go only through OpenProgram's configured providers and their own credentials. An Anthropic model is reached with an Anthropic API key, as everywhere in OpenProgram; the key or token an agent sends only opens the gateway and is never forwarded. No subscription sign-in is relayed: no ChatGPT login traffic, no Claude sign-in token.

The design is a port of magpie (yetone/magpie, MIT License), whose Go code covers about ninety agents. Where code is ported, the module names the magpie file it comes from.

An agent with no model field and no link is a switch: it lists the gateway's models itself and is only turned on and off.

A file whose settings come back as they were gets the user's own bytes back: the stash keeps its text from before the first write (up to 256 KB), as magpie's beforeMagpie does for its copies. A one-line JSON file is edited on one line.

One internal format

A request is read into the same Context, messages and SimpleStreamOptions the agent loop uses, sent through stream_simple, and the provider's events are written back in the client's protocol.

The provider adapters already convert both ways between these types and every upstream API, so the gateway adds only the client side. A call therefore gets the provider layer's credential rotation, retries and fault tolerance; the gateway adds no second retry layer.

Model namesExplicit provider/model refs (split_model_ref), optionally prefixed openprogram:; an unknown name is a 404, never an alias
Thinking signaturesThe model's own value (an Anthropic signature, a Responses reasoning item, a Gemini thoughtSignature) goes to the client wrapped with the model that made it and comes back only to that model. A Claude Code client of an Anthropic model gets Anthropic's own signature. None is made up; an unsigned thinking block never goes to Anthropic.
Codex freeform toolsapply_patch reaches the model as a function with one input string and the grammar in its description, and returns as custom_tool_call
Gemini requestssnake_case or camelCase; a function result is the user's side of the turn whatever role it came under, matched to its call by id, else to the first unanswered call of that name; OpenAPI schemas become JSON Schema

The owner token changes with every Worker start, so a config file could not hold it. The gateway key is random, kept owner-only in the state folder and survives restarts; backups keep gateway/ with the credentials.

Claude Code's Explore and Plan declare model: inherit, which Claude Code reads before CLAUDE_CODE_SUBAGENT_MODEL; with a Subagents model set, the gateway moves their tool turns onto it (claude_subagent.py, magpie #7176), read from the chat's launch file when the request names one, else from the user's settings.json.

ANTHROPIC_MODEL is never set: it would override the model picked with /model. Nothing else is added to an agent's config: no MCP servers, permissions or instructions, and no prompt text names the gateway. Codex's join mode, which would pass ChatGPT sign-in traffic through, is not offered.

The OpenCode format

opencode_format.py is OpenCode's config shape, after magpie's openCodeLike, opencode_v2.go and opencode_providers.go: a provider openprogram with @ai-sdk/openai-compatible, the gateway's Chat Completions and key, setCacheKey, and every enabled model with its window, image input, reasoning and its levels as variants (weakest first; none is an empty set, so OpenCode 2 does not invent low, medium and high).

Models are openprogram/<provider>/<model>. The provider is OpenProgram's own object (Write.owns); what the user adds stays and is no drift: a header, a setCacheKey, a variant, a limit.output they typed.

That last is magpie's outputsKept: the stash records each reply limit OpenProgram has wanted for a model, and a value that is none of them is the user's.

The provider is the model list a sync rewrites; the model picks are a second write on the same file, left as the user changes them. A small model unpicked again is the agent's own: the one OpenProgram wrote goes, with an object it added to hold it.

Agents in Pi's format

Pi keeps the model a session starts on in settings.json and providers in models.json. agents/pi_like.py (magpie piLike, piModelOn) writes the provider openprogram there:

  • Chat at /v1, each model on the API its provider serves natively: Responses, Messages at the Anthropic root, Gemini at /v1beta.
  • Each model's window, reply limit, a thinkingLevelMap naming every level, and a prompt-cache lifetime.
  • The model joins enabledModels when that list exists and nothing in it takes the model in. Keys the user added to the block stay.
  • After a sync, an entry naming a model no longer given leaves enabledModels and comes back with the model; a list left empty goes and comes back (magpie scope_gone.go). What left is kept in the stash record (Wiring.record, saved by a sync too). The same holds for StepCode and omp.
  • On disconnect the pick goes back only while defaultProvider is still openprogram; then enabledModels loses every entry naming one of OpenProgram's models (magpie piScopeWithout).
  • The choice fields: effort (defaultThinkingLevel), and for Pi protocol, every model asked on Chat, Responses or Messages (magpie piProtocolField); a picked protocol replaces an api the user set on the provider.

Gemini's API, and agents with their own models
