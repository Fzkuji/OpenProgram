Remote OpenProgram machines

Each computer, Mac, Linux or Windows, runs its own OpenProgram. A computer paired with it lists its projects and conversations beside its own, marked with that machine, and opens, writes in, stops and approves them there. Nothing is copied.

Terms

TermMeans
Remote OpenProgram machineA machine in the registry (Machines and targets) with an OpenProgram connection: the address of another computer's Worker and the device credential that signs B in there
Home of a conversationThe Worker whose log holds it. It runs every turn: its model accounts, tools, memory and files. Never changes by being viewed elsewhere
DeviceAnything paired with a Worker: a phone, a browser, or another computer's Worker (Paired devices)

Different from an SSH machine. A project on an SSH host keeps its conversations on this computer and runs only commands there.

Decisions

QuestionChoice and reason
Who connects to AB's Worker, not B's page. The credential stays in B's credential store and never reaches browser storage; every page of B, phone included, sees A without pairing with A itself. One connection per machine carries the lists and the online state; each page of B that acts on A's conversations gets a forwarded connection of its own, so A's replies reach that page and no other
Copy or forwardForward. Lists come from A when B asks; a conversation's rows come from A when it is opened, page by page as on A itself. B writes nothing of A's to disk
Which actions go to AEvery WebSocket action that names a conversation whose home is A goes to A unchanged: opening, paging, sending, steering, stopping, approvals, branches. The rule is by conversation, so actions added later follow without a forwarding entry each
Listslist_projects and list_sessions answer with B's items plus each connected machine's, each item carrying its machine_id; A's project ids become @<machine>/<id>. B asks A with local_only, so two computers paired both ways never list each other's lists back. The sidebar groups them as it groups an SSH machine's projects and shows the machine's connection dot
New conversationCreated on the project's machine. Choosing A's project creates it on A
Files, @ search, terminalRead on A through A's own routes, as files on an SSH host are read through its shell. Second step
A offlineA's projects stay listed with the disconnected dot and open to nothing; no error page. B keeps no copy to show stale content from
VersionsA Worker names the remote_machine capability in its handshake. One that does not is not connected: the machine row says it needs an update and nothing is forwarded, so neither side reads frames it does not understand
RoutingB knows which machine each listed conversation lives on, and a conversation started in A's project belongs to A from its first frame. An id that is also one of B's own stays B's; frames from A naming another computer's conversation are dropped
Frames from APassed to the page unchanged, except those about A's Worker itself (functions, providers, build, its own lists), which would overwrite B's
AuthorityB acts on A as A's owner, as any paired device does. Revoking B on A closes the connection at once

Ways in

HowApplies
Same Wi-FiA second listener, in the Worker's process and on the same app, bound to this computer's private network address, whose Origin the running server then answers; web.lan keeps the choice (interfaces/server/lan_listener.py). The address is the route's interface, or the addresses this computer's own name resolves to when a proxy tunnel holds the route; only 10/8, 172.16/12 and 192.168/16 count. A new network moves the listener on the next readAt once; the main bind stays loopback
TailscaleRuns tailscale serve --bg --https=443 to the Worker's loopback port and adds https://<name>.ts.net to the configured and the running Origins. Serve passes the Host it was dialled at and X-Forwarded-Proto: https, which the owner-auth check already believes from a loopback peerAt once; the bind stays loopback

A pairing link names every address: the first with #pair=<code>, each other as &via=<origin>. A browser ignores the rest; another OpenProgram keeps them all and tries them in order on every connection, as T3 Code tries each of a machine's routes.

Peers: OpenClaw and T3 Code both recommend Tailscale for reaching a computer from elsewhere; Claude Code and Codex relay through their own servers, which OpenProgram has none of.
