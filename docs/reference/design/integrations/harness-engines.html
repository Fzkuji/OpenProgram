Harness Engines

A conversation can be run by an outside coding agent instead of OpenProgram's own agent loop. The agent makes the model calls and runs its own tools in its own sandbox; OpenProgram shows what it does, asks the person its approvals and keeps the record.

The engines are Codex, Claude Code and DeepSeek Harness (over ACP); other ACP agents follow the same shape.

Threads, machines and switching

Machine
The engine runs on the conversation's machine, with that machine's Codex and sign-in; a paired machine's list comes from that machine. The Environment and Channel chips do not change.
Which Codex
The one the user installed: harnesses.codex.binary when set, else codex on PATH, else what the login shell finds. Codex lists only the models its version can run, so updating Codex brings its newest models.
Folder
Each turn/start carries the conversation's current folder.
Branch
Each branch keeps its own Codex thread and the id of the last message it saw.
Handoff
When a thread starts on a conversation with history, or resumes after turns it did not run, it first gets those turns as a budgeted transcript, newest kept. Switching back to OpenProgram needs nothing: Codex's turns are stored as ordinary messages and tool calls.
Crash
A process that exits fails the running turn; the next turn starts a process and resumes the thread. A second turn while one runs gets a process of its own, closed when it ends; the kept process then reloads the thread before its next turn.
Keeping it currentHow
Newest versionnpm for an npm, bun or pnpm install, else OpenAI's release channel; read hourly (runtime/harnesses/codex/maintenance.py)
Models it would bringThose in model-manifest.json the installed Codex does not list. Bundled, refreshed hourly from this repository's main; add a model there when Codex ships one
UpdateThe installer the file belongs to: npm/bun/pnpm global add of @openai/codex@latest, brew upgrade [--cask] codex, mise upgrade codex or codex update. Any other install shows the models without the Update row

DeepSeek Harness over ACP

DeepSeek Harness is the second engine (runtime/harnesses/deepseek/). It is driven as an Agent Client Protocol client: dsh --profile acp, one process per conversation, the same line protocol and process pool as Codex. Its sessions are saved with the DeepSeek Harness app's own and use the app's sign-in.

Claude Code

The person's own Claude Code runs the turn (runtime/harnesses/claude_code/): claude -p in stream-JSON mode, the protocol Anthropic's Agent SDK speaks to it. Claude Code signs in and calls the model itself; OpenProgram never reads its credentials or calls Anthropic for it.

App threads
Once an engine went on in an app's thread on one branch, the app's record of it is neither resumed nor forked by another branch; that branch starts a session with the handoff.
Two turns at once
A branch's process runs one turn. A second turn on the same branch gets a process of its own, closed when it ends; the kept process then resumes the session again.
Images
Attached images go in with the message as image blocks.
Lost session
When Claude Code says it has no such session, the turn starts a new one with the handoff, and later turns go on in it once it begins. Any other failure keeps the old session's record.
Steering
A message sent mid-turn may be answered as a turn of its own, and the turn waits for that one's result. A process that took steering is not reused, so nothing queued in it reaches a later turn.
Effort
No request unsets an effort, so going back to Claude Code's own default starts another process. A model change sets the effort again.
Written turns
The person's message goes in with a uuid of its own. That uuid and the record uuids a turn writes are kept while it runs and when it fails, so the app sync never copies them back, even after a Stop. Claude Code's interruption note is not a message.
Unanswered messages
A DeepSeek Harness message stopped before any answer has no id. The sync skips such a message when the conversation here already shows it. An app's last unanswered message waits a minute for an answer, then is written as stopped.
Earlier readings
When an earlier reading counted turns this one does not, the sync finds the newest turn it wrote that the app still has and numbers new turns after it.
A process that ended
A kept process that ended between turns is replaced, and the turn is sent to the new one.

Implementation status

Codex runs chats, natively or through OpenProgram's models, and the Codex app's conversations are synced both ways. DeepSeek Harness runs chats over ACP and its app's conversations continue in their sessions.

Claude Code runs chats with the person's own sign-in, and the Claude app's and terminal's conversations continue in their sessions. Next, with the same engine shape: other ACP agents (Gemini CLI, OpenCode).
