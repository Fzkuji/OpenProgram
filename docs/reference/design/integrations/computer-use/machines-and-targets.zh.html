机器与目标

三条规则

规则含义
调用写明落点device 指明机器，type 指明操作它上面的什么：window、screen 或 browser。不写 device 就是这台电脑，也就是 Worker 和 App 所在的那台，任何对话都一样。环境和之前的调用都不会改变一次调用落在哪里。
工具从不改变工具的说明和参数在整段对话里保持不变。现在能操作什么，写在用户消息旁边的 <devices> 说明里（模型读到什么）。
一个意思一种写法同一个动作在所有目标上只有一个动作名和一套参数名。模型从别的工具带来的名字会被改写，不会被拒绝。

概念

概念是什么
机器一台有自己操作系统的电脑：这台电脑、SSH 主机、Docker 机器、虚拟机、装了 OpenProgram 的另一台电脑。只有一份注册表。一台机器就是 id、名字、启用开关和一种连接。
这台电脑内置，连接方式是 local，不存进配置；调用不写 device 就是指它。
设备调用怎样指明一台机器：它的 id（也接受它的名字）。操作系统是设备的属性，写在 <devices> 里，从不作为调用参数。
连接怎样够到一台机器：一种方式（它的 kind）加这种方式的设置（连接方式）。它不说在那里做什么。
项目某台机器上的一个文件夹：（机器，文件夹）。它的对话在那台机器的那个文件夹里运行。
环境一个角色：对话的命令和文件工具运行在哪台机器上，即它项目的机器。它的连接方式必须能跑命令：local、ssh 或 docker。
类型操作的是哪一类东西，它决定动作词表。window：按元素树操作应用窗口。screen：整块显示器。browser：网页；不写 app 是 OpenProgram 运行的浏览器，写 app="chrome"、"safari"、"firefox" 等是用户自己的浏览器（用户的浏览器）。类型属于 computer_use，不是机器的属性。
目标一次调用的 device、type，以及浏览器的 app 所指的东西。它的键把三者连起来，略去这台电脑和 OpenProgram 自己的浏览器：window、browser chrome、lab screen。锁、权限规则和资源列表用这个键；模型从不写它。
对象目标里的哪一个：窗口用 app 和 title（窗口标题，是数字时为 window_id），浏览器用 title（标签页 id 或标题），整屏用 display。
提供方经一种连接方式给出一类目标的模块。

规则细节
设备层不懂功能一种方式登记名字、显示名、设置结构、可达检查、区分两条连接的信息和它够到的地址。host/machines 里没有任何地方说经它做什么。
每个功能自己对应方式命令功能：host.backend.SHELLS，把 local、ssh、docker 对应到命令怎么跑。computer_use：registry.offer(method, opener)，每个提供方模块登记一个打开函数；没人登记的方式不给出目标。新功能加自己的对应，不碰设备。
这台电脑没有可编辑的设置。它给不给整屏由 computer_use.whole_screen 决定，不属于它的连接。
密钥标为密钥的设置（配对凭据 token）按设置名存在 state/auth/machines/<id>.json。

虚拟机是一台机器：vm 不再是类型，computer_use.vm_url 删除。

机器和环境

问题决定
注册表一份，machines，取代环境注册表。身份、配置和连接由所有功能共用。
绑定两种，互不合并。环境来自项目（项目记录上的 machine_id，resolve_for_project），从不来自对话：对话有了 session 后项目就固定，机器也就不变，它保证命令在哪里生效。目标每一轮列一次，每次调用选一次。
SSH 或 Docker 对话里不写 device 的调用仍然作用在这台电脑上。工具说明、<devices> 和 <environment> 段都会写明，内置浏览器那一行还会写明它的 localhost 是这台电脑的。
既跑命令又被操作的机器只有这台电脑。SSH 主机和 Docker 机器是环境，不给 computer_use 任何目标；另一台电脑的 OpenProgram 用 device="<m>" 操作，不在这里跑命令。是环境不会让一台机器成为默认。
实例shell 声明 instance_scope。machine：只有一个实例。conversation（Docker）：每个对话一个，第一次用到时创建，随对话删除。状态、锁和屏幕服务进程都按实例区分。
身份机器的 id 不变，能改的只有名字。不带 id 添加的机器，id 由名字生成（Dev Box 变成 dev-box，再有就是 dev-box-2）。删除或停用一台机器时，先让正在进行的调用结束，再关闭它的提供方，并按标签删除它的实例。
选机器在打开项目时：在…上打开文件夹先选机器，再选那台机器上的文件夹。这台电脑和 Docker 机器（它挂载这台电脑的文件夹）用文件夹选择器；SSH 主机通过它的 shell 浏览（list_machine_folder），从它的远程文件夹设置开始，文件夹在主机上转成绝对路径（resolve_folder）。
一个文件夹一个项目一台机器上的一个文件夹是一个项目；这台电脑上的文件夹不论哪台机器运行，都只属于一个项目。主项目总是这台电脑。没有默认环境，也没有按对话的选择。
项目的机器不在了被停用、连接方式不能跑命令或被删除：它的对话的命令和文件调用被拒绝，绝不换成这台电脑。选择器把它的项目置灰。
连接状态host/machines/status.py：已连接、连接中（还没有回应）、已断开（已停用）或出错。列出机器时，上次结果超过 60 秒就在回答之后检查一次；它上面每次 shell 文件调用也报告所见。machines 帧里每台机器带 status，变化时广播。App 把它显示为机器图标上的点：绿、转圈、灰、红。
App 在哪显示机器项目选择器按机器分组，这台电脑在前。侧栏的项目标题对另一台机器上的项目显示那台机器的图标（另一台电脑上的机器用 Solar 的 server-2，和文件夹图标一样大）、点和名称；对话行从不显示机器。输入框的机器胶囊显示项目的机器，不能切换；菜单说明由项目决定。
SSH 主机上的项目文件夹在主机上读写：文件面板、它的搜索、@ 文件搜索和文件工具都走它的 shell；删除的条目移到主机上的 ~/.openprogram/trash。快照、自动提交、工作树和分支标签需要文件夹在这台电脑上，所以不为它提供。
不能是这台电脑以下会被拒绝：解析到这台电脑 22 端口的 SSH 目标（回环地址上的其他端口是转发过来的虚拟机或容器，可以添加）；报告自己就是这台电脑的屏幕服务或 cua-driver；回环地址，且添加机器时取到的截图就是这台电脑自己的画面。这台电脑靠不写 device 来指明。
一个地址一台机器两台机器不能共用它们连接方式够到的同一个地址，比如同一个 OSWorld 服务器的 URL。
用词设置 → 设备用的是模型在 device 里写的那个词。openprogram machines（list、add、remove、enable、disable、test）和配置键 machines 保留原名。add ID [--name NAME] METHOD [KEY=VALUE ...]；list --kinds 列出连接方式和它们的设置。设置 → 设备里每台设备只有一个“连接”：先选方式，再填它的字段。项目选择器写在…上打开文件夹。
代码host/environments 变成 host/machines。连接方式在那里登记（kinds.py）；解析、校验、设置和 CLI 里不出现任何方式的名字。

目标

调用写落在何时列出
type="window"这台电脑的应用窗口，按元素树操作；驱动做得到时在后台进行本机驱动受支持：macOS、Windows、Linux X11
type="screen"这台电脑的一整块显示器；会移动真实指针所有者打开了整屏（computer_use.whole_screen，默认关闭），且本机驱动受支持或 Wayland 会话带桌面门户
type="browser"OpenProgram 浏览器里这个对话的页面浏览器应用已启用
type="browser", app="chrome"、"safari"、"firefox" 等用户自己的浏览器，带着他们的登录状态装了这个浏览器，Chromium 系还要装扩展
device="m", type="window"m 上的应用窗口，在那边运行m 经 openprogram 连接且已启用
device="m", type="screen"m 的整块屏幕m 经 osworld 连接，或经 openprogram 连接且已启用
device="m", type="browser"，任意 appm 上 OpenProgram 的浏览器或用户的某个浏览器，在那边运行；它的 localhost 是 m 的m 经 openprogram 连接且已启用

一个目标被列出，当且仅当为那台机器的连接方式登记的某个打开函数给出了它。SSH 主机和 Docker 机器不给出目标。

列表的规则

规则细节
列出就是已配置只有配置变了列表才变：设置、装上的扩展。能力按提供方声明，从不探测。关着的机器照样列出，调用时回答 MACHINE_UNREACHABLE:；检查连不上的机器会在它的段落里说明（模型读到什么）。每一轮不做网络探测。
配对的电脑只要它启用着，就列出它的 window、screen 和 browser，不去问它。去问的话，每一轮都要和每台配对的电脑往返一次，常常是一台睡着的笔记本；而那台电脑本来就会准确拒绝，并附上它确实有的目标：它没有的类型、够不到的浏览器、关着的整屏。
名字配置的机器用它的 id 指明；也接受它的名字，不区分大小写。设备写 local、localhost 或 this computer 都是这台电脑。
窗口标题title 按标题的一部分选窗口，是数字时按 window_id 选。标题匹配到多个窗口时拒绝，并列出候选窗口和它们的 id，这样调用不会落到没想要的窗口上。标签页标题匹配到多个标签页时同样拒绝。
只有一条路有自己目标的表面，不再通过显示它的本机窗口来操作。提供方可以为发起询问的对话认领这类窗口：这个对话的连接已附加其标签页的 Chrome 或 Edge 页面（不报告地址的窗口，如在 Linux 和 Windows 上，仍归 type="window"）。
被认领的窗口type="window" 保留窗口自己的控件，略去被认领的内容，并指出该怎么调用它。机器可以写明 viewer，也就是显示这台机器的本机应用和窗口。没被认领的内容仍归 type="window"。
window 还是 screenwindow 用于某一个应用的窗口。screen 用于桌面、菜单栏、系统对话框、跨窗口拖动，以及不理会后台输入的窗口。两者并存是有意的：如果禁止 screen 点进窗口，这类窗口就无法操作。
screen 默认关闭所有者打开 computer_use.whole_screen 之前关闭：local 不打开整屏，所以 type="screen" 既不列出也不能调用，调用会在任何审批之前得到 UNKNOWN_TARGET:。
为什么关闭一般任务只需要一个应用，所有者决定默认不把整个屏幕交给 agent。Codex 的电脑操作没有整屏这一层（每次调用都指定一个应用，按键只发给这个应用），所以关闭时能做的事和它相同，需要时这条路仍在。
替换本机驱动这台电脑自己的另一种驱动，比如同时用于 window 和 screen 的 cua_driver，会是为 local 登记的另一个打开函数。调用、键和锁都不变；这台电脑不会有第二个名字。
停用每台机器有启用开关。列表不会被自动裁剪。

模型读到什么

工具本身，整段对话不变：

computer_use(device?, type, app?, display?, title?, action?, args?, actions?, code?, timeout?)

Operate application windows, a whole screen or web pages, on this computer or on another device.

Where a call lands
- device: left out for this computer. Another device by its name in <devices>. …
- type="window": an application's windows, read as an element tree. app names the application (without app the call lists the running ones); title picks one of its windows.
- type="screen": a whole display, by pixels; it moves the user's pointer. display picks one, the main one without it.
- type="browser": web pages. Without app, OpenProgram's built-in browser; app="chrome" or app="edge" is the user's own browser with their sign-ins, … title picks a tab.
<devices> lists what can be operated now; anything else is refused.

对话里的第一条 <devices> 说明：

<devices>
What computer_use can operate now, by device:
- this computer (device left out): the user's Mac, where OpenProgram runs; calls may send code.
  - type="window": application windows, read and operated in the background; app names the application.
  - type="browser": OpenProgram's built-in browser, this conversation's pages. Its http://localhost is this computer's.
  - type="browser", app="chrome": the user's own Google Chrome with their sign-ins; only when the user names it or the task needs their sign-in.
- devbox (device="devbox"): SSH host me@devbox; this conversation's shell and files are here.
- studio (device="studio"): another computer running its own OpenProgram.
  - device="studio", type="window": application windows of that computer (it lists its own with list_apps)
  - device="studio", type="screen": its whole screen, when that computer has Whole screen on
  - device="studio", type="browser": OpenProgram's browser there, or with app one of the user's browsers there
- lab (device="lab"): virtual machine, pixels only.
  - device="lab", type="screen": virtual machine, pixels only
A target not listed here is refused. A later message says what changes.
</devices>

之后的一轮，用户在 Edge 里装了扩展：

<devices>
Changed devices, as they are now:
- this computer (device left out): …
  - type="browser", app="edge": the user's own Microsoft Edge with their sign-ins; …
</devices>

studio 的检查连续失败 45 秒时，以及之后一次检查成功时：

<devices>
Changed devices, as they are now:
- studio (device="studio"): another computer running its own OpenProgram.
  Cannot be reached right now (last check: ConnectError); calls to it will most likely fail. A later message says when it is back.
  - device="studio", type="window": …
</devices>

<devices>

- studio (device="studio"): another computer running its own OpenProgram.

部分规则
参数device、type，然后是里面的哪一个：app（窗口的应用；浏览器写 chrome 或 edge）、display（整屏）、title（窗口或标签页）；再是做什么：action 和 args、actions 或 code，以及 timeout。只有 type 必填。actions 里的一步仍可写自己的 tab。
为什么 device 可以不写不写永远是这台电脑，从不是对话的环境，所以默认值不会随项目移动：循环、App 和用户都在这里，用户说“我的屏幕”指的就是它。
为什么是 type 和 app每台设备上都是同样三种类型，所以类型和设备是两个独立的词，加一台设备不会多出新名字。用户的浏览器用 app 指明，意思是“哪个应用”，因为用户就是这么说的（“在我的 Chrome 里”）。操作系统不是参数：它属于设备，模型在 <devices> 里读到。
定义固定不变说明和 JSON schema 从不提配置了什么，也没有目标的枚举。请求按工具、系统提示、消息的顺序发送，所以设备连上或权限变化时改写定义，会让整个提示缓存失效。
<devices>用户消息旁边单独一段，从不放进系统提示（BESIDE_ONLY_SECTIONS 里的 devices，紧挨在 deferred_catalog 之前）。按设备分组：先是这台电脑，再是其他设备；没有可操作内容的设备，只在对话的 shell 在那里时才列出。每个目标一行：调用怎么写它、它是什么、缺什么权限（“Not usable yet: …”）。
先整张列表，再只写变化看得到的历史里没有更早的说明时发整张列表：对话的第一轮，以及摘要之后的第一轮。之后只发 Added devices、Changed devices, as they are now 和 Removed devices，没有变化就什么都不发。每轮看到的列表存在它的用户消息上，下一轮和看得到的那份比较，机制和延迟工具目录相同（catalog_shown、catalog_stored 带上列表的 id）。
能否连上另一台电脑的连接检查连续失败 45 秒、中间没有成功过（status.OFFLINE_AFTER；至少两次失败，相隔这么久），它的段落里就多一行：现在连不上，附上次检查的原因（最多 80 个字符），调用多半会失败，之后的消息会说它什么时候恢复。它的目标照样列出。第一次检查成功就去掉这一行，下一条说明的 Changed devices 条目在第一行下面写 "Reachable again"。
不为它探测这一行只读设置页、侧边栏和调用已经做过的检查（host/machines/status.py 的 unreachable）；生成说明从不等网络。正在失败的设备如果上次检查早于 STALE_AFTER，就在回答之后再查一次，同一台一次只查一个，这样不用打开设置也能发现它回来了；连得上的设备不多花任何流量。
为什么要去抖忙碌网络上的一次失败、刚醒的笔记本，否则会让设备在一两轮里先离线再恢复，每次都是模型要读、要据此行动的一条 Changed。去抖只放在记录检查的 status.py 一处；设备旁的图标照样立刻显示最近一次检查。
有自己提示的回合签到、验证或为任务启动的 agent 没有更早的说明可比，所以整张列表放进它系统提示的能力段（components._build_devices）。
回合中途连上的设备在下一条用户消息旁边出现。在那之前指名它的调用会被拒绝，并附上现在列出的目标，和其他未知目标一样。
指南某一类型（window、screen、browser）的指南随第一次操作该类型目标的调用送出。某个目标第一次被操作时再送出几行目标说明：它在哪台机器、什么操作系统、缺什么、快捷键是什么。
结果抬头来自另一台设备的结果以调用对它的写法开头：[device="lab", type="screen"]。环境是另一台机器的对话里，来自这台电脑的结果也加抬头：[type="window", this computer]。
缺少权限目标照样列出并附注；调用时回答 PERMISSION_MISSING:，并说明在哪里授权。
代码cu 只是这次调用的目标，且限于调用写明的对象；它的授权和一次动作调用完全一样，在 Bypass 下每一步也照样受主人的拒绝和询问规则约束，和一次动作调用一样。无人值守的回合，或依据非主人所写文字工作的回合（交接、自动 Goal 回合），代码不运行页面脚本。
在两个目标上用代码要操作两个目标就调用两次，解释器里的变量会在两次之间保留。每一步各自取锁。
cu它的方法就是目标的动作（await cu.click(element=3)）；用另一个目标命名的属性会报错并给出该发的调用，只提现在列出的目标；用它自己类型命名的属性也会报错，因为 cu 本身就是这个目标。某一步指定了别的应用、窗口、标签页或显示器，回答 BAD_ARGUMENT:。
隐藏一个目标都没有时，不提供这个工具。

错误

错误码说明什么
UNKNOWN_TARGET:现在列出的目标，按调用的写法；在权限决定之前检查，所以无论哪种模式，它都先于审批卡片、审查或因无人审批而拒绝
UNKNOWN_ACTION:这一类型里最接近的动作，或者同一台设备上有这个动作的目标
NOT_SUPPORTED:这个目标缺什么，以及可以改用的做法
BAD_ARGUMENT:这个动作的参数写法，再加上这个类型的共用参数；标题匹配到多个窗口或标签页时，附上候选
PERMISSION_MISSING:缺哪项权限，在哪里授予
DEPENDENCY_MISSING:那台机器缺什么，以及安装它的命令
MACHINE_UNREACHABLE:原因；只在什么都没发出去时使用，比如调用找到机器之后机器被关闭或删除
OUTCOME_UNKNOWN:哪几步已完成，哪一步发出后没有回音；先读状态，不要重发
SCREEN_BUSY:另一个 agent 已占用 60 秒，按整次调用计；什么都没发出去
ELEMENT_GONE:元素已不在，或者是别的目标打印的；后面附当前状态
TIMEOUT:已经生效的步骤，或什么都没发出去；动作调用 300 秒后停止（registry.FINISH_SECONDS）；代码里的一步在等锁时被停下（到期、停止、授权被收回），回答 TIMEOUT: stopped while waiting for <target>: …; nothing was sent，并记为没有生效

type 和浏览器的 app 匹配不区分大小写（Google Chrome 就是 chrome），调用绝不会被移到另一台设备或另一种类型上。一批步骤的结果会写明完成了几步。

别的类型的动作回答 UNKNOWN_ACTION: 并列出有它的目标；本类型里这个目标缺的动作回答 NOT_SUPPORTED:，并列出同一台设备上有它的其他目标。

open 和 close 从不把模型指向别的目标：每个类型把它们读成自己的操作，目标没有它们时，UNKNOWN_ACTION: 给出最接近的动作和这个目标自己的动作。

经 OSWorld 的整屏上，一批步骤在发出第一步之前整体检查：一个参数不对就回答 BAD_ARGUMENT: step N (action): …，什么都不发出去；其中的 get_state 一步算作完成，因为屏幕在这些步骤之后读取。

动作的规则

规则细节
按能力放行核心动作需要提供方声明相应的输入能力（pointer、hover、keyboard）；find 和 set_value 需要 tree。缺少时回答 NOT_SUPPORTED:，并给出可行的做法。
元素element 填状态里打印的值：元素树里是数字，页面上是 e12、f1e3 这样的 ref。一个 id 只在打印它的目标上有效。页面还接受 role 和 name。
输入文字type_text 在所有表面上都是插入。clear 先清空字段（字段接受时用 set_value 设为 ""，否则全选再 BackSpace），submit 之后按 Return；这个键失败时，文字算作已完成，结果给出错误和状态。替换输入框的内容用 set_value。
等待带 text 的 wait 反复读状态直到文字出现，最多 seconds 或 10 秒；文字始终没出现不算错误。在窗口上它也读窗口截图里的文字，照顾元素树很少的窗口。
按键用 xdotool 的写法：Return、Escape、ctrl+shift+Tab。super 在 macOS 上是 Command，在别处是 Windows 键。其他写法会被规范化，不是键名的名字回答 BAD_ARGUMENT:；浏览器提供方再转成它自己的名字。快捷键写在目标说明里，不写在类型指南里。
标签页tab 在所有浏览器目标上都是稳定的 id。list_tabs 打印它，每个结果都写明作用在哪个标签页。带 tab 的步骤先选中那个标签页；不带的作用在这个 agent 在该目标上最后用过的标签页，那个标签页没了就回答 BAD_ARGUMENT: 并指出它，什么都不发送。填数字或不存在的 id 回答 BAD_ARGUMENT: 并列出打开的标签页。
用户浏览器的标签页在用户的 Chrome 和 Edge 里，id 由这边生成（t 加一个哈希），扩展重新连接后仍跟着原来的页面；还没选过标签页、或已用 close_tab 关掉自己最后一个标签页的 agent，作用在扩展当前选中的那个上。close_tab 只关闭这一步写明的标签页。带 pattern 或 limit 的 read_console_messages，以及带 only_errors 或 limit 的 read_network_requests，回答 NOT_SUPPORTED:。
用户浏览器的标签页没了别的 agent 关掉了这个 agent 的标签页时，它下一步不带 tab 就回答 BAD_ARGUMENT: 并写明那个标签页。list_tabs 把一步会作用的那个标签页标为当前；agent 的标签页没了时，它会说明这一点，要求每一步都带 tab，并且不标任何一个。选择或列出标签页时，扩展若已没有连接的标签页，就回答 MACHINE_UNREACHABLE:，什么都不发出去；紧跟在 create_tab 之后则回答 OUTCOME_UNKNOWN:。
移动设备（未实现）click 就是点按。scroll 的意思不变：显示那个方向上更远的内容。swipe 给两个点。press_button 用提供方声明的按钮名；把 home、back、音量键交给 press_key 时会转到这里。
应用app 在窗口上指明应用。不写时调用列出正在运行的应用；带它的 get_state 会在应用没打开时打开它。open、open_app 和 launch_app 是带来的名字，意思相同。
类型新提供方加入某个类型，只动它自己的模块。新类型（既没有指针也没有触摸的设备）在 actions/vocabulary.py 加一张表、一份指南和 type 的一个取值。Android 电视会属于 mobile，只是去掉了指针输入。
显示器display 是操作系统给显示器的 id，和 list_displays 打印的一样；不写就是主显示器。截图长边最多 1568 像素，x,y 是那块显示器最近一张截图上的像素。
路径upload_file 和 open_file 里的路径是目标所在机器上的路径。
带来的名字在目标所属的类型里改写。改写会补上它隐含的参数（double_click 补 click_count=2），并且不丢内容：一组键合成一个组合键。完整的表在 actions/vocabulary.py。
带来的参数也会改写：click 的 text 或 key 为空或只写修饰键时变成 modifiers，别的文字回答 BAD_ARGUMENT: 并附 click 的签名；scroll_amount 按每格滚轮 100 变成 pixels；zoom 的 region=[x0,y0,x1,y1] 由四个有限的数或数字字符串组成时变成 x、y、宽、高，其他角值（包括布尔值、NaN 和无穷大）回答 BAD_ARGUMENT: region is [x0, y0, x1, y1] in screenshot pixels.

状态按什么区分

规则细节
指针或前台按平台、按动作在任何一步执行前决定：驱动在步骤执行时才选前台送达，所以凡是有这条路的动作都占住机器，按元素的步骤也一样。macOS：没有。X11：click、scroll、press_key、type_text、hover、drag。Windows：click、drag、press_key、type_text、paste，还有 focus，因为 UI Automation 的 SetFocus 可能把窗口带到前台；scroll 和 hover 是投递的消息。列表不加锁。
顺序跨进程先到先得：在等的请求，无论共享还是独占，都排在所有后来的请求前面，排在本进程另一个请求后面的也一样。每个在等的请求从到达起就在这个键的文件夹里持有一个票据文件 q-*，只有别的进程没有更早的票据还被持有时才去取 gate。一次调用的各次等待共用一个 60 秒的期限，过了就回答 SCREEN_BUSY:。
范围锁是状态目录下的文件，所以在 Worker 的各个进程之间都有效。一次调用持有目标所在机器的锁，以及它驱动的本机窗口的锁：通过模拟器窗口操作模拟器时，也要取那个窗口的锁。
窗口和整屏锁跟着步骤走：同一台机器上的 window 调用和 screen 调用唯一会争的是那一个物理指针。
系统未知时机器的屏幕服务还没报告操作系统之前，它窗口上的指针和按键步骤独占整台机器。
取消远程调用被取消后，锁会保留到那台机器回应或过去 10 秒。
调用只问一次规则键
type="window"computer_use controls <application>；list_apps 不问window <application>，应用的显示名，靠精确匹配读出，不启动任何东西，保留 5 秒：macOS 上任何精确写法（显示名、文件名、bundle id、.app 路径、运行时用的名字、运行中的 pid:N）都得到它，不管运行与否；Linux 上是桌面 id、条目名、可执行文件或 pid；Windows 上 pid 或 exe 得到去掉 .exe 的文件名。其他名字，包括名字的一部分，按原样保留。
type="screen"computer_use controls the whole screen of this computer；list_displays 不问screen
type="browser", app="chrome"computer_use controls your Google Chromebrowser chrome, browser edge
type="browser"对话有 Page 时不问，只有 upload_file 不在 Page 授权之内：每次都由 Ask 和 Plan 询问、Auto 审查；没有 Page 时由模式决定无
带 device、指向另一台电脑的 OpenProgram 的调用每个目标问一次，和这台电脑一样（computer_use controls safari on Studio）；只列出的调用不问<device> <type> 加上应用或浏览器：studio window safari、studio screen、studio browser chrome
其他带 device 的调用不问：配置这台机器就是同意。解析不出的调用在决定之前回答 UNKNOWN_TARGET:；在这次检查和决定之间变得解析不出的，按模式处理（Ask 和 Plan 询问，Auto 审查）<device> <type>（lab screen），用户自己写的规则可以匹配一台或所有设备

应用名里含 *、? 或 [，或以 :* 结尾的规则键不会保存：这样的调用只能允许一次。

screen 的授权就是按表面授权，只是这个表面包含了所有应用；没有它，screen 就绕过了每个应用各自的授权。破坏性步骤仍由说明里的确认段落约束。screen 和 window 共用同一项操作系统授权 computer_use:desktop。用户的浏览器需要 process.exec 权限，只被允许 browser.control 的说话者拿不到它。

另一台电脑的 OpenProgram

部分决定
发送端调用不在这里检查或运行。它的 type、app、display、title、action、args、actions、code 和 timeout（从不带 device）带着配对的 Bearer 令牌发到 POST /api/computer-use/call，依次试每个配对地址，每个连接限时 6 秒。回答是 {text, images, is_error}，图片为 base64；这边在前面加上 [device="studio", type="window"]。
接收端只在那台电脑上运行 computer_use：设备固定为那台电脑，不会再转到别处。用它自己的设置：整屏除非在那边打开否则关闭，操作系统权限是它自己的，computer_use 的 tools.permission_rules 也在那边读：拒绝规则会拒绝，询问规则同样拒绝，因为那边没人被问。
开关允许已配对设备操作这台电脑（computer_use.paired_devices，默认关闭），在接收端的 设置 → 设备 → 这台电脑。关闭时端点回答 403 paired_devices_off，发送端得到 PERMISSION_MISSING:，写明去哪里打开。
其他回答检查已连续失败 45 秒的设备（也就是让 <devices> 出现那一行的同一状态）立刻回答，什么都不发，并在回答之后再查一次，除非正在查或上次检查不到 10 秒（RECHECK_AFTER）。刚失败一次的设备照样去试，丢一个包不会把调用挡回去。401：那边撤销了这台电脑，重新配对。404：那边的 OpenProgram 较旧，去更新。
询问这边对每个目标问自己的用户一次，规则键里带设备名（状态、锁和授权）。

协议MCP 工具 screen_describe、screen_list、screen_get_state、screen_act；通知 screen/report（字段同 native.action、native.window、native.control）和 screen/frame。别人写的服务只要说这套协议，填配置就能接入。
策略随每次列表、读状态和操作调用发送；服务端不保存。元素 id 按 agent 分开保存。
代码computer_use/desktop/ 整个移到 host/desktop/。驱动改为接收一个策略对象（拒绝的应用、密码框、权限模式、取消、录音目录）和一个上报器（action、control、window），不再直接导入 runtime 和资源模块。Linux 和 Windows 驱动现在什么都不上报，改为在和 macOS 相同的位置调用它。
分发把这部分代码（不含嵌入窗口的部分）打成 zipapp。经 shell 时，第一次使用把它传到机器的缓存目录并在那里启动；摘要变了就重传。按地址连接的服务，由 machines add 写出 zipapp、令牌和启动命令给用户拷过去；版本旧了回答 DEPENDENCY_MISSING:。
找到会话在 Linux 上用配置的 display，没有配置时读用户图形会话的环境变量。没有 X 会话回答 DEPENDENCY_MISSING:；是 Wayland 会话回答 NOT_SUPPORTED:；没有无障碍服务时它的窗口类型回答 DEPENDENCY_MISSING:，它的整屏照样按像素工作。
进程每个 Worker 进程里每个机器实例一个，空闲五分钟后关闭，由这台机器的 window 和 screen 共用；进程之间靠文件锁互斥。它不安装任何东西。

怎么显示

行种类归属
OpenProgram 浏览器的页面，在另一台设备上时带设备名web创建的：关闭之前一直列出
本机应用窗口、用户浏览器、本机整块屏幕desktop共用的：调用操作它时才列出
另一台设备的窗口或整屏machine共用的：操作期间列出
对话自己的机器实例machine创建的：对话删除之前一直列出
部分规则
创建的行来自拥有它们的提供方的 created()，所以 Worker 重启后还在。操作对话自己的实例时，只把它那一行标为使用中，不会多出第二行。
预览另一台机器：调用返回的最后一张截图，提供方能推送时显示实时画面。agent 光标由 App 画在这张画面上。
嵌入只有本机窗口能嵌进标签页。用 @ 交出的窗口会写明它的应用和 window_id。

几种情况，各只有一种写法

情况唯一的写法
本机应用里的一个按钮computer_use(type="window", app="Calculator", action="click", args={"element": 12})
几个窗口中的一个带 app 的 action="list_windows"，然后把 title 设为那个窗口的 id
内置浏览器里的页面type="browser"：create_tab 带 url，然后 click 带 element
用户 Chrome 里的页面type="browser", app="chrome"：list_tabs，然后 click，title 设为标签页 id，带 element
带 OSWorld 服务的虚拟机机器 lab，经 osworld 连接：device="lab", type="screen"，click 带 x、y
同一台机器装了屏幕服务改经 ssh 连接，为它登记屏幕服务：device="lab", type="window"，以及同一个服务进程给出的 type="screen"。一台机器只有一种连接方式，所以它的屏幕要么是 OSWorld 服务，要么是屏幕服务，不会两者都是。
另一台 Mac 上的应用机器 studio，已配对，那边打开了“允许已配对设备操作这台电脑”：device="studio", type="window", app="Safari"，在 studio 上运行
远程 Windows 桌面那边装 VNC 服务：device="office-pc", type="screen"。改装屏幕服务就是上一行。
SSH 主机 localhost 上的网页应用device="devbox", type="browser"：create_tab 带 http://localhost:3000
Docker 容器里的桌面机器 builder：device="builder", type="window"，作用在这个对话的实例里
命令在 SSH 主机上，点击在这台电脑上bash 在主机上运行；不写 device 的调用作用在这台电脑上
两台虚拟机device="lab" 和 device="lab-2"，都是 type="screen"
别人的操控电脑服务单独一个提供方（cua_driver）；说屏幕服务协议的用 screen_server。在这台电脑上它登记给 local，替换本机驱动，调用写法不变。
用 @ 交出的窗口type="window"，带上提及里给出的应用，window_id 写进 title
没有桌面的 Worker内置浏览器以无窗口方式运行；window 和 screen 不列出
整块屏幕或第二块显示器type="screen"：list_displays，然后用 display
多个 agent 并行操作不同应用：同时进行，各有各的元素 id；在 X11 和 Windows 上，需要指针或前台的步骤轮流进行。操作同一台虚拟机：一次一个，第二个最多等 60 秒。
手机或模拟器未实现：它会是一台带 type="mobile" 的设备。现在 iPhone 通过“iPhone 镜像”窗口，用 type="window" 按像素操作。
本机 Wayland 会话type="screen"，经桌面门户，按像素；window 不列出

决定和依据

决定依据原因
项目决定机器Codex 把远程项目绑定到主机：项目在 SSH 主机上打开，它的线程都在那里运行对话在哪运行取决于它的文件在哪；按对话选择可能把命令发到没有这个文件夹的机器
没有默认环境同上；Codex 也没有默认主机默认值正是把新对话放到错误电脑上的原因；主项目就是这台电脑
先机器，后文件夹Codex 的远程项目流程：先选主机，再选上面的文件夹文件夹选择器只能显示所选机器的文件夹
主机上做不到的就隐藏所有者的规则：不放报错页快照和工作树在这台电脑的磁盘上运行；为主机上的文件夹提供它们只会失败
设备只说怎么够到；每个功能自己决定对每种方式做什么所有者的决定按能力分连接（shell、window、screen、browser）把两个问题混在一起：怎么够到一台机器，和在那里做什么；还允许自相矛盾的组合：一台设备上 SSH 的 shell 加 OSWorld 的 screen，手改这台电脑的连接。一种连接让每台设备只是一样东西，设备层不懂功能，新功能（操作配对的电脑）只加一条对应，不碰设备
机器和屏幕在同一条记录上cua 的 Sandbox、Claude 远程设备、E2B desktop跑命令的和被点击的是同一台机器，只该有一个身份
每次调用写明设备OpenClaw（每次调用写 node，不猜）。Anthropic 的 computer-use 工具和 OpenAI 的 computer_use_preview 把显示器或环境写进工具定义，一块屏幕一个工具；Claude in Chrome 用列出和选择工具来选浏览器一块屏幕一个定义，屏幕一来一走工具就变；选中的浏览器是后来的调用看不见的状态；写明设备的调用自成一体
能操作什么写在消息里Claude Code 的延迟工具增量：目录先整份发一次，之后只发增删请求里工具排在最前，改任何工具定义都会让整个提示重读；用户消息旁边的说明只改变末尾
不写设备就是这台电脑产品范围；参考框架都没有把命令和屏幕分在两台机器上，这里是有意不同循环、App 和用户都在这台电脑上；含义随对话变就违反了第一条规则
type 代替目标字符串Codex Computer Use，每次调用都指名一个应用每台设备上都是三种类型；按设备和表面拼字符串（screen:lab）名字成倍增加，还得解析
一个工具Gemini 用一个工具覆盖浏览器、桌面和移动设备按表面分工具，正是 Claude 有两套浏览器工具的原因
核心动作名Codex 的 sky、cua-driver只有 Codex 用一套接口同时覆盖窗口和标签页
get_state, element两家都不是这样：Codex 和 Claude 每种表面一个名字现在一张表同时服务元素树和页面；两家的写法都会被改写
用户的浏览器用 app 指明Claude Code：自带浏览器和 Chrome 是两套工具它是单独的目标，有自己的锁和规则键；用户说“在我的 Chrome 里”，而 app 正是“哪个应用”的那个词
不写 app 就是 OpenProgram 的浏览器Claude 桌面 App 把自带的叫“内置浏览器”（built-in browser）它在任何对话里都能用，又不带用户的登录状态，所以是安全的默认；作为应用的 Chrome 仍是 type="window", app="Google Chrome"
操作系统不是参数Anthropic 和 OpenAI 的工具都描述环境，而不是要模型填它它是设备的事实；<devices> 说一次就够
mobile 在同一个工具里，仍用 clickGemini 的移动模式；名字取自 Claude 的模拟器工具和 cua一个名字在所有屏幕上都能用
浏览器额外动作create_tab：Codex 和 Claude 一致；控制台和网络的名字：Claude模型本来就带着这些名字
列出就是已配置原来 vm 的可用性判断每一轮不探测
配置过的机器不再授权产品规则：少弹窗添加它就是同意
配对的电脑和这台一样询问这台电脑自己的窗口、整屏和浏览器授权那是一台真电脑，有别人的应用和登录状态；那边谁也不问，所以在这里问，每个目标一次
不问配对的电脑就列出它的类型列出就是已配置每一轮都和每台配对的电脑往返一次，常常是睡着的笔记本，会拖慢回合；那台电脑会准确拒绝，并附上它有的目标
被另一台电脑操作，那边默认关闭整屏默认关闭配对让那台电脑的对话可以在这里用；被操作是它的所有者在那边再迈的一步
手机要先添加同一条规则插上充电的手机不会被意外操作
整屏授权Claude 对屏幕访问只问一次这个表面包含了所有应用
权限状态和错误码写成文字OpenClaw模型能告诉用户该授予什么
声明的能力和生效的能力分开OpenClaw提供方不能给自己加权限
屏幕服务说 MCPOpenClaw 把 cua-driver 注册为 MCP 服务自己的服务和外面的服务走同一个入口
由 Worker 去连每台机器产品范围让设备主动连进来，解决的是这个产品没有的网络问题
SSH 和 Docker 桌面只用屏幕服务一台机器上每种类型只有一条路走 shell 按像素操作会成为第二条路，而且命令输出是文本

不提供

不提供原因
SSH 主机或 Docker 机器作为目标有屏幕服务之前，computer_use 不为 ssh 和 docker 登记任何东西；这样的机器是环境
RDP参考框架都没有客户端；Windows 桌面用 VNC 或屏幕服务
设备主动连进来由 Worker 去连每台机器；另一台 OpenProgram 通过配对添加，按它的地址去连
iPhone 真机需要在手机上装签名的测试代理；还没有这个种类
远程 Wayland 会话；按元素树操作 XWayland不经门户的对话框就没有输入通道
watchOS、tvOS、visionOS 模拟器没有适合它们的词表
多个工具、每台设备一个工具、以环境为默认违反那三条规则
旧配置和旧的调用写法2.0 之前不为旧版本保留兼容：带 target 的调用和任何未知参数一样被拒绝
