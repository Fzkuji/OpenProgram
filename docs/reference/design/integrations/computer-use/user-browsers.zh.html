用户的浏览器

带 app 的 type="browser" 驱动用户已经在用的浏览器，带他们的标签页和登录状态。每个浏览器动作相同、快照格式相同，背后是三种引擎。

引擎app通道模块
Chromiumchrome、chrome-beta、chrome-dev、chrome-canary、edge、edge-beta、edge-dev、edge-canary、brave、vivaldi、opera、arc、chromium扩展模式的 Playwright MCP，经 Playwright Extension 中继 CDPextension.py
Safarisafari（macOS）osascript：标签页和 doJavaScript 用 JXA，新标签页用 AppleScriptsafari.py，基于 script_page.py
Firefoxfirefox远程代理 WebSocket 上的 WebDriver BiDifirefox.py，基于 script_page.py

模块都在 openprogram/programs/applications/browser/。catalog.py 每个浏览器一行（名字、显示名、引擎、Playwright 渠道、数据目录、可执行文件、bundle id、进程名）；注册表、工具描述和参数检查、提供方以及网页上的名称（apps/web/lib/computer-use/browsers.ts）都按这个顺序读。

决定

决定原因
所有 Chromium 系浏览器都走 Playwright Extension这个扩展在 Chrome 应用商店上，Brave、Vivaldi、Opera、Arc 和 Chromium 都从那里安装。一种通道只需一套动作映射和一套 ref。
没有 Playwright 渠道的浏览器用可执行文件指定，并设 PWTEST_EXTENSION_USER_DATA_DIRPlaywright MCP 0.0.79 只认 Chrome 和 Edge 的渠道。给了 --executable-path 时，它只能通过这个变量找到装了扩展的配置文件，并据此加上 --user-data-dir 和 --profile-directory；不设的话，连接页会在没有扩展的配置文件里打开。
Safari 用 AppleScript，不用 WebKit 或 safaridriverPlaywright 的 WebKit 不是用户的 Safari，没有他们的登录状态。safaridriver 驱动一个单独的自动化窗口，会把用户锁在外面，也不留状态。Apple 事件能到达用户自己的标签页，do JavaScript 在里面运行页面层。
Safari 的异步结果在一次 osascript 运行里轮询doJavaScript 只返回同步值。启动脚本开始工作，把结果按令牌存在页面上；同一次 JXA 运行每 50 毫秒读一次，所以一步只起一个进程，而不是每次轮询一个。
Safari 的标签页键靠启发式保持Safari 的标签页没有 id。只要窗口和序号、或 URL 和标题仍与上次列表相符，标签页就保留它的键；两者都不符的标签页得到新键，所以过期的键会被拒绝，而不是落到别的页面上。
Safari 把错误对应到解决办法-1743 是缺少自动化权限；错误里出现“Allow JavaScript from Apple Events”说明开发菜单里的设置没开；两者都返回 PERMISSION_MISSING 并写明开关。-600 和 -1728 表示 Safari 或标签页没了，调用会说明是哪个。
Safari 截图用窗口截取Safari 没有经 Apple 事件的页面截图。桌面驱动的 capture_window（ScreenCaptureKit）不抬起窗口就能截取，再裁到视口；不是窗口里正显示的标签页会被拒绝，因为它没有像素。create_tab 在后台开新窗口，新页面可以截图，用户看到的也不变。
Firefox 用 WebDriver BiDiFirefox 没有供 Playwright 用的扩展模式，CDP 支持也已移除。Firefox 内置的远程代理对用户自己的配置文件说 BiDi，动作需要的命令都有：树、导航、执行脚本、输入、文件、截图、控制台和网络事件。
端口 9222，在后台启动9222 是 Firefox --remote-debugging-port 的默认值。Firefox 关着时，首次调用带代理启动它（macOS 上用 open -g，不切到前台）。没带代理运行的 Firefox 无法附加，调用返回 PERMISSION_MISSING，请用户重启它。
每个进程一个 BiDi 会话Firefox 只允许一个 BiDi 会话。各对话共用这条连接，各自记住自己选中的上下文；最后一个对话结束时关闭会话，Firefox 继续运行。
Safari 和 Firefox 共用一个页面层两种通道都没有 Playwright 的快照。script_page.py 注入一个脚本，写出与 Playwright 相同的大纲（角色、名称、[ref=eN]）并按这些 ref 操作，复用内置浏览器的指针、悬停、滚动、插入和字段脚本，指南和模型在哪里看到的都是同一种格式。
ref 存在页面上的 WeakMap 里ref 要在调用之间保留，又不能标记 DOM。window.__openprogram 把 ref 映射到 WeakRef、把元素映射到 ref，页面删掉的节点会被释放，它的 ref 返回 ELEMENT_GONE；导航后重新开始。
只对前台标签页用真实输入BiDi 输入以可信事件送达页面，但要求标签页可见；Safari 没有经 Apple 事件的输入。后台标签页由页面层发合成事件（输入、Enter 提交表单、Tab 移动焦点、Backspace 和 Delete），所以选标签页从不改变用户看到的东西。
应用名不区分大小写，浏览器简称是别名模型写 chrome 或 Safari 的次数不比写完整名少。type="window" 的匹配在各平台上本来就不区分大小写；macOS 在精确匹配失败后还会映射简称（chrome 到 Google Chrome，edge 到 Microsoft Edge 等）。
