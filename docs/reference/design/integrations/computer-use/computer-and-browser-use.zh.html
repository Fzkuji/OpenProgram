决定

决定原因
所有屏幕一个工具上下文里只留一份小 schema，而且从不改变，所以设备连上时提示缓存仍然有效。动作随首次结果、在类型指南里送达，模型不需要多一次调用，也不需要记住它们。
目标是同一份约定后面的提供方computer_use 为设备的连接方式登记的打开函数，给出的每个目标打开一个提供方。工具、权限代码和代码模式都问提供方，不点名目标，所以新提供方只是一个模块，只在 <devices> 里多一行，不改工具。
后端共用结果类型和动作名desktop/common/base.py。指南和工具在每个平台上读起来一样，平台缺什么就在目标说明里写明，而不是悄悄不同。
调用方自己操作与 Codex 一样，知道任务的 agent 掌握屏幕。工具里没有任何东西会启动别的 agent，交接时不丢上下文。
状态按 agent，标签页按对话并行运行的 agent 不能互相替换元素编号（state_scope）。浏览器标签页对每一轮、每个 agent 保持同一个 id，所以有意共享。
锁是文件调用和代码里的一步从 routing/locks.py 取同样的键，每个 worker 进程都看得到，所以两个 agent 不会同时操作同一个应用或同一整块屏幕。
页面属于对话，其他窗口不属于谁页面是为这项工作打开的，留到关闭为止。另一个应用的窗口是用户的，每个对话都可以用，所以只在操作时显示。
每一种都是同一个小窗框页面、窗口、终端和应用共用框、手势和标题。新的一种只添加框里的内容。
在标签页打开显示的是同一个对象从不复制：标签页和小窗是同一个页面或窗口的两个持有者，不重新加载，也不会分叉。
画面只在内存里它们是 Agent 看到的东西，不是记录。用户屏幕上的任何东西都不会为显示而写到磁盘。
显示从不阻塞步骤标记流在自己的线程上打开，广播失败就丢掉。步骤既不等待显示，也不因显示而失败。
代码只经 broker 够到屏幕生成的 Python 拿到不透明的资源名和调用的审批范围，每个原语都记为这次执行的一个效果。

computer_use

形态

computer_use(device?, type, app?, display?, title?, action?, args?, actions?, code?, timeout?)
参数含义
device配置过的设备，用 id（或名字）；不写就是这台电脑
typewindow、screen 或 browser；<devices> 没列出的组合，或已停用、未安装的，回答 UNKNOWN_TARGET: 并列出现有目标，无论哪种模式，都先于任何审批卡片、审查或因无人审批而拒绝
app窗口：应用，不写就列出正在运行的应用；浏览器：用户自己的写 chrome 或 edge，OpenProgram 自己的不写
display整屏：显示器，不写就是主显示器
title窗口标题或 window_id，或标签页 id 或标题；匹配到多个时拒绝并列出候选
action、args一步和它的参数；省略时调用打开目标
actions同一目标上最多 20 步 {action, args}，遇到第一个错误就停；状态只返回一次。一步可以写自己的 tab
code在隔离解释器里运行的 Python（见“代码”）；<devices> 写明哪里的调用可以发送它（macOS）
timeout代码调用最多运行的秒数，最多 120（默认 60）；与 code 一起出现
为什么定义固定不变
  • 请求按工具、系统提示、消息的顺序发送，所以设备连上或授权变化时改变的工具定义，会让整个提示重读。因此 computer_use 的说明和 schema 是 tool.py 里的常量，没有目标的枚举。
  • 设置了什么写在用户消息旁边的 <devices> 里：看得到的历史里没有更早的说明时发整张列表，之后只发新增、变化和移除的（机器与目标）。它列出：
    • type="window" 在平台后端能加载的地方，type="screen" 在 macOS 上、所有者打开 computer_use.whole_screen 之后
    • type="browser" 在浏览器应用启用时
    • 用户自己的浏览器（app="chrome"、"safari"、"firefox" 等）在装了的地方，Chromium 系浏览器还要装了 Playwright Extension（extension.installed_browsers，读数据目录，从不碰浏览器；见用户的浏览器）
    • 沙箱能运行的地方，调用是否可以发送代码
  • 缺少操作系统授权的目标仍然列出，附一条说明告诉去哪里授权。
  • 一个目标都没有时，check_fn 隐藏这个工具。

action、actions 和 code 互斥。参数按词汇检查，错误会给出正确的写法，因为 schema 不列出每个动作的参数。

指南投递与用户的浏览器
项
指南每种类型有一份指南（guides/<type>.md：window、screen、browser）：它的动作、参数和结果的样子。每个目标再加几行说明（Provider.note）：它的机器、操作系统、缺什么、快捷键。
投递type_guides.py 把它们登记为内含的工具指南：computer_use.<type> 随第一次操作该类型目标的调用结果送达，computer_use.note.<target> 随第一次调用该目标送达，computer_use.code 在能运行代码的主机上随第一次操作任何目标的调用送达，所以模型在发送代码之前已经读过代码怎么用。
不等待没有调用会等指南：在看到任何一份指南之前就发代码的调用照样运行，指南随它的结果返回。
已知的指南指南是否已知，从 agent 循环最后发出的请求里读取，所以压缩、清除的工具结果和 worker 重启都会让指南重新发送；另一个 agent 写的提示里的指南，会包在发言者的 JSON 信封里到达模型，所以 guides.known 也匹配引号被转义的标记。
按需action: "guide" 返回目标的类型指南、说明和代码指南；help("computer_use.<type>") 返回其中一份。
项
动作OpenProgram 的浏览器和用户自己的浏览器用浏览器类型的动作，参数相同（机器和目标）；只有内置浏览器有窗格和视频。
先选浏览器与 Codex 一样，浏览器用 app 先选定，动作不随它变化。
列出无论扩展现在是否连上，用户的 Chromium 系浏览器都会列出；对连不上的那个调用会用错误码回答。没有扩展时，那个浏览器里的页面是它窗口的一部分，用 type="window" 操作。
服务providers/browser/user.py 把每一步交给浏览器应用的 extension.py，它通过自己的 MCP 客户端运行固定版本的 @playwright/mcp --extension，使用 --browser <渠道>，没有渠道的浏览器用 --executable-path，每个对话和浏览器一个服务，在调用之间保留，只要用过它的 agent（哪怕只列过标签页）还有一个在运行就一直保留；最后一个结束时，连接和它的标签页表一起结束。
关闭agent 结束时从不等待：连接在后台关闭，等其中仍在运行的步骤结束之后，并且只在这期间没有别的 agent 开始用它时才关闭。
连接服务在那个浏览器里打开 chrome-extension://<id>/connect.html，带上它中继的地址，Playwright Extension 连回来，为用户共享的标签页中继 CDP；设置了 computer_use.chrome_extension_token 时，服务传入 PLAYWRIGHT_MCP_EXTENSION_TOKEN，扩展连接时不再询问。
动作映射extension.py 用标签页驱动读取的同样参数，把每个动作翻译成 Playwright MCP 的工具；元素是服务快照里的 ref，或 role 和 name，以 getByRole(role, { name, exact: true }) 找到它。
窗口提供方认领页面是这个对话的连接已附加、且在最近一次列表里的标签页的浏览器窗口，已经不在的标签页不算：type="window" 从它的树里去掉页面，写明调用 type="browser", app="chrome"（或 "edge"），标签条、工具栏和菜单留在那里。不报告地址的窗口（Linux、Windows）和其他页面完整地留给 type="window"。

代码
项
解释器code 在 computer_use/code_mode/sandbox/runner.py 的常驻沙箱解释器里运行（macOS 上用 seatbelt，不能访问文件、网络和进程）。
命名空间cu 就是调用的目标：await cu.click(element=3) 是在那个目标上带这个参数的 click 一步，由主机经同样的检查和锁派发（dispatch.run_steps），每一步一张效果回执（computer_use/code_mode/sandbox/broker.py）。
文档字符串前导代码把类型指南里该动作的那一行作为每个 cu 方法的文档字符串，没有就用它的签名，所以解释器里 dir(cu) 和 help(cu.click) 都能用。
参数说明code 参数自己的说明写着 await cu.get_state() 和 await cu.click(element=3)，所以看不到代码指南的模型仍会写 cu.click(...)，而不是光秃秃的 click(...)。
项
对象代码调用在它的调用于 args 里写明的对象（应用、标签页、显示器）之内操作：一步可以省略它，但不能写另一个。
授权调用的授权覆盖这个对象，所以 code._validator 拒绝会要问别的东西的步骤，目标提供的其他一切都放行，包括页面脚本和打开网站。Bypass 下调用没有要守的授权范围，每一步都得到它作为单独动作调用会得到的判定（code._as_action_calls），只有判定为允许才运行，所以所有者的拒绝和询问规则照样有效。
上传代码里拒绝：从内置浏览器上传会发送本地文件，每次都要问，所以作为单独的动作进行。
页面脚本没人值守的轮次里，或依据非所有者所写文字工作的轮次里（交接、自动 Goal 轮次），不运行页面脚本，代码和动作都一样：code.run 在调用开始时从本轮请求里读取这一点。
项
生命周期一个解释器服务一次执行尝试，所以变量在本轮剩下的时间里保留，不管它的调用针对哪些目标；失败或超时时换一个新的。
持有者解释器按对话和执行持有，元素编号和窗口状态按对话和任务持有（tool.operator，取自调用所在的任务）。
共用的键对话自己的轮次共用一个键，所以一轮操作的是上一轮读过的窗口。对话启动的 agent 作为自己的任务运行，它的读取和代码从不替换主轮次或另一个 agent 正在操作的东西。
项
限制每次调用最多运行 120 秒、100 步。
打印的文字打印的文字保留到 256 KB，其余丢弃并在结果里注明；一步返回的东西交给代码，不计入这个限制。
未派发在输入到达目标之前就停下的一步（带错误码的拒绝、已不存在的元素、找不到的应用、等锁时被停下：到期、停止或授权被收回，回答 TIMEOUT: stopped while waiting for <target>: …; nothing was sent）返回 action_dispatched: false，broker 把它记为未提交。
输入后失败可能已发出输入后才失败的一步，在代码里抛出目标给的消息，之前的步骤保持已执行。
超时超出时间、或解释器停止的调用返回错误结果：已执行的步骤保持已执行，正在运行的那一步可能生效也可能没有，下一次代码调用启动新的解释器，没有这次的变量。
未结回执调用返回时，broker 关闭那些始终不知道结果的步骤的回执（GuiBroker.settle，回执状态 unknown）：由结果告诉模型，没有未结回执比调用活得久。
平台代码模式需要 macOS 沙箱；其他地方的代码调用报告沙箱不可用。
谁来操作
项
调用方调用工具的 agent 自己操作屏幕，把任务做完。工具没有把任务交给别的 agent 的参数，所以失败的一步在失败的地方重试。
长任务code 在一次调用里运行许多步，只返回它打印的东西，中间的屏幕不进入对话。
多块屏幕同时在不同屏幕上工作要经过 agent 工具，基础指令只在用户或项目指令要求子 agent 时才允许。每个 agent 有自己的窗口状态、元素编号和代码解释器，锁让两个 agent 不会同时在一个应用上。
时间限制工具没有总时间限制。动作调用在期限 300 秒时停下（registry.FINISH_SECONDS，即释放时等待进行中调用的时长），回答 TIMEOUT:；代码在自己的超时停下。
