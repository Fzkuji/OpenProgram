同类框架

对比的 21 个框架里有两个提供这个端点：Hermes Agent（/v1/chat/completions 与 /v1/responses）和 OpenClaw（/v1/chat/completions，默认关闭）。Claude Code 和 Codex 提供的是自己的 SDK 和 app-server 协议，OpenProgram 对应的是 ACP 和 MCP 服务端。下面的选择在两者一致时照它们做，不一致时写明跟的是哪个。

决定

问题选择、跟随的框架与理由
端口与密钥Worker 自己的端口，用它的主人令牌作 Authorization: Bearer；不另设密钥、开关或权限关卡。两家都把端点放在服务端已有的 bearer 密钥后面。这个令牌本来就能打开 Worker 的所有主人 API，包括发起一轮对话，所以再加一个密钥或开关只多一道关卡，并不缩小持有令牌者能做的事。
模型model 是 Agent 的 id；/v1/models 列出各个 Agent，默认的在最前。跟 OpenClaw：它的模型名选择 agent。Hermes 只有一个 agent，所以只公布一个固定模型；OpenProgram 有多个。
对话每个请求新开该 Agent 的一个对话；请求体里的 conversation_id 接着已有对话，每个回答都在请求体和 X-OpenProgram-Conversation-Id 头里写明所属对话。两家都是每个请求无状态，另用一个可选键延续（Hermes 用请求头，OpenClaw 用 user 字段）。请求体字段能经 OpenAI SDK 的 extra_body 传过去，大多数工具都开放了它。
之前的消息最后一条用户消息是这一轮的消息；它之前的消息按角色标注、指令在前，合进同一份输入。OpenClaw 就是这样拼 agent 提示的。对话存储里只放真实发生过的轮次，所以不把调用方的历史写成 Agent 从没给过的存储轮次。
这一轮对话的正常一轮：占用运行槽，用 Agent 自己的模型、工具和权限模式，被存下并在 App 里可见。来源是 api，用 bearer 的主人权限并标为非交互，加上无人值守的运行说明，和 openprogram --print 一样：没有人能回答审批或提问，所以这类步骤直接拒绝而不是等待。采样参数和 tools 字段被忽略，两家也是如此：用的是 Agent 自己的设置。
流式回复文字作为 chat.completion.chunk 增量，然后是带 finish_reason 的最后一块、可选的用量块，最后 data: [DONE]。工具活动不写进 content：客户端会把它当成回复显示。客户端关闭流就取消这一轮，和 OpenAI API 停止生成一样。
错误所有拒绝都用 OpenAI 的 {"error": {message, type, param, code}}，包括认证中间件对 /v1 路径的拒绝，这样 OpenAI 客户端能显示原因；本服务不提供的 /v1 路径同样以这种格式返回 404，而不是 App 的页面。流开始后才出的错，是 [DONE] 之前的一个错误事件。
