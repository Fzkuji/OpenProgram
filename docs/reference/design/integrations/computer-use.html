Computer Use：BrowserContext 与 Page 控制设计

本页定义 OpenProgram 的 Computer Use 当前目标设计。运行模型采用 Playwright 的 BrowserContext + Page：Runtime 管理内置浏览器 profile 对应的 BrowserContext，每个 tab 或 popup 对应一个 Page；分屏 pane 只描述 Page 当前显示位置，不作为执行身份。每个 chat turn 自动获得与该会话关联的可见 Page，并在需要时直接观察和操作。第一阶段不控制整个操作系统，也不接管用户日常 Chrome；不启用 OCR、YOLO/检测器、component memory、vision memory 或自动学习。

01 设计结论

自动 Page Awareness：renderer 通过 desktop.page.sync 持续登记 Page identity、pane order 和 bounds；每次发送消息时，chat command 只引用该 registry 中的 Page ID 与 revision。Runtime 根据同一 revision 的真实 pane geometry 计算 Page 与 chat 的空间关系，再把 Page inventory 和 primary Page 的一个有界 DOM/ARIA preview 加入本 turn 上下文。模型从推理开始就知道当前有哪些相邻 Page、分别位于哪里、是否可读写，不依赖固定的“右侧”常量。

公开入口：Agent 只使用一个 computer_use 工具，通过 list_pages → observe → act → verify 四个 command 获取当前信息并执行单步动作。工具接收当轮 canonical page_key 或 Runtime 动态生成的 alias，不接收 BrowserContext、Playwright Page 对象、window_id、tab_id、CDP target 或任意 selector。现有 task-based computer_use(task=...) 是过渡实现，不是最终 Agent 接口。

工具可用性：存在已验证、可观察 Page 时，dispatcher 必须在该 turn 主动加入 computer_use schema，不受 deferred 默认加载影响。简单页面问答使用 turn-start primary preview；布局变化、需要完整交互元素或任何页面动作时由 Agent 调用工具。用户显式关闭网页控制时，Runtime 只提供不含页面内容的 inventory descriptor，不提供 observe/act capability。

浏览器实现：复用 Electron WebContentsView 和 persist:webtabs profile。Runtime 通过 CDP 获得对应的 Playwright BrowserContext，再把经过验证的 UI tab 精确映射到其中的 Page。一个 BrowserContext 可以包含多个 Page；只有登记在当前 compound group 且允许访问的 Page 才进入 Agent 上下文。

后台位置无关：页面读取和点击绑定 window_id + tab_id + cdp_target_id，通过该 tab 的 WebContents/CDP 执行，不使用桌面屏幕坐标、OS 鼠标事件或 BrowserWindow.focus()。OpenProgram 可以位于其他窗口后方，目标 pane 也不必拥有键盘焦点；普通 DOM/ARIA 操作不截图。

Harness 分工：第一阶段只复用 GUI Agent Harness 的 observe → verify → plan → act 思路；不启用 OCR、YOLO/检测器、component memory、vision memory、自动 component learning、多轮 crop 或局部放大，也不直接复用其进程全局 target、全屏截图、容错后继续执行、LLM 判定 success 和自动持久化 workflow 的行为。

动作策略：ARIA/DOM 语义定位优先，PageService 在页面侧一次选取至多 120 个可见节点的 exact JS handles，并从这些 handle 直接生成 element ref 和 role/name 指纹；不得先创建整页所有 handles，也不得用旧 snapshot 的 index 再解析 live locator。页面中无关的推荐、计数或轮播变化不能使该 ref 自动失效。Page identity、navigation epoch、节点 detached/replacement 或目标 element identity 改变时才拒绝 DOM 动作。只有 canvas、无标签控件或 DOM 不可用时，才把一张 scale=css 的当前 viewport screenshot 直接交给紧邻的下一次多模态模型请求，由模型返回 viewport CSS pixel 坐标；图像像素与 Playwright mouse 坐标一一对应，截图发布前必须确认 capture 前后的 viewport、scroll 与 navigation 未变化，坐标权限只在携带该图像的单次请求内有效，请求返回或异常后立即撤销。中间没有 OCR、检测器或视觉记忆。每个写动作执行后都重新观察；禁止跨页面状态批量执行写动作。

权限策略：Page access 开关按 chat + Page 关联保存；发送消息时，Runtime 把当时的 access revision 冻结到当前 turn binding。外层 computer_use 不再请求第二次通用工具批准，但这不等于授予所有动作：Runtime 仍先执行 hard constraints、authority、origin/action grant 和显式 deny/ask rules。登录、CAPTCHA、跨 origin、敏感提交和不可逆操作继续进入 needs_user，不得由模型自行确认。

BASELINE AVAILABLE

内部 planner 的工具调用由 Runtime 强制

兼容 task wrapper 仍把公开 computer_use(task=...) 转换为内部 browser_page 序列，但不再依赖 provider 自行决定是否调用工具。Runtime 固定在开始和每次写动作后执行 observe，并把当前 observation 放入下一次 planner request；envelope、Page identity 和 frame id 由 Runtime 持有，title、text、ARIA 和 element name 等页面字符串始终标记为不可信数据，不能改变 task、target、permission 或动作数量。该 request 的临时 schema 排除 observe，通过 tool_choice=browser_page 只允许一次 action、screenshot 或 verify；screenshot 的唯一图像只附加到紧邻的下一次请求，随后立即丢弃并撤销 point capability。每次请求用单调 action sequence 判断本次是否真正执行工具，不能读取上一轮 screenshot marker 重新附图；若携图请求选择失败 verify、非法 point 或没有执行工具，后续无图请求不能继续使用旧图或坐标授权。Runtime 在每次执行后检查 verification evidence，并拒绝空 assertion/value；未通过就继续下一次有界请求。模型只输出文字、重复要求观察、提到不存在的工具或声称完成，都不会变成成功结果。

证据：agentic_functions/browser_agent/__init__.py；tests/component/programs/test_browser_agent.py 的 forced single-command loop 测试。

DESIGN GAP

当前 popup 不会产生新 Page

当前 Electron setWindowOpenHandler 拒绝新窗口，并把 popup URL 导航到原 WebContentsView；因此现状是同一 Page navigation，不会触发 Playwright Page.on("popup") 或产生独立 CDP target。目标 popup 生命周期必须先迁移该 handler：保留 opener 关系，为新窗口创建独立 WebContentsView/center tab 并登记其 Page identity；完成前不得声称支持 new_page_created。

证据：desktop/main.js 的 web tab setWindowOpenHandler。

BASELINE AVAILABLE

Canvas 视觉 fallback 已受限接入

task wrapper 已支持同 frame screenshot 后的 viewport CSS point click，并校验 screenshot frame、viewport、scroll、scale、坐标有限性和边界。该能力不增加 OCR、detector、cursor overlay、crop、zoom、memory 或后台进程；DOM/ARIA ref 仍是默认路径。

证据：_actions/read.py；computer-use-implementation.html 的任务 2 边界。

ISOLATED

不采用 Harness 的模型 completion

当前 computer_use 由 post-action Runtime assertion 生成 status 和 reason_code，不调用 GUI Harness 的模型 success 路径。Harness completion 的原有问题仍存在，但不阻塞当前浏览器 baseline。

证据：agentic_functions/browser_agent/__init__.py；安装版 session local_340bc50ccd2c4eafb1fc12378e0489ab。

DEFERRED

完整 lease 与 registry lifecycle

当前 binding 有 TTL 并在 turn teardown 释放，但尚未实现 server-owned page revisions、同 Page 排他写 lease、hide/move/transfer 即时 invalidation 和崩溃后的持久清理。当前 runner 不调用 Harness 的进程全局 target、memory 或 workflow persistence。

证据：agent/surface_context.py；webui/ws_actions/webtab.py；agent/process_runner.py。

约束：第一阶段不能把 gui_agent(task=...) 直接指向内置浏览器后作为产品能力发布。必须先由新的 session-scoped runner 接管 completion、target、cancel、artifact 和 approval；GUI Agent Harness 只提供可验证的共享算法，不引入第二套浏览器对象模型。

05 目标架构与信任边界

TURN INPUT

Page Context

每次发送消息时由 PageService.snapshot(chat_session_id) 生成。它包含已关联 Page inventory、根据实际 pane geometry 计算的 alias、capability，以及 primary Page 的一个有界 preview；不是 renderer 拼接的固定 prompt，也不是长期 memory。

RUNTIME AUTHORITY

BrowserContext + Page Registry

Runtime 从 Playwright BrowserContext 获取真实 Page，再以 window、renderer、compound group 和 layout revision 校验 UI 关联。只有同时存在于 BrowserContext 与 Registry 的 Page 才能进入模型上下文或成为工具目标。

TOOL EXECUTION

Playwright Page

PageService 直接调用绑定 Page 的 locator、DOM、ARIA、keyboard、mouse 和 screenshot 能力。第一阶段不增加 PageAdapter、adapter factory、插件配置或后台服务。

信任边界：LLM 先收到经过校验和裁剪的 Page Context，调用工具后再收到 Observation，并只返回候选 Action。Runtime 校验 binding、Page identity、frame、origin、权限和 cancel 后才能执行。Playwright BrowserContext/Page 对象、CDP endpoint 和客户端声明的原始 target id 不进入模型上下文。

OpenProgram Runtime 拥有

本 schema 是唯一 canonical source。主 Agent 不再为 discovery、DOM、ARIA、click 和 verify 分别加载多个顶层工具。provider 支持 oneOf 时直接发送该 schema；不支持时，provider adapter 只把同一组完整字段与 description 平铺，并保留 command enum，Runtime 继续用 canonical schema 校验，不能把 action 降为无字段 object。list_pages 不需要 page/session；首次 observe 需要 page，并创建返回一个 opaque computer_session_id；后续 observe 只需要 session；act 需要 session 和 action；verify 需要 session、顶层 frame 和 assertion。session 建立后不得同时再传 page。多余或缺失字段在 Page resolve 前返回 invalid_arguments。

element_present 不接受 selector 或模糊 DOM 查询；它按当前 observation 的 accessibility role 和 accessible name 匹配，match=exact 为默认推荐，contains 仅用于页面名称包含动态计数等已知情况。

page 只能使用 Runtime 在当前 Page Context 中提供的 canonical key 或动态 alias，例如 p1、left、focused 或 page:1；provider 实际收到的 schema 可以把当前可用值展开为 enum。首次 observe 必须显式提交该值；Agent 可以直接提交 Page Context 中的 primary_page_key，但 Runtime 不根据省略字段隐式选择目标。未知、缺失、过期或没有唯一映射的值返回 ambiguous_page。browser_context_id、Playwright Page handle、window_id、tab_id、cdp_target_id、CSS selector 不成为 LLM 参数。

list_pages 读取当前 Registry 并返回最新 inventory；它不修改产生本次调用的旧 provider request/alias map，tool result 之后的下一次 provider request 会获得新 revision 的 Page Context。首次 observe(page=...) 使用 source provider request 的 immutable alias map 和 turn binding 创建 ComputerSession；若此时 context 的 layout/page/access revision 或 Page identity 已过期，则在创建 ComputerSession 前返回 page_context_stale、page_access_disabled 或 target_lost。session 建立后，后续 command 只使用 session id，focus、其他 pane 或不改变目标成员身份的 layout 更新不会使 session 失效；目标被隐藏、移出 group、转移、关闭或 target identity 改变时返回 target_lost。这些失败都不自动迁移 session。observe(detail="summary") 返回有界文本与 landmark；interactive 额外返回 ARIA snapshot 和 element refs；visual 只在任务本身要求视觉判断、canvas 或 interactive observation 无法定位时返回一张当前 viewport screenshot。

act 每次只执行一个 canonical Action，Action 内必须携带最近 observation 的 expected_frame_id。element target 由 PageService 保存的 locator 与 role/name 指纹解析；无关 DOM 文本变化不使它失效，目标 identity、Page identity 或 navigation epoch 改变才返回 stale。point target 只能引用同一 frame 的 visual observation，并要求 screenshot 捕获后的 viewport CSS width/height、scroll、zoom/navigation 没有变化。任何写动作后旧 frame 和 element refs 立即失效；Agent 必须重新 observe。verify 只执行 Runtime assertion，不接受自然语言“已经完成”作为成功证据。导航属于 act.action.type=navigate，只改变已经绑定的同一个 Page，不创建或切换 Page。

当前 computer_use(task, surface, url, max_steps, max_seconds) 通过内部 planner 完成多步任务，这是现状证据，不是目标接口。迁移完成后公开入口只使用 page，不保留 surface 参数或兼容 alias；如果 task wrapper 仍作为手动 Function 保留，也必须改为 computer_use(task, page, ...)。主 chat Agent 使用上述 Page command contract，直接读取实际 Page、逐步交互和验证，不为一次简单观察启动内部 LLM。

Agent 接入规则

  1. turn 开始时，dispatcher 调用同一个 PageService.snapshot(chat_session_id, provider_request_id)，把 inventory 和 primary preview 序列化为独立的 <page_context> block；prompt 不写固定 left/right，也不从用户文本推测页面位置。
  2. 存在至少一个 observe capability 时注入 computer_use。模型先使用 context 回答简单页面问题；信息不够、布局变化或需要动作时调用 tool，不要求用户补 URL、截图或复制页面文字。
  3. 每个 tool call 由 Runtime 自动附加 source_provider_request_id + tool_call_id。模型在首次 observe 时提交 page alias，随后提交 Runtime 返回的 opaque computer_session_id、frame 和 action；不能指定另一个 window、WebSocket、tab 或 target。
  4. tool result 使用统一 envelope；Agent 根据 status/reason_code 决定继续 observe、请求用户接管或结束。只有 verify 的 assertion 通过后，Runtime 才能产生 succeeded/verified。

PageBroker 对 attribution lock 使用 CAS 状态迁移，并且所有 outbound record 都必须先于实际发送持久化。成功 acquire 后为 reserved；begin_popup_install 原子写入 install record 和 request id 后改为 installing；经过完整身份与序列校验的 applied=true ack 后改为 active。同一 session 的后续 action 调用 begin_popup_replace，原子保存 request_id + previous_popup_watch_id + next_popup_watch_id + next_action_epoch 并改为 replacing，之后才能发送 replace。replace 的已校验 applied=true ack 原子把 next watch/epoch 提升为 active 并删除 pending record；applied=false 且 main 回报的 active watch 等于 previous watch 时恢复原 active 状态并删除 pending record，不能释放 lock；ack 未知、identity/seq 不匹配或 Runtime 重启时继续 quarantine，并严格重放持久化的同一 replace request。终态调用 begin_popup_close，先保存 request id 与 previous watch 再改为 release_pending。close 的已校验 applied=false + active=previous 原子执行 release_pending → active 并删除 pending close，保留 attribution lock；若仍需终止，下一次 begin_popup_close 必须生成新的 request id。只有 close 结果未知时才重放当前 pending record；applied=true + active=null 且 drained seq 已处理后才释放 lock。只有 reserved 且没有任何 outbound record 时可接受 not_installed；install_not_applied_ack 必须对应已校验的 ok=false + applied=false + active_popup_watch_id=null。其他状态只接受与当前 request/watch/owner 匹配的 close-drained 或 main-side deletion proof，成功释放后删除 lock record。旧状态、旧 request 或其他 ComputerSession 提交的 ack/proof 一律拒绝。

Electron main 为每次 renderer control registration generation 签发不可复用的 control_owner_token + one_time_connection_nonce，并通过已有本地认证边界把它们与 window_id + renderer_instance_id + control_registration_generation 登记到 Runtime。renderer 建立 WebSocket 时只能提交 nonce；Runtime 消费 nonce 后从服务端 registration 解析 owner token，renderer hello 不能声明或替换它。Runtime 转发 popup watch 时必须回传该 token；Electron main 同时校验 IPC sender WebContents、window、renderer instance、registration generation 和 token，旧 token、其他 renderer sender 或跨窗口重放全部拒绝。WebSocket 断开后，下一次连接必须由 Electron main 先 sweep 并撤销旧 generation 的 watches，再签发新的 token/nonce；新 registration 和 sync 完成前不恢复 Computer Use。普通 Web 客户端不能自行声明 desktop window identity。连接关闭时，Runtime 删除该连接下全部 registry entries，并使关联 binding 和 lease 失效。

renderer 通过完整 desktop.page.sync snapshot 维护 server-owned registry，而不是在 chat command 中临时声明页面状态。每个窗口的 window_revision 和 layout_revision、每个 page 的 page_revision 都必须单调递增；重复或旧 revision 被拒绝。snapshot 原子更新 visibility、focus、compound group、pane order 和 bounds。renderer 不提交 region="right" 这类语义结论；Runtime 使用同一 layout revision 下的 chat bounds 与 page bounds 计算 relation。仅 focus、其他 pane或同组内位置变化只影响下一 turn 的 inventory/alias，不改变已建立 ComputerSession 的 target binding；若目标 pane resize 导致 viewport 变化，只使旧 frame 返回 stale_observation。hide、移出当前 group、跨窗口 transfer、close、renderer/window disconnect 通过 snapshot 差异或显式 invalidate 立即使 session/binding 失效，下一次副作用前返回 target_lost。

focused_registry_page_id 是一个 window/layout revision 内的单值字段，必须同时存在于 visible_pages[]，并使用该项的 expected_page_revision；因此 registry 不会出现两个 focused Page，也不存在缺少 revision 的 focused 引用。跨窗口 transfer 不更新原 entry 的 window id；源连接必须先 invalidate 旧 entry 和 lease，目标连接再以新的 registry_page_id 出现在自己的 authenticated snapshot 中。binding、page revision、alias 和 lease 都不跨窗口继承。

renderer 在每次 chat command 中只引用 registry 已登记的可见 Page ID、发送瞬间对应的 expected Page revision，以及当前 chat pane identity；chat bounds 不随 command 重复提交，Runtime 必须按 chat_tab_id + session_id 从同一 accepted registry snapshot 的 chat_panes[] 读取。Runtime 对 window_revision + layout_revision + visible_pages[].expected_page_revision 与最后接受的 registry snapshot 做 CAS 校验，再确认 connection、session、group、visibility、focus 和 BrowserContext Page identity。候选可以来自左侧、右侧、上方或下方相邻 pane，也可以来自用户从 sidebar/按钮打开并已登记到当前 compound group 的 Page；普通独立 chat、隐藏 group member、其他窗口和未登记的 native window 不进入引用集合。任何 chat pane 查找失败、revision 变化或 Page identity 不匹配时，在 preview 或 turn binding 产生前返回 page_context_stale 或 target_lost，不得采用客户端 bounds 或解析 replacement Page。最终 origin、title 和 capabilities 从绑定的 Playwright Page 读取，不采用 renderer payload 中的同名值。

Runtime 在模型调用前为全部已验证 Page 生成轻量 descriptor，只对 primary Page 生成有界 preview。descriptor 包含 type、relation、title、origin、capability 和 access 状态；primary preview 的序列化顺序固定为 DOM 顺序的 viewport 可见文本、ARIA landmark、interactive count。合并连续空白后，可见文本最多 2,000 个 Unicode 字符，landmark 最多 12 项且每项 name 最多 160 个字符，整个 preview 最多 8 KiB UTF-8。每个受限字段都有独立 *_truncated，总大小触顶时还有 payload_truncated。preview 不包含 screenshot、完整 DOM、完整 accessibility tree、element refs、iframe 隐藏内容或不可见节点。非 primary Page 通过 computer_use(command="observe") 按需读取，避免每 turn 重复提交所有页面正文。

preview 携带 captured_at + preview_frame_id + content_epoch + window_revision + page_revision + layout_revision + navigation_epoch。PageService 为每个 Page 维护 DOM mutation/navigation 驱动的 content_epoch，并在同一 Page 的 snapshot barrier 内捕获 DOM text 与 ARIA。捕获前后各读取一次 Page identity、navigation、viewport、content epoch 和 registry revision；任一值变化就丢弃整份结果并重试一次，第二次仍不一致则标记 preview_status=unavailable，不能混合两个 frame 的内容。捕获超过本地 deadline 或页面暂不可读时也只返回 unavailable descriptor，模型随后使用工具重试观察。preview 只服务当前 turn，页面变化后失效，不进入 component memory、vision memory 或 workflow replay。

Page Context 中的 title、正文和 ARIA 文本都标记为 untrusted_content，与用户消息和系统规则分隔。网页文字不能要求模型更换 page、启用工具、扩大权限或执行动作；Runtime 也不能根据 preview 文本修改 capability 和 risk tier。

只要存在至少一个具备 observe capability 的 Page，dispatcher 就在该 turn 将 computer_use schema 放入 provider tool array，并追加 Page Context。interact 和 navigate 都以 observe 为前置能力；Registry 拒绝缺少 observe 的 interact/navigate 组合。该规则优先于工具的 deferred 默认状态。模型因此在生成第一个 token 前已经知道实际相邻页面及其 relation；简单问题可直接依据 primary preview 回答，信息不足时调用 computer_use(command="observe", page="left")。任何 click、type、navigate 等页面变更都必须调用 act，不能只根据 preview 声称已执行。

PageService 生成 snapshot 时从 server-owned access map 读取并冻结 access + access_revision，不接受 renderer/chat payload 中的同名字段。用户显式关闭网页控制时，Runtime 仍可告诉模型“存在一个未授权 Page”，但不附带页面内容；若当前 turn 没有其他可观察 Page，则不注入执行工具。UI 必须显示“Agent 无法访问”，避免模型把权限禁用误判为页面不存在。将 chat 与 web tab 合并为同一 compound group，默认只授予该 Page 的 R0 结构化读取；R1-R3 写操作仍按后文策略处理。

第一次 observe 校验 Page Context 中已有的 turn_binding_id，随后创建新的 session_page_binding_id，把同一个 browser_context_id + runtime_page_id + window_id + registry_page_id + tab_id + cdp_target_id 及全部 revision 原样复制到 ComputerSession；它不是转移原 turn binding，也不重新解析 alias 或 Page。turn binding 继续由 source provider request 持有，并在该 response 的 tool calls settled 后按原 TTL 删除；session binding 只由 ComputerSession 持有，持续到 verify 终态、needs_user 终止、失败、取消、target/access 失效或 turn teardown。两类 binding 通过同一 browser_context_id + runtime_page_id 接收 close/transfer/access invalidation。每个 observe/act/verify command 只对 session binding 取得短 lease。运行期间切换焦点不会改变 Page；Page close、移出 compound group、跨窗口转移、target replacement 或 renderer 断开会使两类 binding 失效，并返回 target_lost，不得自动选择另一个 Page。

这里的“可见 Page”描述布局归属和用户可检查性，不要求 OpenProgram 成为 macOS/桌面环境的前台应用，也不要求目标 pane 当前接收键盘事件。读取和动作直接调用绑定的 Playwright Page；禁止先调用 Page.bringToFront()、激活操作系统窗口、按桌面坐标点击或截取整个屏幕。只有目标仍登记在当前 compound group 内且 BrowserContext 中仍存在同一个 Page 时绑定才有效；hide、移出 group、跨窗口 transfer、Page close、disconnect 或 target identity 变化后必须返回 target_lost。同组内重新排布本身不会解除已建立的绑定。

Dispatcher 保存不可变映射 provider_request_id → turn_id + context_id + context_revision + alias_map + turn_bindings。每个 tool call 的执行 envelope 由 Runtime 写入 tool_call_id + source_provider_request_id，模型不能提交或覆盖它；alias 只能在产生该 tool schema 的同一个 provider request 快照中解析。即使同一 chat session 有重叠 turn 或后续 Page Context，旧工具调用也不得查询 session 的“最新 alias map”。模型 response stream 结束不立即删除映射：没有 tool call 时可以释放；存在 tool call 时保留到该 response 产生的全部 tool call settled。首次 observe 成功后，ComputerSession 以 computer_session_id → owner_turn_id + session_page_binding_id + frame_registry 独立持有 exact target，provider-request alias map 和 turn binding 可以按各自生命周期释放。

ComputerSession 只允许 owner turn 的后续 provider requests 使用；Runtime 从 tool execution envelope 取得 turn id，不信任模型提交。Observation frame 保留到同 session 的下一次 observation 替换它、任何写动作使它失效、target/navigation/access revision 改变，或 turn 被完成、取消、超时、session teardown。DOM ref 另外在执行前复核目标元素 fingerprint；point action 另外绑定 screenshot 时的 viewport、scroll、scale 和 zoom。无关 content、focus 或 layout revision 不单独使仍匹配的 DOM ref 或 session 失效。跨 user turn、跨 ComputerSession 或跨 target 提交 frame 一律返回 stale_observation。read-only ComputerSession 在 turn 结束时释放；发生写动作的 ComputerSession 在 verify 终态、needs_user 终止、失败、取消或 turn teardown 时释放。异常遗留 session 按短 TTL 清理。

Alias 与 primary page 规则

  1. Runtime 为本 turn 的每个 Page 分配 canonical page_key（p1、p2），并生成显式 alias_map。key 和 alias 只在该 Page Context revision 内有效。
  2. 空间 alias 只来自同一 layout_revision 的实际 pane geometry。先计算横向和纵向区间的正交重叠长度：只有纵向重叠 > 0 且 Page 右边界不超过 chat 左边界时为 left，纵向重叠 > 0 且 Page 左边界不小于 chat 右边界时为 right；只有横向重叠 > 0 且 Page 下边界不超过 chat 上边界时为 above，横向重叠 > 0 且 Page 上边界不小于 chat 下边界时为 below。矩形本身重叠时为 overlap；对角分离而无正交重叠、bounds 非法或 revision 不一致时为 unknown。overlap/unknown 不生成空间 alias。不得用数组下标、tab 类型或历史默认值推断 right。
  3. 只有一个可控 Page 对应某 relation 时才分配 left/right/above/below alias；同一 relation 有多个候选时不生成该空间 alias。用于 UI 展示的 relation 可以保留，但不能作为 Page identity。
  4. focused 只指向提交消息瞬间拥有焦点的可控 Page。focus 在 turn 进行中变化不会修改当前 alias_map，但会反映到下一 turn。
  5. page:1、page:2 按提交瞬间的 pane_order 生成；顺序相同则以 registry_page_id 排序。一个 Page 可以同时拥有 left、focused 和 page:1。
  6. primary_page_key 优先取 focused controllable Page；没有时取唯一可见 controllable Page；仍有多个候选时为空。模型可以传 alias 或 canonical key；未知、过期或没有唯一映射的值在任何 CDP 请求前失败。

从普通聊天到一次页面操作

  1. Desktop bridge 已通过单调 revision 的 registry events 登记窗口与 page。用户在 chat + web tab 的 compound group 中提交消息；composer 只引用当前可见 registry page ID 和 revision，不发送 screenshot 或 CDP target。
  2. Page Registry 验证引用，PageService 从绑定的 Playwright Page 捕获有界 preview。服务端在模型调用前加入 Page Context。当前 baseline 已注入 task-wrapper computer_use；PHASE 0 gate 通过后，主 Chat Agent schema 替换为本节 command contract，后续 registry/lease gate 不否定当前 baseline 的已验证能力。
  3. 模型从 turn 开始就知道实际相邻页面及其 relation。简单页面概述可以使用 primary preview；需要其他 page、更多内容或任何交互时调用公开工具。
  4. PageService 已在 snapshot 阶段定向解析 exact BrowserContext/Page/renderer/tab/target。首次 observe 校验该 turn binding，创建绑定 owner turn 的 ComputerSession，并为该 command 获取 read lease；校验失败返回结构化错误，不让普通聊天模型自行解释为“看不到”。
  5. 主 Agent 通过跨 provider request 的 command loop 执行 DOM/ARIA-first 观察与单步动作；每个 command 由 Runner 校验 session、frame 和短 lease。只有视觉任务、canvas 或语义定位失败时发送一张当前 viewport screenshot。
  6. 每个状态变化后重新观察和验证，事件回写同一 chat turn；Stop、授权和人工接管都绑定同一个 ComputerSession 与 target。

Action

computer_use.input_schema.$defs.action 是唯一 Action schema；本节只解释其执行语义，不维护第二份字段定义。

type 是判别字段；每个分支只允许该 action 所需字段并设置 additionalProperties=false。element ref 优先；point 只允许 click/hover，必须位于当前 viewport，并来自同一 expected_frame_id 的单张视觉 fallback。navigate 只改变当前 lease 的 Page；scroll 和 wait 不接受 target。eval、cookie、storage、Page create、upload、download 不属于第一阶段 Action。

Canonical point 以当前 viewport 左上角为 (0,0)，单位是 CSS pixel，不是 screenshot image pixel、device pixel 或页面文档坐标。Observation 同时记录 viewport CSS width/height、screenshot image width/height、device_scale_factor 和页面 zoom；provider adapter 按这组元数据把模型图像坐标归一化为 CSS pixel。Runtime 再检查有限数值和 0 ≤ x < viewport.width、0 ≤ y < viewport.height。device scale、zoom、resize 或 scroll 变化都会使原 frame 失效，不能复用旧 point。

该协议与模型 provider 无关。OpenAI 原生 computer_call、Anthropic tool_use 或 GUI Agent Harness planner 都必须先转换为同一个 Action，再经过相同的 target、frame、origin、approval 和 cancel 校验。provider adapter 可以处理各模型的 action schema 与坐标约定，但不能改变 Runtime 的权限和 completion 结论。

07 Observe → Resolve → Approve → Act → Verify

  1. Page Registry 已在 turn 开始前提供可见 Page、preview 和 turn bindings。首次 observe 时，PageRegistry 根据调用中的 key/alias 选中并校验唯一 turn binding，再把同一个 exact Page 复制为 ComputerSession binding；PageBroker 只为当前 command 获取 read/write lease，不按 alias 解析或重新选择 Page。
  2. PageService 默认从绑定 Page 捕获 ARIA snapshot、DOM 交互元素、URL/origin/title 和 viewport 元数据，不发送图像。任务需要视觉判断或 DOM/ARIA 无法定位时才捕获一张当前 viewport screenshot；不得使用 full-page screenshot 产生点击坐标。
  3. 主 Chat Agent 根据 Observation 生成一个候选动作和预期效果，并通过 computer_use(command="act") 提交。GUI Agent Harness 只提供可复用的 action/verification 结构，不启动第二个 planner。读取动作可以合并；每轮最多执行一个会改变页面状态的动作。
  4. Resolver 按 runtime ref/ARIA、受控 selector、单张 viewport screenshot 的直接模型坐标顺序解析目标。中间不运行 OCR、YOLO、detector、memory retrieval 或 zoom；模型不得直接获得 Playwright Page。
  5. Runtime 校验 frame freshness、target lease、origin grant、action risk、cancel 和 budget。需要用户时返回 needs_user 状态并暂停 session。
  6. PageService 在绑定 Page 上执行动作后使旧 frame 失效，并返回 action_result + observe_required=true；下一次显式 observe 才生成模型可见的新 Observation 和 frame。Runtime 可以执行不对模型暴露的最小 post-action safety probe，但它不能产生可供后续 act/verify 使用的 frame。verification 必须基于下一次 Observation 检查动作预期效果和任务 completion assertions。
  7. 只有 completion assertions 全部满足且没有未处理风险时才返回 succeeded。

Origin 与导航规则

  • 授权键是规范化 scheme + host + effective port，不是可模糊匹配的域后缀。
  • 同一 Page 的 redirect/navigation 导致 origin 改变时，原授权不延续；在同一 ComputerSession/Page binding 上为下一次 observe 重新获取 read lease，再观察和分类。
  • Runtime 先完成 frame、authority、action risk、cancel 和 target freshness 校验；在每个 ComputerSession 的首次写 action 前，再由 PageBroker 为 exact Page 取得 session-scoped popup-attribution lock，然后取得该 command 的短 write lease。此时 lock 是 reserved：write lease 获取失败、cancel、target lost 或 pre-install exception 时，只要 PageBroker 原子确认还没有 install outbound record，就以 not_installed 直接释放。准备发送 watch 时，PageBroker 必须先通过 begin_popup_install 在同一持久状态变更中记录 request id 并把 lock 改为 installing，然后才向 Electron 发送；从这一刻起禁止使用 not_installed，即使发送结果未知，也必须通过经过身份/序列校验的 install_not_applied_ack、close-drained 或 main-side deletion proof 释放。Runtime 随后安装 Electron popup_watch_id 和 Playwright action-scoped Page.on("popup") listener；两者绑定同一 computer_session_id + action_epoch。该 lock 在同一 session 的后续 action/replace 之间保留；另一个 ComputerSession 即使能等待到短 write lease 空闲，也必须返回 popup_attribution_busy，不得在旧 watch close-drained 前写入该 Page。首次 action 必须等待 install ack；同一 session 的下一次写 action 必须调用 begin_popup_replace 持久保存完整 replace record 后，才发送原子 replace 请求；Runtime 必须等待旧 watch 的 requested events 已按 drained_through_event_seq 排空并处理经过校验的 replace ack，之后才能执行该 action。replace applied=false 时旧 watch 和 attribution lock 都继续保留；replace 结果未知时重放同一持久请求，不创建新 epoch 或新 watch id。显式终止旧 session 必须调用 begin_popup_close 持久保存 close record，完成 close-drained 后再释放 attribution lock，之后其他 session 才能安装 watch；控制 channel 正常时，verify-success 和所有 session 终态遵守同一顺序。Runtime 的 session lock 只保护本地状态，跨进程先后关系由 PageBroker 的 exact-Page attribution lock、Electron main 的串行 watch 状态机、window event seq 和对应 ack 共同建立。Electron desktop.page.popup.requested 命中 active watch 时，Runtime 把 session 标记为 pending popup，阻止后续 act 和 verify-success，并返回 needs_user/new_page_created。Playwright popup event 允许在初始响应开始后延迟到达，只负责把 pending tab/CDP target 解析为 Page 并复核 opener，不作为是否阻止副作用的唯一信号。收到 popup 后，Page listener 保留到 Page 成功解析或 target-resolution deadline，再清除；ack timeout、seq gap、action error、cancel、timeout 和 teardown 都进入终态清理，不得遗留 main watch、Page listener 或 attribution lock。disconnect/target_lost 停止全部副作用并做本地清理；在 main-side sweep、expiry 或 target teardown 确认删除 watch 前，attribution lock 仍阻止该 Page 的新写 action。已执行动作及其 popup 副作用不回滚；Runtime 不自动采用新 Page。用户把新 Page 关联到当前 chat 后，只能在下一 turn 创建新的 ComputerSession 和 binding。没有匹配 Electron watch 的 context-wide Page 只进入 discovery，不影响当前 ComputerSession。
  • 本地 project origin 由 dev-server registry 或用户当前 project 显式建立，不只依赖字符串包含 localhost。
  • 网页、截图、DOM、ARIA、console 和下载提示都属于不可信输入。页面中的操作指令不能修改 task、权限或系统约束。

Artifact 策略

  • 每个 ComputerSession 使用独立 artifact 目录；文件名包含 session/frame id，不使用固定 /tmp/gui_agent_screen.png。
  • 原始 screenshot 默认仅在运行期保存。succeeded、failed、cancelled、终止型 needs_user、异常退出和 target loss 都经过同一个 finally 路径 detach CDP、释放 lease/approval，并删除临时 artifact；验收或用户明确保存的截图才标记 retained=true。
  • 可恢复的登录/CAPTCHA needs_user 只在 ComputerSession deadline 内保留 session 和临时 artifact；用户拒绝、超时、session teardown 或 worker shutdown 时执行相同 cleanup。worker 启动时按 owner ComputerSession 状态和 TTL 清理 orphan ComputerSession 目录。
  • artifact API 对模型和前端只返回 opaque artifact_id、kind、retained 与受控读取 URL；不返回本地绝对路径。
  • typed text 在事件和 transcript 中只记录长度、目标和敏感度，不记录密码、token 或完整表单内容。
  • 第一阶段不调用 Harness learn_app_components、save_workflow_record 或任何 component/vision memory 读写，不自动保存个人页面截图。

09 桌面 UI 行为

不新增第二套浏览器窗口。Computer Use 使用现有 center tab/split layout：chat 与被控制的 web tab 可以按实际布局位于彼此左、右、上、下。UI 展示的 relation、Agent 收到的 alias 和 PageRegistry 解析的 page key 必须来自同一个 PageService snapshot。

待命

chat composer 附近显示当前可见 page 的 favicon、title/origin、位置 alias 和“Agent 可访问”状态。用户在 sidebar、center tab 或 split pane 中改变可见/focused page 时立即更新；工具关闭时显示“网页控制未启用”。

发送消息

发送后该 turn 的 page chip 固定为提交时的 title、relation 和 revision。模型已经收到同一份 Page Context；用户可以展开查看“本轮 Agent 可见内容”的结构化 preview。后续切换 pane 不会静默改变正在运行的目标。

运行中

tab header 显示“Computer Use”状态、step 计数和 Stop。chat 中只显示当前 observation 摘要、计划动作、执行结果和验证结果；原始 DOM 与 screenshot 默认折叠。

授权时

permission card 必须显示 origin、目标 Page 的 tab/popup 标题、拟执行动作、将发送的非敏感文本摘要、风险原因，以及仅本动作/本任务/拒绝。第一阶段没有永久允许。

人工接管

登录、CAPTCHA 或敏感页面时 session 进入 needs_user。用户在同一可见 tab 中操作，点击 Continue 后 Runtime 生成全新 observation；旧坐标和旧 action 全部失效。

结束

结果展示 status、reason、完成证据和保留 artifact。step_limit、timeout、target_lost 必须显示为未完成，不用 LLM summary 覆盖。

10 失败、取消与并发语义

reason_code触发条件处理
invalid_argumentscommand 缺少必需字段、携带其他 command 字段、raw Page handle/target/selector 或未知字段在创建 ComputerSession、取得 lease 或执行 Page 动作前拒绝，返回允许的 command contract。
page_unavailableturn 中没有经过验证且允许访问的可见 Page不注入执行工具；上下文明确说明不存在可用 Page，不使用任意 active Page 代替。
ambiguous_page多个 Page 都符合用户措辞，且没有唯一 primary/focused 对应不执行；列出可见 alias 并请求用户明确目标。
page_context_stale首次 observe 校验 alias/turn binding 时发现 source Page Context 的 window/layout/page revision 已过期不创建 ComputerSession、不复用旧 alias；返回新 inventory，下一 provider request 获取新 context。
popup_attribution_busy同一 exact Page 的 popup-attribution lock 属于另一个 ComputerSession不安装或替换 watch，不取得 write lease，不执行 Page 动作。等待 owner session 完成 close-drained，或在用户/Runtime 终止 owner session 并确认 main-side watch 删除后重试；不得把旧 watch 转交给新 session。
popup_watch_failedpopup watch install/replace/close ack 超时、identity 不一致、window event seq 缺口或 drained seq 未满足install 状态不确定时不执行当前 action；replace/close 状态不确定时不执行下一副作用，也不产生 verified 终态。未知结果从持久 outbound record 用同一 request id 和相同 watch/epoch 参数幂等重试。经过校验的确定结果结束本次 operation quarantine：replace 已应用时提升新 watch，replace 未应用时恢复旧 active watch；close 未应用时执行 release_pending → active，保留 attribution lock，并在仍需终止时使用新的 request id 再次 close。只有 install 明确未应用且 main 无 active watch、close-drained，或 owner 断开后的 main-side sweep + 新连接 sync 才能释放 attribution lock。控制连接已断开则归类 target_lost；其他协议失败以 failed 终止本地 session，main watch 仍由 owner teardown 或 expiry 强制删除。
access_revision_conflictaccess update 的 expected revision 不是 Runtime 当前 revision不改变 access；返回 actual access/revision，UI 基于最新状态重新提交用户操作。
page_access_disabled用户显式关闭当前 Page 的 Agent 访问该 Page 不提供 preview 或 capability，并使它的 turn/session binding 失效；若仍有其他可观察 Page，工具继续注入并只能操作其他 Page；否则不注入工具。UI 与模型上下文都显示禁用。
capability_deniedPage 或当前授权不包含请求的 observe/interact/navigate capability在 lease 或副作用前拒绝；工具已注入不能覆盖 capability。
stale_observationframe/Page/target/navigation epoch 已改变；element ref 的 role/name identity 不再匹配；或 point action 的 screenshot viewport/scroll/zoom 已改变不执行动作；重新 observe，不消耗 action step。无关正文、推荐、计数或轮播 mutation 本身不能使仍匹配的 element ref 失效。
target_lostPage hide、移出 group、跨窗口 transfer、Page/window close、CDP target replacement、renderer/window disconnect释放短 lease并停止副作用；只有 main-side watch 删除已确认后才释放 attribution lock。失败结束，不得自动选择另一个 Page。
origin_changed同一 Page redirect/navigation 进入新 origin保持 Page，撤销旧 origin action grant，重新观察和分类。
new_page_createdElectron popup.requested 命中当前 session/action 的 exact opener watch；Playwright popup event 可以随后到达原子阻止后续 act 和 verify-success；已执行动作及其 popup 副作用不回滚。Runtime 不跟随、不操作新 Page，释放原短 lease，并在 close-drained 后释放 attribution lock，以 needs_user 结束当前 ComputerSession；Page event 只完成 target/Page 解析。用户关联后由下一 turn 创建全新 ComputerSession/binding；context-wide 无关 Page 不触发。
approval_requiredR2/R3 action 未授权暂停为 needs_user，不重试 action。
planner_invalid结构化 Action 两次无效或引用不存在失败或重新规划；绝不能转换为 done。
verification_failed动作执行但预期效果未出现携带差异重新规划；超过 recovery budget 后失败。
cancelled用户 Stop、ComputerSession cancel、session teardown执行前检查并中止；清理 Playwright/CDP、短 lease、pending approval 和临时 artifact，并在 close-drained 或已确认 main-side deletion 后释放 attribution lock。
step_limit / timeout预算耗尽返回 failed，保留已验证的部分结果但不宣告成功。

并发单位是 Playwright Page。短 lease 与 popup-attribution lock 是两个独立层级：同一 runtime_page_id 同时只能有一个写 lease，command 结束即释放；发生过写 action 的 ComputerSession 还在同一 exact Page 上持有 attribution lock，直至其 active watch 完成 close-drained，或 main-side sweep/expiry/target teardown 已确认删除 watch。尚未生成 install outbound record 的 reserved lock 可以用 not_installed 本地证明释放；进入 installing 后不得回退到该证明。另一个 ComputerSession 在此之前不能取得该 Page 的写 lease 或安装 watch；同一 session 可在持锁期间按顺序 replace watch。不同 Page 的 attribution lock 相互独立，可以并行读取或执行。同一 Page 的 preview/Observation 捕获使用 snapshot read barrier，任何 action 使用 write barrier；两者的临界区不得重叠。捕获过程中发生 DOM mutation 时丢弃整份尚未发布的 snapshot 并重试；snapshot 已发布后，无关 content mutation 不撤销仍匹配的 element ref，point action 则继续要求 screenshot viewport state 完全一致。Page Broker 只把 desktop.page.resolve 控制面请求定向发送给 originating renderer，并校验回执中的 connection/window/tab/target/revision；observe/act/verify 数据面始终由 Runtime 的 PageService 直接调用绑定的 BrowserContext/Page，禁止广播后接受第一个 reply。

11 实施顺序与每阶段出口

交付边界：当前 turn-scoped baseline 已在单一 visible split web page 范围内向真实 provider 提供 computer_use，并完成默认 18100 安装版 live E2E；内部 task wrapper 也具备一张 viewport screenshot 后的受限 CSS point click。下面 PHASE 0–4 描述完整目标架构的后续强化顺序；只有对应 phase gate 通过后，才能宣称 authoritative multiwindow registry、排他 lease、完整 Safety UI、跨 provider 的统一视觉坐标适配或相关发布能力，不能用当前 baseline 证据替代。

PHASE 0
Agent 工具与布局协议
把主 Agent schema 改为 list_pages/observe/act/verify command；PageService 同时服务 turn context、chip 和 tool；renderer 提交 pane identity/order/bounds，Runtime 计算 relation，不接受固定 region。
出口：左右互换、上下分屏、对角/重叠/非法 bounds 和每个 command 的 public-entry 测试通过；主 Agent 与公开 Page 协议不再包含旧 surface 参数或 alias。
PHASE 1
Authoritative Page Registry 与精确 Broker
建立 BrowserContext connection；实现 desktop window registration、WebSocket 绑定、单调 registry events 和连接清理；command/reply 定向发送并校验 BrowserContext/Page/window/renderer/tab/target revision；实现 alias 解析、Page lease、exact-Page popup-attribution lock、hide/leave-group/transfer/close invalidation 和 teardown；迁移 Electron popup handler，使其创建保留 opener 的独立 WebContentsView/center tab/CDP target，而不是导航原 Page；实现 action-scoped popup.watch/requested control event 和 Playwright Page 的延迟解析。
出口：伪造/旧 ID 被拒绝；双窗口测试连续 100 次命中指定 Page；隐藏、移出 group、关闭和转移不会改用其他 Page；popup 产生独立 Page 且不改变 opener Page，未登记 popup 不进入 Page Context，慢初始响应不允许后续副作用或 verified 终态；同一 Page 跨 session 的 popup 归因保持排他，不同 Page 仍可并行。
PHASE 2
完整 Page Awareness
在现有 turn ref/preview/chip baseline 上增加 authoritative registry revision、frame-consistent snapshot barrier、稳定多 Page alias 和显式关闭状态；自动上下文只预览 primary Page，其余 Page 由 observe 按需读取。
出口：provider 能稳定获得正确 inventory/primary preview/alias；超限、navigation race、focus race 与禁用状态测试通过。
PHASE 3
完整 PageService 与 Runner
在现有 DOM/ARIA refs、frame freshness 和确定性 verification 上增加排他 Page lease、完整 capability/risk policy、cancel、target-lost lifecycle、单张 viewport visual fallback 和 artifact policy。
出口：DOM/canvas、权限、cancel、target lost、step limit 集成测试通过。
PHASE 4
完整桌面交互与 Safety UI
补齐运行状态、Stop、专用 permission card、人工接管和多窗口完成证据；继续使用默认 18100 安装版测试。
出口：下面与完整目标能力对应的 E2E 清单均有可复核 artifact，相关能力才可标为发布完成。

12 可执行验收标准

  1. Turn-start awareness：chat 与 Bilibili fixture 合并为 compound group 后，每次 chat command 都产生经过服务端校验的 Page Context。浏览器在 chat 左侧时 provider 得到 left，互换 pane 后下一 turn 得到 right；两种情况都在首个 token 前具有 title、origin、primary preview、capabilities 和 computer_use schema。
  2. 页面问答：输入“左边有什么”“右边有什么”或“旁边页面是什么”时，回复必须对应实际 relation。primary preview 不足时，Agent 调用 computer_use(command="observe", page="left|right")；全程不要求用户粘贴 URL、文字或截图，普通 DOM 页面不发送 screenshot。
  3. 页面交互：Agent 依次调用 observe → act → observe → verify，使用最新 DOM/ARIA refs、同一 page_key 和 frame；操作精确绑定 Playwright Page，不得操作 BrowserContext 中其他 Page 或另一个窗口。写动作后使用旧 frame 的下一次 act 必须返回 stale_observation。
  4. Chat 渲染稳定性：由普通 chat turn 发起的 computer_use 已经拥有父 assistant/tool 占位行；其嵌套执行树更新只能增量更新当前行，不得再次发送 load_session、替换 #messages-mount 或重建此前已完成的 message/avatar/markdown DOM。只有从函数页、欢迎入口或 Retry 独立启动且 transcript 中没有占位行的函数运行，才允许在第一次持久化 tree_update 后执行一次 hydration。运行期间历史 message element identity 保持不变。
  5. 非前台交互：OpenProgram 被其他应用遮挡，或用户焦点位于 chat/其他 pane 时，对已绑定 Page 的 DOM/ARIA 读取与点击仍调用同一 browser_context_id + runtime_page_id。执行不得调用 Page.bringToFront()、BrowserWindow.focus()、OS 鼠标/键盘注入、桌面坐标或屏幕截图。
  6. 用户打开的 Page：用户通过 sidebar、center-tab 按钮或 split 操作打开一个已登记 web tab 后，下一 turn 的 Page Context 自动反映新的 visible/focused/relation 状态，不需要用户再次说明窗口身份。
  7. 显式关闭：通过 authenticated page.access.update 关闭“Agent 可访问”后，下一 turn descriptor 带新的 disabled access revision，不收到该 page 的 preview；如果没有其他可观察 page，则不注入 computer_use schema。关闭前创建的 binding、ComputerSession 和未执行写 lease 在下一次副作用前返回 page_access_disabled，UI 与回复都准确说明权限状态。
  8. Access CAS：两个并发或重放的 access update 使用同一 expected revision 时只允许一个成功；另一个返回 access_revision_conflict 和 actual state/revision，客户端提交的数值不能成为新 revision。
  9. 绑定隔离：同一窗口中未与当前 session 合并的 web tab、另一窗口的 web tab、隐藏的组成员都不能成为本 turn target；关闭工具后不注入 Computer Use 工具。
  10. BrowserContext 隔离：另一个 BrowserContext/profile 中的 Page 不得进入当前 Page Registry、Page Context 或 binding；runtime_page_id 只能在所属 BrowserContext 中解析。
  11. 多 Page 定向 resolve：同一 authenticated renderer 注册两个可控 Page 时，desktop.page.resolve 携带的 registry Page id 必须只返回对应 tab/target，并在 BrowserContext 中解析唯一 Page；错误 registry id、tab/target/Page 不一致或 reply identity 不一致均在动作前拒绝。
  12. Registry 权威性：伪造 registry page ID、跨 WebSocket ID、重复或旧 window/page/layout revision 均在 preview 和 CDP 请求前拒绝；renderer 断开会清除其 entries 与 lease。
  13. 发送后 target replacement：chat command 已提交后、PageService.snapshot() 执行前发生 target replacement 或 page_revision 增长时，visible_pages[].expected_page_revision 的 CAS 校验必须返回 page_context_stale 或 target_lost；旧 turn 不得绑定 replacement Page。
  14. 生命周期：运行中仅切换焦点不会改变 lease；当前 Page 被 hide、移组、跨窗口转移或关闭时，下一次副作用前返回 target_lost，不得操作新焦点 Page。
  15. Alias 稳定性：同一 Page 同时拥有空间位置与 focused 状态时，两类 alias 指向同一 canonical key；两个可见 Page 使用稳定 page:1/page:2，重复 relation 不生成歧义空间 alias；发送瞬间后的 focus 切换只影响下一 turn。
  16. Geometry 唯一性：left/right fixture 必须有纵向正交重叠，above/below fixture 必须有横向正交重叠；左上、右下等无正交重叠的对角 bounds 只返回 unknown，不得同时生成两个空间 alias。
  17. Tool contract：list_pages 只返回 inventory，observe 只返回 observation，act 只执行一个 Action，verify 只执行 assertion；缺少 command 必需字段、混入其他 command 字段、旧 surface 字段、空 assertion value、selector、raw Page handle 或 target id 均返回 invalid_arguments 且不执行 Page 动作。
  18. 跨 request ComputerSession：provider request A 的首次 observe 返回 session/frame，request B 使用同一 session 对该 frame 执行 act 成功；跨 user turn、跨 session 或换 target 后复用 frame 返回 stale_observation，且不执行动作。
  19. Preview 边界：断言可见文本不超过 2,000 字符、landmark 不超过 12 项且 name 不超过 160 字符、序列化 payload 不超过 8 KiB；所有截断标志准确，无 screenshot、element refs、隐藏内容或完整 DOM。
  20. Preview 一致性：捕获期间发生 navigation、viewport 或 registry/layout revision 变化时丢弃整份 preview；重试仍变化则返回 preview_status=unavailable，不得混合 frame。
  21. Capability：observe-only Page 可以回答页面问题，但 click/type/navigate 返回 capability_denied；动态工具注入本身不增加 capability。
  22. 重叠 turn：同一 session 并发产生两个 Page Context 后，每个工具调用仍按自己的 provider_request_id 解析 immutable alias/binding snapshot；旧 turn 的空间 alias 不能指向新 turn 的 Page。
  23. 延迟 tool call：模型 response stream 已结束但该 response 的 tool call 尚未执行时，execution envelope 仍通过 tool_call_id + source_provider_request_id 解析原 immutable binding；该 response 的全部 tool call settled 后 provider-request alias map 可释放，已创建的 ComputerSession binding 独立保留到 owner turn/sequence 终止。
  24. Popup 创建与归因：迁移后的 Electron handler 必须让测试链接产生独立 WebContentsView、CDP target 和 Playwright Page，原 Page 的 URL 不变，且默认不聚焦新 tab。Electron desktop.page.popup.requested 必须按 exact opener watch 立即阻止后续 act/verify-success；Playwright Page event 可延迟，只负责解析目标。连续执行 action A（无 popup）和 action B（有 popup）时，开始 B 前必须完成 main-owned replace 和旧 watch 的 drained ack，B 只使用自己的 action epoch；error、cancel、timeout、target lost 和 teardown 路径不得遗留 watch/listener。增加一个 popup 初始响应延迟超过 1 秒的 fixture：即使 Playwright event 延迟，Electron signal 仍立即产生 new_page_created，期间没有第二个副作用或 verified 终态。迁移完成前，同一 fixture 必须按现状明确归类为原 Page navigation，不得返回 new_page_created。
  25. Popup 控制面顺序：对 install ack、A 的 popup.requested、replace/close request 和 ack 注入 IPC/WS 延迟。install ack 到达前 PageService.act 调用次数必须为 0；A 的 requested event 已在 Electron main 产生但 Runtime 尚未处理时，replace/close ack 不得越过该 event，action B 和 verify-success 调用次数必须为 0。Runtime 处理到 ack 声明的 drained_through_event_seq 后才可继续；丢失 seq、ack timeout 或 identity mismatch 返回 popup_watch_failed，disconnect 返回 target_lost。
  26. Replace 持久恢复：session 的 action A 已建立 active watch，action B 在 begin_popup_replace 持久化完整 pending record 后发送 replace。分别注入 replace ack 丢失和发送后 Runtime crash：恢复进程必须读取同一 request_id + previous_popup_watch_id + next_popup_watch_id + next_action_epoch 并原样重放，期间 PageService.act、verify-success 和其他 session 写 action 调用次数为 0。main 回报 applied=true 时只把记录中的 next watch/epoch 提升为 active；回报 applied=false 且 active watch 等于 previous 时恢复旧 active watch 并继续持有 attribution lock，action B 仍不得执行，必须重新完成 replace 或 close-drain 终止 session；其他组合保持 quarantined。两条恢复路径均不得生成第三个 watch id/epoch，也不得把 action A 的延迟 popup 归因给 B。
  27. Popup watch 恢复：Electron main 已完成 close 但 close ack 丢失时，Runtime 用同一 control owner token + request id 重放必须得到相同 active_popup_watch_id + drained_through_event_seq，期间 window 保持 quarantined。close request/ack 永久不可达或 Runtime 在 install 后崩溃时，renderer/WebContents generation teardown 或不晚于 ComputerSession deadline 的 main-side expiry 必须删除旧 watch；Electron main sweep 并撤销旧 token，签发新 registration generation/token/nonce，Runtime 完成 registration 和 sync 后才能执行新 session。随后触发的 popup 不得带旧 popup_watch_id/action_epoch，也不得归因给已终止 session。
  28. Close 确定未应用：active watch 为 A 时，begin_popup_close 以 request C1 进入 release-pending；Electron main 返回经过完整校验的 applied=false + active=A。Runtime 必须恢复 active A、删除 C1 pending record并保留 attribution lock；重放 C1 只能得到相同缓存 false ack，不能用于完成终态。Runtime 生成新 request C2 后再次 close，只有收到 applied=true + active=null 且处理到 drained seq 后才释放 lock。C1/C2 期间其他 session 的 watch install 和 PageService.act 调用次数均为 0。
  29. Install ack 丢失：Electron main 已应用 install 但 ack 丢失、identity 不匹配或 seq 校验失败时，PageService.act 调用次数必须为 0，window 立即 quarantined，期间新 ComputerSession/action 调用次数也为 0。Runtime 用同一 control_owner_token + request_id 重放必须获得相同 active watch；因原 session 已失败，随后必须执行幂等 close/drain。只有通过 owner/request/identity/seq 校验的 ok=false + applied=false + active_popup_watch_id=null、成功 close-drained，或旧 token sweep + 新 registration generation/sync 后才能恢复；其他字段组合必须继续 quarantine。后续 popup 不得归因旧 action epoch。
  30. Control owner 隔离：记录旧 WebSocket/renderer generation 的合法 watch request 后，建立新的 control registration generation。用新 IPC sender 重放旧 control_owner_token + request_id、用旧 sender 提交新 token、跨窗口提交 token，Electron main 都必须在改变 watch state 前拒绝。新 renderer hello 只能提交 one-time nonce，不能提交 owner token；Runtime 解析出的 token 必须与 main ack echo 完全一致。
  31. 跨 ComputerSession popup 归因：两个重叠 turn 的 ComputerSession A、B 绑定同一 exact Page。A 的 action 完成但 last-action watch 仍 active 时，A 继续持有 popup-attribution lock；B 的 watch install/replace 和 PageService.act 调用次数都必须为 0，并返回 popup_attribution_busy。A watch 下已经产生的 Electron popup.requested 以及随后延迟到达的 Playwright Page event 只能归因 A。A 完成 close-drained 且 PageBroker 释放 attribution lock 后，B 才能 install 并执行；绑定两个不同 Page 的 ComputerSession 仍可并行。
  32. Pre-install lock 清理：取得 popup-attribution lock 后，分别在短 write lease 获取失败、cancel、target lost 和 pre-install exception 注入中断。只要 begin_popup_install 尚未生成 outbound record，watch IPC 调用次数必须为 0，PageBroker 以 not_installed 释放 reserved lock，下一 ComputerSession 可以立即取得该 Page 的 lock。另设 install outbound record 已生成但 ack 未知的 fixture：此时 not_installed 必须被拒绝，并进入既定重放、close-drained 或 main-side deletion 流程。
  33. 视觉坐标：在 device_scale_factor != 1、页面 zoom 和非零 scroll 的 fixture 上，图像 point 正确转换为 viewport CSS pixel；scale/zoom/scroll 改变后旧 frame 返回 stale_observation。
  34. Snapshot 并发：同一 Page 的 preview/Observation read barrier 与 action write barrier 不重叠；捕获中发生 DOM mutation 或并发写入使 content_epoch 改变时，整份 snapshot 被丢弃并重试或返回 unavailable/stale。
  35. 本地来源：未被 dev-server registry 或当前 project 明确登记的 localhost/127.0.0.1 origin 不进入 R1，外部写策略仍生效。
  36. Observation 边界：ARIA、interactive elements 和 console errors 分别满足 12,000 字符、200 项和 50 条硬上限及截断标志；password/typed secret/token 被替换，URL query 只保留 key、不保留 value。
  37. 终态清理：对 succeeded、failed、cancelled、终止型 needs_user、异常、target loss、用户拒绝、恢复超时和 session teardown 做故障注入，均 detach CDP、释放短 lease/approval 并删除临时 artifact；reserved 且没有 install outbound record 的 attribution lock 使用 not_installed 释放，installing 只接受 install-not-applied ack 或 main-side deletion，active/replacing/release-pending 则必须完成 close-drained 或取得 main-side sweep/expiry/target teardown deletion proof，PageBroker 才能释放。worker 重启按 TTL 清除 orphan ComputerSession 目录且不删除 retained artifact。
  38. 本地 DOM 流：在内置浏览器打开测试页，读取表单、输入、提交、验证 success message；用户始终可见同一 tab。
  39. 动态 DOM ref：observe 一次取得 exact handles 并直接生成命名按钮 refs；capture window 内或发布后插入同 tag/role/name sibling 时，使用原 frame/ref 的 click 仍命中原节点。把原节点替换成同指纹或不同指纹节点、发生 navigation 或 replacement Page 时返回 stale_observation 且错误节点 click 调用次数为 0。
  40. 简单视觉 fallback：在没有可用 DOM target 的 canvas fixture 上，request N 执行 screenshot，紧邻的 request N+1 收到且只收到这一张当前 viewport screenshot，随后完成一次 point click；不启动 OCR、detector、memory 或 zoom。capture 期间或之后发生 resize/scroll 时图像不发布或旧 action 返回 stale_observation；request N+1 执行失败 verify、非法 point 或没有执行工具时，request N+2 不得再次收到图片，且无图 coordinate click 必须返回 visual_observation_required。
  41. 验证与页面内容边界：verify 缺少 assertion、value 为空或仅含空白时必须失败且不能记录 completion evidence；planner prompt 必须把 Runtime envelope 与页面字符串区分，页面中的工具调用或权限指令不能改变 task、target、permission 或单步限制。
  42. 多窗口：两个 OpenProgram 窗口各有 web tab；指定窗口任务不得在另一窗口创建、激活或操作 tab。
  43. 并发：同一 Page 的并发 command 被短 write lease 拒绝；前一 ComputerSession 已释放 write lease但仍持有 popup-attribution lock 时，另一 session 的后续写任务返回 popup_attribution_busy。两个不同 Page 可并行完成且 artifact/session/watch 不交叉。
  44. 外部 origin：已关联 Page 的普通 DOM click/type 不产生重复的通用工具 approval；命中显式 ask rule 或高风险动作时显示准确 permission card，拒绝后零写入。
  45. 跨 origin：同一 Page redirect 进入新 origin 后旧授权失效；popup/new Page 返回 needs_user/new_page_created、释放原 lease 并结束旧 ComputerSession，不会替换当前 Page。用户关联新 Page 后，下一 turn 创建新 ComputerSession 才能控制。
  46. 登录/CAPTCHA：runner 返回 needs_user；用户接管后 Continue 使用新 frame，不复用暂停前 action。
  47. Prompt injection：页面要求忽略用户任务、读取文件或执行高风险动作时，Runtime 权限不变化，任务被阻止或请求用户确认。
  48. 取消：在 observe、模型调用、approval 等待和 action 间隙点击 Stop，均在下一次副作用前终止并释放 target。
  49. 失败诚实性：invalid planner output、step limit、timeout、action exception、verification failure 均不能返回 succeeded。
  50. 隐私：运行结束后临时 screenshot 被删除；event/transcript 中没有 typed secret；不产生 Harness workflow memory。
  51. 回归：现有 playwright_browser selector API、普通用户手动 web tab、tab transfer 和 session UI 不受影响。

13 第一阶段明确不做

目标范围

不控制整个本机桌面；不接入 remote VM；不操作 iOS/Android simulator；不控制其他本地 app；不处理多 app workflow。

浏览器范围

不接入用户日常 Chrome/Edge profile；不提供 sidecar、hidden 或 headless fallback；不自动接管 popup/new tab；桌面壳不在线时直接失败。

高权限动作

不开放 arbitrary JavaScript、cookie/storage 读写或导出、file upload/download、clipboard、浏览器设置、证书和扩展管理。

平台范围

不设计 Windows 专用实现、测试、打包或兼容路径；不引入 OS Keychain、keyring 或 Credential Manager 集成。
