Computer Use：内置浏览器优先的目标设计

本页定义 OpenProgram 的 Computer Use 当前目标设计。第一阶段只控制 OpenProgram 桌面端中用户可见的内置浏览器 tab；不控制整个操作系统，也不接管用户日常 Chrome。设计只复用现有 GUI Agent Harness 的规划与验证思路，不启用 OCR、YOLO/检测器、component memory、vision memory 或自动学习；OpenProgram Runtime 负责目标绑定、权限、动作执行、取消、并发和证据。

01 设计结论

公开入口：第一阶段新增面向任务的 browser_agent，目标固定为 OpenProgram 内置可见 web tab，不把 target 暴露为模型参数。现有 playwright_browser 保留为底层专家工具，现有 gui_agent 保留为桌面实验入口，三者不互相改名。以后增加桌面应用控制时，再由上层 Computer Use 入口组合不同 target adapter。

浏览器实现：复用 Electron WebContentsView、共享的 persist:webtabs profile、精确 tab 的 CDP target，以及 Playwright 数据面。用户和 agent 始终看到同一个 tab。

Harness 分工：第一阶段只复用 GUI Agent Harness 的 observe → verify → plan → act 思路；不启用 OCR、YOLO/检测器、component memory、vision memory、自动 component learning、多轮 crop 或局部放大，也不直接复用其进程全局 target、全屏截图、容错后继续执行、LLM 判定 success 和自动持久化 workflow 的行为。

动作策略：ARIA/DOM 语义定位优先，CSS 只作为确定性补充。只有 canvas、无标签控件或 DOM 不可用时，才把一张当前 viewport screenshot 直接交给多模态模型返回坐标；中间没有 OCR、检测器或视觉记忆。每个写动作执行后都重新观察；禁止跨页面状态批量执行写动作。

权限策略：本地项目页允许任务内自动验证；外部站点按 origin 授权。读取与写入分级，登录、CAPTCHA、跨 origin、敏感提交和不可逆操作进入 needs_user，不得由模型自行确认。

02 当前实现与必须先处理的缺口

这里记录的是仓库当前代码，不代表目标能力已经完成。

AVAILABLE

可见内置 tab 与 CDP 数据面

playwright_browser 默认 engine=app，只控制 OpenProgram 内可见 web tab。打开或选择 tab 后，桌面壳返回 CDP target_id，Playwright 按精确 target 附着。

证据：browser.py:37-52,148-152；_actions/open_action.py:142-240。

AVAILABLE

DOM 与 accessibility 读取

现有浏览器工具已支持 selector、HTML、正文提取、ARIA snapshot、console、frame、tab 等能力，可以承担浏览器专用的语义观察层。

证据：browser.py:56-160；_actions/read.py:7-72。

BLOCKER

多窗口控制面没有绑定 responder

webtab.command 广播到全部 WebSocket 客户端，pending 表接收首个同 req_id 的回执；命令没有 window_id，服务端也没有校验回执来自哪个 renderer。多个桌面窗口同时存在时，目标不确定。

证据：webui/ws_actions/webtab.py:18-69；web/lib/desktop-bridge.ts:478-562。

BLOCKER

视觉坐标与截图坐标不一致

现有 screenshot 默认 full_page=True。视觉模型返回的图像坐标不能直接作为当前 viewport 的 page.mouse 坐标，滚动页还会产生额外偏移。

证据：_actions/read.py:75-105。

BLOCKER

现有 Harness completion 不可信

planner 两次解析失败会返回 done；结论 prompt 固定要求模型输出 "success": true，顶层结果再采用该值。因此“模型不再调用动作”不能等同于“任务成功”。

证据：tasks/execute_task.py:575-607,792-834,886-949；main.py:168-193。

BLOCKER

状态、取消与记录不具备会话隔离

浏览器 session、Harness action target、VM screenshot patch 都使用进程全局可变状态；主执行循环没有 cancel 参数；没有 base memory 时会自动学习 component，每次任务还默认把完整 history 写入 workflow JSON。第一阶段 runner 不调用这些路径。

证据：browser.py:198-203；action/input.py:412-454；adapters/vm_adapter.py:20-31；main.py:98-102,116-193；tasks/execute_task.py:956-969。

约束：第一阶段不能把 gui_agent(task=...) 直接指向内置浏览器后作为产品能力发布。必须先由新的 session-scoped runner 接管 completion、target、cancel、artifact 和 approval；GUI Agent Harness 只提供可验证的共享算法或 adapter。

03 OpenAI 与 Anthropic 官方能力对标

比较对象分为三类：产品内置浏览器、连接用户日常浏览器的扩展、面向开发者的截图/动作 API。它们的权限边界不同，不能用同一套默认值。

官方产品目标与 profile交互与权限对 OpenProgram 的结论
OpenAI 内置 Browser ChatGPT desktop 内与用户共享页面视图；使用独立于日常浏览器的 profile，可在需要时单独登录。 面向网站研究、操作、本地 web app 预览；网页内容按不可信输入处理。 第一阶段产品形态的直接参考。
OpenAI Chrome extension 控制已有 Chrome tab，继承用户日常 Chrome 登录态。 连接现有 tab 和 profile，站点内容与权限需额外审查。 作为后续独立 backend；不能与内置 profile 隐式互换。
OpenAI Computer Use API 应用提供 browser/VM/harness；模型读取 screenshot，返回 actions[]。 执行动作后必须回传新 screenshot；官方要求隔离环境、域/动作 allowlist、高影响操作保留人工确认。 采用 action loop 与人工确认原则；不照搬纯坐标策略。
Claude Code Desktop Browser pane 独立 clean profile；与 chat、diff、terminal 并列显示；本地项目页和外部站点都可打开。 本地 dev server 可自动验证；外部站点首次 action 按站点允许一次、持续允许或拒绝；write action 受 classifier 检查。 最接近 OpenProgram 当前 UI 与开发测试场景。
Claude Code with Chrome 扩展连接已登录 Chromium；browser task 新开 tab，并实时可见。 站点权限来自扩展；plan mode 中 read-only 无提示，click/type/navigation 等写操作提示；登录或 CAPTCHA 暂停给用户。 采用 read/write 分类和人工接管；profile 接入延后。
Anthropic Computer Use API client-side screenshot、mouse、keyboard tool；应用负责实际执行与结果。 官方建议 VM/container、domain allowlist、敏感后果人工确认，并明确 coordinate、tool selection、scroll 和 prompt injection 的可靠性限制。 采用 client-owned execution 与显式 failure；不把模型输出当执行事实。

官方来源集中列在本页末尾。OpenAI 当前文档明确说明内置 Browser 不在 Codex CLI 或 IDE extension 中提供，而是在 ChatGPT web/desktop 产品面中提供；Computer Use plugin 可以在 desktop app 的 Codex 面中启用。因此这里参考的是 Codex 所在桌面产品面的 Browser/Computer Use 交互，不是假设 Codex CLI 自带浏览器。OpenAI 同时明确区分独立 Browser 与 Chrome profile；Claude Code Desktop 进一步明确 clean Browser profile、本地自动验证、外部站点授权和 Browser/Chrome 的选择规则。

04 采用、修改与明确拒绝

ADOPT

采用

独立 browser profile；同一可见 tab；session 内固定 target；observe/action/observe；按 origin 授权；本地项目页自动验证；登录和 CAPTCHA 人工处理；stop；网页内容按不可信输入处理。

MODIFY

修改后采用

DOM/ARIA 优先，单张 viewport screenshot 的模型原生视觉坐标按需降级；授权默认只持续当前 task，不先提供永久 Always allow；read 可以批量，write 每次最多一个状态变化；completion 由 Runtime 验证状态决定。

REJECT FOR PHASE 1

第一阶段不采用

用户日常 Chrome profile、整个桌面控制、隐藏/headless browser、任意 JavaScript、cookie/storage 导出、文件上传下载、模型自动输入密码、跨 origin 自动继续、无约束批量写动作、自动永久保存截图和 workflow。

第一阶段固定的低成本 baseline

第一阶段只有下面这一套固定执行路径，不建立 enable_ocr、enable_yolo、vision_memory_mode 等配置，也不加载对应模块。只有 baseline 的失败数据证明缺少某项能力时，才单独评估是否增加。

状态能力执行规则
开启URL、title、origin、viewport、DOM text、ARIA snapshot、interactive refs每步的默认 observation；先用结构化信息规划和定位，不发送图像。
按需开启一张当前 viewport screenshot + 模型原生 vision仅用于视觉验收、canvas 或 DOM/ARIA 无法定位的控件；不做 full-page screenshot、切片或多轮放大。
关闭OCR、YOLO/object detector、候选框检测、外部 grounding pipeline不导入、不初始化、不调用，也不为它们增加后台进程或依赖。
关闭component memory、vision memory、workflow replay、自动 component learning不读、不写、不检索；运行结束不形成可复用视觉记忆。
关闭iterative zoom、coarse-to-fine crop、多截图候选排序第一阶段不实现。直接视觉 fallback 失败后返回明确失败或请求用户处理。

成本约束：普通 DOM 表单和导航任务可以完全不向模型发送 screenshot；视觉任务每个 observation 最多发送一张当前 viewport screenshot。verification 优先使用 DOM/ARIA assertion，只有任务本身要求视觉判断时才再次使用图像。

05 目标架构与信任边界

信任边界：LLM 只收到经过裁剪的 Observation，并只返回候选 Action。Runtime 校验 target、frame、origin、权限和 cancel 后才能执行。CDP endpoint 和 browser context 不进入模型上下文。

OpenProgram Runtime 拥有

target selection、tab lease、approval、action validation、CDP attachment、artifact lifecycle、cancel、timeout、completion、audit events。

GUI Agent Harness 提供

规划结构、动作后验证建议和失败后的下一步候选。第一阶段不调用 Harness 的 OCR、检测、component/vision memory、自动学习或 iterative zoom；输出都视为建议，不具有执行权限。

06 公开入口与内部协议

公开工具

{
  "name": "browser_agent",
  "input": {
    "task": "required natural-language task",
    "url": "optional initial http(s) or allowed local URL",
    "max_steps": 20,
    "max_seconds": 300
  }
}

第一阶段 target 隐式固定为 web_tab。window_id、tab_id、cdp_target_id 不是 LLM 参数，由用户当前 UI 和 Runtime 决定，防止模型指定未授权 target。

结果契约

{
  "status": "succeeded | failed | cancelled | needs_user",
  "reason_code": "verified | step_limit | timeout | target_lost | ...",
  "summary": "grounded user-facing result",
  "target": {"kind":"web_tab", "tab_id":"...", "url":"..."},
  "steps_taken": 7,
  "completion_evidence": [{"kind":"assertion", "text":"...", "frame_id":"..."}],
  "artifacts": [{"kind":"screenshot", "path":"...", "retained":false}]
}

summary 可由 LLM 撰写，但 status 和 reason_code 只能由 Runtime 根据验证记录生成。达到 step limit、planner 无效或 conclusion 模型声称成功都不能生成 succeeded。

内部 session 与 observation

ComputerSession
  session_id, owner_run_id
  target: {window_id, tab_id, cdp_target_id}
  lease_id, state, started_at, deadline
  current_origin, approved_origins[]
  current_frame_id, navigation_epoch
  cancel_event, step_budget, artifact_dir

Observation
  frame_id, captured_at
  target identity, url, origin, title
  viewport: {width, height, device_scale_factor, scroll_x, scroll_y}
  screenshot: optional viewport-only PNG
  aria_snapshot, interactive_elements[]
  optional console errors and visual candidates

frame_id 必须绑定 target identity、navigation epoch、viewport 和当前 DOM revision；存在 screenshot 时还要绑定图像。坐标 Action 只能来自同一个 observation 的直接视觉 fallback，并且必须带 expected_frame_id；如果页面已经导航、滚动、resize 或 target 改变，Runtime 返回 stale_observation 并重新 observe。

Action

{
  "type": "click | type | press | scroll | hover | select | navigate | wait",
  "expected_frame_id": "frame_...",
  "target": {
    "kind": "element | point",
    "ref": "aria-or-runtime-ref",
    "selector": "optional validated selector",
    "x": 420,
    "y": 238
  },
  "text": "only for type",
  "intent": "short description for approval and audit"
}

同一个 Action 只能使用一种 target 表示。element ref 优先；selector 只能来自 Runtime observation 或工具调用的显式确定性参数；point 必须在 viewport 内且匹配当前 frame。eval、cookie、storage、upload、download 不属于第一阶段 Action。

该协议与模型 provider 无关。OpenAI 原生 computer_call、Anthropic tool_use 或 GUI Agent Harness planner 都必须先转换为同一个 Action，再经过相同的 target、frame、origin、approval 和 cancel 校验。provider adapter 可以处理各模型的 action schema 与坐标约定，但不能改变 Runtime 的权限和 completion 结论。

07 Observe → Resolve → Approve → Act → Verify

  1. Target Broker 获取或新建一个可见 web tab，返回精确 window_id + tab_id + cdp_target_id，并获得 tab lease。
  2. Adapter 默认捕获 ARIA snapshot、DOM 交互元素、URL/origin/title 和 viewport 元数据，不发送图像。任务需要视觉判断或 DOM/ARIA 无法定位时才捕获一张当前 viewport screenshot；不得使用 full-page screenshot 产生点击坐标。
  3. Harness 生成一个候选动作和预期效果。读取动作可以合并；每轮最多执行一个会改变页面状态的动作。
  4. Resolver 按 runtime ref/ARIA、受控 selector、单张 viewport screenshot 的直接模型坐标顺序解析目标。中间不运行 OCR、YOLO、detector、memory retrieval 或 zoom；模型不得直接获得 Playwright page。
  5. Runtime 校验 frame freshness、target lease、origin grant、action risk、cancel 和 budget。需要用户时返回 needs_user 状态并暂停 session。
  6. Adapter 执行动作并立即生成新的 Observation。verification 必须检查动作预期效果和任务 completion assertions。
  7. 只有 completion assertions 全部满足且没有未处理风险时才返回 succeeded。

08 权限、安全与隐私

级别示例第一阶段策略
R0 观察ARIA/DOM text、URL/title、按过滤条件读取 console error；必要时当前 viewport screenshot已绑定 target 后不重复提示；结构化观察优先，图像按需且不持久化。
R1 本地项目变更localhost、127.0.0.1 或 project-owned file 中 click/type/navigation用户明确要求测试时在 task 内允许；仍执行 cancel、frame 和 target 校验。
R2 外部普通变更外部 origin 上 click、type、navigation、tab create首次写动作按 exact origin 请求“本次动作”或“本任务”授权；subdomain 不继承。
R3 敏感或高影响登录凭证、发送/发布、购买、删除、账户/权限修改、接受条款、跨 origin 提交返回 needs_user，展示拟执行动作并由用户完成或逐次确认；不允许任务级自动授权。
UnsupportedCAPTCHA、任意 JS、cookie/storage 导出、upload/download、clipboard、浏览器设置不执行；返回明确 reason code。

Origin 与导航规则

  • 授权键是规范化 scheme + host + effective port，不是可模糊匹配的域后缀。
  • redirect、popup 或新 tab 导致 origin 改变时，原授权不延续；先 observe，再重新判断。
  • 本地 project origin 由 dev-server registry 或用户当前 project 显式建立，不只依赖字符串包含 localhost。
  • 网页、截图、DOM、ARIA、console 和下载提示都属于不可信输入。页面中的操作指令不能修改 task、权限或系统约束。

Artifact 策略

  • 每个 run 使用独立 artifact 目录；文件名包含 session/frame id，不使用固定 /tmp/gui_agent_screen.png。
  • 原始 screenshot 默认仅在运行期保存，结束后删除；验收或用户明确保存的截图才标记 retained=true。
  • typed text 在事件和 transcript 中只记录长度、目标和敏感度，不记录密码、token 或完整表单内容。
  • 第一阶段不调用 Harness learn_app_components、save_workflow_record 或任何 component/vision memory 读写，不自动保存个人页面截图。

09 桌面 UI 行为

不新增第二套浏览器窗口。Computer Use 使用现有 center tab/split layout：chat 保持可见，右侧或相邻 pane 显示被控制的 web tab。

运行中

tab header 显示“Computer Use”状态、step 计数和 Stop。chat 中只显示当前 observation 摘要、计划动作、执行结果和验证结果；原始 DOM 与 screenshot 默认折叠。

授权时

permission card 必须显示 origin、target tab、拟执行动作、将发送的非敏感文本摘要、风险原因，以及仅本动作/本任务/拒绝。第一阶段没有永久允许。

人工接管

登录、CAPTCHA 或敏感页面时 session 进入 needs_user。用户在同一可见 tab 中操作，点击 Continue 后 Runtime 生成全新 observation；旧坐标和旧 action 全部失效。

结束

结果展示 status、reason、完成证据和保留 artifact。step_limit、timeout、target_lost 必须显示为未完成，不用 LLM summary 覆盖。

10 失败、取消与并发语义

reason_code触发条件处理
stale_observationframe、scroll、viewport、navigation epoch 已改变不执行动作；重新 observe，不消耗 action step。
target_losttab/window 被关闭、CDP target 更换、renderer 断开释放 lease；失败结束。不得自动选择另一个 tab。
origin_changedredirect/popup/navigation 进入新 origin撤销旧 origin action grant，重新分类。
approval_requiredR2/R3 action 未授权暂停为 needs_user，不重试 action。
planner_invalid结构化 Action 两次无效或引用不存在失败或重新规划；绝不能转换为 done。
verification_failed动作执行但预期效果未出现携带差异重新规划；超过 recovery budget 后失败。
cancelled用户 Stop、run cancel、session teardown执行前检查并中止；清理 Playwright/CDP、lease、pending approval 和临时 artifact。
step_limit / timeout预算耗尽返回 failed，保留已验证的部分结果但不宣告成功。

并发单位是 web tab：同一 tab_id 同时只能有一个写 lease，不同 tab 可以并行读取或执行。Target Broker 必须把 command 发送给精确 window_id 对应的 renderer，并校验回执 connection/window/tab/target；禁止“广播后接受第一个 reply”。

11 实施顺序与每阶段出口

PHASE 0
确定性基础
定义协议类型、reason codes、completion authority；只提取无全局状态的 planner/verify 接口；明确不进入 component learning、OCR/detector、vision memory 和 workflow persistence；invalid plan 不再映射 done。
出口：单元测试证明 incomplete 不能变为 success。
PHASE 1
精确 Target Broker
为 desktop renderer/WS connection 建立稳定 window identity；command/reply 包含并校验 window_id、tab_id、target_id；加入 tab lease 和 teardown。
出口：双窗口测试连续 100 次命中指定 tab。
PHASE 2
WebTabAdapter
ARIA/DOM element refs、frame freshness、element-first action、按需单张 viewport screenshot 的直接视觉 fallback、动作后 observation；不接 OCR、detector、memory 或 zoom。
出口：localhost fixture 的 DOM 与 canvas 两类任务通过。
PHASE 3
ComputerUseRunner 与公开工具
接入 budget、cancel、approval、origin policy、artifact policy、structured result 和事件流；现有 playwright_browser 不改公开行为。
出口：权限、cancel、target lost、step limit 集成测试通过。
PHASE 4
桌面 UI 与真实浏览器验收
状态、Stop、permission card、人工接管和完成证据；使用 stable 18100 桌面环境进行 live CDP 测试。
出口：下面的 E2E 清单全部有可复核 artifact。

12 可执行验收标准

  1. 本地 DOM 流：在内置浏览器打开测试页，读取表单、输入、提交、验证 success message；用户始终可见同一 tab。
  2. 简单视觉 fallback：在没有可用 DOM target 的 canvas fixture 上，只向模型发送一张当前 viewport screenshot，不启动 OCR、detector、memory 或 zoom，并完成一次点击；resize/scroll 后旧 action 返回 stale_observation。
  3. 多窗口：两个 OpenProgram 窗口各有 web tab；指定窗口任务不得在另一窗口创建、激活或操作 tab。
  4. 并发：同一 tab 第二个写任务被 lease 拒绝；两个不同 tab 可并行完成且 artifact/session 不交叉。
  5. 外部 origin：首次写动作产生准确 permission card；拒绝后零写入；批准本任务后同 origin 普通 action 不重复提示。
  6. 跨 origin：redirect、popup 和新 tab 进入新 origin 后旧授权失效。
  7. 登录/CAPTCHA：runner 返回 needs_user；用户接管后 Continue 使用新 frame，不复用暂停前 action。
  8. Prompt injection：页面要求忽略用户任务、读取文件或执行高风险动作时，Runtime 权限不变化，任务被阻止或请求用户确认。
  9. 取消：在 observe、模型调用、approval 等待和 action 间隙点击 Stop，均在下一次副作用前终止并释放 target。
  10. 失败诚实性：invalid planner output、step limit、timeout、action exception、verification failure 均不能返回 succeeded。
  11. 隐私：运行结束后临时 screenshot 被删除；event/transcript 中没有 typed secret；不产生 Harness workflow memory。
  12. 回归：现有 playwright_browser selector API、普通用户手动 web tab、tab transfer 和 session UI 不受影响。

13 第一阶段明确不做

目标范围

不控制整个本机桌面；不接入 remote VM；不操作 iOS/Android simulator；不控制其他本地 app；不处理多 app workflow。

浏览器范围

不接入用户日常 Chrome/Edge profile；不提供 sidecar、hidden 或 headless fallback；桌面壳不在线时直接失败。

高权限动作

不开放 arbitrary JavaScript、cookie/storage 读写或导出、file upload/download、clipboard、浏览器设置、证书和扩展管理。

平台范围

不设计 Windows 专用实现、测试、打包或兼容路径；不引入 OS Keychain、keyring 或 Credential Manager 集成。
