Computer Use：可见 Surface 感知与内置浏览器控制设计

本页定义 OpenProgram 的 Computer Use 当前目标设计。核心要求不是单独提供一个浏览器函数，而是让每个 chat turn 自动知道同一窗口中当前可见、与该会话关联的 surface，并在需要时直接观察和操作。第一阶段执行目标是 OpenProgram 桌面端内置浏览器 tab；不控制整个操作系统，也不接管用户日常 Chrome。设计只复用现有 GUI Agent Harness 的规划与验证思路，不启用 OCR、YOLO/检测器、component memory、vision memory 或自动学习；OpenProgram Runtime 负责 surface 注册、目标绑定、权限、动作执行、取消、并发和证据。

01 设计结论

自动 Surface Awareness：只要 chat 与可见 pane/window 同属当前 compound group，renderer 就在每次发送消息时提交 surface identity、布局槽位和 bounds。Runtime 根据实际布局计算 surface 与 chat 的空间关系，再把当前 inventory 和 primary surface 的一个有界 DOM/ARIA preview 加入本 turn 上下文。模型从推理开始就知道“当前有哪些相邻 surface、分别位于哪里、是否可读写”，不会依赖固定的“右侧”常量。

公开入口：Agent 只使用一个 computer_use 工具，通过 list_surfaces → observe → act → verify 四个 command 获取当前信息并执行单步动作。工具接收当轮 canonical surface key 或 Runtime 动态生成的 alias，不接收 window_id、tab_id、CDP target 或任意 selector。第一阶段只有 web_tab adapter；现有 task-based computer_use(task=...) 是过渡实现，不是最终 Agent 接口。

工具可用性：存在已验证、可观察 surface 时，dispatcher 必须在该 turn 主动加入 computer_use schema，不受 deferred 默认加载影响。简单页面问答使用 turn-start primary preview；布局变化、需要完整交互元素或任何页面动作时由 Agent 调用工具。用户显式关闭网页控制时，Runtime 只提供不含页面内容的 inventory descriptor，不提供 observe/act capability。

浏览器实现：复用 Electron WebContentsView、共享的 persist:webtabs profile、精确 tab 的 CDP target，以及 Playwright 数据面。用户和 agent 始终看到同一个 tab。

后台位置无关：页面读取和点击绑定 window_id + tab_id + cdp_target_id，通过该 tab 的 WebContents/CDP 执行，不使用桌面屏幕坐标、OS 鼠标事件或 BrowserWindow.focus()。OpenProgram 可以位于其他窗口后方，目标 pane 也不必拥有键盘焦点；普通 DOM/ARIA 操作不截图。

Harness 分工：第一阶段只复用 GUI Agent Harness 的 observe → verify → plan → act 思路；不启用 OCR、YOLO/检测器、component memory、vision memory、自动 component learning、多轮 crop 或局部放大，也不直接复用其进程全局 target、全屏截图、容错后继续执行、LLM 判定 success 和自动持久化 workflow 的行为。

动作策略：ARIA/DOM 语义定位优先，CSS 只作为确定性补充。只有 canvas、无标签控件或 DOM 不可用时，才把一张当前 viewport screenshot 直接交给多模态模型返回坐标；中间没有 OCR、检测器或视觉记忆。每个写动作执行后都重新观察；禁止跨页面状态批量执行写动作。

权限策略：用户在已关联 chat + web surface 上发送任务时，形成只覆盖该 turn、该 binding 的访问授权；外层 computer_use 不再请求第二次通用工具批准。Runtime 仍先执行 hard constraints、authority 和显式 deny/ask rules；登录、CAPTCHA、跨 origin、敏感提交和不可逆操作继续进入 needs_user，不得由模型自行确认。

02 当前 turn-scoped baseline 与后续缺口

当前代码已经支持单个已登记 split web surface 的首轮感知和绑定控制；这里同时记录完整目标架构尚未覆盖的部分。

AVAILABLE

可见内置 tab 与 CDP 数据面

playwright_browser 默认 engine=app，只控制 OpenProgram 内可见 web tab。打开或选择 tab 后，桌面壳返回 CDP target_id，Playwright 按精确 target 附着。

证据：browser.py:37-52,148-152；_actions/open_action.py:142-240。

AVAILABLE

DOM 与 accessibility 读取

现有浏览器工具已支持 selector、HTML、正文提取、ARIA snapshot、console、frame、tab 等能力，可以承担浏览器专用的语义观察层。

证据：browser.py:56-160；_actions/read.py:7-72。

BASELINE AVAILABLE

Turn-scoped exact responder binding

preview 只发送到发起 chat turn 的 WebSocket；Runtime 记录并复核 window_id + tab_id + target_id，子进程只能用 opaque binding_id 请求 bound activate。完整 authenticated window registration、单调 revision、跨窗口 transfer invalidation 和排他 tab lease 尚未实现。

证据：webui/ws_actions/webtab.py；agent/process_runner.py；web/lib/desktop-bridge.ts；tests/unit/test_computer_use_surface.py。

BASELINE AVAILABLE

Turn-start Surface Awareness

composer 已提交当前 compound group 的 web surface ref；Runtime 在首个模型调用前捕获有界 DOM/ARIA preview 并加入上下文。存在有效 binding 时 provider 获得 resident computer_use schema，没有有效 surface 时该工具被移除。

证据：web/components/chat/composer/legacy-send.ts；agent/surface_context.py；agent/dispatcher/loop_runner.py。

DESIGN GAP

布局与 Agent 工具接口仍是固定 baseline

当前 renderer 只提交一个 surface，并把 region、chip 文案和工具 enum 固定为 right；公开 computer_use 仍接收自由文本 task 并启动内部 planner。浏览器 pane 位于左侧时仍可能按 tab identity 被控制，但位置语义错误；主 Agent 也没有可独立调用的 list/observe/act/verify 契约。

证据：web/lib/desktop-bridge.ts 的 TurnSurfaceRef/surfaceRefForChat；web/components/chat/composer/surface-chip.tsx；agentic_functions/browser_agent/__init__.py。

DEFERRED

Canvas 视觉 fallback 尚未接入

当前 baseline 的 DOM/ARIA 操作不截图。目标设计要求未来只使用单张 viewport screenshot 和模型原生 vision；现有 full-page screenshot 坐标不能用于该目标，因此未接入 computer_use。

证据：_actions/read.py；computer-use-implementation.html 的任务 2 边界。

ISOLATED

不采用 Harness 的模型 completion

当前 computer_use 由 post-action Runtime assertion 生成 status 和 reason_code，不调用 GUI Harness 的模型 success 路径。Harness completion 的原有问题仍存在，但不阻塞当前浏览器 baseline。

证据：agentic_functions/browser_agent/__init__.py；安装版 session local_340bc50ccd2c4eafb1fc12378e0489ab。

DEFERRED

完整 lease 与 registry lifecycle

当前 binding 有 TTL 并在 turn teardown 释放，但尚未实现 server-owned surface revisions、同 tab 排他写 lease、hide/move/transfer 即时 invalidation 和崩溃后的持久清理。当前 runner 不调用 Harness 的进程全局 target、memory 或 workflow persistence。

证据：agent/surface_context.py；webui/ws_actions/webtab.py；agent/process_runner.py。

约束：第一阶段不能把 gui_agent(task=...) 直接指向内置浏览器后作为产品能力发布。必须先由新的 session-scoped runner 接管 completion、target、cancel、artifact 和 approval；GUI Agent Harness 只提供可验证的共享算法或 adapter。

03 OpenAI 与 Anthropic 官方能力对标

比较对象分为三类：产品内置浏览器、连接用户日常浏览器的扩展、面向开发者的截图/动作 API。它们的权限边界不同，不能用同一套默认值。

官方产品目标与 profile交互与权限对 OpenProgram 的结论
OpenAI 内置 Browser ChatGPT desktop 内与用户共享页面视图；使用独立于日常浏览器的 profile，可在需要时单独登录。 面向网站研究、操作、本地 web app 预览；网页内容按不可信输入处理。 第一阶段产品形态的直接参考。
OpenAI Chrome extension 控制已有 Chrome tab，继承用户日常 Chrome 登录态。 连接现有 tab 和 profile，站点内容与权限需额外审查。 作为后续独立 backend；不能与内置 profile 隐式互换。
OpenAI Computer Use API 应用提供 browser/VM/harness；模型读取 screenshot，返回 actions[]。 执行动作后必须回传新 screenshot；官方要求隔离环境、域/动作 allowlist、高影响操作保留人工确认。 采用 action loop 与人工确认原则；不照搬纯坐标策略。
Claude Code Desktop Browser pane 独立 clean profile；与 chat、diff、terminal 并列显示；本地项目页和外部站点都可打开。 本地 dev server 可自动验证；外部站点首次 action 按站点允许一次、持续允许或拒绝；write action 受 classifier 检查。 最接近 OpenProgram 当前 UI 与开发测试场景。
Claude Code with Chrome 扩展连接已登录 Chromium；browser task 新开 tab，并实时可见。 站点权限来自扩展；plan mode 中 read-only 无提示，click/type/navigation 等写操作提示；登录或 CAPTCHA 暂停给用户。 采用 read/write 分类和人工接管；profile 接入延后。
Anthropic Computer Use API client-side screenshot、mouse、keyboard tool；应用负责实际执行与结果。 官方建议 VM/container、domain allowlist、敏感后果人工确认，并明确 coordinate、tool selection、scroll 和 prompt injection 的可靠性限制。 采用 client-owned execution 与显式 failure；不把模型输出当执行事实。

官方来源集中列在本页末尾。OpenAI 当前文档明确说明内置 Browser 不在 Codex CLI 或 IDE extension 中提供，而是在 ChatGPT web/desktop 产品面中提供；Computer Use plugin 可以在 desktop app 的 Codex 面中启用。因此这里参考的是 Codex 所在桌面产品面的 Browser/Computer Use 交互，不是假设 Codex CLI 自带浏览器。OpenAI 同时明确区分独立 Browser 与 Chrome profile；Claude Code Desktop 进一步明确 clean Browser profile、本地自动验证、外部站点授权和 Browser/Chrome 的选择规则。

04 采用、修改与明确拒绝

ADOPT

采用

每 turn 自动 surface inventory；有界的 DOM/ARIA preview；基于可见布局的语义 alias；动态工具注入；独立 browser profile；同一可见 tab；ComputerSession 内固定 target；observe/action/observe；按 origin 授权；本地项目页自动验证；登录和 CAPTCHA 人工处理；stop；网页内容按不可信输入处理。

MODIFY

修改后采用

DOM/ARIA 优先，单张 viewport screenshot 的模型原生视觉坐标按需降级；授权默认只持续当前 task，不先提供永久 Always allow；read 可以批量，write 每次最多一个状态变化；completion 由 Runtime 验证状态决定。

REJECT FOR PHASE 1

第一阶段不采用

用户日常 Chrome profile、整个桌面控制、隐藏/headless browser、任意 JavaScript、cookie/storage 导出、文件上传下载、模型自动输入密码、跨 origin 自动继续、无约束批量写动作、自动永久保存截图和 workflow。

第一阶段固定的低成本 baseline

第一阶段只有下面这一套固定执行路径，不建立 enable_ocr、enable_yolo、vision_memory_mode 等配置，也不加载对应模块。只有 baseline 的失败数据证明缺少某项能力时，才单独评估是否增加。

状态能力执行规则
开启URL、title、origin、viewport、DOM text、ARIA snapshot、interactive refs每步的默认 observation；先用结构化信息规划和定位，不发送图像。
按需开启一张当前 viewport screenshot + 模型原生 vision仅用于视觉验收、canvas 或 DOM/ARIA 无法定位的控件；不做 full-page screenshot、切片或多轮放大。
关闭OCR、YOLO/object detector、候选框检测、外部 grounding pipeline不导入、不初始化、不调用，也不为它们增加后台进程或依赖。
关闭component memory、vision memory、workflow replay、自动 component learning不读、不写、不检索；运行结束不形成可复用视觉记忆。
关闭iterative zoom、coarse-to-fine crop、多截图候选排序第一阶段不实现。直接视觉 fallback 失败后返回明确失败或请求用户处理。

成本约束：turn-start preview 只包含 surface 元数据、可见正文的有界摘录、ARIA landmarks 和交互元素计数，不包含 screenshot、完整 DOM 或完整 accessibility tree。普通 DOM 表单和导航任务可以完全不向模型发送 screenshot；视觉任务每个 observation 最多发送一张当前 viewport screenshot。verification 优先使用 DOM/ARIA assertion，只有任务本身要求视觉判断时才再次使用图像。

05 目标架构与信任边界

TURN INPUT

Surface Context

每次发送消息时由 SurfaceService.snapshot(chat_session_id) 生成。它包含可见 surface inventory、根据实际布局计算的 alias、capability，以及 primary surface 的一个有界 preview；不是 renderer 拼接的固定 prompt，也不是长期 memory。

RUNTIME AUTHORITY

Surface Registry

以 window、renderer、compound group 和 layout revision 校验客户端候选，签发短期 binding。只有 Registry 中已验证的 surface 才能进入模型上下文或成为工具目标。

TOOL EXECUTION

Surface Adapter

第一阶段只有 WebTabAdapter。后续内部 panel、terminal 或文件预览必须各自提供受限 adapter；不能通过一个任意坐标工具隐式扩大到整个桌面。

信任边界：LLM 先收到经过校验和裁剪的 Surface Context，调用工具后再收到 Observation，并只返回候选 Action。Runtime 校验 binding、target、frame、origin、权限和 cancel 后才能执行。CDP endpoint、browser context 和客户端声明的原始 target id 不进入模型上下文。

OpenProgram Runtime 拥有

surface discovery、layout relation、turn preview、tool availability、target selection、tab lease、approval、action validation、CDP attachment、artifact lifecycle、cancel、timeout、completion、audit events。

GUI Agent Harness 可复用

复用 action/observation 结构、动作后验证规则和失败分类，不把 Harness 的内部 LLM planner 放在主 Agent 与工具之间。第一阶段不调用其 OCR、检测、component/vision memory、自动学习或 iterative zoom。

本 schema 是唯一 canonical source。主 Agent 不再为 discovery、DOM、ARIA、click 和 verify 分别加载多个顶层工具。provider 支持 oneOf 时直接发送该 schema；不支持时，provider adapter 只把同一组完整字段与 description 平铺，并保留 command enum，Runtime 继续用 canonical schema 校验，不能把 action 降为无字段 object。list_surfaces 不需要 surface/session；首次 observe 需要 surface，并创建返回一个 opaque computer_session_id；后续 observe 只需要 session；act 需要 session 和 action；verify 需要 session、顶层 frame 和 assertion。session 建立后不得同时再传 surface。多余或缺失字段在调用 adapter 前返回 invalid_arguments。

element_present 不接受 selector 或模糊 DOM 查询；它按当前 observation 的 accessibility role 和 accessible name 匹配，match=exact 为默认推荐，contains 仅用于页面名称包含动态计数等已知情况。

surface 只能使用 Runtime 在当前 Surface Context 中提供的 canonical key 或动态 alias，例如 s1、left、focused 或 web:1；provider 实际收到的 schema 可以把当前可用值展开为 enum。首次 observe 必须显式提交该值；Agent 可以直接提交 Surface Context 中的 primary_surface_key，但 Runtime 不根据省略字段隐式选择目标。未知、缺失、过期或没有唯一映射的值返回 ambiguous_surface。window_id、tab_id、cdp_target_id、CSS selector 和 Playwright page 不成为 LLM 参数。

list_surfaces 读取当前 Registry 并返回最新 inventory；它不修改产生本次调用的旧 provider request/alias map，tool result 之后的下一次 provider request 会获得新 revision 的 Surface Context。首次 observe(surface=...) 使用 source provider request 的 immutable alias map 创建 ComputerSession；若此时 context 的 layout/surface revision 已不是当前值，则在绑定 target 前返回 surface_context_stale。session 建立后，后续 command 只使用 session id，focus、其他 pane 或不改变目标成员身份的 layout 更新不会使 session 失效；目标被隐藏、移出 group、转移、关闭或 target identity 改变时返回 target_lost，对应 access 变为 disabled 时返回 surface_access_disabled。三种失败都不自动迁移 session。observe(detail="summary") 返回有界文本与 landmark；interactive 额外返回 ARIA snapshot 和 element refs；visual 只在任务本身要求视觉判断、canvas 或 interactive observation 无法定位时返回一张当前 viewport screenshot。

act 每次只执行一个 canonical Action，Action 内必须携带最近 observation 的 expected_frame_id。任何写动作后旧 frame 和 element refs 立即失效；Agent 必须重新 observe。verify 只执行 Runtime assertion，不接受自然语言“已经完成”作为成功证据。导航属于 act.action.type=navigate，只改变已经绑定的同一个 tab，不创建或切换 tab。

当前 computer_use(task, surface, url, max_steps, max_seconds) 通过内部 planner 完成多步任务。迁移时保留它作为 Function/旧调用兼容入口，但主 chat Agent 的动态 tool schema 改为上述 command contract；同一请求不能同时使用 task wrapper 和 command API。这样主 Agent 可以直接读取实际 surface、逐步交互和验证，不需要为一次简单观察再启动一个内部 LLM。

Agent 接入规则

  1. turn 开始时，dispatcher 调用同一个 SurfaceService.snapshot(chat_session_id, provider_request_id)，把 inventory 和 primary preview 序列化为独立的 <surface_context> block；prompt 不写固定 left/right，也不从用户文本推测页面位置。
  2. 存在至少一个 observe capability 时注入 computer_use。模型先使用 context 回答简单页面问题；信息不够、布局变化或需要动作时调用 tool，不要求用户补 URL、截图或复制页面文字。
  3. 每个 tool call 由 Runtime 自动附加 source_provider_request_id + tool_call_id。模型在首次 observe 时提交 surface alias，随后提交 Runtime 返回的 opaque computer_session_id、frame 和 action；不能指定另一个 window、WebSocket、tab 或 target。
  4. tool result 使用统一 envelope；Agent 根据 status/reason_code 决定继续 observe、请求用户接管或结束。只有 verify 的 assertion 通过后，Runtime 才能产生 succeeded/verified。

Electron main 先通过已有本地认证边界为每个桌面窗口登记不可复用的 window_id + renderer_instance_id + one_time_connection_nonce。renderer 建立 WebSocket 时只能提交该 nonce；Runtime 消费一次后把连接绑定到已登记窗口。普通 Web 客户端不能自行声明 desktop window identity。连接关闭时，Runtime 删除该连接下全部 registry entries，并使关联 binding 和 lease 失效。

renderer 通过完整 desktop.surface.sync snapshot 维护 server-owned registry，而不是在 chat command 中临时声明页面状态。每个窗口的 window_revision 和 layout_revision、每个 surface 的 surface_revision 都必须单调递增；重复或旧 revision 被拒绝。snapshot 原子更新 visibility、focus、compound group、pane order 和 bounds。renderer 不提交 region="right" 这类语义结论；Runtime 使用同一 layout revision 下的 chat bounds 与 surface bounds 计算 relation。仅 focus、其他 pane或同组内位置变化只影响下一 turn 的 inventory/alias，不改变已建立 ComputerSession 的 target binding；若目标 pane resize 导致 viewport 变化，只使旧 frame 返回 stale_observation。hide、移出当前 group、跨窗口 transfer、close、renderer/window disconnect 通过 snapshot 差异或显式 invalidate 立即使 session/binding 失效，下一次副作用前返回 target_lost。

focused_registry_surface_id 是一个 window/layout revision 内的单值字段，因此 registry 不会出现两个 focused surface。跨窗口 transfer 不更新原 entry 的 window id；源连接必须先 invalidate 旧 entry 和 lease，目标连接再以新的 registry_surface_id 出现在自己的 authenticated snapshot 中。binding、surface revision、alias 和 lease 都不跨窗口继承。

renderer 在每次 chat command 中只引用 registry 已登记的可见 surface ID、revision 和当前 chat pane identity。候选可以来自左侧、右侧、上方或下方相邻 pane，也可以来自用户从 sidebar/按钮打开并已登记到当前 compound group 的 surface。普通独立 chat、隐藏 group member、其他窗口和未登记的 native window 不进入引用集合。Runtime 根据 connection-owned registry 校验 session、group、visibility、focus 和 layout 后签发短期 binding；未知 ID、旧 revision 或跨连接 ID 在生成 preview 前拒绝。最终 origin、title 和 capabilities 由已绑定 adapter 读取，不采用 renderer payload 中的同名值。

Runtime 在模型调用前为全部已验证 surface 生成轻量 descriptor，只对 primary surface 生成有界 preview。descriptor 包含 kind、relation、title、origin、capability 和 access 状态；primary preview 的序列化顺序固定为 DOM 顺序的 viewport 可见文本、ARIA landmark、interactive count。合并连续空白后，可见文本最多 2,000 个 Unicode 字符，landmark 最多 12 项且每项 name 最多 160 个字符，整个 preview 最多 8 KiB UTF-8。每个受限字段都有独立 *_truncated，总大小触顶时还有 payload_truncated。preview 不包含 screenshot、完整 DOM、完整 accessibility tree、element refs、iframe 隐藏内容或不可见节点。非 primary surface 通过 computer_use(command="observe") 按需读取，避免每 turn 重复提交所有页面正文。

preview 携带 captured_at + preview_frame_id + content_epoch + window_revision + surface_revision + layout_revision + navigation_epoch。Adapter 为每个 tab 维护 DOM mutation/navigation 驱动的 content_epoch，并在同一 tab 的 snapshot barrier 内捕获 DOM text 与 ARIA。捕获前后各读取一次 target、navigation、viewport、content epoch 和 registry revision；任一值变化就丢弃整份结果并重试一次，第二次仍不一致则标记 preview_status=unavailable，不能混合两个 frame 的内容。捕获超过本地 deadline 或页面暂不可读时也只返回 unavailable descriptor，模型随后使用工具重试观察。preview 只服务当前 turn，页面变化后失效，不进入 component memory、vision memory 或 workflow replay。

Surface Context 中的 title、正文和 ARIA 文本都标记为 untrusted_content，与用户消息和系统规则分隔。网页文字不能要求模型更换 surface、启用工具、扩大权限或执行动作；Runtime 也不能根据 preview 文本修改 capability 和 risk tier。

只要存在至少一个具备 observe capability 的 surface，dispatcher 就在该 turn 将 computer_use schema 放入 provider tool array，并追加 Surface Context。interact 和 navigate 都以 observe 为前置能力；Registry 拒绝缺少 observe 的 interact/navigate 组合。该规则优先于工具的 deferred 默认状态。模型因此在生成第一个 token 前已经知道实际相邻页面及其 relation；简单问题可直接依据 primary preview 回答，信息不足时调用 computer_use(command="observe", surface="left")。任何 click、type、navigate 等页面变更都必须调用 act，不能只根据 preview 声称已执行。

SurfaceService 生成 snapshot 时从 server-owned access map 读取并冻结 access + access_revision，不接受 renderer/chat payload 中的同名字段。用户显式关闭网页控制时，Runtime 仍可告诉模型“存在一个未授权 surface”，但不附带页面内容；若当前 turn 没有其他可观察 surface，则不注入执行工具。UI 必须显示“Agent 无法访问”，避免模型把权限禁用误判为页面不存在。将 chat 与 web tab 合并为同一 compound group，默认只授予该 surface 的 R0 结构化读取；R1-R3 写操作仍按后文策略处理。

首次 observe 时，Surface Broker 使用 binding_id + registry_surface_id 向精确 renderer 请求对应的 CDP target，随后把 window_id + registry_surface_id + local_surface_id/tab_id + cdp_target_id + layout_revision 固定到 ComputerSession。每个 observe/act/verify command 再按 read/write 模式取得短 lease。运行期间切换焦点不会改变 target；关闭、移出 compound group、跨窗口转移或 renderer 断开会使 session/binding 失效，并返回 target_lost，不得自动选择另一个可见 surface。

这里的“可见 surface”描述布局归属和用户可检查性，不要求 OpenProgram 成为 macOS/桌面环境的前台应用，也不要求目标 pane 当前接收键盘事件。读取和动作直接发送到绑定的 WebContents/CDP target；禁止先激活操作系统窗口、按桌面坐标点击或截取整个屏幕。只有目标仍登记在当前 compound group 内时绑定才有效；hide、移出 group、跨窗口 transfer、close、disconnect 或 target identity 变化后必须返回 target_lost。同组内重新排布本身不会解除已建立的绑定。

Dispatcher 保存不可变映射 provider_request_id → turn_id + context_id + context_revision + alias_map + bindings。每个 tool call 的执行 envelope 由 Runtime 写入 tool_call_id + source_provider_request_id，模型不能提交或覆盖它；alias 只能在产生该 tool schema 的同一个 provider request 快照中解析。即使同一 chat session 有重叠 turn 或后续 Surface Context，旧工具调用也不得查询 session 的“最新 alias map”。模型 response stream 结束不立即删除映射：没有 tool call 时可以释放；存在 tool call 时保留到该 response 产生的全部 tool call settled。首次 observe 成功后，ComputerSession 以 computer_session_id → owner_turn_id + binding + frame_registry 独立持有 exact target，provider-request alias map 可以正常释放。

ComputerSession 只允许 owner turn 的后续 provider requests 使用；Runtime 从 tool execution envelope 取得 turn id，不信任模型提交。Observation frame 保留到同 session 的下一次 observation 替换它、任何写动作使它失效、target/navigation/viewport/content/access revision 改变，或 turn 被完成、取消、超时、session teardown。无关 focus/layout revision 不单独使 frame 或 session 失效。跨 user turn、跨 ComputerSession 或跨 target 提交 frame 一律返回 stale_observation。read-only ComputerSession 在 turn 结束时释放；发生写动作的 ComputerSession 在 verify 终态、needs_user 终止、失败、取消或 turn teardown 时释放。异常遗留 session 按短 TTL 清理。

Alias 与 primary surface 规则

  1. Runtime 为本 turn 的每个 surface 分配 canonical surface_key（s1、s2），并生成显式 alias_map。key 和 alias 只在该 Surface Context revision 内有效。
  2. 空间 alias 只来自同一 layout_revision 的实际 pane geometry。先计算横向和纵向区间的正交重叠长度：只有纵向重叠 > 0 且 surface 右边界不超过 chat 左边界时为 left，纵向重叠 > 0 且 surface 左边界不小于 chat 右边界时为 right；只有横向重叠 > 0 且 surface 下边界不超过 chat 上边界时为 above，横向重叠 > 0 且 surface 上边界不小于 chat 下边界时为 below。矩形本身重叠时为 overlap；对角分离而无正交重叠、bounds 非法或 revision 不一致时为 unknown。overlap/unknown 不生成空间 alias。不得用数组下标、tab 类型或历史默认值推断 right。
  3. 只有一个可控 surface 对应某 relation 时才分配 left/right/above/below alias；同一 relation 有多个候选时不生成该空间 alias。用于 UI 展示的 relation 可以保留，但不能作为 target identity。
  4. focused 只指向提交消息瞬间拥有焦点的可控非 chat surface。focus 在 turn 进行中变化不会修改当前 alias_map，但会反映到下一 turn。
  5. web:1、web:2 按提交瞬间的 pane_order 生成；顺序相同则以 registry_surface_id 排序。一个 surface 可以同时拥有 left、focused 和 web:1。
  6. primary_surface_key 优先取 focused controllable surface；没有时取唯一可见 controllable surface；仍有多个候选时为空。模型可以传 alias 或 canonical key；未知、过期或没有唯一映射的值在任何 CDP 请求前失败。

从普通聊天到一次页面操作

  1. Desktop bridge 已通过单调 revision 的 registry events 登记窗口与 surface。用户在 chat + web tab 的 compound group 中提交消息；composer 只引用当前可见 registry surface ID 和 revision，不发送 screenshot 或 CDP target。
  2. Surface Registry 验证引用并通过 adapter 捕获有界 preview。服务端在模型调用前加入 Surface Context。当前 baseline 已注入 task-wrapper computer_use；PHASE 0 gate 通过后，主 Chat Agent schema 替换为本节 command contract，后续 registry/lease gate 不否定当前 baseline 的已验证能力。
  3. 模型从 turn 开始就知道实际相邻页面及其 relation。简单页面概述可以使用 primary preview；需要其他 surface、更多内容或任何交互时调用公开工具。
  4. 首次 observe 时，Surface Broker 定向解析 exact renderer/tab/target，创建绑定 owner turn 的 ComputerSession，并为该 command 获取 read lease；解析失败返回结构化错误，不让普通聊天模型自行解释为“看不到”。
  5. 主 Agent 通过跨 provider request 的 command loop 执行 DOM/ARIA-first 观察与单步动作；每个 command 由 Runner 校验 session、frame 和短 lease。只有视觉任务、canvas 或语义定位失败时发送一张当前 viewport screenshot。
  6. 每个状态变化后重新观察和验证，事件回写同一 chat turn；Stop、授权和人工接管都绑定同一个 ComputerSession 与 target。

该对象不是单次 command 的返回值，而是 Runtime 在一个 ComputerSession 结束时为 UI、event log 和兼容 task wrapper 聚合的审计结果。summary 可由 LLM 撰写，但 status 和 reason_code 只能由 Runtime 根据 verification 记录生成。达到 step limit、planner 无效或模型文字声称成功都不能生成 succeeded。模型和 transcript 只收到 opaque artifact_id；本地绝对路径不进入结果。终态结果只列用户明确保留或验收要求保留的 artifact，临时 retained=false 文件在返回前删除。

内部 session 与 observation

ComputerSession
  computer_session_id, owner_turn_id, source_context_id
  target: {window_id, registry_surface_id, local_surface_id, tab_id, cdp_target_id}
  binding_id, access_revision, state, started_at, deadline
  current_origin, approved_origins[]
  frame_registry[], current_frame_id, navigation_epoch, action_epoch
  cancel_event, step_budget, artifact_dir

Observation
  frame_id, content_epoch, captured_at
  target identity, url, origin, title
  viewport: {width, height, device_scale_factor, page_zoom, scroll_x, scroll_y}
  screenshot: optional viewport-only PNG
  screenshot_size: optional {width, height}
  aria_snapshot, aria_truncated
  interactive_elements[], elements_truncated
  optional filtered console_errors[], console_truncated

frame_id 必须绑定 target identity、navigation epoch、viewport 和当前 DOM revision；存在 screenshot 时还要绑定图像。坐标 Action 只能来自同一个 observation 的直接视觉 fallback，并且必须带 expected_frame_id；如果页面已经导航、滚动、resize 或 target 改变，Runtime 返回 stale_observation 并重新 observe。

完整 Observation 仍有硬上限：ARIA snapshot 最多 12,000 个 Unicode 字符，interactive elements 最多 200 项且每项 name 最多 200 字符，console error 最多 50 条且每条最多 1,000 字符；每类都带 truncation 标志。密码控件的 value、typed secret、authorization/token 字段和 URL query value 默认替换为 redacted marker；URL 保留 scheme、host、port、path 和 query key，不把 query value 写入模型上下文或事件。

Action

computer_use.input_schema.$defs.action 是唯一 Action schema；本节只解释其执行语义，不维护第二份字段定义。

type 是判别字段；每个分支只允许该 action 所需字段并设置 additionalProperties=false。element ref 优先；point 只允许 click/hover，必须位于当前 viewport，并来自同一 expected_frame_id 的单张视觉 fallback。navigate 只改变当前 lease 的 tab；scroll 和 wait 不接受 target。eval、cookie、storage、tab create、upload、download 不属于第一阶段 Action。

Canonical point 以当前 viewport 左上角为 (0,0)，单位是 CSS pixel，不是 screenshot image pixel、device pixel 或页面文档坐标。Observation 同时记录 viewport CSS width/height、screenshot image width/height、device_scale_factor 和页面 zoom；provider adapter 按这组元数据把模型图像坐标归一化为 CSS pixel。Runtime 再检查有限数值和 0 ≤ x < viewport.width、0 ≤ y < viewport.height。device scale、zoom、resize 或 scroll 变化都会使原 frame 失效，不能复用旧 point。

该协议与模型 provider 无关。OpenAI 原生 computer_call、Anthropic tool_use 或 GUI Agent Harness planner 都必须先转换为同一个 Action，再经过相同的 target、frame、origin、approval 和 cancel 校验。provider adapter 可以处理各模型的 action schema 与坐标约定，但不能改变 Runtime 的权限和 completion 结论。

07 Observe → Resolve → Approve → Act → Verify

  1. Surface Registry 已在 turn 开始前提供可见 surface、preview 和动态工具；Surface Broker 根据调用中的 alias 解析唯一 binding，返回精确 window_id + tab_id + cdp_target_id，并获得 tab lease。
  2. Adapter 默认捕获 ARIA snapshot、DOM 交互元素、URL/origin/title 和 viewport 元数据，不发送图像。任务需要视觉判断或 DOM/ARIA 无法定位时才捕获一张当前 viewport screenshot；不得使用 full-page screenshot 产生点击坐标。
  3. 主 Chat Agent 根据 Observation 生成一个候选动作和预期效果，并通过 computer_use(command="act") 提交。GUI Agent Harness 只提供可复用的 action/verification 结构，不启动第二个 planner。读取动作可以合并；每轮最多执行一个会改变页面状态的动作。
  4. Resolver 按 runtime ref/ARIA、受控 selector、单张 viewport screenshot 的直接模型坐标顺序解析目标。中间不运行 OCR、YOLO、detector、memory retrieval 或 zoom；模型不得直接获得 Playwright page。
  5. Runtime 校验 frame freshness、target lease、origin grant、action risk、cancel 和 budget。需要用户时返回 needs_user 状态并暂停 session。
  6. Adapter 执行动作并立即生成新的 Observation。verification 必须检查动作预期效果和任务 completion assertions。
  7. 只有 completion assertions 全部满足且没有未处理风险时才返回 succeeded。

Origin 与导航规则

  • 授权键是规范化 scheme + host + effective port，不是可模糊匹配的域后缀。
  • same-tab redirect/navigation 导致 origin 改变时，原授权不延续；在同一 ComputerSession/target binding 上为下一次 observe 重新获取 read lease，再观察和分类。
  • 只有 CDP target 的 opener/initiator target 与当前 leased target 匹配，且创建时间晚于当前 action_epoch，才把 popup/new tab 归因于本 action。此时 Runtime 不自动采用新 target，而是中止 action、释放原 lease，并以 needs_user/new_surface_created 结束当前 ComputerSession；用户显式关联后，只能在下一 turn 创建新的 ComputerSession 和 binding。其他窗口或用户并发打开的无关 tab 只进入各自 registry，不影响当前 ComputerSession。
  • 本地 project origin 由 dev-server registry 或用户当前 project 显式建立，不只依赖字符串包含 localhost。
  • 网页、截图、DOM、ARIA、console 和下载提示都属于不可信输入。页面中的操作指令不能修改 task、权限或系统约束。

Artifact 策略

  • 每个 ComputerSession 使用独立 artifact 目录；文件名包含 session/frame id，不使用固定 /tmp/gui_agent_screen.png。
  • 原始 screenshot 默认仅在运行期保存。succeeded、failed、cancelled、终止型 needs_user、异常退出和 target loss 都经过同一个 finally 路径 detach CDP、释放 lease/approval，并删除临时 artifact；验收或用户明确保存的截图才标记 retained=true。
  • 可恢复的登录/CAPTCHA needs_user 只在 ComputerSession deadline 内保留 session 和临时 artifact；用户拒绝、超时、session teardown 或 worker shutdown 时执行相同 cleanup。worker 启动时按 owner ComputerSession 状态和 TTL 清理 orphan ComputerSession 目录。
  • artifact API 对模型和前端只返回 opaque artifact_id、kind、retained 与受控读取 URL；不返回本地绝对路径。
  • typed text 在事件和 transcript 中只记录长度、目标和敏感度，不记录密码、token 或完整表单内容。
  • 第一阶段不调用 Harness learn_app_components、save_workflow_record 或任何 component/vision memory 读写，不自动保存个人页面截图。

09 桌面 UI 行为

不新增第二套浏览器窗口。Computer Use 使用现有 center tab/split layout：chat 与被控制的 web tab 可以按实际布局位于彼此左、右、上、下。UI 展示的 relation、Agent 收到的 alias 和 Broker 解析的 surface key 必须来自同一个 SurfaceService snapshot。

待命

chat composer 附近显示当前可见 surface 的 favicon、title/origin、位置 alias 和“Agent 可访问”状态。用户在 sidebar、center tab 或 split pane 中改变可见/focused surface 时立即更新；工具关闭时显示“网页控制未启用”。

发送消息

发送后该 turn 的 surface chip 固定为提交时的 title、relation 和 revision。模型已经收到同一份 Surface Context；用户可以展开查看“本轮 Agent 可见内容”的结构化 preview。后续切换 pane 不会静默改变正在运行的目标。

运行中

tab header 显示“Computer Use”状态、step 计数和 Stop。chat 中只显示当前 observation 摘要、计划动作、执行结果和验证结果；原始 DOM 与 screenshot 默认折叠。

授权时

permission card 必须显示 origin、target tab、拟执行动作、将发送的非敏感文本摘要、风险原因，以及仅本动作/本任务/拒绝。第一阶段没有永久允许。

人工接管

登录、CAPTCHA 或敏感页面时 session 进入 needs_user。用户在同一可见 tab 中操作，点击 Continue 后 Runtime 生成全新 observation；旧坐标和旧 action 全部失效。

结束

结果展示 status、reason、完成证据和保留 artifact。step_limit、timeout、target_lost 必须显示为未完成，不用 LLM summary 覆盖。

reason_code触发条件处理
invalid_argumentscommand 缺少必需字段、携带其他 command 字段、raw target/selector 或未知字段在 surface resolve 和 CDP 请求前拒绝，返回允许的 command contract。
surface_unavailableturn 中没有经过验证且允许访问的可见 surface不注入执行工具；上下文明确说明不存在可用 surface，不使用任意 active tab 代替。

并发单位是 web tab：同一 tab_id 同时只能有一个写 lease，不同 tab 可以并行读取或执行。同一 tab 的 preview/Observation 捕获使用 snapshot read barrier，任何 action 使用 write barrier；两者的临界区不得重叠。页面自身的异步 DOM mutation 通过 content_epoch 检测，变化时丢弃整份 snapshot 并重试或返回 unavailable/stale。Surface Broker 必须把 command 发送给精确 window_id 对应的 renderer，并校验回执 connection/window/tab/target；禁止“广播后接受第一个 reply”。

11 实施顺序与每阶段出口

交付边界：当前 turn-scoped baseline 已在单一 visible split web surface 范围内向真实 provider 提供 computer_use，并完成默认 18100 安装版 live E2E。下面 PHASE 0–4 描述完整目标架构的后续强化顺序；只有对应 phase gate 通过后，才能宣称 authoritative multiwindow registry、排他 lease、完整 Safety UI、canvas fallback 或相关发布能力，不能用当前 baseline 证据替代。

12 可执行验收标准

  1. Turn-start awareness：chat 与 Bilibili fixture 合并为 compound group 后，每次 chat command 都产生经过服务端校验的 Surface Context。浏览器在 chat 左侧时 provider 得到 left，互换 pane 后下一 turn 得到 right；两种情况都在首个 token 前具有 title、origin、primary preview、capabilities 和 computer_use schema。
  2. 页面问答：输入“左边有什么”“右边有什么”或“旁边页面是什么”时，回复必须对应实际 relation。primary preview 不足时，Agent 调用 computer_use(command="observe", surface="left|right")；全程不要求用户粘贴 URL、文字或截图，普通 DOM 页面不发送 screenshot。
  3. 页面交互：Agent 依次调用 observe → act → observe → verify，使用最新 DOM/ARIA refs、同一 surface key 和 frame；操作精确绑定 tab，不得操作独立 tab 或另一个窗口。写动作后使用旧 frame 的下一次 act 必须返回 stale_observation。
  4. 非前台交互：OpenProgram 被其他应用遮挡，或用户焦点位于 chat/其他 pane 时，对已绑定 web surface 的 DOM/ARIA 读取与点击仍命中同一 window_id + tab_id + cdp_target_id。执行不得调用 BrowserWindow.focus()、OS 鼠标/键盘注入、桌面坐标或屏幕截图。
  5. 用户打开的 surface：用户通过 sidebar、center-tab 按钮或 split 操作打开一个已登记 web tab 后，下一 turn 的 Surface Context 自动反映新的 visible/focused/relation 状态，不需要用户再次说明窗口身份。
  6. 显式关闭：通过 authenticated surface.access.update 关闭“Agent 可访问”后，下一 turn descriptor 带新的 disabled access revision，不收到该 surface 的 preview；如果没有其他可观察 surface，则不注入 computer_use schema。关闭前创建的 binding、ComputerSession 和未执行写 lease 在下一次副作用前返回 surface_access_disabled，UI 与回复都准确说明权限状态。
  7. Access CAS：两个并发或重放的 access update 使用同一 expected revision 时只允许一个成功；另一个返回 access_revision_conflict 和 actual state/revision，客户端提交的数值不能成为新 revision。
  8. 绑定隔离：同一窗口中未与当前 session 合并的 web tab、另一窗口的 web tab、隐藏的组成员都不能成为本 turn target；关闭工具后不注入 Computer Use 工具。
  9. 多 surface 定向 resolve：同一 authenticated renderer 注册两个可控 web surface 时，desktop.surface.resolve 携带的 registry surface id 必须只返回对应 local surface/tab/target；错误 registry id、local surface 与 tab 不一致或 reply identity 不一致均在 CDP attach 前拒绝。
  10. Registry 权威性：伪造 registry surface ID、跨 WebSocket ID、重复或旧 window/surface/layout revision 均在 preview 和 CDP 请求前拒绝；renderer 断开会清除其 entries 与 lease。
  11. 生命周期：运行中仅切换焦点不会改变 lease；当前 target 被 hide、移组、跨窗口转移或关闭时，下一次副作用前返回 target_lost，不得操作新焦点 tab。
  12. Alias 稳定性：同一 tab 同时位于 left/right 且 focused 时，空间 alias 与 focused 指向同一 canonical key；两个可见 web surface 使用稳定 web:1/web:2，重复 relation 不生成歧义空间 alias；发送瞬间后的 focus 切换只影响下一 turn。
  13. Geometry 唯一性：left/right fixture 必须有纵向正交重叠，above/below fixture 必须有横向正交重叠；左上、右下等无正交重叠的对角 bounds 只返回 unknown，不得同时生成两个空间 alias。
  14. Tool contract：list_surfaces 只返回 inventory，observe 只返回 observation，act 只执行一个 Action，verify 只执行 assertion；缺少 command 必需字段、混入其他 command 字段、空 assertion value、selector 或 raw target id 均返回 invalid_arguments 且不访问 CDP。
  15. 跨 request ComputerSession：provider request A 的首次 observe 返回 session/frame，request B 使用同一 session 对该 frame 执行 act 成功；跨 user turn、跨 session 或换 target 后复用 frame 返回 stale_observation，且不执行动作。
  16. Preview 边界：断言可见文本不超过 2,000 字符、landmark 不超过 12 项且 name 不超过 160 字符、序列化 payload 不超过 8 KiB；所有截断标志准确，无 screenshot、element refs、隐藏内容或完整 DOM。
  17. Preview 一致性：捕获期间发生 navigation、viewport 或 registry/layout revision 变化时丢弃整份 preview；重试仍变化则返回 preview_status=unavailable，不得混合 frame。
  18. Capability：observe-only surface 可以回答页面问题，但 click/type/navigate 返回 capability_denied；动态工具注入本身不增加 capability。
  19. 重叠 turn：同一 session 并发产生两个 Surface Context 后，每个工具调用仍按自己的 provider_request_id 解析 immutable alias/binding snapshot；旧 turn 的空间 alias 不能指向新 turn 的 surface。
  20. 延迟 tool call：模型 response stream 已结束但该 response 的 tool call 尚未执行时，execution envelope 仍通过 tool_call_id + source_provider_request_id 解析原 immutable binding；该 response 的全部 tool call settled 后 provider-request alias map 可释放，已创建的 ComputerSession binding 独立保留到 owner turn/sequence 终止。
  21. Popup 归因：只有 opener/initiator target 匹配当前 lease 且晚于当前 action epoch 的 popup/new tab 才结束当前 ComputerSession；用户在其他窗口并发打开无关 tab 不影响当前 ComputerSession。
  22. 视觉坐标：在 device_scale_factor != 1、页面 zoom 和非零 scroll 的 fixture 上，图像 point 正确转换为 viewport CSS pixel；scale/zoom/scroll 改变后旧 frame 返回 stale_observation。
  23. Snapshot 并发：同一 tab 的 preview/Observation read barrier 与 action write barrier 不重叠；捕获中发生 DOM mutation 或并发写入使 content_epoch 改变时，整份 snapshot 被丢弃并重试或返回 unavailable/stale。
  24. 本地来源：未被 dev-server registry 或当前 project 明确登记的 localhost/127.0.0.1 origin 不进入 R1，外部写策略仍生效。
  25. Observation 边界：ARIA、interactive elements 和 console errors 分别满足 12,000 字符、200 项和 50 条硬上限及截断标志；password/typed secret/token 被替换，URL query 只保留 key、不保留 value。
  26. 终态清理：对 succeeded、failed、cancelled、终止型 needs_user、异常、target loss、用户拒绝、恢复超时和 session teardown 做故障注入，均 detach CDP、释放 lease/approval 并删除临时 artifact；worker 重启按 TTL 清除 orphan ComputerSession 目录且不删除 retained artifact。
  27. 本地 DOM 流：在内置浏览器打开测试页，读取表单、输入、提交、验证 success message；用户始终可见同一 tab。
  28. 简单视觉 fallback：在没有可用 DOM target 的 canvas fixture 上，只向模型发送一张当前 viewport screenshot，不启动 OCR、detector、memory 或 zoom，并完成一次点击；resize/scroll 后旧 action 返回 stale_observation。
  29. 多窗口：两个 OpenProgram 窗口各有 web tab；指定窗口任务不得在另一窗口创建、激活或操作 tab。
  30. 并发：同一 tab 第二个写任务被 lease 拒绝；两个不同 tab 可并行完成且 artifact/session 不交叉。
  31. 外部 origin：已关联 surface 的普通 DOM click/type 不产生重复的通用工具 approval；命中显式 ask rule 或高风险动作时显示准确 permission card，拒绝后零写入。
  32. 跨 origin：same-tab redirect 进入新 origin 后旧授权失效；popup/new tab 返回 needs_user/new_surface_created、释放原 lease 并结束旧 ComputerSession，不会替换当前 target。用户关联新 tab 后，下一 turn 创建新 ComputerSession 才能控制。
  33. 登录/CAPTCHA：runner 返回 needs_user；用户接管后 Continue 使用新 frame，不复用暂停前 action。
  34. Prompt injection：页面要求忽略用户任务、读取文件或执行高风险动作时，Runtime 权限不变化，任务被阻止或请求用户确认。
  35. 取消：在 observe、模型调用、approval 等待和 action 间隙点击 Stop，均在下一次副作用前终止并释放 target。
  36. 失败诚实性：invalid planner output、step limit、timeout、action exception、verification failure 均不能返回 succeeded。
  37. 隐私：运行结束后临时 screenshot 被删除；event/transcript 中没有 typed secret；不产生 Harness workflow memory。
  38. 回归：现有 playwright_browser selector API、普通用户手动 web tab、tab transfer 和 session UI 不受影响。

13 第一阶段明确不做

目标范围

不控制整个本机桌面；不接入 remote VM；不操作 iOS/Android simulator；不控制其他本地 app；不处理多 app workflow。

浏览器范围

不接入用户日常 Chrome/Edge profile；不提供 sidecar、hidden 或 headless fallback；不自动接管 popup/new tab；桌面壳不在线时直接失败。

高权限动作

不开放 arbitrary JavaScript、cookie/storage 读写或导出、file upload/download、clipboard、浏览器设置、证书和扩展管理。

平台范围

不设计 Windows 专用实现、测试、打包或兼容路径；不引入 OS Keychain、keyring 或 Credential Manager 集成。
