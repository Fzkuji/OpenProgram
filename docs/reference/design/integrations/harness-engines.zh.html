Harness 引擎

对话可以交给外部编码智能体运行，而不用 OpenProgram 自己的智能体循环。它自己调用模型、在自己的沙箱里运行自己的工具；OpenProgram 显示它做了什么，把它的审批交给用户，并保存记录。

现有引擎是 Codex、Claude Code 和（通过 ACP 的）DeepSeek Harness；其他 ACP 智能体沿用同样的结构。

线程、机器与切换

机器
引擎在对话所在的机器上运行，用那台机器的 Codex 和登录；配对机器的列表由那台机器给出。Environment 和 Channel 芯片不变。
用哪个 Codex
用户自己安装的那个：设置了 harnesses.codex.binary 就用它，否则用 PATH 上的 codex，再否则用登录 shell 找到的。Codex 只列出它这个版本能运行的模型，更新 Codex 就能看到最新的模型。
文件夹
每次 turn/start 都带上对话当前的文件夹。
分支
每个分支有自己的 Codex 线程，以及它看到的最后一条消息的 id。
交接
线程在已有历史的对话上开始，或在它没运行的轮次之后恢复时，先收到这些轮次的限长记录，保留最新的。切回 OpenProgram 不需要交接：Codex 的轮次已按普通消息和工具调用保存。
崩溃
进程退出会让正在进行的一轮失败；下一轮启动新进程并恢复线程。
保持最新做法
最新版本npm、bun、pnpm 安装的查 npm，其他查 OpenAI 的发布频道；每小时读一次（runtime/harnesses/codex/maintenance.py）
新版带来的模型model-manifest.json 里已安装的 Codex 没列出的模型。随包附带，每小时从本仓库 main 刷新；Codex 出新模型时在这里加
更新用这个文件所属的安装方式：npm/bun/pnpm 全局安装 @openai/codex@latest、brew upgrade [--cask] codex、mise upgrade codex 或 codex update。其他安装方式只显示这些模型，没有更新行

App 的线程
引擎在某个分支上接着用了 App 的线程之后，其他分支既不接着用也不分叉 App 那份记录，而是带着交接内容开新会话。
同时两轮
一个分支的进程一次只跑一轮。同一分支上的第二轮用它自己的进程，结束时关掉。
插话
运行中发来的消息可能被当作单独一轮回答，这一轮会等到那一轮的结果。收过插话的进程不再复用，里面排着的内容不会混进之后的回合。
Effort
没有请求能取消已设的 effort，所以改回 Claude Code 自己的默认会换一个新进程。换模型后会重新设置 effort。
写下的轮次
用户的消息带着自己的 uuid 发进去。它和这一轮写下的记录 uuid 在运行中和失败时都会保存，即使中途停止，应用同步也不会再写回来。Claude Code 的中断提示不算消息。
已退出的进程
两轮之间退出的保留进程会被替换，这一轮发给新进程。

Codex App 里的对话

用户在 Codex App 或 Codex CLI 里的每个对话，在 OpenProgram 里也是一个对话，和 OpenProgram 自己的对话混在一起，并且双向连着同一个 Codex 线程（state/store/session/external_import/codex_sync.py）。
