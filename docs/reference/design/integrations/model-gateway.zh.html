模型网关

Claude Code 和 Codex 把模型调用发给 Worker，而不是 Anthropic 或 OpenAI。Worker 用用户在 OpenProgram 的提供商里选的模型回答，用 Harness 自己的协议。

上游调用只经过 OpenProgram 配置的提供商和它们自己的凭据。Anthropic 模型和 OpenProgram 其他地方一样用 Anthropic API key；Harness 发来的密钥或令牌只用于进入网关，从不转发。

部分位置
协议openprogram/models/gateway/messages.py（Anthropic Messages）、responses.py（OpenAI Responses）、chat_completions.py
共用部分conversion.py（模型引用、签名、选项）、stream.py（一次上游调用、错误）
路由openprogram/interfaces/server/routes/gateway.py
密钥keys.py、<state>/gateway/key；在 owner_auth.py 里校验
启动覆盖launch.py：codex_launch、claude_code_launch
终端配置harness_config.py、config_files.py、stash.py、<state>/gateway/harness-stash.json
设置state/settings.py 里的 harnesses.*；GET/PUT /api/harnesses/models；设置 → 第三方 Harness 上的模型卡片

路由

路径客户端
POST /gateway/anthropic/v1/messagesClaude Code；流式和整段回复
POST /gateway/anthropic/v1/messages/count_tokens本地估算（一个 CJK 字符算 1，其他算 ¼）
POST /gateway/openai/v1/responsesCodex；普通 HTTP 加服务器推送事件（Codex 只对声明了 supports_websockets 的提供商用 WebSocket）
POST /gateway/openai/v1/chat/completions只会 Chat Completions 的 Harness
GET /gateway/*/v1/models已启用的模型，写作 provider/model

已有的 /v1/chat/completions 用 OpenProgram Agent 回答，是另一个端点（OpenAI 兼容端点）。

一种内部格式

请求读成 Agent 循环用的同一套 Context、消息和 SimpleStreamOptions，经 stream_simple 发出，提供商的事件再按客户端的协议写回。

提供商适配器已经在这些类型和各家上游 API 之间双向转换，网关只补客户端这一侧。所以每次调用都有提供商层的凭据轮换、重试和容错；网关不再加一层重试。

问题决定
模型名显式的 provider/model 引用（split_model_ref），可带 openprogram: 前缀；不认识的名字返回 404，从不起别名
思考签名模型自己的值包上生成它的模型再交给客户端，只回到那个模型。Anthropic 模型的 Claude Code 客户端拿到的是 Anthropic 自己的签名。从不编造签名；没签名的思考块不发给 Anthropic。
Codex 自由格式工具apply_patch 以一个带 input 字符串的函数交给模型，语法写进描述，再以 custom_tool_call 返回
缓存标记保留客户端在工具和内容上的 cache_control；断点由 Anthropic 适配器照常放置和限数
客户端请求头正文以外的东西都不到提供商：没有密钥，没有 anthropic-beta
错误第一个字节之前：该协议的错误响应（Anthropic {type:"error"}、OpenAI {error:{…}}）；上下文超长写成“prompt is too long”或 context_length_exceeded，让 Harness 去压缩；上游凭据被拒是 502，不是会把 Harness 送去重新登录的 401。第一个字节之后：流内错误事件，不再重发。
用量记进 OpenProgram 的账本，call_kind = "harness"，按 Harness 标注

网关密钥

owner 令牌每次 Worker 启动都会变，配置文件存不住它。网关密钥是随机的，只有本人可读地放在状态目录里，重启后不变。

owner-auth 中间件只在 /gateway/ 路径上接受它（Authorization: Bearer 或 x-api-key）；owner 令牌在那里也可以用。每个网关请求都要其中之一，不论来自哪个地址。备份把 gateway/ 和凭据放在一起，因为写进终端配置的是这个密钥。

Harness 使用它的两种方式

CodexClaude Code
由 OpenProgram 为对话启动-c 覆盖：model_provider = "openprogram"、带 env_key 的 model_providers.openprogram 表、model、model_context_window；密钥放在环境变量里环境变量：ANTHROPIC_BASE_URL、ANTHROPIC_AUTH_TOKEN、Opus/Sonnet/Haiku 档位变量、ANTHROPIC_SMALL_FAST_MODEL、CLAUDE_CODE_SUBAGENT_MODEL；云开关关闭
也用于终端config.toml：model_provider、model 和带 experimental_bearer_token 的表settings.json：env 下同样的变量和顶层 model；开启期间去掉 CLAUDE_CODE_USE_BEDROCK/_VERTEX/_FOUNDRY

从不设置 ANTHROPIC_MODEL：它会盖过用 /model 选的模型。Harness 的配置里不加别的东西：没有 MCP 服务器、权限或指令，也没有提到网关的提示词。

改写 Harness 自己的配置

  1. 先解析文件。解析不了的文件内容未知：什么都不写，页面说明原因。
  2. 第一次写之前，把每个要改的键的原值（或它原本不存在）存进暂存。
  3. 只改这些键。TOML 逐行修改，并解析结果、和预期的改动比对；JSON 保留键的顺序和缩进。注释、CRLF 和符号链接都保留；写入是临时文件改名覆盖原文件。
  4. 关闭它，或改回 Harness 自己的登录时，恢复每个仍是 OpenProgram 所写的值。用户之后改过的值算漂移：卡片上会显示，也不会被恢复覆盖。只有恢复写入成功后才删掉暂存条目。
  5. Codex 的 [model_providers.openprogram] 表从不删除，因为在它上面开始的线程没有它就打不开；只把 model_provider 改回去。

Codex 应用

ChatGPT.app 里的 Codex 应用在同一个 ~/.codex 上运行自己的 codex app-server，所以同一份 config.toml 对它也生效（codex_app.py）。

缺口OpenProgram 的做法
它的模型选择器列的是 model/list，对 Codex 不自带的提供商只显示 Codex 自己的模型。已启用的模型写进 config.toml 旁边的 openprogram-models.json，由 model_catalog_json 指向；选中的排第一。每一项是 Codex 对不认识模型用的元数据：OpenProgram 知道的窗口或 272K，以及所装 Codex 版本的 prompt.md 指令，读一次后保留
读到改动它的 app-server 只在启动时读配置。开启或关闭时，等 20 秒没有会话文件写入（最多等 15 分钟），用 SIGTERM 结束应用自己的 app-server（在应用包内、走 stdio、用这个 Codex 目录）；应用会立刻再起一个，窗口和对话都保留。只换模型不重启

取自 magpie

magpie（yetone/magpie）运行同类网关。

  • 采用的：显式模型引用、不设 ANTHROPIC_MODEL 的 Claude Code 档位变量、从不删除的 Codex 提供商表、Codex 应用的模型目录和路由变化时重启它的 app-server、写前暂存和漂移、拒绝改写解析不了的配置、按客户端协议返回错误且第一个字节后不再回退。
  • 没采用的：靠运行 claude 程序提供 Claude 订阅、把针对一家的规则用到所有家、往 Harness 配置里加没要求的东西。
