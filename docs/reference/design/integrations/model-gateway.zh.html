模型网关

外部智能体（Claude Code、Codex，以及任何使用同样 API 的客户端）把模型调用发给 Worker，而不是发给它们的厂商。Worker 用用户在 OpenProgram 的提供商里选的模型回答，用智能体自己的协议。

上游调用只经过 OpenProgram 配置的提供商和它们自己的凭据。Anthropic 模型和 OpenProgram 其他地方一样用 Anthropic API key；智能体发来的密钥或令牌只用于进入网关，从不转发。不转发任何订阅登录：没有 ChatGPT 登录流量，也没有 Claude 登录令牌。

设计移植自 magpie（yetone/magpie，MIT 许可），它的 Go 代码覆盖约九十个智能体。移植代码的模块里注明了对应的 magpie 文件。

部分位置
智能体注册表openprogram/models/gateway/agents/：base.py（接口）、每个智能体一个模块（codex.py、claude_code.py、crush.py …）、model_rows.py（按智能体自己的写法列出启用的模型）、engine.py（连接、断开、同步、状态）、lifecycle.py、running.py；不靠改文件接入的智能体用 local_api.py、appdb.py、applink.py、keychain.py、userenv.py、shellfn.py、reach.py
配置编辑器edit/：toml_text.py、jsonc.py、yaml_text.py、dotenv.py、mark.py；stash.py、<state>/gateway/harness-stash.json
协议messages.py、responses.py、responses_ws.py、compact.py、chat_completions.py、gemini.py、ollama.py、models_info.py
共用部分conversion.py（模型引用、签名、选项）、stream.py（一次上游调用、错误）
密钥和归属keys.py、<state>/gateway/key；attribution.py；在 owner_auth.py 里校验
路由openprogram/interfaces/server/routes/gateway.py

智能体注册表

一个智能体是一份描述，不是驱动程序（magpie agent.go、agents.go）。它的模块返回一个 Agent，或由 agents() 返回多个（Qoder 和 Qoder CN、QwenPaw 的各个智能体）；agents/__init__.py 在 MODULES 里按显示顺序列出模块。所有动文件的事都归引擎，所以新增一个智能体只需写它的描述。

字段说明
id、name、icon、aliases、kind怎么命名、查找（find：id、别名、唯一前缀）和显示
path、dir、bin、app、held_at它的配置文件和目录、命令、桌面应用；用于检测（installed），以及目录还在但命令已不在（cli_gone，magpie gone.go）。detect_only 让 detect 取代默认检测（和别的程序共用的目录、只是插件），sign 是另一个已安装的迹象，bin_not 排除同名的别家命令
fieldsOpenProgram 设置的项：model，以及在设置前跟随它的安静字段（Claude Code 的 Opus、Sonnet、Haiku 档位）
wire(at)连接时写的文件，用 Write 表示：路径、格式、点分的 sets 和 deletes、keep（写入、从不还原）、listing（它的模型列表副本），或整个文件（format="file"）。at 提供所选模型、某个协议的网关地址和密钥
Write.members和用户自己的条目共用一个列表（整个文件就是一个 JSON 列表也行），按一个字段区分：写在用户条目之后或原来的位置，断开时只拿掉这些；连接前就有的列表留下，空的也留下（没有 provider_sources 的 AstrBot 会被当成 4.10 以前的版本）。同一个文件的两次写入依次生效，所以模型列表可以单独同步
Members.loose智能体自己的设置会改的条目字段：WorkBuddy 的思考档位和开关、OpenPencil 的名字和开关、Tuanjie Cowork 除指向以外的所有字段。不算偏离
Write.owns完全属于 OpenProgram 的对象（它的提供商条目）：用户在里面加的内容保留，加在哪一层都不算偏离；里面的删除照样生效（OpenCode 的插件自己取模型列表后，它的模型列表）；断开时整个拿掉，改没改过都一样（magpie 也删掉自己的条目）
Write.loose用户或智能体会改写的字段（* 表示任意键）：名字、它加密的密钥、JetBrains 的 *.isRegistered。不算偏离，同步和重连照常进行
Write.picks智能体自己的选择器成组改写的键：Pi 的 /model、Aside 的选择、omp 的角色、Craft 的默认连接、LiveAgent 的模型和提供商对。不算偏离。断开时，键 on 仍指向 OpenProgram 就整组还原，否则整组保留（magpie 的 Disconnect）
Write.base文件不存在时当作智能体自己会生成的内容（omp 从 models.json 搬成的 models.yml，magpie JSONToYAML）：不记成 OpenProgram 写的，断开时只拿掉它的提供商
Members.kept、keyOpenProgram 自己的条目里用户可以改的字段（Droid 的名字和上限；对应 magpie 的 droidKept）：每个条目按 key 和上次写的内容配对，值和上次写的不同（改了或删了）就是用户的，下次同步保留
Write.shared几个智能体共写的文件（QwenPaw 所有智能体共用的提供商文件）：原件记在第一个智能体的记录里，没有已连接智能体的存档提到它时才还原；先断开的只还原别人没写过的键（OpenCode 的模型）。后加入的接过前一个写过的键的原值和它建的文件夹，最后一个走时删掉
Agent.shared_used在智能体自己的文件还原之后询问：它自己的某个部分仍在用这个共享文件，文件就留下（在 QwenPaw 里改用 OpenProgram 提供商的 QwenPaw 智能体；magpie qwenpawNamesMagpie）。它的记录连同原先的内容转存到 <state>/gateway/left-shared.json；下次连接接手这份记录，之后最后一次断开就删掉文件或放回原件
protocol、ua、named_key、path_named、path_keyed它说的协议、发送的 User-Agent 前缀，以及是否给它专属的密钥或地址（见归属）
before_copy、notice、on_route、after、harness第一次写入前整份复制；改动后显示的提示；连接或断开后的工作（Codex 应用）；每次改动（包括同步）即时交给正在运行的应用（Aside）；OpenProgram 是否也在自己的对话里运行它
unwire、loose、check、keep在还原原值前，把智能体自己的条目从它的应用会重写的列表里拿掉（magpie Unwire：NewMax、Paseo、ZCode、MiniMax Code）；应用自己会改的键，不算偏离；已连接的智能体为什么没走网关；每 10 秒运行一次的守护（Claude Science 的守护进程、OpenMausBot 的列表）
unwired断开时在原值还原之后运行：Pi 格式的智能体在 OpenProgram 的提供商没了之后，把 enabledModels 里指向 OpenProgram 模型的条目拿掉，否则它们指向不存在的模型（magpie piScopeWithout；omp 连 openprogram/** 一起）；列表空了就删掉
detect、extra_agents()、Field.options它自己在本机的标志；在本机找到的、主行之外的行（其他每个 ~/.claude… 目录，magpie claude_dirs.go）；从选项里选的字段，模型离开列表时不会被挪走（Codex 的作用范围和后台压缩、Kiro Crew 的 Harness、Claude Desktop 的网关和运行位置），没有可选项时不显示
launch、gateway只从启动方式拿网关的智能体的启动命令（状态里的 launch，agy）；模型字段是自家模型选项的智能体为假（Cursor CLI、Devin）。连接只改了选项时也运行 after（agy 的 fast tools）
App.instance、App.reopen一个应用同时跑两份时，哪个进程是接入的那份，以及它自己的重启方式（Claude Desktop 的副本：给跑在它文件夹上的进程发 SIGTERM，再打开它的启动器）
edit.row_path把 SQLite 键值表的一行当作文件文本来读写，在一个 BEGIN IMMEDIATE 事务里完成，从不新建数据库；读时旁边不留任何文件，用 immutable=1 或连同 WAL 的副本（NewMax 的 settings 表 app 行）
live、detect不是改文件的接入（magpie 每个字段的 Set 加 Unwire）：connect、disconnect、sync、check、start 钩子，拿到上次保存的内容，返回这次要保存的，存在 stash 记录里。detect 取代按文件、目录和命令的检测
link、added、open_link只通过自己的导入链接接入网关的应用（magpie Import、Added）：链接本身、应用里是否已有（只读不写；读不了就是未知），以及怎么交出链接。这类智能体没有字段
Field.multi、Field.with_catalog可同时选多个选项的选择，每行一个，显示为勾选菜单（Kimi Code 的子智能体池）；模型字段的选项是智能体自己的模型，和 OpenProgram 的并列（DeepSeek Harness 的 DeepSeek 模型）：两边都能选，重新落座只移动 OpenProgram 的模型
root_paths智能体在端点主机根路径上请求、地址里的密钥够不着的路径（Muse Code 的 /muse-code/models）：按它的专属路径提供（归属）
telemetry.py智能体发给自己厂商的使用数据开关（Crush、Goose、Kimi Code；magpie telemetry.go），是一个保留的选择：关闭时写入它文档里的键，用户自己设过的键不动；改回默认只移除写过的键，连接与否都生效

没有 model 字段也没有链接的智能体是一个开关：它自己列出网关的模型，只能打开或关闭。

引擎负责连接（先存原值，再写每个文件，有一个失败就回滚已写的）、断开（还原）、只同步模型列表文件，并报告状态：是否安装、是否已连接、偏离、改动后是否有在跑的应用。模型卡片列出注册表里在本机或已连接的智能体，Codex 和 Claude Code 始终列出。

设置还原得和原来一样的文件写回用户自己的原始字节：存档在第一次写入前留下它的文本（最多 256 KB），和 magpie 的 beforeMagpie 对它的副本做的一样。单行的 JSON 文件按单行编辑。

改写智能体自己的配置

步骤处理
读取先解析文件。解析不了的文件视为未知：什么都不写，卡片说明原因
暂存第一次写入前，保存每个将要改的键的原值（或它原本不存在）
暂存损坏或是旧格式暂存文件解析不了时一切都停下：不连接、不还原、不忘记，卡片说明原因。连接中途写入失败时，放回已写的文件和这次新加的暂存记录。注册表之前的旧记录（一个文件、原值和写入的值）按单文件记录读取，关掉时照样还原用户自己的设置
写入只改这些键，支持 TOML、JSON 或 JSONC、YAML、dotenv。注释、键顺序、缩进和 CRLF 都保留；每个结果先解析并与预期改动比对；写入是临时文件改名覆盖原文件。符号链接仍是链接，写的是它指向的文件；有其他硬链接的文件原地写（magpie edit.Target、hardLinked）
表数组TOML 里与用户共用的列表（[[providers]]、[[models]]）只改 OpenProgram 自己的块，在其中第一块的位置重写，没有就加在文件末尾。一块到它最后一个键为止，所以下一个表上方的注释留着；用户的块和块之间的内容原样不动。跨多行的值保留右括号后面的注释（仿 magpie SetTOMLArrayTables）
标注OpenProgram 写的每一行 TOML、YAML 或 dotenv 上方都有一行注释（# openprogram: …），说明在 OpenProgram 里关掉即可撤销（magpie mark.go）
还原关掉，或回到智能体自己的设置时，仍是 OpenProgram 所写值的键会被还原。之后改过的值是偏离：卡片显示出来，从不覆盖还原。OpenProgram 添加的对象和文件变空后移除
整文件副本整份写入的文件（DeepSeek Harness 的 patch 列表）在第一次写入前复制一份；文件仍是 OpenProgram 留下的样子时，断开连接把副本逐字节放回。只有别的程序改过文件，副本才会按当时的文件刷新，并去掉 OpenProgram 的条目
保留Codex 的 [model_providers.openprogram] 表从不删除，因为在它上面开始的线程没有它就打不开；只还原 model_provider

让智能体保持同步

事件处理
启用的模型变了重写每个已连接智能体里内容不同的模型列表文件（magpie Sync）。空列表从不触发处理
某个模型不再提供用着它的字段，改用另一个提供商的同一模型（同 id，否则小写、点和下划线换成短横线、去掉日期后相同的 id）；档位找不到就重新跟随主模型；主模型找不到就保留并说明。从不断开智能体，也不清空它在 OpenProgram 里的设置（magpie reseat.go）
由谁来做只有 Worker 做，在不会写到一半被杀掉的线程上，CLI 命令从不做。稳定版和开发版共用 ~/.codex 和 ~/.claude：一个实例只在自己写的每个键、地址和密钥仍是它的值时才动这些文件。重新应用不会忘掉仍在原处的已写键，只有文件真的改了才更新改动时间
Worker 端口变了启动时，记录的地址不同的智能体用原来的选择重新连接（magpie Rewire）。自己记着所选模型的应用（Dim、Kun、Nowledge Mem、OpenHanako、Alma、Shelley、miniQ）只换新的地址和密钥，用户在应用里后来选的模型不变
桌面应用读的是旧配置如果它的进程在改动前就启动了，卡片提供重启：让应用退出再重新打开（magpie apprestart.go）
命令不在了目录还在时卡片会标出（magpie cliHeld）

一种内部格式

请求读成智能体循环用的同一套 Context、消息和 SimpleStreamOptions，经 stream_simple 发出，再把提供商的事件用客户端的协议写回。

提供商适配器已经在这些类型和每个上游 API 之间双向转换，所以网关只补客户端一侧。调用因此获得提供商层的凭据轮换、重试和容错；网关不再加第二层重试。

问题决定
模型名显式的 provider/model 引用（split_model_ref），可带 openprogram: 前缀；不认识的名字回 404，从不做别名
思考签名模型自己的值（Anthropic 签名、Responses 推理项、Gemini thoughtSignature）包上生成它的模型再交给客户端，只回到那个模型。Claude Code 用 Anthropic 模型时拿到 Anthropic 自己的签名。从不伪造；没有签名的思考块从不发给 Anthropic。
Codex 自由格式工具apply_patch 以只有一个 input 字符串的函数交给模型，语法写在描述里，结果以 custom_tool_call 返回
Gemini 请求snake_case 或 camelCase 都行；函数结果无论以什么角色发来都算用户一侧，按 id 对应调用，否则对应同名的第一个未回答调用；OpenAPI schema 转成 JSON Schema
Ollama 请求读成 Chat Completions 请求：裸 base64 图片、参数为对象的工具调用（缺 id 时补上）、num_predict 作为回复上限，本地运行器的其他选项丢弃；空请求是预热，回 done_reason: "load"
缓存标记保留客户端在工具和内容上的 cache_control；Anthropic 适配器照常放置和限制断点
客户端请求头正文之外的内容都不到达提供商：没有密钥，没有 anthropic-beta
错误第一个字节之前：协议自己的错误响应；上下文超长写成让智能体去压缩的样子；上游凭据被拒是 502，绝不是会把智能体送去自己登录的 401。第一个字节之后：流内错误，之后什么都不再发。

密钥和归属

所有者令牌每次 Worker 启动都会变，配置文件存不住它。网关密钥是随机的，只有所有者可读，存在状态目录，重启后不变；备份会和凭据一起保留 gateway/。

问题决定
智能体专属密钥opgw-agent-<id>. 加上以网关密钥对 id 计算的 HMAC（仿 magpie TokenFor），每个智能体都用它（engine.agent_key），Claude Code 的启动文件也是：任何文件都不写网关密钥本身。共用一个提供商的智能体共用一个密钥（key_of：OpenChamber 用 OpenCode 的）。它不泄露网关密钥，只接受已注册智能体的 id
密钥变了存档记下每个智能体所给密钥的哈希。文件里是别的密钥的（在每个智能体都有自己的密钥之前连接的），下次同步或 Worker 启动时（lifecycle.rewire）整个重写
智能体专属地址/gateway/agent/<id>/…，按去掉前缀后的路径服务（magpie agentpath.go）；/gateway/agent/<id>.<mac>/… 带着它的专属密钥，无论它发什么 bearer 都放行（path_keyed，Claude Science）
不发密钥的智能体Command Code、fx、Empryo、Ante 和 OpenBot 没有密钥字段，或有但不会发。magpie 允许它们从本机不带密钥进来；这里把它们自己的密钥放进地址的一段，/gateway/agent/<id>.<mac>/…（path_keyed），这样本机浏览器里的网页仍然用不了用户的提供商
应用自己的窗口Copilot for Obsidian 从 Obsidian 的窗口调用（Origin: app://obsidian.md）。在 /gateway/ 上这个来源会得到 CORS 应答（包括预检）；其他网页一律拒绝（magpie cors.go）
Obsidian 不带密钥它的设置在库里，库会同步和发布，所以那里不写密钥。/gateway/agent/obsidian/…（path_named）只在 HTTP 请求的对端和 Host 都是本机、没有转发、Origin 是 app://obsidian.md 时不带密钥放行，和 magpie 放行 Obsidian 一样
在哪里接受密钥只在 /gateway/ 路径上，形式为 Authorization: Bearer、x-api-key，Gemini 路径上还可以是 x-goog-api-key 和 ?key=。所有者令牌可放在请求头里；URL 和日志会留下 ?key=，那里只接受网关密钥。每个网关请求都需要其中之一，来自任何地址都一样，上面 Obsidian 的窗口和下面 Muse 的模型列表除外
主机根路径Muse Code 在 /muse-code/models 请求模型列表，那里在 /gateway/ 之外，地址里的密钥到不了。它按 Muse 的专属路径提供，只在 Muse 已连接、对端和唯一的 Host 都是本机回环、没有转发（不带 Forwarded、X-Forwarded-* 或 X-Real-IP）、不带 Origin 时不需要密钥，和 Obsidian 的窗口一样，网页和代理都读不到
用量记为 call_kind = "harness"，按智能体标注：先看路径，再看密钥，再看 User-Agent，最后是协议

OpenCode 格式

opencode_format.py 是 OpenCode 的配置形状，移植自 magpie 的 openCodeLike、opencode_v2.go 和 opencode_providers.go：提供商 openprogram，用 @ai-sdk/openai-compatible、网关的 Chat Completions 和密钥、setCacheKey，列出每个已启用模型的窗口、图片输入、reasoning，思考档位写成 variants（从弱到强；没有档位就写空集合，OpenCode 2 不会自己补 low、medium、high）。

模型写作 openprogram/<provider>/<model>。这个提供商是 OpenProgram 自己的对象（Write.owns）；用户加的内容保留且不算偏离：请求头、setCacheKey、variant、自己填的 limit.output。

最后一项是 magpie 的 outputsKept：存档记下 OpenProgram 给每个模型要过的回复上限，不在其中的值就是用户的。

提供商是同步时重写的模型列表；选中的模型是同一文件上的另一次写入，用户之后改选的保持不变。小模型重新不选时归智能体自己：OpenProgram 写过的那个删掉，连同为放它而加的对象。

  • enabledModels 存在且没有条目包含该模型时，把模型加进去。用户在这个块里加的键保留。
  • 同步后，指向已不再提供的模型的条目移出 enabledModels，模型回来时条目也回来；列表空了就删掉，之后再恢复（magpie scope_gone.go）。移出的条目记在 stash 记录里（Wiring.record，同步时也保存）。StepCode 和 omp 同样处理。
  • 断开时所选模型只在 defaultProvider 仍是 openprogram 时还原；之后 enabledModels 去掉所有指向 OpenProgram 模型的条目（magpie piScopeWithout）。
  • 选项字段：effort（defaultThinkingLevel）；Pi 还有 protocol，让所有模型都走 Chat、Responses 或 Messages（magpie piProtocolField）；选了协议就替换用户在提供商上设的 api。

Gemini API，以及只用自家模型的智能体

Gemini CLI 和 Antigravity CLI 用 Google 的 Gemini API 连网关；Cursor CLI 和 Devin 没有网关能顶替的端点，只设它们的模型，模型字段是它们自家模型里的选项（Agent.gateway 为假：reseat 和 rewire 不动它们）。

智能体连接时写什么
Gemini CLI（gemini.py）~/.gemini/.env：GOOGLE_GEMINI_BASE_URL 和 GEMINI_API_KEY；settings.json：security.auth.selectedType = gemini-api-key、model.name。密钥是它专属的。登录方式和模型是 loose：它的 /auth 和 /model 会改写它们，同一模型重新连接时保留那里的选择，断开时两者一起恢复。只按命令检测（detect_only），因为 Antigravity 也用 ~/.gemini。OpenProgram 自己的 Gemini CLI 对话仍用本人的登录：进程拿回暂存的值（GEMINI_CLI_SYSTEM_SETTINGS_PATH）
Antigravity CLI（agy.py）整份写 ~/.gemini/antigravity-cli/openprogram-settings.json：modelProvider = gemini、所选模型、每个已启用模型一个自定义模型（openprogram/<ref>，支持 low、medium、high 中两档以上的再按档各加一个）以及用户自己的。settings.json 不动；agy 用 GEMINI_API_KEY、GOOGLE_GEMINI_BASE_URL、--settings 和 --model 启动，密钥是它专属的（Agent.launch）。同步或以同一模型重新连接时，保留在 agy 的 /model 里选的模型；在卡片上换了模型则以卡片为准。断开时先把这个选择从 settings.json 拿掉（unwire）
Antigravity CLI 的启动连接时在每个 shell 的配置文件里加一个 agy 函数，放在 # >>> openprogram agy >>> 标记行之间（shellfn.py，magpie 的 shell_function：zsh、bash、fish，以及执行策略允许运行配置文件的 PowerShell）；它运行 python -I -m openprogram agy run，当前目录里的 json.py 或 openprogram/ 不会被导入（PowerShell 读 agy env）。链接的配置文件仍是链接。断开时删掉
Antigravity CLI 的选项effort：网关给 agy 请求用的推理强度（agent_effort.py；请求自己写了 thinkingLevel 时不改）。fasttools：fast-tools 插件（agents/fasttools/，OpenProgram 以 fast-tools mcp 运行的 MCP 服务），由 after 写入，keep 让它一直启动当前的 OpenProgram。两项都是 kept 字段：用户自己的设置，存在 stash 之外的 kept_picks.py 里：断开后仍保留，下次连接时带回；断开时也能开关 fast tools（engine.set_kept）
Cursor CLI（cursor.py）~/.cursor/cli-config.json 的 model.* 和 hasChangedDefaultModel。按这个文件或 cursor-agent 检测，不看编辑器的目录
Devin（devin.py）~/.config/devin/config.json 的 agent.model。模型是 devin models list 的模型族之一；effort 选项列出该模型有的档位，两者合成一个变体 id 写入，取最近的档位，距离相同取高的。没选推理强度时，换模型族保留原变体 id 的推理强度
