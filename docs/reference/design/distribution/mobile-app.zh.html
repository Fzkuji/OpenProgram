手机 App

手机通过应用商店里的 App 使用 OpenProgram，不再用浏览器标签页。App 自带全部界面，打开时网络上只传数据；和电脑配对一次，之后一直保持登录。对话、文件和账号都留在电脑上，和远程 Web 访问一样。

  1. 电脑：添加设备一次性二维码，带着这台电脑的所有地址
  2. App：扫码用码换一份设备凭证，存进钥匙串
  3. App：打开界面来自 App，数据来自第一个应答的地址

为什么做 App，为什么是这个形状

手机经 Tailscale Funnel 打开网页界面要 10 到 20 秒：大约五十个请求，每个 0.7 到 1 秒，界面自己的文件也在其中，之后对话列表才出来。手机上快的同类产品，都是把界面放在手机上，网络上只传数据。

同类手机怎么拿到界面和数据采用
PaseoExpo App，界面自己写；经中继或 Tailscale 地址和电脑上的 daemon 之间一条端到端加密的 WebSocket；扫码配对，永不过期；列表和最近消息缓存在手机上界面在手机上、网络上只有数据、配对一次不再要求登录、网络问题只是重连而不是登录提示
Claude Code、Codex、Copilot CLI厂商自己的手机 App；电脑主动连厂商的中继商店 App。不采用：要我们运行的中继
OpenCode网页界面由 service worker 预缓存；启动只发三个请求，其余用到才拉启动时请求少
DSH Mobile电脑提供页面，远程走 Tailscale Funnel，局域网优先局域网优先，Funnel 作为远程方式

App 复用网页界面，不像 Paseo 那样另写一套手机界面：只维护一份界面，手机拥有电脑上的全部功能。它按手机重新排版（布局），而不是直接显示网站。

外壳

apps/mobile/ios 是一个 SwiftUI App，里面一个 WKWebView。不用 Capacitor 或 Cordova：需要的只是一个协议处理器和几个原生调用，框架反而会挡在最关键的请求路径上。

部分做法
界面文件apps/web 的静态导出（output: "export"）在构建时拷进 App，由 WKURLSchemeHandler 在 openprogram://app/ 提供。界面不经过网络。
到电脑的 HTTP同一个处理器接住 /api/、/hooks/ 等服务端路径，通过同一个共享的 URLSession 转发到当前地址，请求复用它的连接，不必每次重新做 TLS 握手，加上 Authorization: Bearer opd1.…，不带 Origin。响应逐块流回，所以服务端事件流照常工作。对页面来说每个请求都是同源：图片、文件预览和下载都不用改。
WebSocket自定义协议承载不了 WebSocket，所以页面自己连 wss://<地址>/ws。App 告诉页面连哪里（window.openprogramMobile.socket）；浏览器的 WebSocket 不能设请求头，凭证放在握手的子协议里：APP_BEARER_PREFIX 后接凭证，和 APP_SUBPROTOCOL 一起（都在 openprogram/interfaces/server/owner_auth.py）。服务端只接受来自 App 源 openprogram://app 的这种握手，回 APP_SUBPROTOCOL，绝不回显凭证。
凭证就是配对设备的设备凭证，没有改：兑换一次，在设置 → 设备里吊销，闲置 30 天被忘掉。存在钥匙串里，首次解锁后才可读。
原生调用扫码（VisionKit）、列出/添加/选择/移除电脑、触感反馈。页面通过一个 WKScriptMessageHandler 调用；App 把配对的电脑列表交给页面（window.openprogramMobile.computers）做选择器，页面再请 App 切换（selectComputer）或配对新电脑（addComputer）。菜单是页面描述、iOS 画出的 UIMenu（点按用 menu，长按用 menuPress）。

配对和地址

  • 第一屏只有一个动作：扫电脑上 设置 → 设备 → 添加设备 显示的码，或者用系统的粘贴按钮粘贴它的链接，不弹授权提示。
  • App 用不带 Origin 的 POST /api/auth/pair 兑换，返回 {"device_id","token"} 而不是 cookie。
  • 链接里有这台电脑所有已打开的地址（同一 Wi-Fi、任何地方）。App 全部保存，同时向每个地址请求 /api/auth/session，用第一个应答的；远程地址先答后 300ms 内局域网也答了，仍用局域网。
  • 启动时先用上次应答的地址，网络变化或回到 App 时重新探测。只有没有任何地址应答时，401 才算被吊销。没人需要选地址。
  • 地址变化时页面不重新加载：请求每次读当前地址，页面会收到新的 socket 地址（openprogram-mobile-address）。从后台回来时，socket 2 秒内不回 ping 就立刻换一个新的。
  • 页面按电脑保存最近一次的对话列表，启动时在 socket 连上前先显示它（lib/mobile/session-list-cache.ts）；第一次绘制前视图显示页面本身的底色，不是白色。
  • 网络上失败的请求换下一个地址重试，绝不显示成登录问题。只有能连上的电脑返回 401 才说明设备被吊销，这时 App 回到这台电脑的扫码页。

布局

App 的页面是一套独立的手机界面，在网页界面里用它的数据和渲染写成（手机界面）：先是项目列表，点进去是项目里的对话，底部固定新对话框；带返回和 ⓘ 的对话页；输入框里一个按钮打开这一轮的设置菜单；详情页放改动、文件、活动、资源和对话操作。

从左边缘滑动返回一页。

第一版把电脑的三栏改成对话两边各一个抽屉，看起来仍是塞进手机的电脑，已经换掉。
