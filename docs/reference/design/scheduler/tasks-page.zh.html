任务页

不用人盯着的工作有两头，设好要跑的和跑回来的，它们共用一个页面。

参考：Codex 的 Automations，把定时自动化和需要查看的结果放在同一个入口下。

部分决定原因
侧栏一行任务，日历图标，在主导航末尾，原来定时任务的位置。右边一个淡色数字是收件箱条数；为零时不显示。待处理和定时任务是同一类工作的两行。数字说明有事等用户，不用彩色徽章。
页头ManagePageHeader：标题任务和两个标签收件箱、定时任务，各在名字后跟淡色数字。工具栏随标签变：收件箱显示“N 项等你处理”；定时任务显示概况、搜索、刷新和新建任务。搜索和新建任务只作用于定时任务。
打开时的标签链接指定了标签（/tasks?tab=inbox 或 scheduled）就用它；否则收件箱有内容时打开收件箱；否则打开上次选的标签（存在 localStorage）；第一次是定时任务。有事等着，用户就是为它来的；没有事时，页面保持离开时的样子。
收件箱“等你决定”（审批）在前，“新发现”（发现、已完成的工作、定时结果）在后，ManageRow 行带打开。图标是 Agent 头像，定时任务的结果用日历图标，说明以“定时任务”开头。为空时：“没有等你处理的事”。汇报从哪来决定怎么回应。
定时结果有话要说的定时运行照样在聊天里发一条消息，它的汇报（task_id）也是收件箱的一条，直到打开该对话。收件箱除了常驻 Agent 的对话，也扫描任务汇报进去的对话（always_on/pending.py）。用户没看到的结果和 Agent 的发现一样需要他；只留在聊天里，就藏在设任务的那个对话里了。
定时任务原定时任务页的内容不变：类型一行（全部、一次性、周期、监控），末尾是列表 / 日历切换（ToggleGroup）；视图照旧记住。页头标签属于整个页面；视图是一个标签里的选择。
旧路由/pending 跳到 /tasks?tab=inbox，/scheduler 跳到 /tasks?tab=scheduled。命令面板、标签页名称和图标、运行记录里的在任务中打开都用 /tasks。保存的标签页和书签照样能到。
定时任务标签的布局
  • 共用页头和主题 token；ManageRow 行保留计划、状态和操作，按可见顺序编号。
  • 类型筛选在页头下一排，没有侧栏；窄时换行。
  • 空状态：介绍和创建任务居中；三张建议卡在最宽 960px 的居中网格里，窄时单列，每张有标题、计划、提示词和使用。
  • 创建和使用打开现有表单，不创建任务；Escape 返回。
  • 代码：apps/web/components/tasks/（tasks-page.tsx、tasks-inbox.tsx、tasks-tabs.ts），apps/web/components/scheduler/scheduler-page.tsx（定时任务标签），apps/web/lib/agents/pending-inbox.ts（收件箱查询）。
  • 测试：apps/web/tests/agents/pending-inbox.test.mjs、apps/web/tests/settings/scheduler/scheduler-page.test.mjs、tests/unit/agent/test_always_on.py。
