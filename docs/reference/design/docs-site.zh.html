文档 HTML 展示与编写规范

本文面向维护产品和实现文档的贡献者。所有发布页面都以 HTML 展示，共享导航、搜索和主题控件。源码按内容选择：需要可视化的实现与设计文档使用原生 HTML，简短用法与参考文字保留 Markdown。

渲染方式#

源码 发布结果 作者负责的内容
Markdown 文档站布局中的 HTML 正文 标题、说明、命令和相对文档链接。
HTML 片段 同一布局中的 HTML 正文 语义化章节、图示和必要的原生交互；使用站点主题变量。
独立 HTML 包含 iframe 的站点页面和 .raw.html 正文 自身的响应式布局、主题和内部导航；外层站点控件仍然可用。

需要共享文档站布局的实现文档优先使用 HTML 片段。可视化需要独立视口时使用完整 HTML 页面。iframe 用于隔离布局，不是不可信脚本的安全沙箱。

阅读结构与视觉规范#

开头说明文档回答的问题、读者、范围和实现边界。先解释公开入口与数据、状态变化，再展开实现细节。代码映射表用于说明所有权，图示用于说明控制或数据流，文末“实现状态”集中列出剩余工作和证据缺口。

HTML 片段使用现有的 --bg、--bg-code、--tx、--tx-soft、--acc 和 --bd 变量。站点采用与 Web 应用一致的暖中性色和橙色强调色，不在正文内另设固定的浅色配色。

标题使用语义化层级和稳定的 id，让 HTML 章节进入本页导航。表格在窄屏无法容纳全部列时使用局部滚动容器。图示提供可访问的标题和说明。原生折叠控件用于区分详细证据与主要解释。键盘焦点、减少动态效果设置和手机阅读都属于文档验收范围。

站点主题偏好保存为 op-docs-theme，切换时在站点窗口派发 documentThemeChange。iframe 有独立文档，不会自动接收该事件。独立页面需要明确维护自己的主题行为，或使用片段继承共享主题。

共享阅读层为宽表格提供可通过键盘操作的局部横向滚动，并保留可读的列宽。独立 HTML 同样获得表格支持和图示滚动区域；源码未指定背景时，阅读层补充不透明底色，避免文字与外层主题冲突。这些处理保留正文和页面自身配色，不代表页面所述实现已经通过验收。

导航与双语源码#

九个 Tab 为 start、install、capabilities、interfaces、models、integrations、server、reference 和虚拟的 design。设计源码位于 docs/reference/design/，不存在 docs/design/ 源码目录。

TAB_SECTIONS 定义产品阅读顺序，PAGE_ORDER 定义显式页面顺序。其余页面按目录分组，目录标题使用配置名称或 README 标题。不能把侧栏理解为文件树的直接复制，也不能假定所有页面都按文件名排序。

英文为默认版本。topic.zh.md 与 topic.md 配对，topic.zh.html 与 topic.html 配对。中文源码通过语言控件访问，不单独占用第二个侧栏入口。修改双语主题时同步两种语言。

构建器兼容已有的同名 Markdown/HTML 配对，为 HTML 附属页分配 .viz.html 输出。相对 topic.md 链接指向正文输出，相对 topic.html 链接指向 HTML 附属页的 topic.viz.html 输出，并保留章节锚点。中文 HTML 附属页输出为 topic.zh.viz.html，中文 Markdown 正文仍为 topic.zh.html；语言控件分别指向这些独立地址。这项兼容机制不意味着应维护两份相同说明。合并前比较内容，保留独立图示和证据，并更新引用链接。

构建产物和仅用于静态资源的目录不参与页面发现，docs/superpowers/ 被显式排除。仅以下划线开头不会自动排除：主动性研究归档当前仍会被发现。

构建与本地展示#

python -m scripts.docs_site.build
python -m scripts.docs_site.checklinks
python -m scripts.docs_site.checklang
python -m scripts.docs_site.check_landing

在仓库根目录、具有文档构建依赖的环境中运行上述命令。贡献指南列出 uv run 环境。链接检查读取构建后的 HTML，因此必须先构建再检查。

checklang 目前只检查产品区默认 Markdown，排除了设计目录，也不扫描 HTML 源码。该命令通过不能证明所有设计页面都满足双语约定；修订的 HTML 需要单独检查语言与对应版本。

构建器重新生成由代码派生的 CLI、配置和 Provider 参考页，先写入 docs/_site.tmp/，成功后替换 docs/_site/。docs/_site/ 被 Git 忽略。docs/_static_root/ 中的文件发布到站点根，不进入导航或搜索。

源码实例读取其 docs/_site/。已安装 runtime 可以读取 Server _frontend/docs/ 中的打包文档；构建另一个 checkout 不会更新该目录。声明本地验收完成前，要比较实际响应内容与预期产物。默认本地验收地址为 http://localhost:18100/docs/。完成应用更新时，遵循仓库本地 App 规则使用 scripts/refresh-local-app.sh。

源码 worker 在注册文档路由时检查是否需要重建，普通 HTTP 读取不会扫描或重建源码树。当前没有持续 watch 模式。

方案比较#

现有设计选择仓库内的 Python 渲染器，以保留原生 HTML、SVG 和脚本内容，并接入单端口 worker。以下比较针对本项目需求，不作为外部产品最新能力调查。

考虑项 当前 Python 渲染器 VitePress 方案 MkDocs 方案
已有原生可视化文档 保留为片段或独立页面 需要评估组件与布局系统的接入方式 需要评估原始 HTML 与主题接入方式
共享导航与搜索 由本仓库维护 对照项目需求评估内置导航和搜索 对照项目需求评估内置导航和搜索
工具链 Python 渲染与静态浏览器资源 增加基于 Node 的文档构建 基于 Python 的文档构建与主题配置
维护职责 项目维护布局、导航和可访问性 框架配置与升级维护 框架和主题配置及升级维护

渲染器使用 markdown-it-py、mdit-py-plugins 和 Pygments，产出静态资源，不引入客户端框架或编辑器/CMS。本次文档优化不迁移站点框架。
