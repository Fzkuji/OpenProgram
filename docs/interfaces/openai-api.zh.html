接入工具

设置值
Base URLhttp://127.0.0.1:18100/v1，或 localhost；改过端口就用 Worker 自己的端口
API key~/.openprogram/web/token 里的 Web 令牌（profile 用 ~/.openprogram-<profile>/web/token）。Worker 每次启动都换一个新的，所以在调用时读这个文件。
ModelAgent 的 id，即 GET /v1/models 列出的那些，默认 Agent 在最前
curl http://127.0.0.1:18100/v1/chat/completions \
  -H "Authorization: Bearer $(cat ~/.openprogram/web/token)" \
  -H "Content-Type: application/json" \
  -d '{"model": "main", "messages": [{"role": "user", "content": "Summarise README.md"}]}'
from pathlib import Path
from openai import OpenAI

client = OpenAI(base_url="http://127.0.0.1:18100/v1",
                api_key=(Path.home() / ".openprogram/web/token").read_text())
for chunk in client.chat.completions.create(
        model="main", stream=True,
        messages=[{"role": "user", "content": "What changed today?"}]):
    print(chunk.choices[0].delta.content or "", end="")

一个请求做什么

部分行为
一轮Agent 的一轮，和在 App 里输入一样：用它的模型、工具、记忆和权限模式。运行时在 App 里可见，之后作为对话留着。
消息最后一条必须是用户的，它就是这一轮的消息。之前的消息，包括 system，作为调用方的上下文一起带上。内容是文本，或文本片段的列表。
对话每个请求新开一个对话。要接着之前的对话再跑一轮，把它的 id 放进 conversation_id；这时只发送最后一条消息。每个回答都在 conversation_id 和 X-OpenProgram-Conversation-Id 头里写明所属对话。
流式"stream": true 把回复文字作为 chat.completion.chunk 事件发出，然后是带 finish_reason 的一块，最后是 data: [DONE]。stream_options.include_usage 会多发一块用量。
审批没有人在场作答，所以需要审批或要问你的步骤会立刻被拒绝，和 openprogram --print 一样。
停止关闭流式请求会停止它的这一轮。
忽略temperature、max_tokens、tools 等采样和函数调用字段：用的是 Agent 自己的设置和工具。n 不是 1 会被拒绝。

错误

每个拒绝都是 OpenAI 的格式：{"error": {"message", "type", "param", "code"}}。

状态何时
401 invalid_api_key没有令牌，或用的是之前某个 Worker 的令牌：重新读令牌文件
400请求格式不对；param 指出是哪个字段
404 model_not_found没有这个 id 的 Agent
404 unknown_url本服务不提供的 /v1 端点，例如 /v1/responses
409 conversation_busy指定的对话正在跑一轮；等它结束再发
429、502Agent 的模型出错；code 是原因。流式时错误是 [DONE] 前的最后一个事件。

范围

  • 令牌就是主人的身份：拿到它的人就是以你的身份操作。除非配置了从其他机器访问，否则让 Worker 只监听本机。
  • 只给浏览器之外的调用方用。来自其他源的网页会被拒绝。
  • 只有 Chat Completions；没有 /v1/responses、embeddings 或图片。
