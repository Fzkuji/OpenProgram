# reading tasks

The reading tasks of auto_research (`tasks/reading/`): `baseline_numbers`, `related_by_paragraph`, `import_annotations` and `skim_test`. Each reads the paper against something outside it: the works whose numbers it copies, the literature around each paragraph, the author's own highlights, and a reader who only skims.

They follow PapersWithCode's results extraction and Elicit's extraction (numbers taken from a paper with the sentence they stand in), Keenious (suggestions from the text being written, paragraph by paragraph), the Zotero and ReadCube annotation plugins (highlights and notes as data), and Semantic Reader and Scim (what a skimming reader sees).

| Item | Contract |
| --- | --- |
| Purpose | `baseline_numbers`: every number the paper copies from another work matches that work. `related_by_paragraph`: works to cite, per paragraph, that the `.bib` lacks. `import_annotations`: the author's highlights and notes as rows keyed by `.bib` entry. `skim_test`: whether the claims survive a skim. |
| Input | `paper_dir` for all four: the paper's repository; `workflow/rules.json` names `main_tex` and `bib_files` (defaults otherwise). `out_dir` (`baseline_numbers`, `related_by_paragraph`, `skim_test`): the report folder, default `<paper_dir>/drafts/<task>`. `related_by_paragraph(paper_dir, out_dir="", arxiv_id="")`: the paper's own arXiv id, when it has one. `import_annotations(paper_dir, source="zotero")`: `zotero` or the path of an export (`.json`, `.csv`, `.md`). A missing folder, main file or export, an unknown export format, no paragraph to search (`related_by_paragraph`), Zotero not answering, or no claim (`skim_test`) raises `ValueError`. |
| Output | JSON with `status` and the paths below; every report folder also holds `run.json` and `run.md`. |
| `baseline_numbers` | Finds table rows with a `\cite` in a cell (the numbers in the other cells, `\multicolumn` and `\multirow` expanded; one header row is the metric, two are dataset over metric) and sentences with a number (decimal point or percent sign) next to a `\cite` (the nearest following citation; metric and dataset from the words around it). Each cited key becomes arXiv full text: the entry's eprint or arXiv DOI, else the OpenAlex work `library.resolve` finds, else an arXiv title search (`reader.arxiv_of`); the arXiv HTML or ar5iv page gives its tables (caption, then rows with cells joined by ` \| `) and its sections, results first (`reader.work_text`). Writes `workflow/sota.csv` (`key, metric, dataset, ours_cited, theirs, quote, location, status`); `location` is `our place → their place`. Status per row: `match`, `mismatch` (differs beyond the rounding of the less precise number; a fraction against a percentage is rescaled), `better_reported` (the work reports a better value for the same metric and dataset; `theirs` and `quote` are that value's), `not_found`, `unverified` (the quote is not in the fetched text or does not hold the value), `no_text`. A row whose status is anything else is the author's: it stays, first, and wins over a new row with the same key, metric, dataset and cited value; code rows of an earlier run are replaced. `FAIL`: any mismatch. `PASS_WITH_NOTES`: any other non-match, an unresolved work, or a failed source. Report folder: `report.md`, `sota.json`. |
| `related_by_paragraph` | Paragraphs of at least 25 words in sections titled introduction, related work, background, prior work, preliminaries, method, approach, framework or overview (at most 30). Query per paragraph, plain code: its two most frequent two-word phrases of adjacent content words, then its most frequent content words, six terms. Searches per paragraph: its three most frequent two-word phrases and the whole query, each in Semantic Scholar (paced to one call a second without `S2_API_KEY`) and OpenAlex relevance search, 15 records each. Recommendations once per run: `GET /recommendations/v1/papers/forpaper/ArXiv:<id>?from=all-cs` for `arxiv_id`, else `POST /recommendations/v1/papers` with the cited works as `positivePaperIds` (`ArXiv:<id>` or `DOI:<doi>`, at most 50); 100 records. Records already in the `.bib` (DOI, arXiv id or normalized title) are dropped; each paragraph keeps the five that share at least two of its twelve top terms, scored by shared terms + search rank (up to 3 for a top hit) + 0.7·log10(1 + citations). Report folder: `report.md` (per paragraph: title, year, venue, URL, shared terms), `related.json`, `candidates.bib` (keys `lastname+year+firstword`, unique against the `.bib`; import with `import_library(paper_dir, ".../candidates.bib")`). `PASS_WITH_NOTES` when a source failed. |
| `import_annotations` | Zotero: `GET http://localhost:23119/api/users/0/items?itemType=annotation&format=json` paged by 100, then each annotation's attachment and its parent item (`/items/<key>`), once each. Exports: Zotero API JSON (annotations, attachments and items together), JSON or CSV annotation records (column names such as `annotationText`/`text`/`highlighted text`, `comment`/`note`, `page`, `color`, `title`, `doi`; an item may carry an `annotations` list), or the Markdown of a Zotero note from annotations (`“quote” ([Author et al., 2017, p. 3](zotero://…)) comment`, a `#` heading naming the item). Items are matched to `.bib` keys by DOI, arXiv id, title (similarity ≥ 0.93), or in Markdown first-author surname and year when one entry fits. Appends to `workflow/annotations.csv` (`key, page, quote, comment, color`) the rows not already there (same key, page, quote). Report folder `<paper_dir>/drafts/import_annotations/<timestamp>/`: `report.md`, `claim_support_candidates.csv` (`claim, work, stance, study, quote, note` with `claim`, `stance`, `study` empty, `note` the page and comment; only annotations with highlighted text). `PASS_WITH_NOTES` when some item matched no entry. |
| `skim_test` | Skim view, plain code: the title, the abstract, every figure and table caption (`Figure n`, `Table n`) and the first sentence of each paragraph with its section. Claims: `Claim` of `workflow/project.md` (id `main`) and each claim of `workflow/claims.md`; without a project claim, `C1` is the main one. For each claim not covered, plain code lists up to three full-text sentences sharing the most content words with it (at least two) and whether a skimmer sees them. `FAIL`: the main claim is missing. `PASS_WITH_NOTES`: any claim partly covered or missing. Report folder: `report.md`, `skim.json`. |
| Effects | Reads the paper, its `.bib` files and `workflow/`. Network: arXiv HTML and ar5iv, OpenAlex and the arXiv API (`baseline_numbers`); Semantic Scholar's search and recommendations APIs (`related_by_paragraph`, with `S2_API_KEY` when set); Zotero's local API on this computer, read only. Writes `workflow/sota.csv`, `workflow/annotations.csv` and the report folders. Never writes the paper sources, the `.bib` files or `workflow/claim_support.csv`. |
| Model calls | `extractor` (`baseline_numbers`): one call per cited work with full text (at most 30 works, 40 numbers each), with the numbers as our paper cites them and the work's text (`reported_numbers` schema: per id `found`, `value`, `quote`, `location`, `setting`, `higher_is_better`, `best_value`, `best_quote`, `best_location`). `skimmer` (`skim_test`): one call with the skim view only, returning `goal`, `method`, `main_result`, `main_claim` in Simplified Chinese (`skim_understanding`). `judge` (`skim_test`): one call with that understanding and the claims, returning per claim `covered`, `partly` or `missing` and a reason (`claim_coverage`). `related_by_paragraph` and `import_annotations` make none. |
| Failure | A malformed reply, an extractor answer for a number it was not shown, a skimmer reply with an empty field, or a judge reply with an unknown, repeated or missing claim or an unknown verdict raises. A quote not in the fetched text is not raised: the row is `unverified`, and an unverifiable best value is dropped. A source that fails returns nothing and is named in `unavailable_sources`. Rerunning is safe. |
| Tests | `tests/reading/test_sota.py` (LaTeX table and sentence parsing, rounding, quote validation, the entry with the network faked and the extractor scripted, author rows), `test_related.py` (the query, search and recommendations faked, ranking, `candidates.bib` through `import_library`), `test_annotations.py` (Zotero's local API faked with paging, JSON, CSV and Markdown exports), `test_skim.py` (what the skimmer sees, statuses, reply checks). |
| Usage | `from auto_research.tasks.reading import baseline_numbers, related_by_paragraph, import_annotations, skim_test` |

## Files

| File | What |
| --- | --- |
| `reader.py` | LaTeX to plain text, citation keys, quote validation, a cited work's arXiv id and full text with tables, the JSON POST. |
| `sota.py` | `baseline_numbers`. |
| `related.py` | `related_by_paragraph`. |
| `annotations.py` | `import_annotations`. |
| `skim.py` | `skim_test`. |

## Not covered

- Numbers in figures, or tables given as images: only LaTeX tables and running text are read, and only arXiv HTML for the cited work.
- Works without an arXiv version: their numbers are listed as `no_text`.
- Writing annotations back to Zotero, or claim_support rows: the author picks from the candidates.
