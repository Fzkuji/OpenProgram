# baselinecode tools

The `baseline_code` task of auto_research (`tasks/baselinecode/`). It finds the code repository of every baseline the paper compares against, says whether it is official, and records its license, last push, stars and archived flag, so the author of the baseline-reproduction task (`baselines`, which reads `workflow/baselines.csv`) does not have to look each one up by hand.

Learned from DeepGit (repository search ranked by what the paper and its authors say) and Papers with Code's paper-to-repository links (official when the paper or its authors link it), now served by Hugging Face Papers.

## baseline_code

| Item | Contract |
| --- | --- |
| Signature | `baseline_code(paper_dir, out_dir="")` |
| Purpose | Every baseline has a repository to run, and the author knows which ones are the authors' own code. |
| Input | `paper_dir`: the project's Git repository (anything else raises `ValueError`). `out_dir`: the report folder (default `<paper_dir>/drafts/baseline_code`). The baselines are the rows of `workflow/baselines.csv` (the template's example row skipped): `name`, and `source` as a `.bib` key, a GitHub URL or `owner/repo`, an arXiv id or URL, or a title; a `repo` column, when present, is read as the current value. Without that file, the works of the `.bib` cited in the sections whose title says experiments, results, evaluation, benchmark, comparison or baseline, once each, named by the table cell that cites them (else the key). No baseline raises `ValueError`. |
| Process | 1. **Paper** (code): the arXiv id from the `.bib` entry, else Semantic Scholar's `search/match` externalIds, else an arXiv title search (title similarity ≥ 0.93); the authors and Hugging Face logins and `githubRepo` from `huggingface.co/api/papers/<id>`. 2. **Candidates** (code): the repository `baselines.csv` names, GitHub links in the arXiv abstract and comments field, the links of the full text (arXiv HTML, else ar5iv; only when the abstract links none), Hugging Face's `githubRepo`, and a GitHub search for the exact title (5 by stars). 3. **Metadata** (code): `repos/<owner>/<name>` for at most 6 candidates (renamed repositories merged, forks dropped unless official). 4. **Official** (code): the abstract links it; the full text links it in a sentence that releases the paper's code ("The code and pre-trained models are available at", "we release our code"); or its owner is an author, by login (`kaiminghe`, `hekaiming`, `khe`, a Hugging Face login) or by the account's display name (at most 3 user lookups). 5. **Choice**: the official candidate with the strongest evidence (abstract, release sentence, owner), unarchived and most starred first; without one, the most starred unofficial candidate, or, when the next ones are within a factor of 3 of its stars, the chooser's pick among them. |
| Output | JSON with `status`, `report`, `run`, `baseline_code`, `edits`, `origin` (`baselines.csv` or `paper`), `baselines`, `official`, `unofficial`, `missing`, `unavailable_sources`. `PASS`: every baseline has an official repository and every source answered. `PASS_WITH_NOTES`: a baseline has an unofficial repository or none, or a source failed. Files: `workflow/baseline_code.csv` (`baseline`, `repo`, `official` yes/no, `license` (SPDX), `last_push`, `stars`, `archived`, `evidence`), and in `<out_dir>/<timestamp>/`: `report.md` (Chinese: the table, archived, unlicensed and stale repositories, failed sources, the proposed edits), `candidates.json` (every candidate with its evidence and metadata), `edits.json`, `run.json`, `run.md`. |
| Edits | `edits.json` in paper_proofread's format (`root`, `edits` with `id`, `file`, `section`, `kind`, `quote`, `replacement`, `problem`). With `baselines.csv`: a `column` edit adding `repo` to the header when it has none, then one edit per row whose repo differs (`official` or `unofficial`), the quote being the row's whole line, found exactly once. Without it: one `create` edit holding a new `baselines.csv` (template columns plus `repo`, status `planned`). `apply_edit(paper_dir, edit)` of this package applies one edit to `workflow/baselines.csv` only. |
| Effects | Writes `workflow/baseline_code.csv` (rewritten each run) and the run folder. Never changes `baselines.csv` or the paper. Reads Hugging Face Papers, Semantic Scholar, arXiv (abstract page, HTML, ar5iv, search) through `citations.sources.fetch`, and GitHub through `gh api` when the gh CLI is logged in, else HTTPS (`GH_TOKEN` or `GITHUB_TOKEN` when set). Searches are spaced 2.2 s apart with a token, 6.5 s without, to stay inside GitHub's search limit. |
| Model calls | `chooser`: only for a baseline without an official repository whose top unofficial candidates are close; one call with at most 3 candidates and the first 4k characters of each README. It answers a candidate, or none, with a verbatim README quote; a repository not among the candidates or a quote not in its README is rejected and the most starred candidate kept. |
| Failure | A source that fails is named in `unavailable_sources` and the report, never an exception; with GitHub down, candidates the paper links are kept without metadata. A malformed chooser reply falls back to stars. Rerunning is safe. |
| Tests | `tests/baselinecode/test_baseline_code.py`: baselines from the paper's results table resolving to official repositories by owner, abstract link and release sentence (a non-release link and ar5iv's own link ignored), the create edit applied; `baselines.csv` with the template row, a given repository, a missing one and close unofficial candidates sent to the chooser, the header and row edits applied in order and empty on a rerun; a choice outside the candidates, a quote not in the README, and "none fits"; GitHub down; no baselines; link, owner and release-sentence parsing. All network calls and the chooser are fakes. |
| Usage | `from auto_research.tasks.baselinecode import baseline_code` |

## Not covered

- Code hosted outside GitHub (GitLab, project pages, Google Drive) is not a candidate.
- An organization owner (google-research, facebookresearch) is official only when the paper links it; organization membership is not read.
- Whether a repository's code runs or reproduces the reported number: that is the `baselines` task.
- Registering the task in the program's task list and app.
