# diagrams tools

Two tools for the paper's figures (`tasks/diagrams/`). `method_diagram` draws the method as an editable TikZ figure from the paper's own words; `caption_check` checks every figure and table caption, and the plotting scripts behind the figures. Each takes the paper's Git repository as `paper_dir` (anything else raises `ValueError`), writes into `<out_dir>/<timestamp>/` with a trail (`run.json`, `run.md`), and returns JSON with `status`, `report` and `run`. Reports are in Simplified Chinese. A role extracts or judges; code validates every reply (labels found in the paper, numbers found in the paper or the results) and computes the layout.

Learned from PaperBanana (method illustrations from the paper text), AutomaTikZ and TikZero (text to editable TikZ), Scicapenter (caption writing help), and SciencePlots and tikzplotlib (publication-style plots).

## method_diagram

| Item | Contract |
| --- | --- |
| Signature | `method_diagram(paper_dir, section="", out_dir="")` |
| Purpose | A method figure whose every box is a component the paper names, editable as TikZ and compiled as it is delivered. |
| Input | `paper_dir`: the paper's Git repository; `workflow/rules.json` names the main file. `section`: the section to draw, by exact title, a `\label` inside it, or part of its title (in that order); empty takes the first section whose title says method, approach, framework, architecture, model, pipeline, system or design. `out_dir`: default `<paper_dir>/drafts/method_diagram`. A missing repository or main file, no text, or no matching section raises `ValueError`. |
| Process | 1. **Read** (code): the main file flattened, cut at `\section`; the chosen section (30k characters) and the rest of the paper (30k) for reference. 2. **Extract**: one `extractor` call (`method_graph` schema): 2 to 12 nodes with `id` (lower_snake_case), `label` (quoted from the paper, at most eight words) and `kind` (`input`, `process`, `store`, `output`), and up to 24 edges with what flows. 3. **Validate** (code): a node is dropped when its id is malformed or repeats, its label is not in the document (commands, braces, `$`, `~`, whitespace and case ignored) or repeats; an edge when an end is not a kept node, it is a loop or a repeat; an edge label not in the paper is cleared, and one that only repeats a box's label is cleared silently; a node left without an edge is dropped. 4. **Lay out** (code): layered left to right (Sugiyama): cycles broken by depth-first search (the edge is drawn backwards with its arrow at the right end), layers by longest path with each source pulled next to its nearest user, edges spanning columns routed through their own slots, order by four barycenter sweeps; widths from the labels, gaps from the longest edge label. 5. **Render** (code): `diagram.tex` (a `tikzpicture` with named styles and coordinates in cm), `standalone.tex` (`standalone` class that `\input`s it), compiled with `pdflatex` in a build folder, rasterized with `pdftoppm` at 200 dpi. When the labels as quoted do not compile, they are drawn as escaped plain text. 6. **Inspect**: when the model takes images, one `inspector` call (`diagram_problems` schema) on the PNG with the node and edge labels: overlap, unreadable, clipped, crossing, other. On a problem code multiplies the spacing by 1.35 (and widens boxes by 0.5 cm for clipped or unreadable text), renders and looks again, at most twice. |
| Output | JSON with `status`, `report`, `run`, `diagram`, `pdf`, `png`, `section`, `nodes`, `edges`, `dropped`, `vision`. `FAIL`: fewer than two connected nodes, or pdflatex is installed and the figure does not compile. `PASS_WITH_NOTES`: something was dropped, the labels fell back to plain text, pdflatex or pdftoppm is missing, the vision check was skipped, or problems are left after the last look. `PASS` otherwise. Files: `diagram.tex`, `standalone.tex`, `diagram.pdf`, `diagram.png`, `graph.json` (nodes, edges, drops, layout, rounds), `report.md`. |
| Effects | Runs `pdflatex` (120 s, no shell escape) and `pdftoppm` (60 s). Never modifies the paper. |
| Model calls | `extractor`: one call. `inspector`: one to three calls, only when the model's input modalities include images (a scripted runtime counts as taking them). |
| Failure | A reply that is not a graph, or a problem of unknown kind, raises. Everything else is a drop or a note. Rerunning is safe. |

## caption_check

| Item | Contract |
| --- | --- |
| Signature | `caption_check(paper_dir, out_dir="")` |
| Purpose | Every figure and table can be understood from its caption alone, is labelled and referenced, and its plotting script makes a print-quality figure. |
| Input | `paper_dir`: the paper's Git repository; `workflow/rules.json` names the main file, the `.bib` files and the plotting scripts (`figure_scripts`, default `workflow/figures/plot_*.py`). `out_dir`: default `<paper_dir>/drafts/caption_check`. A missing repository or main file, or a paper without a figure or table environment, raises `ValueError`. |
| Floats | `figure`, `table` (starred), `wrapfigure`, `wraptable`, `sidewaysfigure`, `sidewaystable` between `\begin{document}` and `\end{document}` (after the bibliography too), numbered per kind; caption with balanced braces (`\caption[short]{...}` read too), every `\label`, every `\includegraphics`, the section it sits in. |
| Code checks | `caption` (FAIL): none. `label`: none. `reference`: no `\ref`, `\cref`, `\Cref`, `\autoref`, `\subref`, `\vref` or `\pageref` to it outside floats. `label_order`: `\label` before `\caption`. `length`: under 6 or over 150 words. `first_sentence`: starts with a filler ("This figure shows", "Here", "We show") or has under 3 words. `abbreviation`: an all-caps token of 2 to 8 letters not defined as `Long form (ABBR)` or `ABBR (long form)` anywhere (WARN), or only in the text (NOTE); common ones, Roman numerals and words of `.bib` titles are skipped. `units`: a sentence about an axis without a unit (parentheses, brackets, %, or a unit word). |
| Model call | `captioner` (`judge_caption`, schema `caption_judgment`), one call per float with the caption, the section, up to three paragraphs that reference it (1,500 characters each), the table source (4k) and, when the model takes images, the figure (png or jpg as is, the first page of a pdf rasterized at 120 dpi). Returns `what_shown`, `how_to_read`, `takeaway`, `standalone`, a Chinese `problem` and an English LaTeX `rewrite`. |
| Rewrite check | `\label` removed; dropped when a number (two or more digits, or a decimal) outside `\cite` and `\ref` keys is not in the paper, `workflow/results.tsv` or `workflow/evidence.csv`; when it cites a key not in the `.bib`; when it describes a defect of the figure ("unlabeled", "not specified", "unclear"); or when braces or `$` do not balance. |
| Scripts (AST, not run) | Each script of `figure_scripts`, matched to the figures whose graphics stem equals a string constant with a figure extension in it. `font`: `rcParams[...]`, `rcParams.update({...})`, `rc(...)` or a `fontsize=`/`labelsize=`/`size=` keyword under 7 pt, or `x-small`/`xx-small`. `vector`: a line-plot call (`plot`, `errorbar`, `step`, `semilog*`, `loglog`, `fill_between`, `stackplot`) and a raster output. `axis_label`: a plotting call and no x or y label (`set_xlabel`, `xlabel`, `supxlabel`, `set(xlabel=)`). `units`: an axis label naming a quantity (time, memory, size, ...) without a unit. Without `science` in a style call or an `import scienceplots`, the report suggests `plt.style.use(["science", "no-latex"])`. |
| Edits | `edits.json` in paper_proofread's format (`root`, `edits` with `id`, `file`, `section` (the float), `kind` (`caption` or `label`), `quote`, `replacement`, `problem`). The quote is the whole `\caption{...}` command, replaced by the rewrite (when kept) and a new `\label` (when missing, `fig:`/`tab:` and the graphics stem); a float without a caption gets the `\includegraphics` command followed by the new caption. Only a quote found exactly once in exactly one `.tex` file becomes an edit; `apply_edit` of `tasks/proofread` applies one. |
| Output | JSON with `status`, `report`, `captions`, `edits`, `run`, `floats`, `not_standalone`, `rewrites`, `dropped_rewrites`, `scripts`, `counts` (FAIL, WARN, NOTE). `FAIL`: a float without a caption. `PASS_WITH_NOTES`: a WARN, a caption judged not standalone, or a dropped rewrite. `PASS` otherwise. Files: `report.md`, `captions.json`, `edits.json`, `images/` (rasterized pdf figures). |
| Effects | Reads the paper, the `.bib` files, results.tsv, evidence.csv and the plotting scripts; runs `pdftoppm` for pdf figures. Never runs a script or modifies the paper. |
| Model calls | `captioner`: one per float. |
| Failure | A reply without the four booleans raises. Rerunning is safe. |

## Tests

`tests/diagrams/test_method.py`: graph validation (labels not in the paper, isolated nodes, dangling edges, cleared edge labels), the layout of a graph with a cycle and a long edge, section choice, a full run with a scripted inspector that finds an overlap and then none (pdflatex and pdftoppm when installed), the plain-text fallback, no pdflatex, and a graph too small to draw. `tests/diagrams/test_captions.py`: floats after the bibliography and in an `\input` file, every code check, rewrites kept and dropped (a number not in the paper, an unknown key, a figure defect), the image sent to the captioner and not without image input, the script checks, edits applied with `apply_edit`.

## Not covered

- Registering the two tasks in the program's task list and app.
- Placing the diagram in the paper, or compiling the paper with it: the author `\input`s it.
- Effective font size after LaTeX scales a figure: the script check reads the nominal size.
- Running the plotting scripts (the `figures` task does) or editing them.
