# power tools

One tool that says, before the runs, how many seeds each claimed comparison needs (`tasks/power/`). claim_stats (`tasks/methods/`) tests a comparison after the runs; this sizes the runs from the pilot. It takes the project's Git repository as `paper_dir` (anything else raises `ValueError`), writes into `<out_dir>/<timestamp>/` with a trail (`run.json`, `run.md`), and returns JSON with `status`, `report` and `run`. The report is in Simplified Chinese. Plain code only; no model call.

Learned from Curasynth's sample-size and power calculator (minimum detectable effect, alpha and power in, sample size out), with G*Power's paired and two-group t test sizes as the reference values.

## power_analysis

| Item | Contract |
| --- | --- |
| Signature | `power_analysis(paper_dir, alpha="0.05", power="0.8", effect="", out_dir="")` |
| Purpose | The seeds each claim's comparison needs to be detected by a two-sided t test at `alpha` with probability `power`, and whether the pilot already has them. |
| Input | `workflow/claims.md`, `evidence.csv`, `results.tsv`, `experiment.md` (`Metric`; `Direction: lower` makes smaller better; an existing `Seeds:` line). `alpha` and `power` in (0, 1). `effect`: the minimum difference worth detecting, absolute (`0.002`) or relative to the worse method's mean (`5%`); empty uses the claim's own difference. A bad number raises `ValueError`. |
| Process (plain code) | Per-seed numbers and groups as claim_stats reads them (`methods.claims.claim_tables`): results.tsv rows by branch or by description without `seed N`, evidence.csv method/value rows, CSV/TSV sources with method, seed and metric columns. results.tsv runs without a seed stay in as one-run groups, so a comparison run once still shows up. The pair: the evidence `compare` column (`A > B`); else the two groups whose means lie closest to the claim's `from A to B`, `A -> B` or `A vs B` numbers (summed relative distance under 0.5); else the best group against each other (claim_stats' pairing). Noise: the standard deviation of the seed-wise differences when both sides have the same two or more seeds (paired t), else each group's (two-group t, n seeds per method). Minimum effect: `effect`, else the claim's stated difference, else the pilot's mean difference. Power of the two-sided t test is the noncentral t probability, integrated numerically over the chi distribution (Simpson, 2000 intervals); the critical value inverts methods.significance's t distribution. Seeds needed: the smallest n ≥ 2 whose power reaches `power`, searched to 1000. |
| Output | Per comparison `claim, a, b, n_a, n_b, means, paired, sd_diff / sd_a / sd_b, effect, effect_from (input, claim, pilot), have, needed, power_now, state`: `enough`, `underpowered`, `pilot` (a side with fewer than two seeds: the report asks for pilot runs with the same seeds), `no_effect` (the pilot goes the wrong way and nothing names an effect), `infeasible` (over 1000 seeds). `PASS`: every comparison `enough`. `PASS_WITH_NOTES`: any other state. `FAIL`: no comparison found (no claims, or no claim with two groups). Files: `report.md` (the table, the proposed seeds), `power.json`, `edits.json`. JSON also has `power`, `edits`, `seeds` (the largest needed) and `comparisons`. |
| Proposed edit | `edits.json` in paper_proofread's format (`{root, edits: [{id, file, section, kind, quote, replacement, problem}]}`): `Seeds: N` for `workflow/experiment.md`, replacing a `Seeds:` line that asks for fewer, or added after the `Direction` (else `Metric`, else last) field line. No edit when the line already asks for N or more. Never applied by the tool. |
| Effects | Writes only the report folder. |
| Tests | `tests/power/`: sample sizes against G*Power (paired dz 0.5, 0.8, 1.0, 2.0 at power 0.8; 0.9 power; alpha 0.01; two groups d 0.5, 0.8), the critical value, a noncentral t power against scipy's value, the null rejecting at alpha; claim numbers and effect parsing; single runs asking for pilot seeds with the claim's numbers picking the pair among four groups; a three-seed pilot needing four seeds with the proposed line, a relative effect, existing Seeds lines kept or raised; five seeds passing; an evidence `compare` with unpaired seeds; no comparison failing; bad inputs. |
| Not covered | Variance from sources other than seeds (data splits, hyperparameter search); correction for many comparisons (the report suggests dividing alpha by their number); sequential or Bayesian designs; non-t tests (bootstrap, Wilcoxon). |
