# codeorigin tools

The `code_origin` task of auto_research (`tasks/codeorigin/`). The code release gate checks that the repository is public, has a README and is linked from the paper; this tool checks what was copied into it, from where, under which license, and whether each copy is credited.

Learned from Codequiry and the code modes of Copyleaks and Plagly (source-code matching against public repositories), Software Heritage (content SWHIDs and its `/known/` endpoint), ScanCode (license detection by matching license texts and notices), and REUSE/SPDX (`SPDX-License-Identifier` lines and per-file license and copyright information).

## code_origin

| Item | Contract |
| --- | --- |
| Signature | `code_origin(paper_dir, code_dir="", out_dir="")` |
| Purpose | Before release, know which files of the code were copied or adapted from other projects, where from and under which license; catch license conflicts and missing credit, and get the notices to add. |
| Input | `paper_dir`: the project's Git repository (else `ValueError`). `code_dir`: the code; empty uses `rules.json`'s `code.repo` when it is a local folder, else the project (as paper_agent and code_wiki do). `out_dir`: default `<paper_dir>/drafts/code_origin`. The files are those `git ls-files` lists (every file when the code is not a Git working tree); `drafts/`, virtualenvs, `.lake`, `node_modules`, `.env` and symbolic links are left out; binaries and files over 1 MB are listed as skipped, not read. No readable file raises `ValueError`. |
| Hashing (plain code) | Each file's Git blob hash (`sha1("blob <n>\0" + bytes)`), the SWHID `swh:1:cnt:<sha1_git>`. |
| Software Heritage | `POST /api/1/known/` in batches of 1000 SWHIDs, no key. The client reads `X-RateLimit-Remaining`/`X-RateLimit-Reset` (anonymous: 120 requests an hour), waits for a reset under 30 s, else stops and names the limit; at most 90 requests a run; `SWH_TOKEN` is sent as a bearer token when set. Content-to-origin lookups need a token, so an origin is a candidate verified by path: the origin's latest visit, its HEAD revision, `revision/<id>/directory/<path>/`, compared by blob hash (exact) or, for code under 200 kB, by fetching the archived file and comparing winnowing fingerprints (near). Without a verified origin a known file is reported with its archive link. A failing archive is `PASS_WITH_NOTES` naming it; local evidence still counts. |
| Classification | Status per file: `known` (the archive holds the same content and the file has 10 or more non-blank lines and 300 or more bytes), `adapted` (in a vendored folder: `third_party`, `vendor`, `external`, `extern`, `contrib`… or a non-root folder with its own LICENSE; a code line "adapted/copied/taken/borrowed/derived/ported… from", or "based on/source:/credit" with a URL; a license header that is not the repository's; at least half of the smaller file's winnowing fingerprints (k = 30 normalised characters, window 30, comment lines dropped, 15 or more shared) shared with a third-party file; a near-copy verified in an origin), `own` (known only because the same blob sits at the same path in the code's own archived origin, from the `origin` remote or `code.repo`), `unique`, `trivial` (too small to judge), `skipped`. LICENSE, NOTICE and README files are never flagged; provenance lines are read only in code files, so a paper's "adapted from \cite{…}" is not one. |
| Origins | Candidates: forge URLs a third-party file states (GitHub, GitLab, Bitbucket, Codeberg; `/blob/<ref>/<path>` and raw URLs give the path), the submodule URL of a vendored folder, and the identifier's candidates. Paths tried: the stated path, the path inside the vendored folder, its trailing parts (3 at most); 12 candidates a run. Siblings: each unique code file is looked up in every verified origin, in the folder its verified neighbour came from (15 lookups), so a modified file copied with an exact one is found. An adapted file takes the origin of the third-party file it copies. |
| Licenses | `SPDX-License-Identifier` first, else the built-in matcher on the distinctive sentences of MPL-2.0, AGPL/LGPL/GPL (version from the title lines of a license text; `-or-later` from a notice offering any later version), Apache-2.0, CC BY-NC/BY-SA/BY/CC0, BSD-3/2-Clause, MIT, ISC, Unlicense, BSL-1.0, Zlib, LPPL, PSF; `scancode-toolkit`'s SPDX expression when it is importable. A file's license: its header, else the nearest non-root LICENSE above it, else the verified origin's top-level LICENSE (read from the archive), else the license of the file it was adapted from. The repository's: a top-level LICENSE/COPYING, else `pyproject.toml` or `package.json`. Compatibility table (file into repository): permissive → yes; Apache-2.0 → yes into Apache/GPL-3/LGPL-3/AGPL/MPL, no into GPL-2.0-only, conditional into permissive; MPL-2.0 and LGPL → conditional (file-level terms) or yes into GPL; GPL-2.0 → yes only into GPL-2.0 (or GPL-3 when or-later); GPL-3.0 → yes into GPL-3/AGPL, else no; AGPL → no except AGPL (conditional into GPL-3); CC BY-NC → no; CC BY-SA → no (conditional into GPL-3); CC BY → conditional; no file license → unknown; a repository without a license → conditional for permissive, no for copyleft. SPDX `OR` takes the best alternative, `AND` the worst. |
| Model calls | `identifier` (`identify`, schema `origin_candidates`): one call when third-party files lack a verified origin and the archive answers; at most 15 files (header 3k characters, evidence, URLs), at most 3 candidates each; `check_candidates` keeps forge URLs for files asked about, without `..`; each is verified as above or dropped. `creditor` (`credit`, schema `credit_review`): one call over at most 40 third-party files (status, evidence, origin and whether verified, license, compatibility, stated source lines, copyright lines, 30 header lines), the README and the notices files (8k each): per file `adequate`/`incomplete`/`missing`, where (`file`, `readme`, `notices`, `license`), a quote, a reason, the copyright line, a note; and a README line. `check_credit`: a verdict whose quote is not found (whitespace runs as one space) in the text it names becomes `missing`; a copyright line not found in the file or its license text is dropped; a README line naming a URL that is not a found origin, or a license not found, is replaced by one code writes. |
| Output | JSON with `status`, `report`, `run`, `origin`, `notices`, `edits`, `code_dir`, `repo_license`, `files`, `known`, `adapted`, `uncredited`, `conflicts`, `unavailable_sources`. `FAIL`: a third-party file whose license conflicts with the repository's. `PASS_WITH_NOTES`: a third-party file without adequate credit, a third-party file whose license is unknown, or the archive could not be asked. `PASS` otherwise. Files in `<out_dir>/<timestamp>/`: `origin.csv` (`file, swhid, status, origin, license, compatible, credit, evidence`; skipped files with their reason), `THIRD_PARTY_NOTICES.md` (grouped by origin and license: files, copied or adapted, SWHID, note, license, copyright lines, and the license text of permissive licenses read from the vendored folder or the origin), `edits.json` (paper_proofread's edit format, root = the code: the notices file as `create` or `replace`, and the README line appended after the README's last line as `credit`), `report.md` (Chinese: table, conflicts, missing credit, the `cp` command for the notices file, the README line), `run.json`, `run.md`. |
| Effects | Reads the code; sends only SWHIDs (hashes), origin URLs and paths to Software Heritage. Never modifies the code: apply_edit writes only `.tex` and `workflow/` files, so the notices file and README line are copied by hand with the command in the report. |
| Tests | `tests/codeorigin/`: the blob hash against `git hash-object`; provenance lines, vendored roots, forge URLs and the paths tried; winnowing finds pasted functions and ignores a shared license header; the license matcher on SPDX lines, headers and license texts (GPL-2.0 text naming the Library GPL, MPL naming the GPL family); the compatibility table; the identifier's candidates filtered; the archive client stopping at a rate limit without waiting and batching `/known/`. A fixture MIT repository with a verbatim copy (known, origin verified by the scripted identifier, a fabricated origin dropped), a modified sibling found in the verified origin, a GPL file (FAIL), a vendored BSD folder and an own file pasting from it (winnowing), the scripted creditor's unfound quote, fabricated copyright and unfound URL dropped; an unavailable archive named in the report; credited permissive code passing; files of the code's own archived origin marked own. Every network call goes through a fake archive. |
| Not covered | Origins of known files that no candidate names (Software Heritage's content-to-origin and provenance endpoints need an account; `SWH_TOKEN` only raises the rate limit here). Snippet-level matches against the whole archive (only whole files are known to it; near-copies are found against vendored files and verified origins). License texts that differ from the matcher's sentences, dual-licensing outside SPDX expressions, and license exceptions (`WITH` is ignored). Legal advice: the table follows common FSF/OSI compatibility guidance. |
