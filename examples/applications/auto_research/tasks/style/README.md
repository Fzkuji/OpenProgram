# style tasks

The `paper_translate` and `writing_style` tasks of auto_research (`tasks/style/`). `paper_translate` translates the whole LaTeX paper into another language and compiles it, with the commands, math, citations, labels and comments guarded in code. `writing_style` learns how the author writes from their earlier papers and proposes exact edits that bring the paper closer to that voice and to the rules of Writing in the Sciences.

Learned from gpt_academic (whole-paper LaTeX translation), PaperSpine (an author's style and motivation learned from their past papers) and Stanford's Writing in the Sciences critique (SciWrite).

## paper_translate

| Item | Contract |
| --- | --- |
| Signature | `paper_translate(paper_dir: str, language: str = "zh", out_dir: str = "") -> str` |
| Purpose | A compiled copy of the paper in another language, its LaTeX structure intact, its terms rendered the same way throughout. |
| Input | `paper_dir`: the paper's Git repository; `workflow/rules.json` names `main_tex`. `language`: `zh` (Simplified Chinese, default), `zh-TW`, `ja`, `ko`, `de`, `fr`, `es`, `it`, `pt`. `out_dir`: the output folder (default `<paper_dir>/drafts/paper_translate`). Not a Git repository, an unknown language, a missing main file or one with no prose raises `ValueError`. |
| Process | 1. **Read** (code): the main file and every file it reads through `\input`/`\include`, each masked (`latex.py`): every command with its options and arguments, environment boundary, math, comment, brace, `&` and control symbol becomes a numbered placeholder `⟦n⟧`; the arguments of text commands (`\section`, `\caption`, `\emph`, `\footnote`, `\title`, ...) stay visible, those of every other command (`\cite`, `\ref`, `\label`, unknown macros) and math, code and drawing environments are hidden whole. Paragraphs are cut at blank lines. 2. **Terms** (`termer`, one call): up to 80 technical terms of the prose with their rendering; code keeps only terms found in the prose. 3. **Glossary** (code): `workflow/glossary.md` (`\| Term \| <language> \|`), created when absent; the author's rows override the model's and new terms are appended; a file for another language is neither used nor changed. 4. **Translate** (`translator`, one call per section chunk of at most 6000 characters, with the glossary terms of the chunk): code checks each paragraph: every placeholder back exactly once, no `\ { } $ & # ^ _ %` written outside placeholders, and after restoring, the same `\begin`/`\end`, labels and brace balance. Failed paragraphs are sent again once with their problem; still failing, they keep the original text. A translated paragraph whose glossary term's rendering is missing is listed. 5. **Build** (code): the source tree is copied (without `.git`, `drafts`, `workflow`, hidden files and build files), the translated files written, `\usepackage[UTF8,fontset=fandol]{ctex}` (Simplified Chinese, with the Fandol fonts TeX Live ships, since ctex's macOS fontset can hang xelatex on a system font lookup) or `xeCJK` with a font from `fc-list` (Traditional Chinese, Japanese, Korean) added after `\documentclass`, and `latexmk -xelatex -f -file-line-error` run (300 s); errors are read from the log with their file, line and the line's text. |
| Output | JSON with `status`, `report`, `translate`, `source`, `pdf`, `run`, `paragraphs`, `kept`, `compile_errors`, `glossary_terms`. `FAIL`: latexmk ran and produced no PDF. `PASS_WITH_NOTES`: a paragraph kept its original, a glossary term was missed, a compile error, no latexmk, or the glossary was for another language. `PASS`: none. Files in `<out_dir>/<timestamp>/`: `source/` (the translated tree and its build files), `paper.<language>.pdf`, `report.md` (Chinese), `translate.json` (`kept` paragraphs with their problems, `missed_terms`, `glossary`, `added_terms`, `build` with `errors`), `run.json`, `run.md`. |
| Effects | Reads the paper; writes the output folder and `workflow/glossary.md` (created, or new rows appended; existing rows never changed). The paper sources are never modified. |
| Model calls | `termer` once; `translator` once per chunk (sections start a new chunk) and once per chunk of failed paragraphs. |
| Tests | `tests/style/test_translate.py`: masking round trip and checks, a placeholder dropped twice (original kept), a raw `%` fixed on retry, ctex, the copied tree, the compile error at its line, the author's glossary overriding and growing, another language's glossary left alone, no latexmk, a failed build. |
| Not covered | Arguments of unknown macros and of `\newtheorem` stay in the source language. Bibliography entries are not translated. Languages whose script needs a font the default xelatex setup lacks (Cyrillic, Arabic, ...) are not offered. |

## writing_style

| Item | Contract |
| --- | --- |
| Signature | `writing_style(paper_dir: str, own_papers: str = "", out_dir: str = "") -> str` |
| Purpose | Exact edits that make the paper read like the author at their clearest: their own voice, active, without clutter. |
| Input | `paper_dir`: the paper's Git repository; `workflow/rules.json` names `main_tex`. `own_papers`: comma-separated `.tex`/`.pdf`/`.txt`/`.md` files or folders of the author's earlier papers (relative to the paper or absolute), read together with everything under `workflow/own_papers/` (`../overlap/gather.py`). In a folder holding a LaTeX source, the main `.tex` (with `\documentclass`) stands for the folder's other files. `out_dir`: the output folder (default `<paper_dir>/drafts/writing_style`). A missing repository, main file or named own paper, or a paper with no prose, raises `ValueError`. |
| Process | 1. **Learn** (code, `profile.py`): each earlier paper as plain-prose paragraphs (`.tex` flattened and stripped of commands, math and floats; `.pdf` through pymupdf's text blocks or pdftotext's paragraphs, before the references; text files by blank lines) and its introduction. Measured: sentence length (mean, median, 90th percentile, share over 30 words), share of sentences with a passive, first person per 1000 words and share of "we" sentences, hedges per 1000 words, nominalisations per 100 words, paragraph length, favourite connectives, and the first sentence of each introduction. 2. **Profile** (`profiler`, one call, only when `workflow/style.md` is absent and earlier papers were read): how the author motivates, states contributions and sounds, with up to six example quotes; code keeps a quote only when it is in the papers. Code writes `workflow/style.md` (the measured table, openings, profile, examples and an "Own rules" section). When `style.md` exists it is used as it is, and the values of its table are the targets. Without earlier papers and `style.md`, the targets are Writing-in-the-Sciences defaults (22 words a sentence, 15% long sentences, 25% passives, 4 nominalisations per 100 words, 150-word paragraphs) and the report says so. 3. **Read** (code): the paper's paragraphs by section, measured the same way and compared with the targets (a gap counts when it is more than 25% and a set amount away); each paragraph's long sentences, passives, clutter phrases, nominalised verbs ("perform an evaluation of") and length are flagged. 4. **Edit** (`editor`, one call per section, at most 12 edits): `old` verbatim, `new`, `why`, under a rule: `active_voice`, `clutter`, `nominalisation`, `sentence_length`, `one_idea`, `topic_sentence`, `author_style`. Code drops an edit whose old text is not in its paragraph, that changes nothing, that changes a `\cite`, `\ref`, `\label` or inline math, that adds a number, or that overlaps a kept edit. 5. **Report** (code). |
| Output | JSON with `status`, `report`, `style`, `edits`, `run`, `profile` (`learned`, `style.md` or `rules`), `own_papers`, `proposals`, `exact_edits`, `counts` per rule, `deviations`. `PASS_WITH_NOTES`: any proposal, gap or note (no earlier papers, an unreadable one). `PASS`: none. Files in `<out_dir>/<timestamp>/`: `report.md` (Chinese: the measures of the paper against the targets, then the edits by rule), `style.json` (`learned`, `current`, `target`, `deviations`, `flags`, `proposals`, `dropped`), `edits.json` in the format of `paper_proofread` (`root`, and `edits` with `id`, `file`, `section`, `kind` (the rule), `quote`, `replacement`, `problem`; only proposals whose old text occurs exactly once in exactly one `.tex` file), `run.json`, `run.md`. `apply_edit(paper_dir, edit)` (re-exported from `tasks/proofread/`) applies one. |
| Effects | Reads the paper and the earlier papers; writes the output folder and `workflow/style.md` when it is absent. The paper sources change only through `apply_edit`. |
| Model calls | `profiler` once when `style.md` is learned; `editor` once per section. |
| Tests | `tests/style/test_style.py`: learning from a `.tex` folder and a `.txt` file, the profile's invented quote dropped, each kind of dropped edit, the edits applied with `apply_edit`, a kept `style.md` and its targets, rules only without earlier papers, an unreadable PDF; the measures. |
| Not covered | The measures are heuristics (a regex passive, a suffix list for nominalisations); PDF paragraphs follow the text blocks, so a paragraph broken across columns counts as two. The editor does not move text between sections. |
