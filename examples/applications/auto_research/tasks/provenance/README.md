# writing_provenance task

The `writing_provenance` task of auto_research (`tasks/provenance/`). It records where each paragraph of the paper came from: written by the author, generated with an AI assistant, edited by an AI tool, pasted from existing text, or still uncommitted. It replays how each paragraph was written, and drafts the sentence of the AI-use disclosure from the numbers. Phase: release.

Learned from Grammarly Authorship. Authorship records whether each passage was typed, generated by AI, edited by AI or pasted, and produces a shareable replay report as evidence for an AI-use disclosure. Here the record is the project's Git history and the run trails Auto Research writes, so nothing has to be recorded while the author types.

| Item | Contract |
| --- | --- |
| Signature | `writing_provenance(paper_dir: str, out_dir: str = "") -> str` |
| Purpose | Each word of the paper with its source, shares per section and overall, a replay per paragraph, and a disclosure sentence whose numbers match them. |
| Input | `paper_dir`: the paper's Git repository. The main `.tex` is `main_tex` of `workflow/rules.json`, or the top-level `.tex` with `\documentclass`, and its `\input`/`\include` files are followed. `out_dir`: the report folder (default `<paper_dir>/drafts/writing_provenance`). Reads `drafts/**/edits.json` with the `run.json` beside it, `drafts/text_overlap/cache/*.txt`, the last `drafts/text_overlap/*/overlap.json` and `workflow/own_papers/`. A folder that is not a Git repository, a missing main `.tex` or a paper without prose raises `ValueError`. |
| Paragraphs | `paragraphs.py`: the document body in reading order, split at blank lines, headings, `\input` points and display environments. Comments are dropped. Math, citations and references are shown but not counted. Tables, equations, algorithms and listings are skipped, except that their captions are kept. Words are compared as tasks/overlap compares them: lowercase, without punctuation. |
| Word history | `history.py` and `workflow.chain`. Each paragraph's versions come from the commits that changed its file, newest first. The version at each commit is the paragraph most like the next newer one (word similarity of at least 0.4), and the walk stops when no paragraph is that close. When `git blame --porcelain -w -M -C` says the oldest version's lines came from another file through an earlier commit (a paragraph moved into an `\input` file), the walk goes on in that file from that commit, at most 3 times. A word diff between consecutive versions gives each word the commit that wrote it. Words of the first version take their line's blame when it names an ancestor commit, and otherwise take the first version's commit. Words that differ from the last commit are `uncommitted`. |
| Classes | `ai`: the commit's message has a `Co-Authored-By:` trailer naming an AI tool (the detection of `ai_disclosure` in `tasks/submission/disclosure.py`: Claude, GPT, Copilot, Gemini, Codex, Cursor, DeepSeek and others), or an Auto Research run made it (author `auto_research`, or a message starting `ablation:`, `sweep trial N:` or `Auto Research`). `ai_edit`: an edit of a `paper_proofread`, `writing_style` or `caption_check` run whose new text is in the commit's version of the file, while its old text, without the new, is in the parent's version. The words that commit wrote inside the span where the new text is found (runs of three or more of its words covering at least 60% of it) are `ai_edit`. Unchanged words keep their author. `pasted`: one non-AI commit wrote 120 or more words of the paragraph, and they match a cited work's full text in text_overlap's cache, an own paper its last run compared, or a file in `workflow/own_papers/`, by tasks/overlap's 8-gram matcher (a passage of at least 25 words with at least 60% shared 8-grams). `bulk`: such an insert that matches nothing. It is recorded without judgement. `human`: everything else. |
| Replay | Each paragraph's versions, oldest first, each with commit, date, author, subject, class, AI tools, file, text and a word diff against the version before. The working tree comes last when it differs. At most 30 versions are kept: the first and the latest 29, with the number omitted. |
| Output | JSON with `status`, `report`, `json`, `html`, `run`, `words`, `shares` (per class, percent), `ai_paragraphs`, `pasted` (paragraph, commit, words, source, title, bib key, matched words, overlap, cited), `bulk`, `uncommitted_files` and `disclosure`. `PASS`, or `PASS_WITH_NOTES` when a paper file has uncommitted changes. Files in `<out_dir>/<timestamp>/`: `provenance.html`, `provenance.json`, `report.md`, `run.json` and `run.md`. `provenance.html` shows the text with every word tinted by its class, the shares overall and per section, and the replay of any paragraph clicked, as one file of inline HTML, CSS and JS. `provenance.json` has every paragraph (file, lines, section, counts, shares, dominant class, first and last commit, commits, inserts, colored segments, replay), the sections, the AI passages, the inserts, the edits found applied and the disclosure. `report.md` (Chinese) has the shares overall and per section, the AI passages, the applied edits, the large inserts and the draft disclosure in English and Chinese. |
| Effects | Runs `git log`, `git blame`, `git show`, `git status`, `git rev-parse` and `git merge-base`. Writes only the report folder. It never changes the paper and never commits. |
| Model calls | None. It is deterministic. |
| Failure | An unreadable own paper or `workflow/own_papers` entry is listed in the report, and the run goes on. A file Git does not know counts as uncommitted. Rerunning is safe. |
| Tests | `tests/provenance/test_provenance.py` builds repositories with real git commands. They cover an author's commits, a Claude-co-authored paragraph the author then edits (word-level shares), an Auto Research ablation commit, an applied proofread edit, a paragraph pasted from a cached cited work, a large insert that repeats nothing, an `\input` file, a paragraph moved into an `\input` file, uncommitted and untracked text, the 30-version cap, a repository without AI, the report, the page and the disclosure numbers. |
| Not covered | Text an AI wrote outside the repository and the author pasted in is the author's commit, so it counts as `human`, or as `bulk` when it is large. Git cannot tell the difference. Edits applied in a different wording than the edits.json proposed are not recognised as `ai_edit`. A paragraph rewritten so much that less than 40% of its words stay starts a new history. History past 300 commits of a file is not read. |
| Usage | `from auto_research.tasks.provenance import writing_provenance`, then `writing_provenance("<repo>")`. |
