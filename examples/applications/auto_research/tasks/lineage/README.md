# lineage tools

One tool that looks for the baseline a reviewer would say is missing (`tasks/lineage/`): an uncited work that reports a stronger number on one of the paper's benchmarks. It takes the project's Git repository as `paper_dir`, writes into `<out_dir>/<timestamp>/` with a trail (`run.json`, `run.md`), and returns JSON with `status`, `report` and `run`. The report is in Simplified Chinese. Plain code parses the tables, searches, ranks and compares; one role reads each candidate work, and every number and setting it gives is checked verbatim in the work's text.

Learned from LINEAGE (baseline lineage retrieval: the works citing a benchmark's dataset paper and its baselines are where stronger baselines live) and from reviewers' "missing strongest baseline" comment. Papers with Code's leaderboards are gone (they redirect to Hugging Face), so the candidates come from citation data instead.

## missing_baselines

| Item | Contract |
| --- | --- |
| Signature | `missing_baselines(paper_dir, since="", count="10", out_dir="")` |
| Purpose | Find uncited works that beat the paper's number, or its strongest cited baseline, on the same dataset, metric and setting. baseline_numbers checks the cited works' numbers; this checks the works the paper does not cite. |
| Input | The main file of `workflow/rules.json` and its `.bib` files. `since`: a year (`2023`) or a date (`2023-11-01`); empty is three years before today. `count`: whole number, default 10; `count*3` candidates per benchmark are read and at most `count` stronger works per benchmark are listed. `workflow/sota.csv` (baseline_numbers) and `workflow/experiment.md` (`Metric`, `Direction`) when present. `ValueError` when no table has a cited row and a dataset. |
| Benchmarks (plain code, `benchmarks.py`) | Every numeric column of a table that holds a `\cite` row (the table parser of `tasks/reading/sota.py`). Dataset over metric from two header rows; one header such as "ImageNet top-1 error" is split at the first metric word; else the caption's "on X". Lower is better for `↓`, error, loss, perplexity, latency, WER, FID and the like, or experiment.md's `Direction: lower` for its Metric; `↑` wins. Rows without a `\cite` are the paper's own (best one kept); cited rows are the baselines, with the value sota.csv verified (`match`, `mismatch`, `better_reported`) replacing the cell. The same dataset and metric in two tables is one benchmark; at most 8. |
| Candidates (plain code, `candidates.py`) | Dataset paper: a .bib entry whose title names the dataset, else the most cited OpenAlex work whose title names it and says dataset, database, benchmark, challenge or corpus (else "<name>: ..."). Seeds: up to 5 cited baselines resolved to OpenAlex. Queries since `since`: `cites:<dataset paper>,cites:<baseline>` and `cites:<baseline>` with the dataset in title or abstract (25 each, most cited first), and Semantic Scholar search "<dataset> <metric>". Dropped: works in the .bib (DOI, arXiv id, title similarity ≥ 0.93) and surveys, reviews, tutorials. Rank: log10 of citations per year since publication plus 0.3 per extra query that found the work. At most 60 works per run. |
| Full text | arXiv HTML with tables (`reading.reader.work_text`), else the author's PDFs or an open-access PDF (`overlap.library.library_text`). A work whose text never names the dataset is not sent to the model. |
| Model call | `extractor` (`extract`, schema `benchmark_results`), one call per work, four at a time, with only the benchmarks its text names: for each, the work's strongest own number (never a baseline it copies) with `quote`, `location`, `method`, `setting` and `setting_quote`, `comparable` with `difference`, and `complement` for accuracy where we name error (or the reverse). `check`: a value whose quote is not in the text, or does not contain the value, is dropped; a setting quote not in the text makes the result not comparable; an unknown benchmark raises and the work is asked once more. |
| Comparison (plain code) | The value (100 minus it for a complement) against our best and the strongest cited baseline with `sota.better`: beyond the rounding of the less precise number, in the benchmark's direction, fractions read as percentages next to percentages. `problem`: stronger than ours and comparable. `note`: stronger than ours with a different setting, or stronger than the cited baselines only. `weaker`: otherwise. |
| Output | `workflow/missing_baselines.csv`: `benchmark, work, id (arXiv:… or doi:…), value, setting, quote, comparable, stronger_than_ours, stronger_than_baselines, status`. `FAIL`: a `problem`. `PASS_WITH_NOTES`: a `note`, a source that failed, or a reply that could not be read twice. `PASS` otherwise. Files: `report.md`, `missing_baselines.json` (benchmarks, dataset paper, seeds, queries, rows, works not read and why), `candidates.bib` (the stronger works, for `import_library`). |
| Author edits | Set a row's `status` to anything else (`cited`, `ignore`): a rerun keeps the row and does not count that work for that benchmark. |
| Effects | One model call per read work. Writes the CSV, the report folder and a text cache in `drafts/missing_baselines/cache/`. Never edits the paper. |
| Tests | `tests/lineage/`: header splitting and directions; benchmarks with own rows and a sota.csv value; since and ranking (cited and older works lower); quote checks and the direction-aware comparison with a complement; an entry with OpenAlex, Semantic Scholar and arXiv replaced in which a comparable stronger work fails the check, an extra-data one is a note, a cited one is never read, and an author's `cited` status turns the rerun into PASS_WITH_NOTES. |
| Not covered | Numbers only in figures or prose; benchmarks without a dataset name in the table; works without full text (listed); judging comparability beyond what the work's text states. |
