# qualitative tasks

The `thematic_analysis` task of auto_research (`tasks/qualitative/`). It codes interview data with two blind coders, measures their agreement, and groups the codes into themes with verbatim quotes, as reflexive thematic analysis (Braun & Clarke) with a codebook and inter-coder agreement does.

Learned from thematicanalysis.ai and the AI coding in NVivo, ATLAS.ti and MAXQDA.

## thematic_analysis

| Item | Contract |
| --- | --- |
| Signature | `thematic_analysis(paper_dir: str, data: str, question: str = "", codebook: str = "", out_dir: str = "") -> str` |
| Purpose | The author gets a codebook two coders apply alike, themes that answer the research question with prevalence and quotes ready for the paper, and a saturation curve, without coding every transcript by hand. |
| Input | `paper_dir`: the project's Git repository. `data`: files or folders inside the project, comma-separated; `.txt`, `.md`, `.docx` (read with zipfile), `.vtt` and `.srt`; in a folder, files named readme, license, source, notice or citation are documentation and skipped, as are other types. `question`: the research question; empty uses the RQ lines of `workflow/claims.md` that state a question (an id alone such as `RQ1` is not one), else a general question with a note. `codebook`: a codebook file in the project; empty uses `workflow/codebook.md` when present. `out_dir`: the output folder (default `<paper_dir>/drafts/thematic_analysis`). Not a Git repository, data or a codebook outside the project or missing, no supported file, or no segment of five words or more raises `ValueError`. |
| Segments | A file whose paragraphs mostly start with a speaker label (`Name:`, `**Name:**`, a leading timestamp allowed) and that has two speakers is cut into turns (unlabelled lines continue a turn); other files into paragraphs (blank-line separated; one per paragraph in `.docx`; markdown headings skipped). Subtitles: cues with `<v Name>` or `Name:`; consecutive cues of one speaker, or unlabelled cues up to a sentence end, are merged. The id is `<file>:<line>` (paragraph number in `.docx`). Interviewer turns (interviewer, moderator, facilitator, researcher, host, I, Q, R, Int) are not coded; each is shown as `asked` with the next answer. Turns under five words are not coded. The participant is the file, or file/speaker when a file has several non-interviewer speakers. |
| Process | (1) Open coding, without a codebook: coder A (semantic, the participants' own words) and coder B (latent, the meaning beneath them) code every segment in batches of about 14k characters (40 segments at most), blind to each other, up to four codes a segment with label, definition and quote; a code whose quote is not in its segment is dropped. (2) Codebook: the merger turns both coders' distinct labels (with use counts; the 400 most used of each) into 5 to 30 codes with name, definition, include, exclude and the labels each absorbs (labels the coders never used are dropped from the mapping); the codebook is written to `workflow/codebook.md` when that file does not exist. With an author codebook (`## name` headings with `Definition:`, `Include:`, `Exclude:` lines), steps 1 and 2 are skipped. (3) Re-coding: both coders apply the codebook to every batch, blind, with a quote per code checked against the segment; segments a coder leaves out are asked once more, and segments still missing from either coder are left out of the agreement. Per code, Cohen's kappa over the segments both coded; overall, pooled Cohen's kappa and Krippendorff's alpha (nominal) over every (segment, code) decision, the mean of the per-code kappas and percent agreement; codes under 0.6 are flagged. (4) Themes: the themer gets each code with definition, kappa, prevalence and up to five example segments (agreed ones first, one per participant first) and writes 2 to 7 themes with a central concept, their codes (a code in one theme only; later repeats are dropped) and 2 to 3 quotes; a quote must be verbatim in a segment that carries one of the theme's codes. Prevalence is counted in code: participants and segments both coders agree on, and those of either coder. (5) Saturation: new codebook codes (either coder) per transcript in file order, and new open labels per coder when open coding ran; saturated when the last two transcripts add none. Batches run four at a time. |
| Output | JSON with `status`, `report`, `run`, `codebook`, `coded`, `themes_file`, `quotes`, `segments`, `participants`, `codes`, `kappa`, `alpha`, `low_kappa`, `themes`, `saturated`. `PASS`: pooled kappa at least 0.6, at least one theme, every theme with a verified quote, and no batch failed. `PASS_WITH_NOTES` otherwise. Files in `<out_dir>/<timestamp>/`: `report.md` (Chinese: kappa table, themes with prevalence and quotes, saturation table, notes), `codebook.md`, `coded.csv` (segment, participant, code, coder, quote), `open_codes.csv` (when open coding ran), `themes.md`, `quotes.md` and `quotes.tex` (appendix of quotes by theme with participant and id), `analysis.json`, `run.json`, `run.md`. |
| Effects | Reads the data and `workflow/claims.md`; writes `workflow/codebook.md` only when it does not exist. The data are never modified. |
| Model calls | `coder_a` and `coder_b`: one open-coding call per batch each (none with a codebook), one re-coding call per batch each, plus one per batch of left-out segments. `merger`: one call (none with a codebook). `themer`: one call. Eight interviews of about 25k characters each make about 30 calls. |
| Failure | A failed coding batch is a note and its segments are missing; no open code at all, or a malformed merger or themer reply (too few codes, repeated name, unknown code), raises. Rerunning is safe; a rerun applies `workflow/codebook.md` as the author left it. |
| Tests | `tests/qualitative/test_segments.py`: the four formats, speaker turns and continuations, interviewer context, documentation skipped, paths outside the project, verbatim quote matching. `tests/qualitative/test_agreement.py`: kappa on a known table, alpha against its pairwise definition, the per-code table, the saturation curve. `tests/qualitative/test_thematic.py`: scripted coders, merger and themer; blind coders; the question from claims.md; dropped quotes; left-out segments asked again; codebook written and reused; low agreement; a failed batch. |
| Usage | `from auto_research.tasks.qualitative import thematic_analysis` |

## Not covered

- Registering the task in the program's task list and app.
- Audio or video files: transcribe them first (the meetings tools or Whisper) and pass the transcript.
- Weighting codes by segment length, or agreement on the quoted span (kappa is on whether a code applies to a segment).
- Translating quotes; non-English data is coded and quoted in its own language.
