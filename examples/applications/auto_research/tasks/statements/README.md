# statements tasks

The `paper_statements` task of auto_research (`tasks/statements/`). It drafts the back-matter statements venues and journals ask for — code and data availability, CRediT author contributions, competing interests, funding, and the ethics or impact statement — from the project's own files, and leaves an explicit `[TODO: ...]` for every fact the files do not record. The AI-use statement is `ai_disclosure` (`tasks/submission/`), and the venue's required sections come from the venue families of `tasks/venue/facts.py`; neither is repeated here.

Learned from Curasynth (boilerplate statements) and journal requirements: the CRediT taxonomy (Elsevier, PLOS, Cell Press) and the data-availability policies of Nature, PLOS and Elsevier.

## paper_statements

| Item | Contract |
| --- | --- |
| Signature | `paper_statements(paper_dir: str, kinds: str = "", out_dir: str = "") -> str` |
| Purpose | The author gets every statement the venue requires as LaTeX ready to `\input`, stating only facts the project records, with each missing fact marked for them to supply. |
| Input | `paper_dir`: the project's Git repository. `kinds`: a comma list of `availability`, `credit`, `interests`, `funding`, `ethics`; empty drafts the statements the venue requires plus `availability`. `out_dir`: the output folder (default `<paper_dir>/drafts/paper_statements`). Not a Git repository or an unknown kind raises `ValueError`. |
| Gather | Plain code. Code locations: `rules.json` `code.repo` (and, when it is a local folder, its remotes and LICENSE), the paper repository's git remotes (ssh turned into https). Data locations: `workflow/datasheet.md` `Location:` and `workflow/croissant.json` (url, distribution), the data files and `data/` folder of the repository, URLs of code and data hosts in the LaTeX. Licenses: LICENSE/COPYING files (SPDX id), the datasheet and croissant licenses. Grants: ids (4+ digits, not a year) in the funding sentences of the acknowledgments, venue.md and project.md `Funding:`, and `rules.json` `notes` keys about funding. Authors: the `\author` block, project.md and venue.md `Authors:`, `rules.json` `required_authors`; for each, the matching Git identities and commits per area (code, paper, experiments, data, figures) as CRediT hints (Software; Writing – original draft; Investigation and Formal analysis; Data curation; Visualization); commit authors that match no author are listed; AI co-authors and bots are skipped. `Affiliations`, `Competing interests`, `Contributions`, `Ethics` fields of venue.md, project.md and `rules.json` notes. Human-data signals: file names (interview, transcript, participant, consent, ...) and `workflow/codebook.md`; sentences of the paper naming IRB, approval or consent; the datasheet's collection and use parts; the Limitations section. Venue: the family of venue.md or of the template (`tasks/venue/facts.py`), whose required ethics, impact or reproducibility section sets the statement and its heading (ICML Impact Statement, ICLR Ethics Statement, TMLR Broader Impact Statement), and the venue.md lines asking for availability, contributions, interests, funding or ethics. Whether the submission is double-blind. Statements the paper already has. The newest `ai_disclosure` draft. |
| Process | One `drafter` call per text statement with that statement's facts. Code checks the body: every URL is a fact URL, every number of two or more digits (grant ids included) occurs in the facts, every license named is a fact license, every capitalised multi-word name occurs in the facts unless all its words are stock words; no `\section` or `\input`, balanced braces, no unescaped `& % # _`, no Markdown; funding names every grant id; availability names the code location, or in a double-blind submission no real repository; interests and funding without a recorded fact must be a `[TODO: ...]`, not a declaration; ethics states approval or consent only when a fact does. A rejected draft is redrafted with its problems, up to 3 drafts; then it becomes a `[TODO: ...]` naming the problems. A command escaped twice in the reply (`\\texttt`) is undone first. Credit is one call assigning CRediT roles to every author (schema: the authors and the 14 roles); a role that neither the Git hints nor a declared contribution shows gets a `[TODO: confirm ...]`. Without authors, credit is a `[TODO: ...]` listing the commit authors, without a model call. |
| Output | JSON with `status`, `report` (report.md), `statements` (statements.tex), `run`, `kinds`, `placeholders`, `redrafts`, `fallbacks`. `PASS`: every statement drafted with no placeholder. `PASS_WITH_NOTES`: a placeholder, a fallback or a note (no main .tex). Files in `<out_dir>/<timestamp>/`: `statements.tex` (`\section*{Heading}` blocks), `statements.json` (facts and each statement with its attempts and rejections), `report.md` (Chinese: venue requirements, each statement with its state and rejections, the facts used, the Git hints), `run.json`, `run.md`. |
| Effects | Reads the repository and runs `git log` and `git remote`. Never edits the paper; the author approves and inputs the file. |
| Model calls | `drafter`: one call per text statement plus up to two redrafts each, and one call for credit when there are authors. |
| Failure | A malformed credit reply (unknown or repeated author, a role outside CRediT, an author left out) raises. A text draft that keeps failing becomes a placeholder. Rerunning is safe. |
| Tests | `tests/statements/test_statements.py`: an ICML repository with two authors, commits per area, an AI co-authored commit, a LICENSE, a grant in the acknowledgments and venue.md requirements; the facts; all five statements with a redraft after an invented URL and license; a clean PASS; redrafts ending in a placeholder; each check; credit without authors. |
| Usage | `from auto_research.tasks.statements import paper_statements` |

## Not covered

- Registering the task in the program's task list and app.
- Journal-specific wording templates (Nature's "Reporting summary", PLOS's submission-form fields); the statements are written for the end of the paper.
- Checking that a URL resolves or a grant id is real; only that it comes from the project's files.
- Affiliations as facts beyond venue.md, project.md and rules.json notes (the `\author` block's affiliations are not parsed).
