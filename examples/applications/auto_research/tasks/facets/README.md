# facets tool

`facet_ideas` breaks the project's paper and the works it cites into facets and recombines them into research ideas (`tasks/facets/`). It takes the project's Git repository as `paper_dir` (anything else raises `ValueError`), writes into `<out_dir>/<timestamp>/` with a trail (`run.json`, `run.md`), and returns JSON with `status`, `report` and `run`. The report is in Simplified Chinese. Code checks every facet's quote and builds the recombinations; the novelty check is idea_generation's own search and assessor, reused unchanged.

Learned from Scideator (papers broken into purpose, mechanism and evaluation facets, recombined across papers into ideas, each checked for novelty).

## facet_ideas

| Item | Contract |
| --- | --- |
| Signature | `facet_ideas(paper_dir, count="6", out_dir="")` |
| Purpose | Ideas for the project that keep what it is about and borrow one concrete facet from a work it already cites, each with where every facet came from and how new it is. |
| Input | `paper_dir`: the project's Git repository; the title and abstract come from the main `.tex` (`scouting.common.paper_text`, the project's claim when there is no abstract), the works from its `.bib` files (`library.resolve.entries`), those the paper cites first in citation order, at most 40. `count`: 1 to 8 (default 6; empty is 6). `out_dir`: default `<paper_dir>/drafts/facet_ideas`. A `count` out of range, or no abstract and no claim, raises `ValueError`. |
| Gather | Abstracts from Semantic Scholar's batch API (one POST for every entry with an arXiv id or DOI, `scouting.common.post`), then OpenAlex (`works/doi:<doi>`, else a title search whose best hit has title similarity ≥ 0.93), then the arXiv API (`survey.search.arxiv_ids`). An entry without an abstract is left out and named. |
| Model calls | `decomposer` (`decompose`, schema `paper_facets`): one call per ten works (the project counts as one, id `PROJECT`): purpose, mechanism and evaluation, each a short English phrase with a quote from that abstract, or empty when the abstract does not say it. `writer` (`write_ideas`, schema `facet_ideas`): one call; `min(count, recombinations)` ideas, each naming its recombination, with title, the idea paragraph, hypothesis, outcome, effort, risk (Simplified Chinese) and one to three English queries. `assessor` (idea_generation's role, `ideas.workflow.study`): one call for all ideas. |
| Check and recombine (code) | A facet is kept when its quote has three or more words and occurs in its abstract (whitespace, typographic quotes and case ignored); others go to `dropped`. A reply that names an unknown work, repeats one or leaves one out raises. Recombination: for each work and each of its facets, the project's facets with that kind swapped for the work's; a facet whose word set overlaps the project's facet of the same kind by Jaccard ≥ 0.5 is skipped; the same facet text from two works is one recombination (`also_from`). The list is taken round-robin over the works (each work's first facet, then its second, ...) and the first 60 go to the writer. The writer must name distinct recombinations it was given, exactly the number asked, each with a query and a known effort. |
| Novelty and rank | `ideas.workflow.study`: every query searched in arXiv, Semantic Scholar and OpenAlex (the last six years), the eight closest records per idea, the assessor's verdict (novel, unverified, incremental, known) with feasibility and impact; an idea whose search found no record is unverified. `ideas.workflow.rank`: known ideas last, then novelty, feasibility, impact (no tournament, so every Elo is 1200). |
| Output | JSON with `status`, `report` (ideas.md), `ideas`, `facets`, `run`, `works`, `candidates`, `novelty` (counts), `unavailable_sources`. `FAIL`: every idea is known, or no idea could be made (no abstract, no recombination). `PASS_WITH_NOTES`: no idea is novel, a source failed, a work had no abstract, or a facet was dropped. `PASS` otherwise. Files: `ideas.md` (ranking table; per idea the paragraph, hypothesis, outcome, risk, each facet with its source work and quote, novelty, closest records, queries; then every work's facets), `ideas.json`, `facets.json` (the project's and every work's facets with quotes and abstract source, every recombination, what was dropped and why), `run.json`, `run.md`. |
| Merging with idea_generation | `ideas.json` has idea_generation's layout (`status`, `topics`, `unavailable_sources`, `ideas`), and each idea carries every field idea_generation writes (`id`, `title`, `hypothesis`, `approach` = the idea paragraph, `outcome`, `effort`, `risk`, `gaps` = `facet:<kind>:<work or PROJECT>`, `queries`, `elo`, `wins`, `losses`, `beat`, `lost_to`, `novelty`, `closest`, `differentiation`, `feasibility`, `impact`, `note`, `rank`) plus `facets`, `swapped`, `work`, `candidate`, `made_by: facet_ideas`. Ids start with `F`, so they never collide with idea_generation's `I` ids. To merge, the author appends the `ideas` list of this file to the `ideas` list of an idea_generation run's `ideas.json` (and, if wanted, the idea sections of `ideas.md` after its own); idea_generation's renderer reads the merged file. |
| Effects | Network: Semantic Scholar, OpenAlex, arXiv. Reads the paper and `.bib`; never writes them or `workflow/`. |
| Tests | `tests/facets/test_facet_ideas.py`: scripted decomposer, writer and assessor with abstracts and searches replaced: a facet with a quote not in its abstract dropped, a facet that repeats the project's skipped, the round-robin order of recombinations, the facet sources in `gaps`, the ranking with a known idea last, the idea_generation fields and renderer, the stage order; writer replies with a repeat or the wrong number; a run with no abstract is FAIL, not an exception; abstracts from Semantic Scholar, OpenAlex by DOI and by title, and arXiv. |
| Not covered | Recombinations that swap two facets at once or combine facets of two cited works without the project's; works outside the `.bib`; full text beyond the abstract. |
| Usage | `from auto_research.tasks.facets import facet_ideas` |
