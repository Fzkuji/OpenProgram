# sweep

The `hparam_sweep` task of auto_research (`tasks/sweep/`). It runs the experiment's Command once per trial with hyperparameters a sampler proposes, records every trial in `workflow/results.tsv` on its own branch, and reports the best setting, how much each parameter matters and what to do next. Plain code, no model calls.

Learned from Ax / BoTorch (an initial space-filling design, then a model of the results choosing the next trial) and Optuna (TPE through ask-and-tell, failed trials told as such, parameter importance).

## hparam_sweep

| Item | Contract |
| --- | --- |
| Signature | `hparam_sweep(paper_dir, space, trials="12", budget="300", out_dir="")` |
| Purpose | The author learns which hyperparameters of the experiment give the best metric, and which of them matter, with every trial recorded and reproducible from its commit. |
| Input | `paper_dir`: the project's Git repository with `workflow/experiment.md` (`Command` and `Metric` required; `Direction` lower unless `higher`; `Budget` limits one trial, 600 s when unreadable; `Edit` may name JSON configs). `space`: `;`-separated `name=spec`: `low..high` (integer range when both ends are integers, else float), `low..high log` (log scale, above 0), or `a,b,c` (two or more choices, read as int, float, true/false or text). Dotted names (`optim.lr`) address nested JSON keys. At most 12 parameters. `trials`: 1 to 200, empty is 12. `budget`: seconds for the whole sweep (`300`, `10 min`), empty is 300. `out_dir`: default `<paper_dir>/drafts/hparam_sweep`. A malformed space, trials or budget, a missing Command or Metric, or a parameter that cannot reach the program raises `ValueError`. |
| Delivery | Read at the reference commit. The Command's script is its first `.py` token (or `-m module`); its `add_argument("--name", ...)` calls are read from the syntax tree (the `dest` keyword wins). Each parameter goes by every route it has: `cli --name value` appended to the Command when the script declares the option and the Command is one simple command (no `&&`, `|`, `;`, redirections); the key in each JSON file of `Edit` that holds it, rewritten in the trial's commit; and `AR_PARAMS`, an environment variable always set to a JSON file of the trial's parameters. A parameter with no CLI option, no JSON key and a script that never mentions `AR_PARAMS` raises. Writing both config and CLI covers scripts where one overrides the other. |
| Process | The reference is the best kept run of results.tsv that is a commit (`ablation.reference`), else HEAD. One worktree on a new branch `sweep/<date>` (`-2`, `-3` when taken) from it. Per trial: the sampler proposes, the JSON configs are rewritten from the reference's content, the trial is committed (`sweep trial k: params`, empty when no config changed), Command runs in the worktree with the options and `AR_PARAMS` within min(experiment.md Budget, time left), and the last `<Metric>: <number>` of the output is the metric. A new trial starts only with at least a second of the budget left. |
| Sampler | Optuna TPE (`TPESampler(seed=0)`, ask-and-tell; a trial without a metric told as FAIL) when `optuna` imports. Otherwise a Latin hypercube for the first max(3, trials/2) trials (each range split into that many strata, each used once; choices in turn), then Gaussian steps around the best trial in unit (or log-unit) scale, sigma 0.2 × 0.75^step, a choice switched with probability 0.3, never repeating a tried setting. Floats are kept to 4 significant digits. |
| Record | One results.tsv row per trial: `commit`, `metric`, `status`, `seconds`, `description` (`sweep: name=value ...`, the outcome when not ok), `branch`, `parent` (the reference commit when it is a kept run); `branch` and `parent` columns are added when missing. `keep` when the metric beats the branch's best so far, which starts at the reference metric when the reference is kept (what `checks.branches` asks), `discard` otherwise, `crash` without a metric (nonzero exit, timeout, no metric line). |
| Importance | Per parameter, over trials with a metric (three or more): trials grouped by level (the choice, or the value when three or fewer distinct ones, else low/mid/high thirds by rank), η² = between-group variance / total variance, with each level's mean and the best level. A rough estimate: parameters sampled together share credit. |
| Output | JSON with `status`, `report`, `json`, `run`, `branch`, `sampler`, `trials`, `kept`, `crashed`, `best` (`params`, `metric`, `commit`), `importance`. `FAIL`: no trial gave a metric. `PASS_WITH_NOTES`: a trial crashed, the budget stopped the sweep early, or experiment.md's Budget was unreadable. Files in `<out_dir>/<timestamp>/`: `report.md` (Chinese: reference, routes, best setting, all trials, importance, recommendations), `sweep.json`, `logs/trial-k.log`, `params/trial-k.json`, `run.json`, `run.md`. |
| Recommendation | Whether the best beats the reference (merge its commit and add a `merge` row) or not (check that the reference reproduces with clean_rerun); a best value in the outer tenth of its range (widen it); a parameter explaining half the variance or more (sweep it alone next); always: rerun the best with several seeds and test it with claim_stats. |
| Effects | Appends to `workflow/results.tsv`, creates the `sweep/...` branch with one commit per trial; the worktree is removed, the branch stays. Runs the experiment's own Command. Never changes the main working tree's files other than results.tsv. |
| Dependencies | Optional `optuna` (pinned `optuna==4.5.0`), imported lazily; without it the plain sampler is used. |
| Tests | `tests/sweep/test_sweep.py`: a tiny repository whose script takes `--lr` by argparse, a nested config key and `AR_PARAMS`; every trial really runs; the rows against `checks.branches`, the trial commit's config, crash rows, the budget stopping the sweep, delivery errors, space parsing, the Latin hypercube and local search, importance and edges, and the Optuna path with a fake module. |
| Usage | `from auto_research.tasks.sweep import hparam_sweep` |

## Not covered

- Several seeds per setting, multi-objective sweeps, and trials run in parallel.
- Parameters that reach the program only through environment variables of their own name, or YAML/TOML configs.
- Merging the best trial back; the author does it and adds the `merge` row.
