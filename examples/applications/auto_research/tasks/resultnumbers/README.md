# resultnumbers tool

One tool that checks the paper's own result numbers against the runs that produced them (`tasks/resultnumbers/`). It takes the project's Git repository as `paper_dir` (anything else raises `ValueError`), writes into `<out_dir>/<timestamp>/` with a trail (`run.json`, `run.md`), and returns JSON with `status`, `report` and `run`. The report is in Simplified Chinese. Plain code extracts, compares and recomputes; one role maps only the numbers code could not, and every quote and source it gives is checked in code.

Learned from PaperDelta, Agent-Cockpit, celsus and arXiv 2610.38691 ("Beyond fabrication": most unsupported numbers in agent-written papers come from the wrong experiment, metric or run).

## result_numbers

| Item | Contract |
| --- | --- |
| Signature | `result_numbers(paper_dir, out_dir="")` |
| Purpose | Find result numbers in the paper that no longer match their run (stale), that belong to another run, metric or split (misattributed), and derived claims ("26% lower", "outperforms") that the current numbers no longer support. |
| Input | The main .tex (`workflow/rules.json` `main_tex`, else the top-level file with `\documentclass`; `ValueError` when none) and its `\input` files. `workflow/results.tsv`, `evidence.csv`, `experiment.md` (`Metric`, `Direction`), and the files evidence rows name as `source` (globs allowed; `.env` and files over 2 MB skipped). |
| Numbers (plain code) | Table rows without a `\cite` (reusing `reading/sota.py`'s table parsing): every numeric cell with its column header, row method and caption. Sentences (`revision`'s paragraph and sentence splitter): every number with a decimal point or `\%` not within 60 characters of a `\cite` (those are baseline_numbers'). Settings are skipped: a number after learning rate, weight decay, batch size, seed, dropout, momentum, temperature… or before epochs, steps, examples, layers… The split (test, val, train) and metric word nearest the number, or in the header and caption, are kept as hints. |
| Derived claims (plain code) | `X\% lower/higher/better/…`, `reduces/improves … by X (\%, points)`, `X points gain`, `X× / X-fold / X times faster`, `from A to B`, and `outperforms/beats/better than/lower … than` without a number. The stated number is not checked as a plain number. |
| Sources (plain code) | Every non-crash row of `results.tsv` as (run = branch, else description without `seed N`; seed; metric = experiment.md `Metric`; split from the metric name; commit). The seed mean of a run with two or more seeds. Evidence `value` cells. CSV/TSV sources by column (metric-like columns are values; the others name the run; `split` column or split from the column name), JSON by key path (a split word in the path is the split, the last key the metric; a list of records reads as a table), logs (`.log`, `.txt`, `.out`) by `name: value` / `name=value`, the last value of each name. Each source file is also parsed in its last 20 Git revisions. The current entry of an identity (file, run, seed, metric, split) is its latest `keep` row (else its latest row) in the working tree; earlier rows and earlier revisions are history. |
| Mapping | Code: the value (compared as below) is held by exactly one current identity under the hinted split and metric → that identity; else held only in the history of one identity → that identity. The rest go to `mapper` (`map_numbers`, schema `number_sources`), up to 40 numbers and 40 derived claims per call, with a listing of at most 400 current entries: per number kind `result`/`not_result`/`unsourced`, `source` (entry id) or evidence, commit, run, metric and split, and a quote; per derived claim the subject `a` and reference `b` entries. A derived claim whose sentence holds exactly two mapped numbers (subject first), or `from A to B`, takes its operands in code. An answer whose quote is not in the paper or does not contain the number, or that names no listed entry (or the same entry twice), is dropped (counted); an id it was not shown raises. |
| Comparison | Exact decimals at the precision of the less precise side, never rounding away the paper number's first two significant digits; a fraction is read as a percentage next to a number above 1.5 or written with `\%`. |
| Verdicts | `match`: the identity's current value. `stale`: the identity now holds another value (the old one is reported from an earlier row or Git revision when found). `misattributed`: the value is another current identity's (another run, metric or split). `derived_wrong`: recomputed from the operands' current values (relative = abs(a − b)/abs(b)·100; absolute = abs(a − b), in points when the operands are fractions; ratio = larger/smaller) it differs at the stated precision, or the direction (lower, higher, better by `Direction`, else lower for loss/error-like metrics) does not hold. `unsourced`: no mapping. `not_result` numbers are left out. Each mapped item also shows when its paper line last changed (`git blame`) and when the source file did, and whether the source changed after the line. |
| Output | `workflow/result_numbers.csv`: `id, kind (number, derived:<kind>), location, value, status, file, evidence, run, seed, metric, split, commit, current, found_in, recomputed, how (code, mapper), context, edit`; rows the author set to `ignore` are kept and the same location and value are not judged again. `edits.json` in paper_proofread's format (`{root, edits: [{id, file, section, kind: result_number, quote, replacement, problem}]}`): a stale or misattributed number replaced by its identity's current value, a derived number by its recomputed value, written with the paper's decimals; replacements in overlapping spans are one edit, and only quotes that occur once in their file are proposed, so `proofread.apply_edit` applies each. `numbers.json` (every item), `report.md`. `FAIL`: any stale, misattributed or derived_wrong. `PASS_WITH_NOTES`: only unsourced numbers, no numbers at all, or an evidence source that could not be read. `PASS`: all match. |
| Effects | At most one model call per 40 unmapped items; none when code maps everything. Writes `workflow/result_numbers.csv` and the report folder. Never edits the paper. |
| Tests | `tests/resultnumbers/`: decimal comparison and rounding; numbers, settings, cited numbers and each derived kind from a paper with an `\input` file, located in the right file; a project mapped fully in code that passes; a rerun appended to results.tsv that makes two numbers stale and the "26% lower" claim wrong, a test-split value written as validation that the scripted mapper maps to the validation entry (misattributed), and the three edits applied with `apply_edit`; a JSON source overwritten in a later commit, found stale through Git history; mapper answers with an unknown source or a quote not in the paper dropped; ignored rows kept. |
| Not covered | Numbers in figures, numbers without a decimal point or `\%` in running text, numbers within 60 characters of a `\cite`, values a source does not hold under a name (computed only in a plotting script), and confidence intervals as such (the mean is checked). |
