# impact tasks

The `impact_forecast` and `tech_transfer` tasks of auto_research (`tasks/impact/`). `impact_forecast` estimates the paper's citations at one, two and three years from comparable published works, as citation forecasting does. `tech_transfer` places the work on the technology readiness scale and maps the patents around its claims, as a technology transfer office's commercialization report does.

Learned from HLM-Cite and "newborn article" impact prediction, Scite and OpenAlex citation trajectories, and academic commercialization agents (TRL assessment and patent landscape).

## impact_forecast

| Item | Contract |
| --- | --- |
| Signature | `impact_forecast(paper_dir: str, venue: str = "", out_dir: str = "") -> str` |
| Purpose | The author sees what citations comparable work reached at one, two and three years, how their own paper compares once published, and which traits go with more citations. |
| Input | `paper_dir`: the project folder; the title and abstract come from the main .tex (project.md's claim stands in for a missing abstract). `venue`: the target venue; empty reads venue.md `Name:` or `Venue:`, else the family venue.md names. `out_dir`: default `<paper_dir>/drafts/impact_forecast`. The published version is rules.json `published` or project.md `Published:` (OpenAlex id, DOI or arXiv id), as after_release reads it. No title and no abstract raises `ValueError`. |
| Process | Comparables: OpenAlex works (article, preprint, conference paper) published 3 to 6 years before today, from a search by the title, a search by the abstract's first sentence (30 words) and a seeded random sample of 100 works of the primary topic. The topic is the published version's when its title matches the paper's (equal, or TF-IDF cosine 0.6), else the one the ten most similar candidates share, weighted by similarity. Similarity = 0.6 × TF-IDF cosine of title and abstract (scaled to the best candidate) + 0.25 × same primary topic + 0.15 × same venue (venue keys of tasks/scouting/venues.py). A known conference or journal keeps only that venue type when ten or more remain. The 30 nearest give weighted 25/50/75% quantiles (midpoint rule) of cumulative citations at each horizon; horizon k of a work of year Y ends with Y+k−1 (published January to June) or Y+k, and a horizon not over yet is left out. Factors over all candidates' two-year citations: median with and without a code link in the abstract and with and without an arXiv version (a group under 5 is not compared), Spearman ρ of the number of authors. The published version's citations at each started horizon are placed below, within or above the band. |
| Output | JSON with `status`, `report`, `json`, `run`, `comparables`, `forecast` (`q25`, `q50`, `q75`, `n` per horizon), `actual`, `unavailable_sources`. `PASS_WITH_NOTES`: a source failed, a horizon has fewer than 10 comparables, the type filter could not apply, or the published version is missing or has another title. Files in `<out_dir>/<timestamp>/`: `report.md` (Chinese; table, inline SVG of the median and band with the actual points, factors labelled as correlation, the 15 nearest works), `forecast.json`, `run.json`, `run.md`. |
| Effects | Reads OpenAlex (`OPENALEX_API_KEY` when set) through `sources.fetch`. Writes only its run folder. |
| Model calls | None. |
| Tests | `tests/impact/test_forecast.py`: fake OpenAlex; the band, type filter and exclusion of the paper's own record; horizons by publication month; actual citations against the band; factors; a failing source; topic from similar works; a published version with another title; quantile and Spearman pieces. |

## tech_transfer

| Item | Contract |
| --- | --- |
| Signature | `tech_transfer(paper_dir: str, out_dir: str = "") -> str` |
| Purpose | The author knows how ready the result is for use outside the lab, by evidence they can point to, and which patents and companies are near its claims. |
| Input | `paper_dir`: the project folder with workflow/claims.md. `out_dir`: default `<paper_dir>/drafts/tech_transfer`. Environment: `USPTO_API_KEY` (USPTO Open Data Portal, header `X-API-KEY`; `USPTO_ODP_URL` overrides `https://api.uspto.gov/api/v1/patent/applications/search`), `PATENTSVIEW_API_KEY` (header `X-Api-Key`; `PATENTSVIEW_URL` overrides `https://search.patentsview.org/api/v1/patent/`). No claims raises `ValueError`. |
| Process | Rows with ids: `claim:C1`, `evidence:E1`, `results:<commit[:12]>`, `experiment` (experiment.md fields), `abstract`. The assessor gets the NASA and EU TRL definitions side by side. Check: each evidence quote must be found verbatim (case and whitespace ignored, four words or more) in the row it cites, else dropped; a level above 3 without a valid `evidence:` or `results:` citation is capped at 3; a search phrase with a word not in the rows is dropped (fallback: the claims' first content words). Patents (`patents.py`), sources in order, the first configured one that answers is used: (1) ODP patent application search, one POST per phrase `{"q": "applicationMetaData.inventionTitle:(w1 AND w2 ...)", "fields": [...], "sort": [{"field": "applicationMetaData.filingDate", "order": "desc"}], "pagination": {"offset": 0, "limit": 25}}`; from `patentFileWrapperDataBag`: patent number (grant) or earliest publication number (application), title, grant or publication date, `cpcClassificationBag`, assignees from `assignmentBag[].assigneeBag[].assigneeNameText`, else applicants; HTTP 404 means no match; ODP search has no abstract, so for the patents kept `associated-documents` is read and, when it names a single grant or pre-grant XML (not a weekly bulk zip), its abstract and claims are parsed. (2) PatentsView PatentSearch, one POST per phrase `{"q": {"_or": [{"patent_abstract": {"_text_all": phrase}}, {"patent_title": {"_text_all": phrase}}]}, "f": [patent_id, patent_title, patent_abstract, patent_date, assignees.assignee_organization, cpc_current.cpc_group_id], "s": [{"patent_date": "desc"}], "o": {"size": 25}}`. Merged by number; the 10 closest kept (phrases matched, then TF-IDF cosine with the claims). Overlap: every patent × claim pair once; the quote must be in the patent's abstract or claims, or, for a patent with neither, in its title (two words or more, overlap at most medium); otherwise the pair is "unverified". Companies of an application area: the assignees (else applicants) of the patents the patent_reader put in it, nothing else. |
| Output | JSON with `status`, `report`, `json`, `run`, `trl`, `capped`, `patents`, `patent_source` (`USPTO ODP`, `PatentsView`, `not configured` or `unavailable`), `unavailable_sources`. `PASS_WITH_NOTES`: no key, a source refused (401/403) or did not answer, a quote or phrase dropped, the level capped, a pair unjudged or unverified, judgements from titles only, or no valid evidence. Files in `<out_dir>/<timestamp>/`: `report.md` (Chinese: level with NASA and EU wording, quoted evidence, what the next level needs, the source used, patent table with Google Patents links and applications marked, a bold line when the judgement rests on titles only, overlaps with quotes, application areas with companies), `transfer.json`, `run.json`, `run.md`. |
| Effects | Requests go only to configured sources; a source that refuses or does not answer is skipped for the next. Writes only its run folder. |
| Model calls | `assessor`: one call (level, evidence quotes, reason, next level, 2–4 phrases, 1–5 application areas). `patent_reader`: one call when patents were found (overlap per pair with a quote, areas per patent). |
| Tests | `tests/impact/test_transfer.py`: scripted roles; requests faked in the documented shapes (ODP `PatentDataResponse` with `patentFileWrapperDataBag`, associated-documents, grant XML; PatentSearch `{error, count, total_hits, patents}`); no key; ODP first with abstract from XML; titles only when only a bulk zip exists; ODP refused falls back to PatentsView; ODP 404 as no match; a silent PatentsView; the cap; foreign phrases; an unknown patent in the reply; XML and publication-number parsing. |

## Not covered

- PatentsView moved to the USPTO Open Data Portal on 20 March 2026 and its PatentSearch API is suspended with no announced return; search.patentsview.org does not answer, so ODP is tried first. The ODP request shape follows the ODP swagger (data.uspto.gov/swagger/swagger.yaml); live, the endpoint answers 401 without a key and 403 with an invalid one, and a run with a real key has not been made.
- Whether ODP's associated-documents names a per-application XML (abstract and claims) or only the weekly bulk zip; with only the zip the overlap rests on titles and the report says so.
- A patent search without any key: Google Patents is not scraped, OpenAlex holds no patents or patent-to-paper citations, and the USPTO's Patent Public Search (ppubs.uspto.gov) requires a USPTO.gov sign-in from 4 December 2026, so every US route needs the author's own registration.
- Whether a comparable released code is read from its abstract only (Papers with Code is closed); when its arXiv version appeared is not in OpenAlex.
