# publist tools

The `publication_list` task of auto_research (`tasks/publist/`). The project page task (`project_page`, `tasks/outreach/`) builds one paper's page; this one keeps the author's whole publication list: every work from OpenAlex, ORCID and DBLP once, with its links and a one-line summary, as a static page, a .bib and a JSON record the author can copy into the project's `docs/`.

Learned from BibBase (a publication page generated from a .bib), Google Scholar profiles (versions of one work merged into one entry), ORCID (works the researcher claimed) and academicpages (a static, self-hosted publications page grouped by year).

## publication_list

| Item | Contract |
| --- | --- |
| Signature | `publication_list(paper_dir, author="", out_dir="")` |
| Purpose | The author has one complete, deduplicated list of their publications with links, and knows which works might belong to someone else of the same name. |
| Input | `paper_dir`: the project's folder. `author`: a name, an ORCID iD (or orcid.org URL), an OpenAlex author id (`A…` or its URL) or a DBLP pid (`34/10307` or its URL); empty takes the paper's first author (LaTeX `\author`, then project.md `Authors:`, venue.md `Authors:`, rules.json `required_authors`). `out_dir`: the output folder (default `<paper_dir>/drafts/publication_list`). A missing folder, or an empty `author` with no author in the paper, raises `ValueError`. |
| Author | ORCID iD: OpenAlex profiles carrying it (`/authors?filter=orcid:`), the name from the ORCID record; with none, a name search among profiles without another ORCID, marked unsure. OpenAlex id: that profile. DBLP pid: the name from DBLP's SPARQL endpoint, then a name search where titles shared with the DBLP works count. Name: `/authors?search=`, same-name matches only (surname and first name or initial); for the five largest, up to 100 works are read and the profile sharing most with the current paper wins (2 per shared coauthor of the paper, 1 per affiliation named in the LaTeX source, 1 per shared DBLP title); with no overlap the one with most works wins, unsure when another has a third of its works or more. Every other match is listed. |
| Works | OpenAlex: every work of the chosen profiles (200 a page, at most 10 pages), with authors, the author's institution on each work, abstract, open-access PDF and arXiv id from its locations. ORCID: `pub.orcid.org/v3.0/<id>/works` (JSON), one work per group with DOI, arXiv id, type, year, journal. DBLP: its SPARQL endpoint (`sparql.dblp.org`, the interface DBLP offers scripts; its web pages and search API answer scripts with a bot check): authors by `dblp:creatorName`, then each work's title, year, DOI (arXiv DOIs give the arXiv id), venue, type and ordered authors; among same-name hits (at most 3) the one sharing most titles with OpenAlex and ORCID, none when no title is shared. A bot check answer is recognised, DBLP is skipped and noted, never bypassed. DOIs that ORCID or DBLP list and OpenAlex's profile lacks are looked up in OpenAlex (50 a request) for authors, abstract and PDF. |
| Merge | Errata, corrections, paratext, peer reviews, datasets and supplements are left out with their reason. The rest are joined by DOI, then arXiv id (an arXiv DOI `10.48550/arxiv.X` counts as the arXiv id), then title with case, punctuation and spaces dropped (one-word and generic titles never match), then a title of 40 or more characters that starts or ends another within a year. The first published version leads (venue, year, DOI); every other venue is kept as a version, one per DOI or venue name. A coverage check confirms every source record is in exactly one entry or left out, and no two entries share a DOI, arXiv id or title. |
| Links | arXiv, DOI, PDF (OpenAlex best open-access location, else arXiv), code (Hugging Face Papers `githubRepo` for up to 200 arXiv ids, else a GitHub repository the abstract links, as in `tasks/baselinecode/`), project page on the current paper's entry (matched by title or project.md `Published:` arXiv id): rules.json `project_url`, else `index.html` when `docs/index.html` exists. Abstracts missing for arXiv works come from the arXiv API. |
| Check | Summaries: dropped when the work has no abstract, has more than 30 words, or has a number (two or more digits, or a decimal) not in the abstract. Namesake flags: overruled when the work shares a coauthor (of the ORCID-listed works when three or more have authors, else of two or more unflagged works, plus the paper's coauthors), a venue of two or more unflagged works, or the author's institution on two or more unflagged works or in the profile; a remaining flag is kept on an ORCID-listed work and excluded otherwise. |
| Output | JSON with `status`, `report`, `page`, `bib`, `json`, `run`, `author`, `entries`, `merged`, `uncertain`, `unavailable`. `FAIL`: no work found, or the coverage check fails. `PASS_WITH_NOTES`: an excluded namesake work to confirm, an unsure author choice, a source unavailable or skipped (a DBLP bot check), or another note. `PASS` otherwise. Files in `<out_dir>/<timestamp>/`: `publications.html` (self-contained, no JavaScript, light and dark, grouped by year with authors, the author in bold, venue and other versions, summary, links), `publications.bib` (`@inproceedings`, `@article`, `@misc` with eprint for preprints and patents, `@incollection`, `@book`, `@phdthesis`), `publications.json` (author, alternatives, entries, excluded, overruled flags, left-out records, dropped summaries, counts, notes), `report.md` (Chinese: the author choice, sources, works to confirm, overruled flags, merged versions, the `cp` commands to put the page in `docs/`), `run.json`, `run.md`. |
| Effects | Reads OpenAlex (`OPENALEX_API_KEY` when set), ORCID's public API, DBLP, Hugging Face Papers and the arXiv API through `citations.sources.fetch`. Writes only the run folder; the page is copied into `docs/` only by the author. |
| Model calls | `curator`: one call per 30 works, a summary, a namesake flag, a field and a reason for each. |
| Failure | A reply that misses or repeats a work raises. A source that fails is a note. Rerunning is safe. |
| Tests | `tests/publist/test_publist.py`: a fake fetch for every source and a scripted curator; profile choice by a shared coauthor, preprint and published versions merged, ORCID works filled by DOI, an erratum left out, code from Hugging Face and from an abstract, the project link, a dropped summary, flags excluded, overruled by a coauthor and kept by ORCID, the page, .bib and report; an ORCID iD input with DBLP works and an arXiv abstract passing; the first author as default; no author; every source down; a malformed reply; author input kinds; the merge rules (spacing, prefixed titles, generic titles, conference and journal versions). |
| Usage | `from auto_research.tasks.publist import publication_list` |

## Not covered

- Registering the task in the program's task list and app.
- Recording the author's own decision on an excluded work other than by adding it to ORCID (a later rerun then keeps it).
- Google Scholar profiles (no public API); DBLP only if its SPARQL endpoint ever answers with a bot check.
- Citation counts and metrics on the page.
