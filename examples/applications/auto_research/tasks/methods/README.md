# methods tools

Two tools that check the experiments' method before their numbers go into the paper (`tasks/methods/`). Each takes the project's Git repository as `paper_dir` (anything else raises `ValueError`), writes into `<out_dir>/<timestamp>/` with a trail (`run.json`, `run.md`), and returns JSON with `status`, `report` and `run`. Reports are in Simplified Chinese. Plain code does the checking; a role only reviews what code found or proposes experiments, and every quote a role gives is checked in code.

Learned from scicode-lint and LeakageDetector 2.0 (leakage patterns read from the syntax tree), MLE-STAR's data-leakage checker (a model reviews the code the pipeline runs), and POPPER (sequential falsification of a hypothesis, with e-values combined by product).

## method_lint

| Item | Contract |
| --- | --- |
| Signature | `method_lint(paper_dir, out_dir="")` |
| Purpose | Find methodology errors in the experiment code that make the reported result untrustworthy. |
| Input | The `.py` files of `workflow/experiment.md` `Edit`, the script its `Command` runs (`python x.py`, `python -m pkg.mod`), and the modules they import from inside the repository (relative and absolute imports; at most 50 files; `.git`, `drafts/`, `workflow/`, virtualenvs and `.env` skipped). `ValueError` when none is found. |
| Rules (plain code, AST) | Each has an id, severity, explanation and fix (`rules.RULES`). high: `preprocess-before-split` (fit/fit_transform of a scaler, encoder, vectorizer, PCA, imputer before `train_test_split`/`KFold.split`/`cross_val_*`/a search's fit in the same scope, data not train-named), `selection-before-split` (SelectKBest, RFE, SelectFromModel, mutual_info_* … on all data before the split), `test-in-tuning` (a test-named variable passed to a call inside a hyperparameter loop or an early-stopping loop with best/patience), `target-leakage` (`y = df["label"]` then `X = df` / `df.drop(...)` without the label / `df[[..., "label"]]`; a feature list with a column named like target/label/outcome/future_*), `evaluate-on-train` (metrics only on train-named data, none on held-out data), `metric-same-split` (`m.fit(A)` then `m.predict(A)`/`m.score(A)` feeding a metric, A not train-named). medium: `no-seed` (per library — random, NumPy, PyTorch, scikit-learn — randomness used and no file sets its seed; `set_seed`/`seed_everything` cover all, `np.random.seed` covers scikit-learn), `shuffled-cv-time-series` (date/time columns, a shuffling split, no `TimeSeriesSplit`). low: `duplicates-unchecked` (a split and no `drop_duplicates`/`duplicated`/`unique`/intersection check). |
| Model call | `reviewer` (`review_file`, schema `method_review`), one call per file, at most 8 files (files with findings first, highest severity first, then the command's script and edited files), 40k characters each with line numbers. Per AST finding: `confirm` or `dismiss` with a quote; at most 5 own findings with rule, severity, finding, fix and a verbatim quote. `check_review`: a verdict whose quote is not in the file (whitespace runs compared as one space) leaves the finding `open`; an own finding without such a quote is dropped, and its line is where the quote starts. Own findings' rules are `review:<kebab-id>`. |
| Output | `workflow/method_lint.csv`: `file, line, rule, severity, finding, fix, status (open, confirmed, dismissed, ignore, fixed)`. Unresolved = `open` or `confirmed`. `FAIL`: an unresolved high. `PASS_WITH_NOTES`: an unresolved medium or low, or a file that does not parse. JSON also has `method_lint, files, unparsed, high, medium, low, high_findings`. File: `report.md`. |
| Author edits | Set `status` to `ignore` or `fixed`. A rerun keeps it when the same file and rule come back with the same finding text or line, and keeps the marked row when the finding is gone. |
| Effects | One model call per reviewed file. Writes `workflow/method_lint.csv` and the report folder. |

## claim_stats

| Item | Contract |
| --- | --- |
| Signature | `claim_stats(paper_dir, mode="tests", alpha="0.05", out_dir="")` |
| Purpose | Show whether each claim's "A is better than B" holds beyond seed noise; in popper mode, plan and score experiments that try to refute it. |
| Input | `workflow/claims.md` (`ValueError` without claims), `evidence.csv`, `results.tsv`, `experiment_plan.csv` (main claims: rows of kind `main`; every claim when there are none), `experiment.md` (`Metric`; `Direction: lower` makes smaller better, otherwise larger is). `mode`: `tests` or `popper`. `alpha` in (0, 1). |
| Per-seed numbers (plain code) | (1) `results.tsv` rows, when the claim's evidence has source `workflow/results.tsv` or a `claim` column names the claim: crashes, merges and `falsify:` rows left out; grouped by `branch`, else by `description` with `seed N` removed; seed from a `seed` column or `seed N`. With no seed anywhere, the best kept run alone stands for the claim (one seed). (2) `evidence.csv` rows of the claim with `method` (or model/name/system) and `value` columns, optional `seed`. (3) A `.csv`/`.tsv` an evidence `source` names with method, `seed` and metric columns (the Metric name, `metric`, `value` or `score`). Each source is its own table. |
| Tests | In each table the best method by mean against every other, or the evidence `compare` column `A > B` / `A < B`. Paired t test when both have the same two or more seeds, else Welch; t distribution through the regularized incomplete beta function (stdlib, no scipy); percentile bootstrap of the mean difference, 10,000 resamples, seeded, level `1 - alpha`. Flags: `single_seed` (a side with fewer than two seeds), `ci_crosses_zero`, `below_seed_std` (difference under the larger seed standard deviation), `not_better` (an explicit comparison going the other way), `no_data`. |
| Popper mode | `falsifier` (`propose_tests`, schema `falsification_tests`), one call per claim that has no tests in `workflow/falsification.md` yet: at most 3 tests with `run`, `refutes`, `command`, `better`, `worse` (`check_tests` rejects a test without run/refutes or comparing a method with itself). The file lists each under `### falsify:<claim>:<n>` with `Run`, `Refuted if`, `Command`, `Better`, `Worse`; the author may edit the fields. results.tsv rows whose text holds the tag are that test's runs, grouped by method label and seed. With both methods at two or more seeds, the one-sided p (better beats worse) becomes e = 1/(2√p) (Vovk–Wang calibrator, κ = 1/2, valid for any valid p; p floored at 1e-12); the claim's E is the product. `supported` when E ≥ 1/alpha; `not_supported` when every test is done and E is short; else `pending` (a test without rows, or `incomplete`). |
| Output | Per claim `verdict (pass, notes, fail)`, `main`, `flags`, and in popper mode `e` and `popper`. `FAIL`: a main claim with `single_seed`, `ci_crosses_zero` or `not_better`. `PASS_WITH_NOTES`: any other flag, or a claim not yet supported in popper mode. Files: `report.md`, `stats.json` (every table, group, comparison and test), `workflow/falsification.md` in popper mode. |
| Effects | Popper mode: one model call per claim without tests. Writes the report folder and, in popper mode, `workflow/falsification.md`. |

## Tests

`tests/methods/`: every AST rule on a leaky snippet and its fix; a fixture repository whose `train.py` has the leakage patterns (and imports `data.py`, which parses dates) and a clean version that passes; a scripted reviewer confirming, dismissing, quoting something not in the file and adding findings; author statuses kept across a rerun after the lines move; the t distribution against the closed forms for 1 and 2 degrees of freedom and table values, Welch and paired statistics, bootstrap and e-values against hand-computed values; a project whose loop claim crosses zero, whose ablation has one seed, and a popper run that a scripted falsifier plans and tagged results support.
