# citationcff tasks

The `software_citation` task of auto_research (`tasks/citationcff/`). It makes the paper's released code citable and checks that it is archived with a DOI the paper cites.

Learned from figshare and the Zenodo–GitHub integration (a release archived with a concept DOI, metadata from `.zenodo.json` or `CITATION.cff`), the Citation File Format 1.2.0 (`preferred-citation` pointing to the paper) and CodeMeta 3.0.

## software_citation

| Item | Contract |
| --- | --- |
| Signature | `software_citation(paper_dir: str, code_dir: str = "", out_dir: str = "") -> str` |
| Purpose | Anyone who uses the code finds how to cite the paper, and the code has an archived, resolving DOI that the paper itself cites. |
| Input | `paper_dir`: the paper's Git repository. `code_dir`: the code repository; empty uses `rules.json`'s `code.repo` when it is a local folder, else `paper_dir`. `out_dir`: the output folder (default `<paper_dir>/drafts/software_citation`). Not a Git repository, or a `code_dir` that is not a folder, raises `ValueError`. |
| Process | Gather (code): the title, abstract and `\keywords` of the main .tex; authors from the `\author` block, project.md or venue.md `Authors:`; affiliations from the lines after each name in `\author`, `\affiliation`/`\institution`, or a single `\affil`; ORCID iDs the paper writes; the version from the latest Git tag of the code (`v` dropped, its commit date as date-released), else `0.1.0` and today; the license of the code's LICENSE file (SPDX, whitespace folded), else the paper's; repository-code from rules.json `code.repo` when it is a URL, else the code's git remote; the paper's own arXiv id or DOI from rules.json `published`/`doi`/`arxiv` or project.md `Published:`/`DOI:`/`arXiv:`, kept only when arXiv or Crossref give it the paper's title; dataset locations from datasheet.md `Location` and croissant.json `url` (the dataset_release facts); programming languages by file count. ORCID (code): the public expanded search by given and family name; an iD is taken only when exactly one record has an institution matching the author's affiliation, or else exactly one of the first five records has a work titled like the paper or one of its references; otherwise it is left out with the reason. Archive (code): the repository's current name from GitHub (renames followed); Zenodo records titled `owner/name` or `name`, and DataCite DOIs found by `"owner/name"` and the title, kept only when a related identifier is inside the repository (by its old or current name); with no repository, DataCite records titled like the paper. The concept DOI is preferred, the newest version DOI kept beside it; the doi.org handle API says whether it resolves; main.tex and every .bib are searched for it. Describe (model): abstract and keywords. Ground (code): the abstract is dropped for the paper's first three abstract sentences when it has more than three sentences, a number not in the paper, a URL not in the facts, or a capitalized word past a sentence start that the facts never write; a keyword not in the paper is dropped, the rest take the paper's spelling (ImageNet, SGD). Write (code): the three files. |
| Validation | CITATION.cff against CFF 1.2.0 in code: required `cff-version` (1.2.0), `message`, `title`, `authors` (non-empty); only known top-level and person keys; each person has `family-names` or `name`; `orcid` as `https://orcid.org/XXXX-XXXX-XXXX-XXXX`; `date-released` as a date; `doi` and identifier values as DOIs or URLs; `license` an SPDX id; `keywords` strings; `preferred-citation` with type, title and authors, and an integer year. The YAML is read back with PyYAML (when installed) and must equal the data; cffconvert validates it too when it is installed. |
| Output | JSON with `status`, `report`, `run`, `files`, `doi`, `doi_resolves`, `cited_in`, `orcids`, `problems`. `FAIL`: CITATION.cff breaks the validation (no author is the usual cause). `PASS`: the files are valid, the archive DOI was found, resolves, and main.tex or a .bib cites it. `PASS_WITH_NOTES` otherwise. Files in `<out_dir>/<timestamp>/`: `CITATION.cff`, `.zenodo.json` (software upload, creators, SPDX license lower-cased, keywords, related identifiers: the paper `isSupplementTo`, the repository, datasets as `references`), `codemeta.json` (SoftwareSourceCode with author ORCIDs and affiliations, license URL, identifier DOI, referencePublication), `report.md` (Chinese: facts with their sources, ORCID taken or left out and why, the archive DOI, the `cp` commands into the code repository, and with no DOI the steps to enable Zenodo's GitHub integration plus a `@software` entry for refs.bib once the DOI exists), `citation.json`, `run.json`, `run.md`. |
| Effects | Reads the paper and code repositories and Git. Network reads only: pub.orcid.org, api.datacite.org, zenodo.org/api, doi.org handle API, arXiv or Crossref for the paper's own record, api.github.com for the repository's current name (`GH_TOKEN` raises its limit). A source that fails is named in the report. The paper and the code are never modified; no account is created and nothing is uploaded. |
| Model calls | `describer`: one call, an abstract of at most three sentences and three to eight keywords from the title, abstract and `\keywords`. |
| Failure | A reply that is not an abstract with keywords raises. Everything else is a drop or a note. Rerunning is safe. |
| Tests | `tests/citationcff/test_citation.py`: ORCID, DataCite, Zenodo, doi.org, arXiv and GitHub faked, the describer scripted; PASS with a cited concept DOI, ORCID by institution and by works, a unique but unmatched record left out; no archive (Zenodo steps and bib entry); found but not cited; an invented number and name dropped; no authors FAIL; ORCID down; a wrong own arXiv id left out; code_dir from rules.json with a multi-line Apache license; the validator; YAML round trip; name splitting and affiliations; keyword case. |
| Usage | `from auto_research.tasks.citationcff import software_citation` |

## Not covered

- Registering the task in the program's task list and app.
- Enabling the Zenodo–GitHub integration, making a GitHub release, or committing the files into the code repository: the report gives the steps and the `cp` commands, and the author does them.
- Software Heritage (`swh`) identifiers, funding (`.zenodo.json` grants) and contributor roles beyond authors.
- ORCID matches for names the ORCID search cannot split into given and family names.
